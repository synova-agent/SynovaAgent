# dev-doc-spec — 活规格撰写（技能化）

## 由来（组织形态变更，创始人 2026-09-23 批准）

原 `📋 synova-devdoc` 常驻 session 已于 2026-09-23 退役：近 7 天 dev doc 产物 **0 变更**，且该职责已被两处吸收——**规格 → CTO 派单件**（"派单即规格"，D821 起口径）、**验收标准 → 派单件 + K3 审计协议**。
本技能 = 把该职责的**能力**保留下来（去常驻成本、留能力），并把"独立规格"改为**触发式**要求。

## 何时必须启用（触发条件，三条满足任一）

1. **跨层改动**：触及两个及以上架构层（L1–L5）
2. **新产品线 / 新子系统**：首次落地、无既有范式可照抄
3. **超预算任务**：预计 >12 文件或 >2 天

不满足触发条件的任务：规格写进 **CTO 派单件**即可，不需要本技能。

## 独立性硬要求（不可放宽）

- **撰写者必须独立于实现者**：写了规格的成员**不得**实现该规格对应的代码（队长亦不得兼任——队长职责是协调与判前提）
- 规格是**独立交付物**，有自己的复核：过 `dev-doc-gatekeeper`（Q0-Q3 / 写集 / DS 清单 / Done 可证伪）+ K3 可核
- 规格**必须先落 main 可读**，实现方不得引用未落 main 的规格路径（小队队长预设禁令原文）

## 11 节活规格模板（逐节非空，缺节即退回）

1. **北星锚定**（front-matter：本任务服务于哪条产品线的哪个验收点）
2. **背景与现状证据**（每条事实性前提附 `命令 + 原始输出`；禁"我认为"）
3. **目标与非目标**（非目标必须逐条列路径）
4. **写集**（逐文件；两两不重叠；机器块格式对齐 `brief_parser.py`）
5. **契约**（输入 / 输出 / 降级 / 错误码；铁律 47）
6. **边界值清单**（每个数值/集合参数：空 / 单元素 / 恰临界（=阈值、=limit） / 超限 / 零 / 负值）
7. **验收标准**（三路径：正常 / 降级 / **反例**；反例 = "删掉即报红"的判别性夹具）
8. **失效条件**（这条规则/门禁何时可撤——无失效条件的规则不许进仓库）
9. **依赖与前置**（前置未满足 → 停，不抢跑）
10. **风险与上限**（写集互斥、重型验证串行、PR ≤12 文件 + 单域）
11. **DS 清单**（delivery statements：逐条可核验的交付声明，供 K3 复审）

## 验收（撰写完成后自检）

```bash
bash scripts/workflow/check-brief-parseable.sh <brief>      # 可解析
bash scripts/control-tower/pre-dispatch-check.sh <规格件>    # 机械项 + 引用可核验
bash scripts/workflow/check-dev-doc-write-set.sh            # 写集 vs 实际改动漂移 0
```

## 红线 · 状态不得自宣（2026-09-26 加，来源 K3 文档契约审计）

- **front-matter 的 `status:` 由流程决定，撰写者不得自宣**：
  `proposed` → （**K3 审计通过 + CTO 收件闸**）→ `implemented`。
- **未过审计即写 `status: 生效 / implemented` = 违反本条**；`生效日期` 同此。
- 理由：**"状态写进文档本体"是同一错误模式的第三次出现**
  （文档契约 §5 越界 / §7 快照 / §8 未审先生效，同根）
  ⇒ **状态是流程的产物，不是撰写者的声明。**
- 批准凭据必须可查（PR 链接 / 决策文件路径），不得只写"创始人批准"。
