# edge-gap-audit — 边缺口审计

> **谁用**：CTO（或 CTO 专项会话）
> **用途**：**不从"读代码找 bug"入手**，而是**拿"架构清单"做审计** ——
> 逐层问「**这一层的产物，去哪了？**」
> 🔴 **本方法的存在理由**：**很多缺口是"静默的"** —— 它不报错、CI 绿、测试过，
> **只是"这条边半截"**。**必须用清单逐条问，才会浮出来**。

---

## 0. 三种模式（**见到就记**）

| # | 模式 | 问法 | 判据 |
|---|---|---|---|
| **1** | 🔴 **断头路** | 「**这条边的读侧是谁？**」 | 答不出 ⇒ **有写无读** |
| **2** | 🔴 **没记账** | 「**这个状态字段，谁写它？**」 | 答不出 ⇒ **状态空转** |
| **3** | 🔴 **只覆盖一种** | 「**这个接口的入参，能表达几类？**」 | 只 1 类 ⇒ **覆盖面窄** |

---

## 1. 三步操作（**照做**）

```
① **画边**：拿架构清单（如宪章 §0.4 的层/回环）⇒ 逐层问：
   · **谁产生数据（写侧）？**
   · **谁消费（读侧）？**
   · **回路闭了吗？**（ActionResult 回到起点了没有）
② **扫状态字段**：把"终态/标志位/结果对象"列出来 ⇒ 逐个问「**谁置位？**」
③ **扫通用接口**：把"提案/事件/任务"这类通用容器列出来 ⇒ 逐个问「**能表达几类 payload？**」
```

## 2. 🔴 为什么"清单法"能发现而"读代码"发现不了

```
 · **读代码**：只能看到"写了什么" ⇒ **看不到"缺了什么"**
 · **清单法**：**先有"应该有什么"的清单**（宪章/图纸/边表）⇒ **再逐条对"实际有什么"**
 ⇒ 🆕 **⇒ 缺口 = 清单有、实现无** —— **那只有"对照"才能发现**
 ＋ 🔴 **且"静默缺口"的三特征**：**不报错 / CI 绿 / 测试过**
   ⇒ **所以"绿"不是"没有缺口"的证据**
```

## 3. 已验证的实例（**照这个样子找**）

| 实例 | 模式 | 怎么发现的 | 后果 |
|---|---|---|---|
| **E6 / J5**：④ 决策台账"**只写不读**" | **1 断头路** | 问"**谁读 ④ 台账？**" ⇒ 无 | **"机器只转半圈"** |
| **E5**：④a 测量值"**只写不读**" ＋ 周报"无 sink" | **1 断头路** | 问"**测量值谁消费？**" | 指标白算 |
| 🔴 **0-2 总闸**：`applied` **恒 0** | **2 没记账** | 问"**`applied` 谁置位？**" ⇒ 无 | **"进化"半截** |
| **E9**：⑥ **只会改阈值** | **3 只覆盖一种** | 问"**`changes` 能表达几类？**" ⇒ 1 | **够不着 ①②④⑤** |
| **E2**：`getCurrentDepartmentIds()` 无消费方 | **1 断头路** | 问"**谁调它？**" | "关了卡 ≠ 边通了" |

## 4. 🔴 判据（**发现之后要立什么**）

```
 · **每个缺口 ⇒ 一条边（E 编号）＋ 一张卡 ＋ 一条"改坏即红"判据**
   —— **没有"改坏即红"的绿 = 未证实的绿**
 · 🔴 **且"缺口"分两级**：
   · **执行缺口**（**有设计、没实现**）⇒ **可派单**
   · **架构缺口**（**设计本身表达不了**）⇒ **必须 CTO 裁定**（如 E9）
```

## 5. 反模式（**见到就退**）

```
 ❌ **拿"CI 绿"当"没有缺口"** —— 静默缺口恰恰"不报错"
 ❌ **只读代码找 bug** —— 那只能发现"写错的"，发现不了"没写的"
 ❌ **把"缺口"直接派单** —— **先分"执行缺口 vs 架构缺口"**
   （**架构缺口派下去 = 执行方只能自造语义 = 越界**）
 ❌ **发现一条就报一条** —— **该"逐层扫完再报"**（**否则漏发/碎发**）
```
