# D734: PR 预算门禁（pr-budget-gate）

> 派单: docs/synova/coordination/派单-第四批-D733-D736-20260913.md §二（批 A，P1）
> 依赖: D733 的 `scripts/control-tower/check-ownership.py`（域校验单域模式）→ 本分支基于 D733 分支（stacked PR），D733 合入后 GitHub 自动改指向 main。
> 背景实测: D721 一个 PR 背三类门禁问题挂半天；K3 审计分支落后 main 差点回退他人成果。冲突概率 ∝ 改动大小 × 分支存活时间。

#CRITERIA: A

## Q0: 定位 — 项目拼图 + 文件审计
### a) 项目拼图
控制塔门禁基建（非五层运行时）。现状：`scripts/pre-commit-check.sh` 有 13 组检查，但**没有一条约束 PR 体积/域跨度/分支落后**；PR 多大、跨几个域、落后 main 多少，全靠人看。本任务加一条机器门禁。
### b) 文件审计
grep 实测（origin/main）: `check-pr-budget` 零命中（不撞车）；`pr-budget` 零命中。复用资产：D733 的 `check-ownership.py`（单域模式 + `domain_neutral` 豁免）、pre-commit 的 `soft_check`/`soft_pass` 助手（D515 语义：本地软提示、SYNO_CI=1 转硬）。
### c) 决策
已有覆盖→复用 D733 校验器（不重写域判定）。无覆盖→新建 check-pr-budget.sh。冲突→无。

## Q1: 调研 — 业界最佳实践 / Anthropic 决策链 / memory 历史教训
业界: 「小 PR + 短存活分支」是降低合并冲突的标准工程实践（DORA/Google 工程实践）；机器化落地即「变更文件数上限 + 单域 + 落后基线告警」三条。Anthropic 工程基线: ① 隔离 —— 门禁复用独立校验器而非内联判定；② fail-closed 三态（D328）—— 检查本身坏了必须 exit 2，不与通过混同；③ 机器可验契约 —— 每条判定有可复跑命令。memory 历史教训: D728/D729 两次派错线（域跨度无机器约束）；D334 多机同步（落后分支直接合的风险）；**D370 bash+中文变量边界**（本任务实测踩到：`$VAR（` 被解析成变量名 → `unbound variable`，且只在失败路径触发）；铁律 11 静默降级禁止。
Q1c 决策参考系: 参考 Anthropic（fail-closed 三态 + 复用独立校验器）+ 第一性原理（三条判定的最简机制 = 一个脚本 + 一次接线，不新建 CI job）+ 开源实证（DORA 小批量交付）。结论: 收敛 —— 单脚本三判定 + pre-commit 附加检查块接入。

## Q3: 验收 — 入口 → 交互 → 结果
入口: `bash scripts/control-tower/check-pr-budget.sh [--base origin/main] [--max-files 12] [--max-behind 20] [--files "<写集>"]`；另经 `scripts/pre-commit-check.sh` 每次提交自动触发（CI strict 下转硬）。
处理: 取 `base...HEAD` 变更集 → ① 计数比对上限 ② 交 D733 `check-ownership.py` 单域判定（`domain_neutral` 路径豁免） ③ `git rev-list --count HEAD..base` 比对阈值。
结果: stdout 逐项 ✅/⚠️/❌ 点名；超预算 → exit 1 且明示「拆 PR，不要调高上限」；检查本身坏了 → exit 2；基线全链不可解析 → ⚠️ 显式留痕 + 跳过（不误红）。
