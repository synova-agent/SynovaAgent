## Q1: 调研 — 业界最佳实践 / Anthropic 决策链 / memory 历史教训
- **第一性原理**：「查不到数据」与「没有数据」是两件事。把前者当后者 ⇒ 系统把安全性失败（authorization/tenancy mismatch）当成正常空态。
- **Anthropic 工程基线**：fail-closed 优于 fail-open；不确定性必须**显式可见**而非静默默认（本仓对应铁律 11「静默降级禁止」+ 铁律 24/31「降级信号传播」）。
- **开源实证**：Postgres RLS / Django ORM 多租户实践 —— 过滤条件命中 0 行时，区分「表为空」与「当前身份不可见」是标准做法（`EXPLAIN`/`count(*)` 双查）。
- **memory / 台账**：`问题修复台-20260925.md` FIX-017 同族（门禁对无卡号对象结构性 fail-closed，同类第 2 次）；`CTO-固化-II` §四 X27「防误报机制：同一形状 = 把『缺失』翻译成『通过』；修三条：根身份硬门禁／缺失进 errors／覆盖率判据」——**本卡即该条「根身份硬门禁」**。
- 铁律引用：**11**（静默降级禁止）、**24**（catch 必 log + degraded）、**31**（降级信号传播）、**47/48**（契约优先 + 测试非空壳）。
- 参考：Anthropic fail-closed 基线 + X27 同一形状 + 第一性原理（「查不到」≠「没有」）+ 结论：**在 loader 包装层做根身份预检，unfiltered>0 且 filtered=0 ⇒ 显式告警 finding + degraded:true**。

## Q2: 范围 — 正确的最简方案
做什么：
- `src/sentinel/sentinel-loader.ts` — `check(context)` 包装内、调用 aggregate **之前**插入根身份预检：对 `manifest.dependsOn.nodeTypes` 逐类型取 `unfiltered = store.queryNodes(type)` 与 `filtered = store.queryNodes(type, { teamId })`；`unfiltered > 0 && filtered === 0` ⇒ `log.error` + 注入 finding `sentinel-<name>-root-identity`（severity `warning`，evidence 含 type / unfiltered 数 / teamId）+ 结果 `degraded: true`；store 无 `queryNodes` 或查询抛错 ⇒ `log.warn` + 跳过预检（degraded，不静默）
