## Q1: 调研 — 业界最佳实践 / Anthropic 决策链 / memory 历史教训
- **第一性原理**：门禁的目标不是"更严"，是**"PR 能合进去、且真拦得住"**。两条推论：
  ① 必需 context 必须**必然上报**（否则 blocked ≠ 红，人无从修复）⇒ 缺陷 B 必修；
  ② 判据必须**可判**（无锚点的白名单 = 判据失效）⇒ 锚点是正确性问题，不是风格问题。
- **Anthropic 工程基线**：改判据**必须配反例夹具**（构造违例 ⇒ 必红 + 复原后一致）；
  读不到判据源 ⇒ **fail-closed 且不静默**（铁律 11/24）；平台自带数据优先于自建插桩（A7）。
- **开源实证**：GitHub Actions 官方语义 —— `needs` 失败默认跳过下游 job，**job 级 `if: always()/!cancelled()`
  才能保证 check-run 仍上报**（矩阵 job 被 skip 时其分片名**不展开**，`Vitest (1/2)` 永不出现）。
  check-runs API 自带 `started_at/completed_at` ⇒ 耗时统计无需插桩。
- **memory 历史教训**：D971（必需 context 消失 ⇒ 405 "N of 12 required status checks are expected"）；
  V3.9（硬阻断 100% 有效、软机制 0% 有效）；D1023/P1（`.gitattributes` 混入白名单 ⇒ 改 CI 本身而零验证）；
  D954（用未定态集合证明"无红"= 空转）；本轮新增教训：**夹具必须对根因判别**（我的 2 条结构断言
  被独立自验实测为纸老虎，已删）。
- 参考：`ctrl-tower-change`（门禁变更模式库：三态退出码/全角变量边界/条件跳过保持 <1s/
  `grep -c` 防 "0\n0"/测试注入与沙箱/改完验收链）＋ `windows-compat`（UTF-8 强制、三级 python 探测）。
