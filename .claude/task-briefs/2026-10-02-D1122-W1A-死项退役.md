## Q1: 调研 — 业界最佳实践 / Anthropic 决策链 / memory 历史教训
- **第一性原理**：门禁的代价是**维护面**。一条注册指向不存在文件的 hook，其成本不是「0」而是**负**——
  它让运维者以为防线在（假绿），并让「hook 有 N 条」这类计数失真。⇒ 死注册**必须删**，不是「无害留着」。
- **Anthropic 工程基线**：删门禁脚本必须先证「零消费者」，且**删除本身要留证**（谁删的/为什么/何时），
  不能靠「反正 CI 绿」——绿只证明没人调用，不证明**不该**调用。⇒ 本件逐条给生产面 grep 证据。
- **开源实证**：GitHub Actions `for t in` 密封清单是一次性真值源；**清单与执行体必须同时收缩**，
  只删一处会留下「登记了不存在的测试」或「测试无登记」两种漂移。A9 正是踩在这条上（清单删了、消费端没删）。
- **memory 历史教训**：D918（gate-stats 夹具日期边界定时炸弹 ⇒ 全 PR 恒红 ⇒ 合并队列堵死）
  ——证明**「测试恒红」与「门禁存在」同源可伤**；D922/W1 卡片明确「退役假门禁」为净收益方向；
  D1007（棘轮基线清理）/D1093（登记去重）确立「基线只减不增」的减项合规先例；
  D1039-A4（CI 关键路径）确立「清单单源提取，不散列不漂移」范式。
- **参考系（D333 收敛）**：`ctrl-tower-change` 模式库（门禁变更三态退出码 / 收件四判据 /
  改完跑验收链）＋ `squad-discipline`（写集越界 = 收件必退，不自扩权）。
  结论：A1/A3/A9 均为机械退役；A9 的**写集外消费端**是第 1 次退回的唯一原因，经 F1 有限扩权后在同一「零行为变更」口径内闭合
  （实测：修复前 `simulate-ci.test.sh` 9 通过 1 失败 rc=1 → 修复后 10 通过 0 失败 rc=0）。
