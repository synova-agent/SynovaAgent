### c) 决策
1. **不改 `src/deploy/bootstrap.ts` / `src/agent/synova-agent.ts`**（写集外）：LoopScheduler 的两个构造点都在写集外，而**创建真 MainAgent 的装配点 `src/server.ts` 在写集内**。⇒ 采用「进程级绑定 + 触发时惰性解析」：新增 `src/loops/main-agent-binding.ts`（L2 装配写入，LoopScheduler 读取），`src/server.ts` 装配时绑定同一实例。**理由**：不动写集外文件即可让两个 LoopScheduler 同时拿到同一 MainAgent；惰性解析使装配先后顺序无关（Bootstrap Phase 2e 先于 2f/469）。
2. **不改名 `src/routes/loops.ts:setMainAgent`**：卡面给的是「真注入**或**统一同名」，选前者；改名要动 `src/routes/loops.ts` + `tests/routes/loops.test.ts`（写集外）。残余同名风险以注释显式标注，记 R2。
3. **补 `executeLoopScale` 优先分派**：LoopScheduler 声明的 `executeLoop(loopId, scale)` 与 MainAgent 真实的 1 参 `executeLoop` 形状不符 ⇒ scale 被**静默丢弃**（loop-1 声明 slow 却按 fast 执行）。同一接线行内修复，否则「点火」点的是错尺度。
4. **聚合改为 per `target_id`**（卡面首选）：`GROUP BY decision, target_type, actor_role, target_id`，`key` = 真 target_id（消费者用它作 sentinelKey/goalType/pathKey/expertKey）。
5. **`EXTENSIONS_DIR` 加 fixture 环境变量接缝**：`INDUSTRIES_FIXTURE_DIR`（先例 `src/sentinel/sentinel-loader.ts:54` `SENTINELS_FIXTURE_DIR`），使「回写 extensions JSON」可在临时目录真实跑通而**不污染仓库 tracked 文件**（默认值不变）。
6. **铁律 37 死代码清除（#975 交付内含，产品线 2026-10-04 裁定）**：原 `LoopScheduler#setMainAgent` 实测零调用 ⇒ **删除**（禁"定义着不调用"的保留式死代码），同名陷阱的另一半随之根除；注入路径唯一化为 `bindMainAgent`。
7. **验收口径订正（产品线已改卡 #975）**：Done = **探针不再输出 `[D9] MainAgent 未注入 — 跳过 loop-N (degraded)`**（本件实测 stderr 命中 0）。`grep -rn "\.setMainAgent(" src/` = 0 是**诊断行、非验收判据**且将永远保持 0；本卡走「真注入」分支（二选一）合法。

## Q1: 调研 — 业界最佳实践 / 决策参考系 / 历史教训
a) 业界最佳实践：**依赖注入的失败模式是「声明了 setter 但组装期零调用」**（本仓 4 次接线事故同型）。修复优先级：① 组装期真实注入 ② 未注入必须可观测（log + degraded）③ 判据必须能区分「接线了」与「被执行」。Phase 2e/2f 的装配顺序问题用惰性解析（lazy resolution）解决，是 DI 容器的标准做法（服务定位器模式），与仓内既有全局单例惯例一致（`setGlobalScheduler` / `setGlobalSentinelRunner` / `routes/loops:setMainAgent`）。
b) 决定性参考：本仓 `docs/synova/presets/synova-product-lead/cordis.patch.yml` 方向锚「0-1/0-2 两总闸不修则第 2 批起全部无效果」+ 派单件 §二 P1/P2 实测前提。
c) memory/ 历史教训：铁律 0-2（WIRE CHECK）、铁律 4/5（写了代码没接线）、铁律 24+31（catch 必须 log + degraded）、铁律 47/48（契约先行 + 测试非空壳）、铁律 9（改核心定义后 grep 全仓传播）、D312（禁 git stash）。参考：第一性原理 + 本仓接线铁律 ⇒ 结论：把「谁调用」变成组装期可见的单一绑定点 + 触发时解析。

## Q4: 契约与测试（铁律 47/48）
- `main-agent-binding.ts`：`@input bindMainAgent(agent|null)`；`@output getBoundMainAgent() → LoopExecutorLike|null`；`@degraded` 未绑定返回 null，调用方必须 log.warn + 跳过（禁静默）。
- `LOOP_EXECUTOR` 分派契约：优先 `executeLoopScale(loopId, scale)`，缺省回退 `executeLoop(loopId, scale)`（scale 参数必须透传，禁静默丢弃）。
- `getAggregatedSignals` 契约：`@input threshold`；`@output AggregatedSignal[]`，`key` = 真 target_id（同一 target_id × 同 decision/target_type/actor_role 才聚合）；`@degraded` db 缺失/查询异常 → log.warn + `[]`。
- 测试覆盖：正常路径 + 降级路径（未绑定 / db null）+ 边界（阈值 3 恰好达标 / 低于阈值不聚合）。
