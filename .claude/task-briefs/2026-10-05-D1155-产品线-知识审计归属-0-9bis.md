## Q1: 调研 — 业界最佳实践 / Anthropic 决策链 / memory 历史教训

- **铁律 5 / L4**：后端能力 ≠ 可用功能；身份**只能**来自验签链路，不得重算（L-4）。
- **铁律 11 / 24**：不新增静默路径；本项不新增 catch。
- **铁律 37**：`req.userId` 无人写 ⇒ 改后全仓零命中，不留死引用。
- **铁律 39**：`routes/`(L1) → `middleware/`(L2) 相邻层合法；本项实际只消费 `req.rbac`（已注入对象），**零新增 import**。
- **D947 姿态**：唯一可信身份来源是验签后的 `req.auth`（`req.rbac` 是其派生物）。
- **D333 四步**：① 第一性原理 —— 审计的价值在「可归属」，不可归属的审计行 = 无审计；
  ② Anthropic 工程基线 —— 结构化审计字段必须来自可信身份，不得来自可伪造/未定义的请求属性；
  ③ 开源实证 —— Express 生态惯例为把身份挂到 `req` 的**单一**权威对象，下游只读该对象；
  ④ 收敛检查 —— 与 `workspaces-api.ts:33` / D1153 守卫读 `req.rbac` 同一形态。
  ⇒ 结论：读 `req.rbac.userId`，不新增第二身份通道。
