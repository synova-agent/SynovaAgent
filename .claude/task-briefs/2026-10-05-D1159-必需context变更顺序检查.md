## Q1: 调研 — 业界最佳实践 / Anthropic 决策链 / memory 历史教训

- **第一性原理**：分支保护是**共享**资源，其变更的代价函数不对称 —— 放宽只丢一道防线（可回滚），
  收紧会让**所有**在飞 PR 卡死（只能人工解）。因此顺序纪律必须是"松可先行、紧等合并"。
- **Anthropic 基线**：改门禁判据必须配**判别性夹具**（改坏必红 + 过紧必红）；读不到判据源 ⇒ fail-closed 且不静默
  （铁律 11/24）；三态 0/1/2 不许混同（`ctrl-tower-change` 模式 1）；新增门禁必须**接线**（否则 D664「建成未接线」）。
- **开源实证（GitHub 语义）**：必需 status check 在 PR 上"必须出现且为 success"；缺失即 `N of N expected`（405）
  ⇒ 在飞 PR 不因新必需项自动获得该 check-run。这正是"收紧必须等合并"的机制根据。
- **memory / 本波次教训**：D971（必需 context 消失 ⇒ 405 永久 blocked）；D1112（`needs:` 上游红 ⇒ 下游必需 context 消失）；
  K3 #1077 判词（保护先于 PR = 顺序风险）；D1111/收件修正（降级旗标**不得**吞违规 ⇒ 本器刻意不给 `--allow-degraded`）。
- 参考系：`ctrl-tower-change`（门禁变更模式库）+ `claim-verifier`（声称↔物理证明）+ `windows-compat`（双语法/禁裸 python3）。

**放宽允许先行**（`L ⊂ M` ⇒ exit 0，逐条点名）/ **收紧必须等 PR 合并后**（`L ⊃ M` ⇒ exit 1）。
判定对象 = live required contexts（L） ⇄ base-ref 登记表（M）；候选登记表（C）只作信息级打印（判事实不判意图）。
