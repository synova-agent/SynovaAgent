## Q1: 调研 — 业界最佳实践 / Anthropic 决策链 / memory 历史教训
- 铁律 35（能写 check 的不靠 review）+ 铁律 0-2（spec→test→impl→wire→review→merge）；
  Anthropic 工程基线：门禁必须**先红后绿夹具**且**三态退出码**（ctrl-tower-change 模式 1）。
- 桥协议事实：**只有 exit 2 阻断**，其余退出码 = 非阻断失败 ⇒ 闸若"执行失败"而返回非 2，
  门禁会静默消失（本卡三道 fail-closed 保险：闸内 / 入口 / 命令串 `|| exit 2`）。
- memory 教训：D954「C 段空转」定罪 + D564r7「绝对路径注入 ⇒ 检查空转」+
  V3.9「软机制 0% 有效，硬阻断 100% 有效」⇒ 闸必须物理阻断，但**误拦代价不对称**（CTO 收发全停），
  故触发面按"声称才拦"设计并逐条标代价。
- 平台教训（PLATFORM-CHECKLIST 1/2/7/9 + D938）：本卡六件全程过 `scan-fullwidth-vars.sh`
  （实测 bash 3.2 下 `$var；` 会 unbound —— 开发中真踩两次，已入测试作平台守卫）。
参考：Anthropic（hook 三态+先红后绿）/ DSH 源码（exit 2 语义、进程级配置）/ 第一性原理（误拦与漏拦不对称）
+ 结论：**两道闸按"声称即拦、非声称放行"实现；自身失败一律 fail-closed；退出码做 cli(0/1/2) 与宿主(0/2) 双层映射**。
