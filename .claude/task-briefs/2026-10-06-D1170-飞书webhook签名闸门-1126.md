## Q1: 调研 — 业界最佳实践 / memory 历史教训

- 权威规格（唯一来源，不再引第二处）：open.feishu.cn「Step 3: Receive events」签名校验样例代码（六语言）
  ⇒ `sha256(X-Lark-Request-Timestamp + X-Lark-Request-Nonce + encrypt_key + rawBody)` hex；
  **是 SHA-256 不是 HMAC**；rawBody 必须是**未反序列化的原始字节**（官方 Go 样例逐字：
  `bodystring refers to the entire request body, do not calculate it after deserialization`）。
- 时间窗 ±1h｜分层闸门 pre-auth 64KB → post-auth 1MB（OpenClaw `monitor.transport.ts:75` /
  `webhook-request-guards.ts:43-49`，见派单件 §二 F3）。
- 铁律：0-2（测试先行/接线验收）、11（禁静默降级）、24/31（catch 必落 log）、38（`as any` 零容忍）、
  47（契约优先：JSDoc 输入/输出/降级）、48（测试非空壳）、0-3（禁 stash）。
- 历史教训（本仓）：**「接线了 ≠ 被执行」**（4 次接线失败）⇒ 判据①必须断言 handler 副作用
  （响应 `sessionId` + `agent_sessions` 真有行），禁只断言状态码。
- **决策参考系**（D333 四步）：① 第一性原理 —— 入站 webhook 的信任边界只能建在「共享密钥 + 原始字节 + 时间窗」上，
  缺失任一即不可信；② Anthropic 工程基线 —— 校验函数纯化、失败默认关闭（fail-closed）、拒绝要可观测；
  ③ 开源实证 —— OpenClaw 的 pre-auth/post-auth 分层闸门＋±1h 窗口；**结论** = 采三层闸门
  （判定级尺寸闸 → 常数时间验签 → ±1h 时间窗），且**不替代段2 的内存级前置闸门**。
