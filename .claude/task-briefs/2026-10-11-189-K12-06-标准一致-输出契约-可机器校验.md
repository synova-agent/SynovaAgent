# Task Brief: #189 → K12-06 — 标准一致（输出契约 · 可机器校验）

## 〇、为什么要做这个（通俗版 · 先读这一节）

**① 一句话**：产出（一页纸/KPI 表/周报/诊断报告）**提交时自动体检**——缺字段就报错，不是"给你个模板建议"。

**② 解决什么问题**：院方《02》§三机制3 原文：「**"给格式"不等于"保障一致"——要给可校验的格式**」。
 没有校验 ⇒ 每个人交出来的"一页纸"字段顺序、口径、必填项都不一样 ⇒ **无法复核，也就无法比较**。

**③ 做完对项目的推动**：一致性**第③层（标准一致）的载体**；
 而且它有**第二职务**：每次不合格**自动成为"下次预设更新"的输入**（院方 §四飞轮）——
 **校验器同时是反馈采集器**。

**④ 不做行不行**：**不行**。第③层明文要求"同一类判断用同一把尺子"；没有校验器，那把尺子只是建议。

**⑤ 现在有什么基础**：
 · ✅ 模板侧已有：`extensions/reports/` **3 件**，且**已接线**（`src/init/file-driven-loaders.ts:35`）
 · ❌ 校验器侧**不存在**：`src/output/contract-validator.ts` 无；`extensions/reports/contracts/` 无
 ⇒ 结论：**模板在、校验器不在**——差的就是"提交时自动检查"这一步

**⑥ 还需要做什么**：四类产出契约（`one-pager` / `kpi-table` / `weekly` / `diagnosis-report`）＋ 校验器 ＋ 测试（含反例：短路校验器必红）

**⑦ DSH 借鉴方式**：**参考自研**
 · 可借：**schema 强校验 + 早失败**（`packages/settings/settings/src/index.ts:7` `import type z from '@deepseek-ai/schemastery'`；其 Config 用 `z.object(...)` 声明）
 · 可借：**失败可归因、机器可读**（`dsh-invariants/lib/index.js:11-13` `InvariantError{code:'INVARIANT', packageName}`）——
 失败必须带"哪条契约、哪个字段"
 · ❌ **不借**：宿主统一校验（DSH 是**包自带判据**，宿主只保证"不生效就报错"）

**⑧ 涉及代码文件**：`extensions/reports/contracts/*.yaml`（新建）｜`src/output/contract-validator.ts`（新建）｜
 `tests/output/contract-validator.test.ts`

## Q1: 调研
- **院方《02》§三 机制 3**：一页纸＝固定字段（缺字段→报错）｜KPI 表＝固定口径｜周报＝固定结构+必填｜诊断报告＝固定章节+引用；「**产出提交时自动检查**，这才叫保障」
- **院方《02》§四**：输出契约有**第二职务** —— 每次不合格自动成为下次预设更新的输入（→ K12-08）
- **DSH 依据**：
  | 采纳/不采纳 | file:line | 说明 |
  |---|---|---|
  | ✅ 采纳：**schema 强校验 + 早失败** | `packages/settings/settings/src/index.ts:7` → `import type z from '@deepseek-ai/schemastery'`（`Config = z.object(...)`） | 用 schema 声明形状，不合法即失败 |
  | ✅ 采纳：**失败可归因（机器可读）** | `@deepseek-ai/dsh-invariants/lib/index.js:11-13` → `InvariantError{code:'INVARIANT', packageName}` | 失败带**稳定 code + 归属**（哪条契约、哪个字段） |
  | ❌ 不采纳：宿主统一校验 | `dsh-invariants/lib/index.js:6-8`（package-owned：宿主只提供注册表） | 校验器**随契约走** |
- **memory 教训**：宪章 P9（只能追加不能覆盖）⇒ 契约**带版本**，诊断产物**记录用了哪版**。

## Q3: 验收 — 入口 → 交互 → 结果
入口：产出**提交时**（K12-03 产出 / 报告交付链）经 `contract-validator` 处理：按产出类型加载契约 → 校验字段/口径/必填 → 不合格则报错 + **记录**
结果：
- V1 `npx vitest run tests/output/contract-validator.test.ts` ⇒ exit 0
- V2 **穿生产入口**：提交缺字段的一页纸 ⇒ **被拒 + 点名缺哪个字段**
- V3 口径：KPI 表口径与定义不符 ⇒ 报错
- V4 **第二职务**：每次校验失败**自动记录**为预设包更新输入（接 K12-08）
- V5 反例：校验器短路（恒 true）⇒ V2 **必红**
- V6 可版本化：契约带版本；产物**记录所用契约版本**
