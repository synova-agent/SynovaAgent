# Task Brief: #201 → K12-18（登记件 `1-13`）— locales 死指针修复

## 〇、为什么要做这个（通俗版 · 先读这一节）

**① 一句话**：修一个**指向不存在文件的死指针**（manifest 里写的加载器，库里根本没有）。

**② 解决什么问题**：`extensions/locales/manifest.json` 里写着 `./locale-loader.ts`，
 实测**两种解析口径都不存在这个文件**（文件相对 / extensions 根相对**都悬空**）。
 危害不在这一处，在**它代表的病**：**"文档即配置"——manifest 自述当事实，没人验证**。
 院方当年正是栽在这里：v0 曾把「locales 自包含，形态可作范本」当结论，复核后**撤回**。

**③ 做完对项目的推动**：让"**声明必须与实际消费者一致**"成为可检查的事（CC3 的一条）；
 也把 `locales` 从"不可达清单"里拿掉。

**④ 不做行不行**：**可以做，但很便宜**：修一处 = 改 1 个文件；
 不修 ⇒ 不可达清单里永远挂着一个"其实只是写错了"的条目，掩盖真问题。

**⑤ 现在有什么基础**：
 · ✅ 真加载器存在：`src/locale/locale-loader.ts`（`file-driven-loaders.ts:24` 接线）
 · ✅ 真内容在：`extensions/locales/` = **7 个 json**
 · ❌ manifest 里的指针是**死的**

**⑥ 还需要做什么**：删死指针（或改名 `loader` 降为纯文档 + 标注真加载器）；**不动** `src/locale/locale-loader.ts`

**⑦ DSH 借鉴方式**：**参考自研**
 · ✅ 可借：**声明必须与实际消费者一致；不生效就报错**（`dsh-invariants/lib/index.js:6-13`）
 · ✅ 可借：**类型/依赖走包名而非相对路径**（`packages/webhook/webhook-github/src/index.ts:3`）
   ⇒ 从根上消除"双口径解析"

**⑧ 涉及代码文件**：`extensions/locales/manifest.json`
