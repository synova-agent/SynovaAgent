### 🔴 V1 与 V2 的表面矛盾 —— 已由创始人 2026-10-11 明令消解（**按此实现，不再自行解释**）

- **原文**：`--all` = **exit 0**，但末行必须**显式披露** `pass=/notimpl=`（**不许只报 PASS**）。
- **语义**：ladder 的退出码表达**"测量件自身是否健康"**（全跑通且契约自洽 ⇒ 0）；
  **个别探针 exit 2 表示"目标未实现"，不影响 ladder 自身的 0**，但**必须**在末行计数里暴露。
- **末行格式（本批统一）**：
  ```
  RESULT=PASS probes=13 pass=<n> fail=<n> notimpl=<n> error=<n>
  ```
- **反假绿保证**：`notimpl=11` 是**机器可读的显式披露** —— 读者一眼可见"11 个还没做"。
  若某探针**本该 exit 2 却 exit 0**，则由 V4 的恒绿反证夹具判红（不是靠 ladder 退出码）。
- 🔴 **禁止**：只印 `RESULT=PASS` 而不带计数（那就是假绿，本卡存在的全部理由就是防它）。

## Q4: 契约与测试 — 12 探针的输入/输出/降级契约（**写码前定义**）

### 4.1 统一契约（铁律 47）

```
@input    — CLI 参数:
            · --case <场景名>  跑指定场景（场景名取各卡 Q3 原文: no-answer / cross-org / multi-dept /
                              custom-role / customer-defined / dept-diff / dry-run / finance ...）
            · --all            跑该探针全部已知场景
            · 无参数且该探针有「唯一场景」⇒ 跑该唯一场景（卡面判据命令即无参数，须支持）
            · 未知场景名 ⇒ exit 2（不猜、不回落默认场景 —— 回落会把判据报成绿色的假事实）
            · --dry-run 作为 --case dry-run 的别名（兼容 K12-03 卡面判据命令原文）
@output   — stdout 逐条:
              ✅ PASS        （断言成立）
              ❌ FAIL        （断言不成立）
              ⚠️ 未实现       （目标件不存在）
              ⚠️ UNVERIFIED  （无法核实，不计入 PASS —— V-09）
            每条断言标级别 [L1-静态可达] / [L2-真跑通]
            ＋ 末行恒为 RESULT=PASS | FAIL | NOT_IMPLEMENTED | ERROR
@degraded — 依赖缺失/生产入口跑不通/仓库根定位失败 ⇒ exit 2 ＋ 明确原因（fail-closed，铁律 31）
@exit     — 0 = 全部场景 PASS
            1 = 有断言 FAIL（目标件在但卡没做好）
            2 = 目标能力未实现 或 探针自身无法判定
```

### 4.2 「未实现必须 exit 2」三层实现（全用）

1. **前置存在性闸**：探针启动先 `existsSync` 目标件；缺失 ⇒ `⚠️ 未实现` ＋ `RESULT=NOT_IMPLEMENTED` ＋ `exit 2`。
   ⇒ 保证「目标未建时**不可能** exit 0」，不靠人记得。
2. **动态 import 符号缺失**：目标模块在但导不出探针所需符号（如 `resolveContext`）⇒ 捕获 ⇒ `exit 2`
   （**不是** exit 1 —— 符号不存在 = 能力未实现）。
3. **元层反证**（V4/V-07）：契约自测注入**恒绿假探针** `.claude/fixtures/probe-always-green.ts`
   （`echo RESULT=PASS; exit 0`，其"目标件"实际不存在）⇒ 断言**它必须被判红**
   ⇒ 证明「exit 2 门」真在工作（**拔掉实现照样通过 = 假绿**）。

### 4.3 单一实现决策（M-04）

契约**只写一次** —— 落在 `probe-ladder.ts` 内以**具名导出**提供：
`locateRepoRoot()` / `parseProbeArgs()` / `assertTargetsExist()` / `ProbeOutput` / `ProbeError`
／`PROBE_VERDICTS` / `EXIT_BY_VERDICT` / `LADDER_VERDICTS`（ladder 词元）
（🔴 独立复核 probe-verifier 2026-10-11 指出本 brief 初稿写的 `emitResult()`/`assertTargetExists()`/`runCases()`
**在实现中不存在** —— 已按实测改名同步；「末行由 `ProbeOutput.finish()` 签发」）
12 探针 `import { ... } from './probe-ladder'` —— 共享契约无第二份副本；
且这 12 条 import 是**真实调用**，不构成"空 import 绕过接线门禁"。

> ⚠️ 边界（如实标注）：探针被 ladder 编译期依赖。若 ladder 崩溃，12 探针**仍可单独 `npx tsx` 直跑**
> （各自带直执行守卫）⇒ 不构成单点故障。此边界写进每个探针头部 JSDoc。

### 4.4 ladder 聚合语义

```
@input    — --all（跑全部 13 探针）｜ --probe <名>（跑单个，便于取证）
@output   — 13 行清单（每行: 探针名 ＋ PASS/FAIL/NOT_IMPLEMENTED/ERROR ＋ 该探针退出码）
            ＋ 末行 RESULT=PASS probes=13 pass=<n> fail=<n> notimpl=<n> error=<n>
@exit     — 0 = 13 探针全部执行完且契约自洽（NOT_IMPLEMENTED 不计入失败，但计入 notimpl 计数）
            1 = 有探针 FAIL 或契约不自洽（末行无 RESULT= / 退出码越界）
            2 = ladder 自身异常（仓库根定位失败 / 参数不可识别）
```

**既有件口径（不得改它）**：`probe-content-registry.ts` **不输出 `RESULT=`**（🔴 实测**末行**是
`CONTENT-REGISTRY-OK: 四段全绿（PRESENCE/INTEGRITY/RESOLVE/CALL）`；`SUMMARY: sections=4 failures=0`
是它的**倒数第二行** —— 本 brief 初稿写错，由独立复核 probe-verifier 2026-10-11 实测纠正），
与卡面 V3「13 个末行均为 `RESULT=...`」**字面不一致**。处置：ladder 对它**按退出码判定**，
清单行打**显式标注** `[legacy-no-RESULT]`；契约自测 T2 只对**本批新建的 12 个**断言 `RESULT=`。
⇒ 实为 **12/13**，**显式披露**，不隐藏，也不越写集去改既有件。

## 🔴 独立复核结论回写（probe-verifier，2026-10-11）—— 已修项 / 已知边界

### 已按复核修掉的（逐条，附证据口径）
1. **🔴 自洽假绿漏网 5/12（最重要）** —— 原防线用**硬编码 7 条**目标存在性清单；复核者把
   "目标不存在却 `RESULT=PASS` + exit 0"的假探针换上 output-contract / decision-ledger /
   rbac-multitenant / department-axis / role-config ⇒ 整套自测**仍 79/0 全绿**，
   而那 5 件里正含**唯一在报产品真红**的两件。
   **修法**：改为**探针自声明 `TARGETS` + 机械校验不变式「报 PASS ⇒ TARGETS 非空 ∧ 全部存在」**
   （不依赖硬编码清单，可自动覆盖未来新探针）。ladder 与契约自测**两处独立复算**（不互信结论）。
2. **`ERROR` 旁路** —— 原 `… && last !== 'ERROR'` 使"自报 ERROR 却 exit 0"被判 PASS/exit 0。
   已按 `EXIT_BY_VERDICT` 唯一映射收紧：ERROR 只许配 exit 2，否则记 malformed。
3. **词元级假绿** —— 原末行 `RESULT=PASS … fail=2` 同行自相矛盾，`grep RESULT=PASS` 的消费者会被骗。
   现改三态词元（**退出码不变，仍守 `expectExit:0`**）：`PASS` / `DEGRADED`（探针如实报了产品红）/ `ERROR`（测量件自身坏）。
4. **`COVERAGE` 误印**（选手 B 报、复核者独立核）—— `pass()` 原先不记 verdict ⇒ 全绿探针印"无断言被执行"。
   已改为每条断言都进 `verdicts`，覆盖计数如实，另单列 `UNVERIFIED=`。
5. **清单标注误导** —— 原先 13 行**全部**打 `[legacy-subprocess]`；现只有真正的既有件带 `[legacy-no-RESULT]`。
6. **死代码** —— 删掉进程内执行路径与随之失去调用方的 `captureRun`/`firstLine`（铁律 37）；
   并修 `ProbeOutput.label` 未使用（TS6138）。

### 已知边界（**未修**，如实列出，不算通过）
