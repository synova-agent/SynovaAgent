## 〇、为什么要做这个（通俗版 · 先读这一节）

**① 一句话**：让 CI 的「绿」重新有信息量 —— 把"空绿"分成**合法跳过**与**异常**两类。

**② 解决什么问题**：CI 第 ③ 步（`vitest run --changed`）在**无测试命中**时打印
`No test files found, exiting with code 0` ⇒ **该步恒绿**（本机日志实测连续 33 个 job 全是这一行）。
于是"有代码改动、却一个测试都没跑"也报绿 —— 绿灯不再证明任何事。

**③ 做完对项目的推动**：这是"准度可测量"的**前置**：门禁不区分"没测"与"测过"，
后续一切"判据 exit 0"都不可信（K12 前四批 型 G：把"判据 exit 0"等同"已完成"）。

**④ 🔴 不做行不行**：**不行**（创始人裁决② / CTO 裁定 004④）：区分两种空绿是**裁决项**，不是优化项。
