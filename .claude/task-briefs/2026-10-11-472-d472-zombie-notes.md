> 🔴 **这条判据我第一版写错了，已更正（记在卡上，防后人再踩）**：
> 初版写 `git diff --diff-filter=D` 里不出现 `memory/notes/` —— **它恒成立、零判别力**。
> 原因：`git mv` 把删+增记成一对，git 的**重命名检测默认开启** ⇒ 该路径被归为 `R`（rename）而非 `D`（delete），
> `--diff-filter=D` 永远看不到它。**实测对照**：
> ```
> $ git show --name-status --diff-filter=D HEAD | grep '^D'      ⇒ 零输出（假绿）
> $ git -c diff.renames=false show --name-status --diff-filter=D HEAD | grep '^D'
>    D  memory/notes/proposed/2026-09-28-D1039-ci-signal-classify.md
>    D  memory/notes/proposed/2026-09-28-D1044-b1-archive-outbound.md
>    …（6 条全在）
> $ git show --name-status -M --summary HEAD | grep -E "^R"      ⇒ R088/R087/R082/R086/R090/R086 六对
> ```
> ⇒ 有判别力写法 = **「重命名对数 = 6」∧「未被配对成重命名的删除 = 0」**（`-M` 下 `--diff-filter=D`）。
> 这一条本身也是纪律 ④ 的实例：**判据必须验它「改坏了会不会红」**——恒绿的判据不是判据。
