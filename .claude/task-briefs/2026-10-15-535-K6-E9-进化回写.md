## 〇、为什么要做这个（通俗版 · 先读这一节）

### ① 一句话

**让"进化回环"从一个旋钮变成四个旋钮，并且每次拧完都留痕。**

### ② 解决什么问题

```
 🔴 **现状**：Synova 的"进化回环"（⑥）**只会改报警阈值**一种东西。
 · 它改不动 **① 循环参数 / ② 本体 / ④ 参数先验 / ⑤ 导航权重**
 · 且 **`applied`（"已生效"）终态没人置位**
【实测证据（代码注释原文）】`src/loops/middle-evolution-engine.ts:88-90`：
 「K6/0-2: 阈值回写必须落到**配置实体**（`thresholds.json` 的 `thresholdOverrides[sentinelKey]`）。
  此前用 `sig.key`（类别级）当 `sentinelKey` ⇒ **永远查不到实体**
  ⇒ `found=false` ⇒ `skipped++` ⇒ **`applied` 恒 0** ⇒ `loop-3` 永远 degraded（**总闸关死**）。」
⇒ 🆕 **⇒ 这就是 CTO 最早立的「0-2 总闸」**
```

### ③ 做完对项目的推动

```
 · **宪章 §0.4 的 ⑥ 层**（进化回环）**从"名义存在"变成"真闭环"**
 · 🔴 **关掉「0-2 总闸」** ⇒ **"进化"这条线第一次点火**
 · 🔴 **且"话术红线"（不许宣称"越用越准/自我进化"）从这里开始才有资格松动** ——
   现在那句宣称**想吹都吹不了**（因为它确实是假的）
```

### ④ 🔴 不做行不行 —— **不行**

```
【结论】**不行**（**禁令级，不是欠账级**）
【理由】三层：
 ① 🔴 **它是"两个总闸"之一**（`0-2 进化回写 applied 恒 0`）——
    **不关它 ⇒ 系统"看起来会进化、实际没进化"** ⇒ 那是**功能层面的假象**
 ② 🔴 **它决定"进化"这条线是否可宣称** —— 不修 ⇒ 话术红线**永远不敢松**
 ③ 🔴 **它是"自我调参"的唯一通路** —— 不修 ⇒ **参数层（护城河资产）只能靠人工标定**
【⚠️ 但要诚实分档】：
 · **③ 阈值回写**（现有一条链路）⇒ **已通**
 · **①④⑤ 三类新回写** ⇒ **可分批**（**不是"一次全要"**）
 · **② 本体回写** ⇒ **结构性，影响最大** ⇒ **可最后做**
```

### ⑥ 还需要做什么

```
 ① **`changes` 扩成按层分型**：`loop-param` / `ontology` / `param-prior` / `nav-weight`（**＋现有 `sentinel-threshold`**）
 ② **审批分级**：L0 自动（③阈值 ④先验 ⑤导航）｜ L1 人工批（①循环 ②本体）
 ③ **`applied` 置位**：每次回写 ⇒ 置位 ＋ 记"谁置的、依据哪条 approve"
 ④ **每周期上限**：自动回写 ≤ N（首版 10）；**超限 ⇒ 停下来等人看**
 ⑤ **四类各自的"单一写入口"**（**不是各写各的**）
```

### ⑦ DSH 借鉴方式 —— **参考自研**（借原则，不借实现）

```
【借什么】`dsh-user-approval`（**审批接缝**）——《`@deepseek-ai/dsh-user-approval` README》：
 · 🔴 **"a grant applies only to the requested action"**（**一次授权只对一次动作**）
   ⇒ 借为：**L1 的"人工批"只对"这一条提案"生效**，**不是"批一次管一类"**
 · 🔴 **"missing or failing answerers fail closed"**（**审批者缺失即 fail-closed**）
   ⇒ 借为：**L1 类回写"没人批 ⇒ 不落盘"**（**不许默认放行**）
 · 🔴 **"An audit append that fails before commit rejects rather than returning an unlogged decision"**
   （**审计写失败 ⇒ 拒绝，而不是返回一个"没记账的决定"**）
   ⇒ 🆕 **⇒ 那正是"`applied` 必须置位"的纪律来源** —— **记账失败 = 不许落盘**
 · `ApprovalPolicy = 'ask' | 'never'`，`setApprovalPolicy()` 是**写路径**
   ⇒ 借为：**审批级别有"显式写路径"**（**不是散落在各调用点**）
【不借什么】
 · ❌ **不借它的"channel/answerer 瀑布"机制**（那是为"人在回路 + UI 通道"设计的；
   我们是**批量提案 + 单机**，不需要多 answerer 委托）
 · ❌ **不借它的"turn 绑定"**（它要求"每个 request 属于一个 open agent turn"；
   我们的回写是**周期任务触发**，没有 turn）
【为什么"自研"而非"照搬"】
 · DSH 的审批是**"逐次交互"**（**人点一下**）；E9 的审批是**"批量策略"**（**按类分级**）
 ⇒ **两者形状不同** ⇒ **借原则、实现自研** ✅
【另借一条】**`dsh-invariants`**：「**每个包发布一个 `./invariant` 伴生，注册自己的 npm 包名**」
 ⇒ 借为：**每类回写的"判据"由该类自己声明**（**不集中写在一处**）
```
