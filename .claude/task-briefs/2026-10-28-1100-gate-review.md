# #1100 W3 豁免证据链收窄（新件须带复核件 · 存量冻结为 legacy）

## Q0: 定位
- **项目拼图**：门禁本体保护（`scripts/control-tower/check-gate-protection.sh` ＋ `gate-exemptions/**`）。
  问题：豁免文件是**可审证据链**，但「这份豁免由哪次复核背书」无机器可判字段 ⇒ 存量 86 份豁免件
  全部只有路径/理由/裁定号，无法回答「谁看过」。W3 只对**新增**豁免件补这一层指针，存量冻结
  （不迁移、不加 expiry），避免一次性 86 份迁移把门禁判据与历史证据搅在一起。
- **文件审计（grep 实证）**：检查器 diff 段只做「受保护路径 → 合规豁免行」覆盖判定
  （`exempt_info` + `parse_exempt_text`）；`is_exempt_file()` 已排除 README；无任何 base 存在性判定
  ⇒ 新增「legacy vs 新增」区分必须新加判据（`git cat-file -e <merge-base>:<path>`）。
- **决策**：复用现有三态/typed error/降级约定；**不新增错误码**（复核件缺失复用 `E_EXEMPT_INVALID`，
  phase=review）；开关 `--require-review=0|1` 默认 1，为唯一回滚点。

## Q1: 调研
- **业界基线**：证据链（evidence pointer）与审批签名分离 —— 指针可自动核形态，签名需要人。
  W3 只做指针形态（PR# / 复核 JSON 路径），不伪装成"谁批准"。
- **本仓教训**：#623（裁 217）删作者校验的结论是「豁免=可审证据链，不是授权」；本条沿用同一口径，
  故复核件只是**指针字段**，不核 PR 是否存在、不核指向文件是否已落盘（写入脚本头「已知限制 15/16」）。
- **反启发式**：#1100 硬要求 legacy 判据只认 base 存在性，禁日期/内容启发式 ⇒ 实现为
  `in_base()` 单函数（`git cat-file -e`），测试 M-2′ 用「改一版存量件仍免检」锁死该语义。
