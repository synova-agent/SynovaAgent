# cto-bookkeeping — 一本账：决策进台账，状态进 #671

## 0. 意图（为什么有这件）
> 创始人要"**一张能真实反映项目的账**"，而不是多套账/靠记忆。⇒ 一个决策账 + 一个状态页；其余只读或派生。

## 1. 两个唯一载体
| 载体 | 写什么 | 禁止 |
|---|---|---|
| `CTO-裁定台账.md`（handbook） | **只记决策**：`## 裁定 NNN · 结论` + 3–10 行（决定/依据/边界） | ❌ 不复制状态、不贴长表、不写"当前 sha/在飞数" |
| Gitea **#671** | **只记状态**：§11 在飞线程、§12 五步状态 | ❌ 不写决策历史 |

其余：活账已归档只读；周报/交接是派生；Issue 评论是证据。

## 2. 每个 CTO 会话（开工 / 收工）
```
开工：读 #671 §11/§12（重建"在飞/卡在谁"）→ 读台账最后 3 条裁定
收工（有决策才写）：
 ① 决策 → 台账追加 `## 裁定 NNN`（编号 = 上一条 +1）
 ② 状态变了 → 改 #671 对应节（只改状态，不复制裁定）
 ③ 两处都不写长文；台账一行"详见 #671 §N"
```

## 3. 每周日核对（10 分钟）
```
 □ 台账新增裁定编号连续、无重复标题
 □ 台账里是否混入"状态类"内容 ⇒ 移到 #671
 □ #671 §11：每条线程有「状态/卡在谁」；已收口的移入"已收口"行
 □ #671 §12：五步状态与事实一致（数字必须可命令复跑）
 □ 过时/重复条目：合并或删除（保留裁定号与结论）
```

## 4. 每月 1 日归档（清理）
```
 · 把 >30 天的裁定整段移到 `CTO-裁定台账-归档-<YYYY>.md`（原号保留，主账留一行索引）
 · 归档后主账目标：≤ 2,000 行；归档件不参与日常阅读
 · 归档 commit message：`docs(cto): 归档裁定 a..b`
```

## 5. 判据（机器可判）
```
 ① 台账每个新条目标题匹配 `^## 裁定 [0-9]+ ·`
 ② 台账内不出现 `as_of`/`open PR`/`在飞` 等状态词（出现即提示迁 #671）
 ③ #671 §11 每条线程必须有"卡在谁"非空
 ④ 主账行数 > 2,000 ⇒ 提醒归档（launchd 周检可发 issue）
```
