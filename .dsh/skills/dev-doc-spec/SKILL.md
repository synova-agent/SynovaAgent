# dev-doc-spec — 活规格撰写（**v2：按读者重排**）

## 由来与 v2 的改动理由

- **2026-09-23（v1）**：原 `📋 synova-devdoc` 常驻 session 退役，能力技能化。读者＝**线负责人（长期 session，有上下文）**，目的＝**给 K3 审计 ＋ 规格论证** ⇒ 11 节，大量篇幅在"论证"。
- **2026-10-18（v2）**：分工改为 **L1（包负责人）→ 创始人 → L2（squad-lead，一任务一会话，fresh 无记忆）**。
  **读者变了** ⇒ dev doc 的使命从"**规格论证**"变为"**操作说明书**"。

🔴 **v2 的唯一判据**：**一个零上下文的小队，只读这份 dev doc，能否不提问就开工并自证完成？**

🔴 **动笔之前必须先跑 `pre-plan-thinking` 的 9 问**（问题/现状/有没有现成/最小改动/最危险假设/失败路径/边界/可观测/拆步）。
**9 问的产物就是本文档的八节** —— 不跑 9 问就写八节 ＝ 抄格式。

## 【封面】四行开场包（**放文档最顶部**；可从正文自动派生）

```
① 批次名：<例：P4-A类第1条>
② 写集（逐文件；由 L1 划，L2 不得扩）：
   - <path>（改什么）
③ 判据（含"改坏必红"）：
   - 命令：<...>　期望：<...>
   - 反例：<改坏 X ⇒ 必红，命令＋期望输出>
④ 域守则指针（必须显式 read）：
   - <path/AGENTS.md>
```

## 【front-matter】`id` / `status`（由流程定，禁自宣）/ `北星`（产品线验收点，供 K3）/ `批次规模`（文件数·预估行数）

## 8 节必填（逐节非空，缺节即退回）

### §1 做什么
- **目标**：一句话 ＋ 可观测结果
- **非目标**：逐条列**路径**（L2 不许碰的地方）；**禁碰清单**必须含 `scripts/audit/**`

### §2 在哪做
- 🔴 **改动点 file:line**（不是"改哪个文件"，是"**改哪一行/函数**"）：
  `- <path>:<line> — <改什么>`
- **写集**：逐文件；**两两不重叠**；机器块格式对齐 `brief_parser.py`
- **新建文件**须标 `<新建>` 并说明父目录

### §3 凭什么做（现状证据）
- 每条**事实性前提**：`- <前提> | <命令> | <原始输出摘要>`
- 🔴 **禁"我认为"/"应该是"**；前提不成立 ⇒ **停，退回 L1**

### §4 怎么算做完（**最重要**）
- **三路径**：
  - **正常**：命令 ＋ 期望输出
  - **降级**：触发条件 ＋ 期望的 `degraded:` 输出（若有）
  - 🔴 **反例**：**改坏什么 ⇒ 必红**（命令 ＋ 期望输出）—— **没有反例＝没判据**
- **DS（交付声明）**：逐条可核验（并入本节，不再单列）

### §5 🆕 怎么跑（**v1 缺，L2 fresh 必问**）
```
 取树：git fetch gitea → git worktree add .synova-wt-<批次>-$(date +%m%d) -B ct/<批次> gitea/local-main
 依赖：<装依赖命令；或"无依赖">
 运行：<启动/执行命令>　　端口：<例 PORT=18790（3000 被 Gitea 占）>
 环境：node <版本>／<其他硬约束>　　无 timeout 命令 ⇒ 长任务用后台 job
 落盘：证据放 <路径>（**不放 /tmp，会被清理**）
 自检：<一条能证明"环境对"的命令>
```

### §6 有什么基础（禁止重复建设）
- 逐条：`<能力> | grep 命令 | 命中 N | 结论：复用 / 扩展现有 / 确需新建（说明为何不能复用）`
- **必查四类**：`scripts/control-tower/`（**136 件**：check-* **26**（全树 check-* 60）／probe-* 28）／`scripts/doc-system/`·`workflow/`·`integration/`／相关 skill／**既有约定**
- 🔴 **四个必须复用的既有约定**：① 三态退出码（0/1/**2**）② `@降级`＋`SYNO_GATE_DEGRADED_LOG` ③ UTF-8 强制（D732）④ 判别力自检
- 写"确需新建"但未说明**为何不能复用** ⇒ **退回**

### §7 前置与红线
- **前置**：`- <前置> | 判据（已完成/进行中）| 未满足则停`
- **全局红线**：禁碰 `scripts/audit/**`（K3 专属）／禁改别人写集／禁 `git stash`／不在主树写码

### §8 交什么（给 L1）
```
 回执三信号：① 判据通过率（绿/红）② 例外清单 ③ 在飞数
 R2 指针 ≤10 行：批次名 ｜ 写集（逐文件）｜ 自验结论 ｜ 证据 ｜ 未决项
 证据留存：<路径>（原始输出，禁手写数字）
 🔴 不判"通过"：只能给 自验结论 / 可提请独立复核 / 退回（附理由）
```

## 3 条件节（**适用就写，不适用必须显式注明"不适用"**）

- **C1 契约**（有接口/脚本/新模块）：输入／输出／降级／错误码（铁律 47）
- **C2 边界值**（有数值/集合参数）：空／单元素／恰临界（=阈值、=limit）／超限／零／负值
- **C3 失效条件**（**新增规则/门禁/契约**时）：这条规则何时可撤——**无失效条件的规则不许进仓库**

## 何时必须启用（触发，三条任人一条）

1. **L1 要把批次交给 squad-lead**：待办 **≥2 件** 或 单件 **>300 行 / >5 文件**（**硬要求**）
2. **跨层改动**（触及两个及以上架构层）
3. **新子系统/新产品线**（无既有范式）
4. **超预算**（>12 文件 或 >2 天）

不满足触发条件的：规格写进**包守则/派单件**即可，不需要本技能。

## 独立性硬要求（不可放宽）

- **撰写者独立于实现者**：写规格的人**不得**实现该规格对应的代码
- 规格**先落 main 可读**，L2 不得引用未落 main 的规格路径
- 规格是独立交付物，有自己的复核（判据/写集/Done 可证伪）

## 验收（撰写完成后自检）

```bash
bash scripts/workflow/check-brief-parseable.sh <brief>       # 可解析
bash scripts/control-tower/pre-dispatch-check.sh <规格件>     # 机械项 + 引用可核验
bash scripts/workflow/check-dev-doc-write-set.sh             # 写集 vs 实际改动漂移 0
# ④ DSH 代码标准 8 项（缺则 L1 不收）：见 .dsh/skills/dsh-code-standards/SKILL.md
```

## 红线 · 状态不得自宣（2026-09-26 加，来源 K3 文档契约审计）

- **front-matter 的 `status:` 由流程决定，撰写者不得自宣**：`proposed` →（**K3 审计 ＋ CTO 收件闸**）→ `implemented`
- **未过审计即写 `status: implemented` = 违反本条**；`生效日期` 同此
- 理由：**"状态写进文档本体"是同一错误模式的第三次出现** ⇒ **状态是流程的产物，不是撰写者的声明**
- 批准凭据必须可查（PR 链接／决策文件路径），不得只写"创始人批准"
