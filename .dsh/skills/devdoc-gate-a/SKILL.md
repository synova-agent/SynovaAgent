# devdoc-gate-a — 关卡 A：北星对齐 ＋ 七镜头评审

> **一句话**：判断「一个零上下文的 L2 小队，只凭这份 dev doc ＋ 卡 ＋ 仓库，能否独立完成并交出可验收证据」。
> **不是**评文字好坏，**是**评"能不能照做、做完能不能验"。**先过 §2 北星（方向），再过 §3 七镜头**。
> 🔴 **镜头 7（DSH 纪律）自 2026-11-01 起为 blocking 级**：凡规格声称「借 DSH」，必须能给全路径原文＋不变量；给不出＝**未借**，按 blocking 处理（依据裁 429 ⑥「禁自造／禁假对齐／禁倒着借」）。

## 0. 何时用 / 不用

| 用 | 不用 |
|---|---|
| L1 写完 dev doc／派单件，**派 L2 之前** | 单卡实现细节 review（`pr-review`） |
| dev doc 大改后**复审**（同一套镜头） | 纯文档镜像存档（裁 244 免） |
| 跨包/跨机（Mac→Win）交接前 | 已在跑的批次中途纠偏（用 R2 对账） |

**前置**：dev doc 已在 `.handbook/派单件/`（handbook 仓）且 commit＋push——没提交＝没交付。

## 1. 输入与纪律（缺一即不合规）

```
输入：dev doc ＋ 批次卡 ＋ 验收点卡 ＋ 包守则 ＋ 仓库（只读，钉 SHA）＋ 既有证据原件
纪律：
 ① **零上下文**：不看作者/CTO 结论，只给材料
 ② **不采信作者结论**：每条断言自己跑命令核（`claim-verifier` 口径）
 ③ **每条判断带 file:line 或命令**；无法核实 ⇒ 单列「无法核实」
 ④ **只读**：不改任何文件；⑤ 至少 5 个视角独立跑，**不许一个视角代替全部**
```

## 2. 北星对齐（并入原 `north-star-guard`；不齐 ⇒ 打回）

**时机**：① 收到 dev doc／方案／设计提案 ⇒ **先判对齐再谈技术**；② 自己写完 ⇒ 提交前自裁决一遍。
**输入**：候选文档（**必须带北星 front-matter**）＋ `.claude/PRODUCT-BRIEF.md`（唯一事实源，先读）。

**四问（逐问缺一即偏离；问 4 于 2026-09-26 加）**：
```
 问1 **服务真实用户场景吗**：锚定的服务用户是 PRODUCT-BRIEF 里的真实用户（GA／企业主）吗？
      凭空造没人要的功能 ⇒ 偏离。
 问2 **让模块更接近终态吗**："模块终态"与 PRODUCT-BRIEF 里该模块定位一致吗？
      朝终态走一步 vs 横向加个无关的东西——横向 ⇒ 偏离。
 问3 **会不会让产品"变成另外的样子"**：做完还是"驻扎企业、主动诊断、为增长服务"的 Agent 吗？
      变成 ChatBot／报表工具／别的产品 ⇒ 偏离（**最高优先级**）。
 问4 **这条约束会拦截哪条既有工作流**：凡约束类条款（白名单／禁令／必须／阻断／门禁），必须列出
      它会拦截的现有工作流并逐条确认；答不出 ⇒ **不得生效**（先补再放行）。
      教训（K3 契约审计 P0-1）：入库白名单本意挡过程文档，却挡住「加目录就能加专家/技能」这一
      核心机制 ⇒ 不能只看想挡什么，还要看误伤什么。
```

**输出**：**对齐** ⇒ 放行，写明"对齐北星 §X ＋ 终态推进点"｜**偏离** ⇒ 打回，附理由＋PRODUCT-BRIEF 引用行号＋改哪里。裁决是**物理判断**，非感觉。
**红线**：❌ 这是方向裁决，不是技术 review｜❌ 无北星 front-matter ⇒ 直接打回（锚定块是硬前提）｜拿不准方向 = **升级创始人**（产品方向是创始人的领域）。

## 3. 七镜头（逐个跑；每个都出 verdict ＋ blocking_gaps）

### 镜头 1 · 卡面审计（复用 `line-audit-and-cards`）
```
 □ 六字段：Q0 定位（块号＋块现状＋新增/替换/扩展总判）｜Q1 调研（memory 具名事故）｜
   Q2 范围（不做什么**逐条裸路径**，禁 glob——G12 字面匹配）｜Q3 验收（入口→交互→结果）｜
   架构层｜写集（逐文件）
 □ §〇 七问：问题/现状/不做行不行/最小改动/最危险假设/失败路径/可观测
 □ §3.5 横向查重：写集重叠（全仓与在飞 PR）｜跨块同判据｜语义关键词｜同源
```

### 镜头 2 · 规格完整性（`dev-doc-spec` v2）
```
 □ 9 节齐（＋出生证六件套）：做什么／在哪做（file:line）／凭什么／怎么算做完（含反例）／
   怎么跑／既有基础盘点／前置与红线／交什么
 □ 既有基础盘点达「必查四类」：scripts/control-tower、scripts/{doc-system,workflow,integration}、
   相关 skill、既有约定；写「确需新建」必须说明为何不能复用
 □ pre-dispatch-check 机械项真过（④ 路径提取对反引号路径会假通过，须人核）
 □ 写集机器可解析（devdoc_writeset.py 能抽）；不是就退回
```

### 镜头 3 · 零上下文执行者（Win/L2 视角）
```
 □ 从"取树"开始走：clone/remote 名/依赖安装/node 版本/编码（Win: git-bash + UTF-8）每步可行？
 □ 每个判据能答：跑什么命令？期望值从哪来？怎么造反例？怎么证明"真的跑了"？
 □ 卡间串行：新会话怎么知道上一卡的 merge sha？有没有可执行检查？
 □ 遇到不清时的停工规则写明（停，报 L1，不自改判据）
```

### 镜头 4 · 判据红队（对抗）
```
 □ 恒真断言：`>=0`／`ok===true`／0 failed 但 0 条执行（`-t` 零命中 exit 0）
 □ 自证：期望值与被测对象同源派生 ⇒ 必须独立来源＋内容断言
 □ 反例只测 mock／只测既有函数 ⇒ 必须打在"新代码被消费"的缝上
 □ "无回归"有无机器绑定（CI 只跑 --changed 时必须显式全量命令＋基线）
 □ 跳过／恒真能否满足「两 Provider 同套绿」「配对测试」
```

### 镜头 5 · 写集/边界/并发
```
 □ 写集三源一致（卡面/批次卡/dev doc）；有冲突就写"以哪为准"
 □ 与在飞 PR 求交：给命令与输出（不是声明）
 □ 卡间同改文件是否真串行（给命令：`git merge-base --is-ancestor <sha>`）
 □ 红线路径是否排除（dsh/plugins、package.json、scripts/audit、.gitea）
 □ 平台：CRLF/UTF-8/路径/remote 名
```

### 镜头 6 · 声明核实（`claim-verifier`）
```
 □ 抽验现状断言：file:line 对不对、grep 是否真 0、命令是否存在、证据原件是否随附
 □ "脚本原文见证据文件"⇒ 证据文件里必须真有；临时脚本必须随附
 □ as_of：doc 钉的 SHA 与现场差几 commit；差集是否涉本批面
```

### 镜头 7 · DSH 纪律与代码品味（**blocking 级；2026-11-01 立**）

> 由来：2026-11-01 一轮实战里，标准六镜头连跑三轮都放行，但**四条「假对齐」**只有专门的 DSH 视角才抓到
> （注释自称「DSH timeout-policy 同款」实为 `Promise.race`／`toolPairingBalanced*` 当作事后检查实为切点前置守卫／
> 借 `flush` 我方根本没有／「N 调用⇒N 结果」实为调度器失败不造结果）。⇒ 借名字不借不变量，六镜头全拦不住。

```
 ① 引用可核：每条「借 DSH」必须给 包名＋全路径＋行号＋原文摘句；禁「默认 lib/index.js」捷径
    （该捷径已制造两处错位：日志真身在 surface.js:3、TurnEndReasonMap 在 lib/types/types.d.ts:135-167）。
 ② 借的是不变量：必须写出「DSH 的不变量一句话」＋「我方等价断言」；写不出 = 未借 ⇒ blocking。
 ③ 禁反着借：每条对照给「DSH 方向 vs 我方实现」两列，方向相反即 blocking。
    已发生三种：切点前置守卫 vs 事后检查／失败时「不造结果」vs「必须补齐」／有异步写窗才有 flush vs 我方无此物。
 ④ 禁假对齐：注释/文档出现「DSH 同款/DSH 一致」必须与原文逐字对得上；对不上即当缺陷。
 ⑤ 自建区要论证：DSH 没有或不该借的，逐条写「为什么没有／为什么不该借」＋「照它的纪律该怎么写」。
 ⑥ 上限即纪律：无界队列/重试/轮次/并发必须给显式常量与超限处置；常量须 grep 得到且与文档一致。
 ⑦ 失败关闭与归因：每个 catch/降级必须带 code＋归属，禁「把失败变成不存在」
    （例：allSettled 只取 fulfilled、无 log 无计数 ⇒ blocking）。
```

**判据**：①–⑦ 任一条不成立即 **退回**；①⑦ 可机器判，②③④ 需对照表存在，⑤ 只能人判。
**取材**：`.dsh/skills/dsh-code-standards/SKILL.md`（8 项标准＋4 条约定，带 file:line）＋六条纪律原文
（日志即真相／一次调用一个结局／终态具名／语义屏障／上限即纪律／机械与业务分离）。

## 4. 输出模板（落 handbook ＋ Issue 评论）

```
## 关卡 A：通过／退回（N 视角：x 不够／y 有条件）
### 各视角结论表（视角｜verdict｜代表问题）
### 必修清单（按阻塞度；每条：问题｜证据 file:line/命令｜改法）
### CTO 侧已改（不属于 L1 的，如卡面/守则修正）
### 另开卡（门禁面/CI 面，不塞进本批写集）
### DSH 借法对照表（镜头 7 必附；每条：DSH 原文位置｜不变量｜我方等价断言｜方向是否一致）
### 账：裁 NNN ＋ 评论链接
```
**判据**：退回时每条必修都能让 L1 直接改（有位置/改法/验收方式）；通过时写明"复审抽验哪 3 条"。

## 5. 常见坑（本轮实证，逐条查）

```
 ① claim 死链：要求建 .claude/claims 却不在写集 ⇒ 组 6 建也红不建也红
 ② `-t "S4"` 零命中假绿 ⇒ 稳定标签＋断言 numTotalTests/numPassed/numPending==0
 ③ 期望值同源派生 ⇒ 独立扫描＋内容断言｜④ 写集三源不一致 ⇒ 定唯一源
 ⑤ 卡1 依赖卡2 的新文件 ⇒ import 不存在必红｜⑥ 类型/默认值矛盾 ⇒ tsc 必红
 ⑦ 新 export 未被 src 引用（组 4a 硬红）｜⑧ 既有能力漏盘（可复用却重写）
 ⑨ 证据原件缺失（"原文见证据文件"但文件里没有）｜⑩ 关闭时序（Closes 早于回填）
 ⑪ as_of 漂移（SHA 已落后；差集须核是否涉面）｜⑫ Win 环境（remote 名/nvm/CRLF）缺失 ⇒ 起手就失败
 ⑬ CI 固定工作区无 concurrency ⇒ "CI 绿"不绑定被审 sha（另开卡）
 ⑭ **借名不借不变量**：写了「借 DSH」却给不出原文/不变量 ⇒ 未借（镜头 7 ①②）
 ⑮ **反着借**：方向相反（切点前/后、造不造结果、有没有该 API）⇒ 比不借更危险（镜头 7 ③）
 ⑯ **假对齐**：注释写「DSH 同款」但原文相反 ⇒ 按缺陷记（镜头 7 ④）
 ⑰ **借不存在的层**：把某文件当 seam，而该文件在锚上不存在（`git cat-file -e` 即可证）
```

## 6. 角色卡（每个角色 = 一个独立会话；不得互看、不得看作者结论）

> 下表每行即一张 prompt 骨架；材料/问题/纪律相同，**并行跑、互不通气**。

| 角色 | 一句话任务 | 必查 |
|---|---|---|
| **R1 卡面审计** | 用 `line-audit-and-cards` 审六字段/七问/横向查重 | 缺项、写集重叠、判据不可判 |
| **R2 规格完整性** | 按 `dev-doc-spec` 9 节逐节判"齐不齐、能不能执行" | 既有基础盘点、怎么跑、交什么 |
| **R3 零上下文执行者** | 假装第一次拿到它，从取树开始走一遍 | 哪一步会停、缺什么命令/期望值 |
| **R4 判据红队** | 证明判据能被钻空子/造假绿 | 恒真断言、同源自证、skip 当绿 |
| **R5 写集/边界/并发** | 写集是否闭合、与在飞 PR 是否撞、红线是否排除 | 三源不一致、串行无命令、平台差异 |
| **R6 声明核实** | 抽验 doc 里的现状断言 | file:line、grep 是否真 0、证据件在不在 |
| **R9 DSH 纪律（2026-11-01 新增·必跑）** | 逐条核「借 DSH」是否借到**不变量**：原文可核／方向一致／无假对齐／自建有论证／上限显式／失败有归因 | 借名不借不变量、反着借、假对齐、无界、失败被静默 |

🔴 **R9 与 R1–R6 同级必跑**（不再是「高风险才加」）：凡规格出现「借 DSH／对齐 DSH／DSH 同款」即触发。

**高风险任务（跨机/自动化/门禁）加两个角色**：
- **R7 架构/安全**：公开面、凭据、攻击面、可用性（如 self-hosted runner 在公开仓）。
- **R8 验收裁判**：只拿交付物判"能否据此开工/交付"（四项回执：不一致/无法核实/跑不通/总评）。

## 7. 聚合规则（谁来合、怎么判）

```
 ① 任一角色 verdict=不够 ⇒ 本关**退回**（不允许"多数通过"）
 ② 有条件 ⇒ 只允许"附条件通过"，条件落成必修项
 ③ 每条 blocking gap 必须有证据（file:line 或命令）；无证据降为建议
 ④ 去重后按"会不会导致假绿/卡死"排序；Top5 单列
 ⑤ 作者回应表**不作证据**：只认正文与命令
 ⑥ 复审只验上轮 blocking ＋ 3 条抽验，同一套角色卡
 ⑦ **镜头 7 的 verdict 与其余镜头同级**：任一「借 DSH」给不出原文/不变量 ⇒ 退回，不得降为建议
```

## 8. 反模式（见到即判流程失败）／纪律红线

```
 ❌ 一个角色代替全部｜❌ 作者在场解释｜❌ 评审者看到 CTO/作者结论
 ❌ 只审文字不跑命令｜❌ 拿"抽样通过"当"全量通过"
 ❌ 用"多数票"压过单个致命缺口｜❌ 退回意见不写改法／只写"不清楚、再完善"
 ❌ 评审者参与写作（不可自审）｜❌ 不通过不能"先派了再说"
 ❌ **把「借 DSH」当装饰**：只写「参考 DSH」不给原文／不给不变量／方向反了也照抄
 ❌ **自造还自称借鉴**（2026-11-01 实证：注释写「DSH timeout-policy 同款」，实为 `Promise.race`，与原文相反）
 ❌ **对镜头 7 打折扣**：「实现期再对齐」——契约分叉在实现期只会更深
 ✅ `pre-dispatch-check` 只是机械前置，不代替本评审；技术取舍走 `dsh-decision-lens`
```

## 9. 运行方式（固化 · 裁 267）

```
 评审者：由 **L1 自己安排**的零上下文独立会话（**不得是作者、不得是 CTO**）；
   K3 只做高风险抽查/合并后审计/事故复盘，**不逐卡介入**。
 并行：5–9 个 fresh 会话（按风险），互不共享上下文。**R9（DSH 纪律）默认必跑**，不必等「高风险」才加。
 输出：**一条 Issue 评论**（verdict＋blocking＋停点确认），**不出报告文件**；报告落 handbook。
 CTO：只抽验 4 节点（规格/首次写数据/改门禁/周抽）＋签字，不逐卡评审。
🔴 未过关卡 A 不许开工（Win/Mac 同规）；依据裁 255/256＋AGENTS.md §15。
```
