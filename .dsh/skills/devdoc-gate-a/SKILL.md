# devdoc-gate-a — 关卡 A：dev doc 六镜头评审

> **一句话**：判断「一个零上下文的 L2 小队，只凭这份 dev doc ＋ 卡 ＋ 仓库，能否独立完成并交出可验收证据」。
> **不是**评文字好坏；**是**评"能不能照做、做完能不能验"。

## 0. 何时用 / 不用

| 用 | 不用 |
|---|---|
| L1 写完 dev doc／派单件，**派 L2 之前** | 单卡实现细节 review（那是 pr-review） |
| dev doc 大改后**复审**（同一套镜头） | 纯文档镜像存档（裁 244 免） |
| 跨包/跨机（Mac→Win）交接前 | 已在跑的批次中途纠偏（用 R2 对账） |

**前置**：dev doc 已在 `.handbook/派单件/` 且已 commit＋push（本地写完没提交＝没交付）。

## 1. 输入与纪律（缺一即不合规）

```
输入：dev doc ＋ 批次卡 ＋ 验收点卡 ＋ 包守则 ＋ 仓库（只读，钉 SHA）＋ 既有证据原件
纪律：
 ① **零上下文**：评审者不看作者的解释、不看 CTO 结论，只给材料
 ② **不采信作者结论**：每条断言自己跑命令核（claim-verifier 口径）
 ③ **每条判断带 file:line 或命令**；无法核实⇒单列「无法核实」
 ④ **只读**：不改任何文件
 ⑤ 至少 5 个视角独立跑，**不许一个视角代替全部**
```

## 2. 六镜头（逐个跑；每个都出 verdict ＋ blocking_gaps）

### 镜头 1 · 卡面审计（复用 `line-audit-and-cards`）
```
 □ 六字段：Q0 定位（块号＋块现状＋新增/替换/扩展总判）｜Q1 调研（memory 具名事故）｜
   Q2 范围（不做什么**逐条裸路径**，禁 glob——G12 字面匹配）｜Q3 验收（入口→交互→结果）｜
   架构层（如「−1 运行时（宪章 §4.2）」）｜写集（逐文件）
 □ §〇 七问：问题/现状/不做行不行/最小改动/最危险假设/失败路径/可观测
 □ §3.5 横向查重：写集重叠（对全仓与在飞 PR）｜跨块同判据｜语义关键词｜同源
```

### 镜头 2 · 规格完整性（`dev-doc-spec` v2）
```
 □ 8 节齐：做什么／在哪做（file:line）／凭什么／怎么算做完（含反例）／怎么跑／既有基础盘点／前置与红线／交什么
 □ 既有基础盘点达「必查四类」：scripts/control-tower、scripts/{doc-system,workflow,integration}、相关 skill、既有约定；
   写「确需新建」必须说明为何不能复用
 □ pre-dispatch-check 机械项真过（注意：④ 路径提取对反引号路径会假通过，须人核）
 □ 写集机器可解析（devdoc_writeset.py 能抽）；不是就退回
```

### 镜头 3 · 零上下文执行者（Win/L2 视角）
```
 □ 从"取树"开始逐步走：clone/remote 名/依赖安装/node 版本/编码（Win: git-bash + nvm + UTF-8）每一步都可行？
 □ 每个判据能回答：跑什么命令？期望值从哪来？怎么构造反例？怎么证明"真的跑了"？
 □ 卡间串行：新会话怎么知道上一卡的 merge sha？有没有可执行检查？
 □ 遇到不清时的停工规则是否写明（停，报 L1，不自改判据）
```

### 镜头 4 · 判据红队（对抗）
```
 □ 恒真断言：`>=0`/`ok===true` 单独成立/0 failed 但 0 条执行（`-t` 零命中 exit 0）
 □ 自证：期望值与被测对象同源派生（如 E 与 loader 同源）⇒ 必须独立来源＋内容断言
 □ 反例只测 mock/只测既有函数 ⇒ 必须打在"新代码被消费"的缝上
 □ "无回归"有无机器绑定（CI 只跑 --changed 时，必须显式全量命令＋基线）
 □ 跳过/恒真能否满足「两 Provider 同套绿」「配对测试」
```

### 镜头 5 · 写集/边界/并发
```
 □ 写集三源一致（卡面/批次卡/dev doc）；有冲突就写"以哪为准"
 □ 与在飞 PR 求交：给命令与输出（不是声明）
 □ 卡间同改文件是否真串行（给命令：merge-base --is-ancestor <sha>）
 □ 红线路径是否排除（dsh/plugins、package.json、scripts/audit、.gitea）
 □ 平台：CRLF/UTF-8/路径/remote 名
```

### 镜头 6 · 声明核实（`claim-verifier`）
```
 □ 抽验 doc 里的现状断言：file:line 是否对、grep 是否 0、命令是否存在、证据原件是否随附
 □ "脚本原文见证据文件"⇒ 证据文件里必须真有；临时脚本必须随附
 □ as_of：doc 钉的 SHA 与现场差几 commit；差集是否涉本批面
```

## 3. 输出模板（评审报告；落 handbook ＋ Issue 评论）

```
## 关卡 A：通过／退回（N 视角：x 不够／y 有条件）
### 各视角结论表（视角｜verdict｜代表问题）
### 必修清单（按阻塞度；每条：问题｜证据 file:line/命令｜改法）
### CTO 侧已改（不属于 L1 的，如卡面/守则修正）
### 另开卡（门禁面/CI 面，不塞进本批写集）
### 复审重点（哪几条必须验）
### 账：裁 NNN ＋ 评论链接
```

**判据**：退回时每条必修都能让 L1 直接改（有位置、有改法、有验收方式）；通过时写明"复审抽验哪 3 条"。

## 4. 常见坑（本轮实证，逐条查）

```
 ① claim 死链：要求建 .claude/claims 却不在写集 ⇒ 组 6 建也红不建也红
 ② `-t "S4"` 零命中假绿（vitest 0 条 exit 0）⇒ 用稳定标签＋断言 numTotalTests/numPassed/numPending==0
 ③ 期望值同源派生（E 与 loadSentinels 同源）⇒ 独立扫描＋内容断言（id/layer）
 ④ 写集三源不一致（卡/批次卡/dev doc）⇒ 定唯一源
 ⑤ 卡1 依赖卡2 的新文件 ⇒ import 不存在，必红
 ⑥ 类型/默认值矛盾（联合类型 vs 默认值）⇒ tsc 必红
 ⑦ 新 export 未被 src 引用（组 4a 硬红）
 ⑧ 既有能力漏盘（content-registry/initContentTypes 可复用却重写）
 ⑨ 证据原件缺失（"脚本原文见证据文件"但文件里没有）
 ⑩ 关闭时序（PR Closes 早于证据回填）违反卡关规则
 ⑪ as_of 漂移（钉的 SHA 已落后；差集须核是否涉面）
 ⑫ Win 环境（remote 名、nvm install、CRLF/UTF-8）缺失 ⇒ 起手第一条命令就失败
 ⑬ CI 固定工作区无 concurrency ⇒ "CI 绿"不绑定被审 sha（门禁面 A 类，另开卡）
```

## 5. 与其他 skill 的关系

```
 · `line-audit-and-cards`：镜头 1 的完整方法（六字段/七问/查重）
 · `dev-doc-spec`：镜头 2 的 8 节定义
 · `claim-verifier`：镜头 6 的核实口径
 · `pre-dispatch-check`：机械前置（CTO 自核，不代替本评审）
 · `pr-review`：合并前审查（关卡 B），不是本 skill
```

## 6. 纪律红线

```
 ❌ 评审者不参与写作（不可自审）｜❌ 不给作者结论/自查结果（否则只会附和）
 ❌ 不通过不能"先派了再说"｜❌ 退回意见不许只写"不清楚/再完善"
```
