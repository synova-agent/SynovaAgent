# dsh-code-standards — 通用编码标准

**用法**：动手前对照 A（稳定原则）与 B（按对象适用）；C–E 只在对应对象上适用，不是所有代码的统一门禁。判定「不适用」时说明理由即可，不要求形式化豁免。

## A. 稳定原则（默认全部适用）

1. 先理解真实行为，再修改代码；
2. 优先复用现有能力；
3. 选择满足当前契约的最小实现；
4. 边界输入需要校验；
5. 错误必须可见、可诊断、可归因；
6. 禁止静默降级和伪造成功；
7. 公开或高风险边界说明输入、输出与失败；
8. 关键业务行为必须有真实测试；
9. 测试覆盖正常、失败和必要边界；
10. 不写没有当前消费者的通用框架；
11. 不用类型逃逸、空测试、模板常量或假数据掩盖问题；
12. 不因为 DSH 提供某能力就把该能力变成 Synova 需求。

**简单设计**：能复用就复用，能少一层就少一层；新增抽象要有当前消费者与明确收益。

## B. 按对象适用（不机械覆盖所有代码）

| 规则 | 适用对象 |
|---|---|
| typed error／错误 code | 跨边界、需要调用方处理或诊断的错误 |
| schema 校验 | 外部输入、配置、内容包和持久化边界 |
| 三态退出码 | 脚本、检查器和自动化判定 |
| 完整公开契约 | 公开接口、共享模块、领域计算与高风险边界 |
| Known Limitations／Source map | 需要被他人使用或维护的包、工具和复杂模块 |
| 配对测试 | 有明确配对约定的控制塔或特定工程对象 |
| DSH 源码 file:line | 实际依赖或核对版本行为时 |

不得再把「每个 catch 都返回 degraded」「每个文件都写同一种 README」「所有模块统一三态」当作普遍代码品味。

## C. 契约与错误（按边界适用）

- 公开接口、共享模块、领域计算、高风险边界、外部输入/配置/内容包/持久化边界 ⇒ 先写清输入、输出、失败与降级，再写实现（JSDoc 或等价约定）。
- 错误跨边界 ⇒ typed error 带机器可读 code，调用方能区分「可重试／不可重试／需人工」。
- **fail loud**：不吞异常、不返回假成功、不把「看不见」当「没问题」；降级必须可归因（日志或错误对象带 code／phase／retryable）。
- 只在任务确实位于该边界时填这套契约；纯内部小实现不强填无意义全套。

## D. 复用约定（控制塔／脚本任务按需适用）

以下四条是既有约定；改控制塔、门禁脚本或判定类工具时优先复用，不重复发明：
- **三态退出码**：0 通过／1 真红／2 检查自身失败（判不了 ≠ 通过）。
- **降级显式**：stderr `degraded: <原因>` ＋ 结构化降级日志（含 time／component／code／phase／retryable）。
- **UTF-8 强制**：读写按 UTF-8；跨平台脚本显式声明编码。
- **判别力自检**：关键判定要能证明「改坏确实红」，不是只看绿。

产品业务代码不因这四条存在就被要求套用；是否适用看 B 表。

## E. DSH 核查（只在任务需要时）

只有修改 DSH 适配边界、正确性依赖 DSH 具体契约、或声称沿用某 DSH 行为且影响验收时才核查，**以当前锁版安装实物为准**：

```bash
dsh --version        # 1 当前锁版（版本锚，不写死数字）
npm root -g          # 2 全局安装根；CLI 包在 <root>/@deepseek-ai/dsh（桌面应用版在应用 resources 下的 dsh 目录）
ls "<root>/@deepseek-ai/dsh"   # 3 先证实物存在，再从实物读路径与行为
```

- 版本、路径与行号随锁版变化 ⇒ 不存进本技能，用前现场核；**实物读不到 ⇒ 报「不可核实」，不得引用**。
- 引用格式 ＝ 当前实物路径 ＋ 可复跑命令 ＋ 观察到的行为。
- 普通业务任务不附「DSH 借鉴证明」；DSH 提供某能力不等于 Synova 需要该能力。

## F. 交付前自检（按任务范围挑相关项）

```bash
git diff --stat                                   # 1 改动范围与声称一致
grep -nE "@input|@output|@degraded|@exit" <file>  # 2 契约（边界对象）
grep -nE "class .*Error|raise .*Error\(" <file>   # 3 typed error（跨边界）
grep -nE "exit 2|exit\(2\)" <file>                # 4 三态（脚本/检查器）
ls <name>.test.* 2>/dev/null || echo "缺测试"      # 5 配对（有配对约定时）
```
自检结论按「通过／失败／跳过／未验证」如实报告，附命令原始输出。
