# package-selfsufficiency-audit — 包自足性审查（十项，缺一不可）

## 使用时机

**任何包首次开工前**（发开工令之前）｜**MVP 权威文件升版后**｜**发现"包里信息与实测不符"后**。

🔴 **本技能是硬流程，不是建议**：**未过审 = 不许开工**（否则执行者只能猜，猜错就是返工/事故）。

## 一句话判据

> **一个零上下文的 session，只拿【预设 ＋ 包守则（`agents/P#/AGENTS.md`）＋ 包 README（handbook）】，
> 能不能不问我一句就开工并自证完成？**

不能 ⇒ 不自足 ⇒ 先补信息。

## 十项判据（**缺一即不通过**）

| # | 判据 | 怎么验 | 不合格表现 |
|---|---|---|---|
| **1** | **落点存在性** | 从 ②③④ 抽路径 ⇒ `git cat-file -e <ref>:<path>` | 引用了不存在的文件 |
| **2** | **判据可执行** | ③判据**每条**有：命令 ＋ 期望输出 ＋ **反例（改坏必红）** | 只有"要做完 X"无命令 |
| **3** | **写集精确** | ④写集是**文件级**（目录级须说明为何不能到文件） | 只写"改 `src/**`" |
| **4** | **依赖明确** | ⑤依赖写"已完成/进行中/未开始"＋**判据** | "依赖 M1"就完 |
| **5** | **不做含路径** | ⑥不做至少一条**具体禁碰路径** | 只有抽象表述 |
| **6** | **域守则清单** | ⑦给出**路径 ＋ 何时用**（不是只有路径） | 只给路径不说用途 |
| **7** | 🔴 **事实落点** | 有"事实落点"节：每条任务 **file:line 或复现命令** | 只有编号（"2.1"）没落点 |
| **8** | **编号可查** | 所有内部编号（`B6`/`2.1`/`K12-05`…）在**产品仓**能查到定义 | 编号只在 handbook 或只在 CTO 脑里 |
| **9** | **跨仓依赖标注** | 凡引 handbook/过程档案，**文内必须有摘要** | "详见 handbook 某某" |
| **10** | **合并规则** | 写明"本包是否可四条件自合并"；有例外写例外 | 默认四条件但没写 |

## 五步流程（固定）

```
 步骤 1 **跑机器检查**（十项里 1/2/3/4/5/6/7/10 可自动；8/9 半自动）
        🔴 脚本由 P4 交付：`scripts/control-tower/check-package-selfsufficiency.py`
        （三态退出码：0 通过／1 有缺口／**2 检查自身失败**；输出缺口矩阵）
 步骤 2 **人工补不可自动的两项**：⑧ 编号可查 ／ ⑨ 跨仓摘要
 步骤 3 **缺口分派**：
        · **事实性缺口**（落点不存在／判据无命令／编号查不到）⇒ **CTO 补**（判据是方向锚，不是包负责人的活）
        · **过程性缺口**（在飞/回执格式）⇒ **包负责人补**
 步骤 4 **复跑**：缺口清零才发开工令
 步骤 5 **留痕**：结果写进包守则「十一、自足性审查记录」（日期 ＋ 十项结论 ＋ 补了什么）
```

## 迭代规则（**发现新缺口怎么办**）

```
 🆕 每发现一类新缺口 ⇒ **加进十项**（→ 十一项、十二项…），**编号只增不改**
   （改编号会破坏历史记录可比性）
 ⇒ 协议有版本号：`v1` = 十项；`v2` = 十一项（并记录"新增第 N 项，起因：<事故>"）
```

## 与 `pre-dispatch-check` 的关系（**别混**）

```
 · **本件 = 包级基线**（每包一次，长期有效）：判"这个包的信息够不够一个陌生人开工"
 · **pre-dispatch-check = 派单件级增量**（每次派单前，8 项）：判"这一单的前提/写集/判据是否真实"
 ⇒ **上游做掉的重叠项**（路径存在/判据可达/写集准确）下游只需核"本单新增"
```

## 历史事故（为什么存在）

- **2026-10-18 创始人两问**：「信息是否完全」「流程是否符合任务性质」
  ⇒ 机器检查：**判据无命令 9/10 ／ 不做无路径 10/10 ／ 域守则不在包守则 10/10 ／ 事实落点 9/10 缺**
- **P4 的 2.5 最典型**：包守则写「U3 门禁可被改（`protected_file_patterns` 空）」，实测 **4 个候选名全 0 命中**
  ⇒ **机制根本不存在**（是"从零新建"，不是"改配置"）⇒ 陌生人会照着改一个不存在的字段
- **P4 的流程自相矛盾**：P4 要修"门禁可被普通 PR 改"，而 P4 自己的 PR 就是改门禁的普通 PR
  ⇒ **P4 绝不能四条件自合并**（用要消灭的洞消灭洞）

## 三处同步（改判据必须同时改）

```
 ① handbook `包自足性审查-协议v1.md` —— **唯一真源**
 ② 每个包守则 `agents/P#/AGENTS.md` —— 末尾「## 十一、自足性审查记录」
 ③ `CTO冷启动入口.md` §六 下钻索引 —— 加一行指针
```
