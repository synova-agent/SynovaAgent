# pre-dispatch-check — 派单前复核（派单十项 ＋ 包自足性十项）

> 🔴 **两层别混**：**§A 派单件级增量**（每次派单，十项）｜ **§B 包级基线**（每包一次，长期有效）。
> **包未过 §B ⇒ 不许派单**；§B 已做掉的（落点存在／判据可达／写集准确）§A 只核「本单新增」。

## 使用时机
- **§A**：CTO 向任何 session 发出派单指令之前（写派单文档／复制块／口头指派）。
- **§B**：包首次开工前（发开工令前）／MVP 权威文件升版后／发现「包里信息与实测不符」后。
- 🔴 都是硬流程：**未复核 = 未派单｜未过审 = 不许开工**（否则执行者只能猜，猜错即返工／事故）。

## 为什么存在（历史事故 · 一条一句）
D732 把员工转述当事实写进派单 ＋ 写集路径凭印象写（`src/l4/evidence/**`，实在 `src/evidence/`）｜K3-P1-2 派单称「前置 #511 已合并」实际未合并｜D384 凭计划号臆写 D#（写 D727 实 D725）｜D733 同一单对 `src/` 提互斥要求（执行方替 CTO 发现）｜2026-10-18 创始人两问「信息是否完全」「流程是否符合任务性质」⇒ 十包审查：判据无命令 9/10、不做无路径 10/10、域守则不在包守则 10/10、事实落点 9/10 缺；P4「2.5 改配置」实测 4 个候选名全 0 命中 ⇒ 机制根本不存在（是从零新建，不是改配置）。

## §A 派单十项复核（逐项留证据）

### ① 任务号真实（禁臆写）
```bash
for d in D727 D728; do ls task-state/$d.json || echo "MISSING $d"; done   # 或 alloc-task-id.sh 现场分配
```
新任务走 `bash scripts/control-tower/alloc-task-id.sh "<title>"`；派单里每个编号必须能查到。

### ② 前置状态真实（禁转述）
「已完成／已合并／已在 main」必须 API 核：
```bash
curl -s -H "Authorization: token $TOKEN" ".../pulls/<N>" | grep -o '"merged": *[a-z]*'
```
并核 main 上**物理存在**（`git ls-tree origin/main <path>`）——PR merged ≠ 内容在 main（#524 踩过）。

### ③ 技术声称亲自复现（最重要）
每句「X 坏了／Y 不存在／Z 零调用方」必须 CTO 亲自跑出证据（命令＋输出＋file:line），**不得采信员工报告**；核不出来就写「待执行方先复现」，不写成结论。

### ④ 写集路径当场验证
```bash
for p in <派单中每个路径>; do [ -e "$p" ] && echo "✅ $p" || echo "⚠️ 不存在（新建？）: $p"; done
```
不存在的必须显式标「新建」；写错路径 = 执行方直接走错方向。

### ⑤ 写集零交集 + 串行规则
本批所有写集两两比一遍；重叠面写明「谁先谁后」。特别检查：铁律 46 白名单桥接文件、`src/server.ts`、`scripts/audit/`（K3 域）。

### ⑥ 引用行号可漂移
引用的 `file:line` 当场 `sed -n` 看一眼（D524：行号因他人提交漂移）；写法用「<文件> 内 <符号>」优于纯行号。

### ⑦ 依赖图 + 禁止并行项
写明「A 依赖 B」「X 与 Y 不得并行（共享文件）」。缺这条 = 执行方必然撞车。

### ⑧ 交付物齐备
每单必须有：写集／红线／Done（可证伪）／前置；四段创始人复制块，每段含「完整派单: <文档> §X」。

### ⑨ 派单内部一致性（D733，血换的）
逐单列**验收命令与期望结果**两两比对：**不得对同一路径提互斥要求**。派单文档必须含「派单内部一致性」自检段（脚本第⑨项查其存在性＋做互斥启发式告警）。

### ⑩ 主线计划锚定（创始人 2026-09-13）
发派单前必读 `docs/synova/coordination/整体推进计划-主线-*.md`，并在派单文档写 `依据计划: v<版本>@<文件哈希前 8 位>`；脚本校验哈希——**哈希不符 = 计划已更新，重读后再派**（把「读了没读」从自觉变成物理证据）。

## §B 包自足性十项（每包一次 · 缺一即不通过）

> **一句话判据**：**一个零上下文的 session，只拿【预设 ＋ 包守则（`agents/P#/AGENTS.md`）＋ 包 README（handbook）】，能不能不问我一句就开工并自证完成？** 不能 ⇒ 不自足 ⇒ 先补信息。

| # | 判据 | 怎么验 | 不合格表现 |
|---|---|---|---|
| **1** | 落点存在性 | 从 ②③④ 抽路径 ⇒ `git cat-file -e <ref>:<path>` | 引用不存在的文件 |
| **2** | 判据可执行 | ③判据每条有：命令 ＋ 期望输出 ＋ **反例（改坏必红）** | 只有「要做完 X」无命令 |
| **3** | 写集精确 | ④写集是**文件级**（目录级须说明为何不能到文件） | 只写「改 `src/**`」 |
| **4** | 依赖明确 | ⑤依赖写「已完成／进行中／未开始」＋**判据** | 「依赖 M1」就完 |
| **5** | 不做含路径 | ⑥不做至少一条**具体禁碰路径** | 只有抽象表述 |
| **6** | 域守则清单 | ⑦给出**路径 ＋ 何时用** | 只给路径不说用途 |
| **7** | 🔴 事实落点 | 有「事实落点」节：每条任务 **file:line 或复现命令** | 只有编号（「2.1」）没落点 |
| **8** | 编号可查 | 内部编号（`B6`/`2.1`/`K12-05`）在**产品仓**能查到定义 | 编号只在 handbook／CTO 脑里 |
| **9** | 跨仓依赖标注 | 凡引 handbook／过程档案，**文内必须有摘要** | 「详见 handbook 某某」 |
| **10** | 合并规则 | 写明「本包是否可四条件自合并」；有例外写例外 | 默认四条件但没写 |

🔴 **第 10 项的血教训（P4 自相矛盾）**：P4 要修「门禁可被普通 PR 改」，而 P4 自己的 PR 就是改门禁的普通 PR
⇒ **P4 绝不能四条件自合并**（用要消灭的洞消灭洞）。凡「本包改的是它自己的守门机制」⇒ 合并规则必须写例外。

### 五步流程（固定）
```
步骤 1 跑机器检查（十项里 1/2/3/4/5/6/7/10 可自动；8/9 半自动）
       🔴 scripts/control-tower/check-package-selfsufficiency.py
          （三态：0 通过／1 有缺口／2 检查自身失败；输出缺口矩阵）
步骤 2 人工补不可自动的两项：⑧ 编号可查 ／ ⑨ 跨仓摘要
步骤 3 缺口分派：事实性缺口（落点不存在／判据无命令／编号查不到）⇒ CTO 补；
       过程性缺口（在飞／回执格式）⇒ 包负责人补
步骤 4 复跑：缺口清零才发开工令
步骤 5 留痕：写进包守则「十一、自足性审查记录」（日期 ＋ 十项结论 ＋ 补了什么）
```

### 迭代规则 ＋ 三处同步
每发现一类新缺口 ⇒ **加进十项**（→十一项…），**编号只增不改**（改编号破坏历史记录可比性）；协议带版本号：`v1`=十项、`v2`=十一项（记「新增第 N 项，起因：<事故>」）。
改判据**必须同时改**：① handbook `包自足性审查-协议v1.md`（唯一真源）② 每个包守则 `agents/P#/AGENTS.md` 末尾「## 十一、自足性审查记录」③ handbook `CTO冷启动入口.md` §六 下钻索引加一行指针。
