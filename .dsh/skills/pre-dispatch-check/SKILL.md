## 使用时机
**CTO 向任何 session 发出派单指令之前**（写派单文档 / 给创始人复制块 / 口头指派）。
本技能是硬流程，不是建议：**未复核 = 未派单**。

## 为什么存在（历史事故）
- **D732 前**：CTO 把员工报告里的技术声称（"X 文件有重复键" / "Y 函数不存在"）直接写进派单，**未亲自复现**；且写集路径凭印象写（`src/l4/evidence/**`，实际代码在 `src/evidence/`）→ 执行方拿到的派单本身有错。
- **K3-P1-2**：派单文档写「前置已完成 #511」，实际该 PR 未合并 → 审计判定「派单前置失实」。
- **D384 取号**：曾凭计划号臆写 D#（写 D727，实际分配 D725）。

## 八项复核（逐项留证据）

### ① 任务号真实（禁臆写）
```bash
for d in D727 D728; do ls task-state/$d.json || echo "MISSING $d"; done   # 或 alloc-task-id.sh 现场分配
```
新建任务必须走 `bash scripts/control-tower/alloc-task-id.sh "<title>"`；派单文档里的每个 D# 必须能在 `task-state/` 找到。

### ② 前置状态真实（禁转述）
派单里凡是「已完成 / 已合并 / 已在 main」的**必须用 API 核**：
```bash
curl -s -H "Authorization: token $TOKEN" ".../pulls/<N>" | grep -o '"merged": *[a-z]*'
```
并把 main 上的**物理存在**也核一遍（`git ls-tree origin/main <path>`）——PR merged ≠ 内容在 main（#524 踩过）。

### ③ 技术声称亲自复现（本轮最重要的一条）
派单里每一句「X 坏了 / Y 不存在 / Z 零调用方」，**必须由 CTO 亲自跑出证据**（命令 + 输出 + file:line），
**不得采信员工报告**。核不出来就写成「待执行方先复现」，而不是写成结论。

### ④ 写集路径当场验证
```bash
for p in <派单中每个路径>; do [ -e "$p" ] && echo "✅ $p" || echo "⚠️ 不存在（新建？）: $p"; done
```
不存在的路径必须显式标注「新建」；写错的路径会让执行方直接走错方向。

### ⑤ 写集零交集 + 串行规则
把本批所有 D# 的写集列表两两比一遍；重叠面必须写明「谁先谁后」。**特别检查**：铁律 46 白名单桥接文件、`src/server.ts`（Claude 专属）、`scripts/audit/`（K3 域）。

### ⑥ 引用行号可漂移
派单里引用的 `file:line` 当场 `sed -n` 看一眼；行号会因他人提交漂移（D524 教训），
写法用「<文件> 内 <符号>」优于纯行号。

### ⑦ 依赖图 + 禁止并行项
写明「A 依赖 B」「X 与 Y 不得并行（共享文件）」。缺这条 = 执行方必然撞车。

### ⑧ 交付物齐备
每单必须有：写集 / 红线 / Done（可证伪）/ 前置。四段创始人复制块 + 每段含"完整派单: <文档> §X"。

### ⑨ 派单内部一致性（D733 教训，血换的）
逐单列出**验收命令与期望结果**，两两比对：**不得存在对同一路径互斥的要求**
（例：D733 我同时要求「删默认规则 → 两条变绿」与「Win 域显式列出 `src/`」——对 `src/` 互斥，是执行方替我发现的）。
派单文档必须含「派单内部一致性」自检段（脚本第⑨项会检查其存在性 + 做互斥启发式告警）。

### ⑩ 主线计划锚定（创始人指令，2026-09-13）
**发派单前必须读一遍** `docs/synova/coordination/整体推进计划-主线-*.md`，并在派单文档写：
`依据计划: v<版本>@<文件哈希前 8 位>`。
脚本会校验哈希是否等于当前文件——**哈希不符 = 计划已更新，重读后再派**。
（目的：把"读了没读"从自觉变成物理证据。）
