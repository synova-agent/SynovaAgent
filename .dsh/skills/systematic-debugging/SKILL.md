# systematic-debugging — 先根因，后修复

> 来源：obra/superpowers（MIT）· `skills/systematic-debugging/SKILL.md` @ 8ca22dba。
> 本文件是中文改写版（结构保留、按 Synova 语境收敛），许可与原文以上游仓库为准。

## 铁律

```
没有根因调查，就不准提出修复。
```

症状修复＝失败。**"违反流程的字面，就是违反调试的精神。"**

## 何时用

任何技术问题：测试失败 / 生产 bug / 行为不符预期 / 性能问题 / 构建失败 / 集成问题。

**尤其在这些时刻必用**：赶时间（急＝最想猜）；"就一个小修"看起来很显眼；已经试过多次修复；上一次修复没生效；你并不真正理解问题。

**不准跳过的借口**：问题看着简单（简单 bug 也有根因）；来不及（急着修＝保证返工）；有人要你现在就修好（系统化比乱试更快）。

## 四阶段（每阶段完成才进下一阶段）

### 阶段 1 · 根因调查（在提出任何修复之前）

1. **逐字读错误**：不跳过 error/warning；完整读 stack trace；记下行号、文件、错误码。
2. **稳定复现**：能可靠触发吗？确切步骤是什么？每次都发生吗？**不能复现 → 继续收集数据，不许猜**。
3. **查最近变更**：`git diff`、最近 commit、新依赖、配置变更、环境差异。
4. **多组件系统先插桩取证据**：在每个组件边界记录"进去什么/出来什么"，跑一次拿到"到底哪一层断"的证据，再定位到具体组件。
5. **逆流追溯数据**：坏值从哪来？谁用坏值调用了它？一路追到源头；**在源头修，不在症状修**。

### 阶段 2 · 模式分析
找同仓库里能工作的相似代码 → 对照参考实现（**完整读，不跳读**）→ 列出工作版与坏版的**每一处**差异（不许假设"这点不可能有影响"）→ 搞清依赖与隐含假设。

### 阶段 3 · 假设与验证
写成一句话："我认为 X 是根因，因为 Y" → **最小改动**验证（一次只动一个变量）→ 成立则进阶段 4；不成立则**提出新假设**，绝不在旧修复上叠新的修复 → 不知道就说不知道，别装作知道。

### 阶段 4 · 实现
1. **先做失败用例**（能自动化的自动化；没有框架就写一次性脚本）——修之前必须存在。
2. **只做一处修复**，针对已定位的根因；**不许"顺手"重构或改进**。
3. **验证**：用例通过？其它测试没被打破？问题真的解决了？——未验证不得宣称完成。
4. **修复没生效** → 停，数一下：< 3 次则回到阶段 1 用新信息重析。
5. **≥ 3 次失败 → 停下来质疑架构**：每次修复都在别处暴露新的共享状态/耦合；修复需要"大重构"；每次修复又制造新症状 —— 这**不是失败的假设，是错的架构**。停下来和人类伙伴讨论，别试第 4 次。

## 红旗（出现即停，回阶段 1）

- "先快速修一下，回头再查"
- "先改改 X 试试看行不行"
- "一次改几处，跑测试看"
- "跳过测试，我手工验一下"
- "大概是 X，我把它改了"
- "我没完全搞懂，但这样可能行"
- 还没追数据流就开始给方案
- **已经试过 2 次以上，还想"再试一次"**
- **每次修复都在不同地方冒出新问题**

## 反合理化对照表

| 借口 | 现实 |
|---|---|
| "问题很简单，不用流程" | 简单问题也有根因；流程在简单 bug 上最快 |
| "紧急，没时间走流程" | 系统化比猜—改—再猜的来回折腾更快 |
| "先试这个，之后再调查" | 第一次修复就定下了模式，一开始就做对 |
| "确认修好了再补测试" | 没测试的修复留不住；先有测试才能证明 |
| "一次改多处省时间" | 无法归因是哪处生效，还会引入新 bug |
| "参考太长，我照大概意思改" | 半懂必然出 bug，完整读完再用 |
| "我看到问题了，我来修" | 看到症状 ≠ 理解根因 |
| "再试一次"（已失败 2 次以上） | 3 次失败＝架构问题，质疑模式，别再修 |

## 与 Synova 门禁的结合（本项目附加约束）

- **数字/结论必须贴命令原始输出**，"我看着像是"不算证据。
- **禁把 grep 命中当验收**（命中 ≠ 生效）：根因结论要有"删掉即报红"的判别性证据。
- **修完再宣称完成**：走"入口可触达 + 链路走通 + 结果可见"三环节，自检 6 问。
- **同类第二次立即升级**：同一类问题第二次出现，报 CTO，不再自行消化。
- 流程走完仍判定为环境/时序/外部原因时：记录调查过程 → 做合适的处理（重试、超时、错误提示）→ 补监控日志。**但"没有根因"里约 95% 是调查不充分。**
