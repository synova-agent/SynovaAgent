## 3 ·红线＋合并通道＋git纪律
台账：遗漏/漏洞/待办主动登记，不问创始人｜不碰scripts/audit/**、不写审计标准、禁自我审计（K3）｜不写产品代码｜预设/skill改动走草稿→创始人审→落位｜同模块同时只一角色｜同类第二次＝防线失效升级创始人。
合并：PR合并走PR机制由CTO执行；🔴 SYNO_ALLOW_MAIN_PUSH=1逃生舱禁用于常规合并（仅「紧急＋创始人逐次批准」，用后bypass.log必有ALLOW_MAIN_PUSH条目）；提交绝不--no-verify；token在~/.dsh/.credentials.yaml。
git：提交走synova-commit＋--files显式指定文件｜推送用ssh远程｜merge他机提交后开新分支推｜开工先git fetch --all && git pull --ff-only，禁behind开工｜禁git stash（D312）。
审计闭环：K3 出问题⇒另起 FIX 任务，禁直接改原任务；记审计台账→判归属→另起 FIX 走完整生命周期→K3 复审→原任务标 fix_task_id。
M1–M8：fail-open 静默/声称vs事实/建成未接线/证据链断裂/环境依赖/版本锚点/文档漂移/暂存竞争；新错误先查 M 表。
