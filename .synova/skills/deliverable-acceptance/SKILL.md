# deliverable-acceptance — 所有交付验收（研究/审计/编码 session/模块）

> 一句话：**验收 = 交付是否满足了"委托"，不是报告是否自洽。**
> 触发过的事故：报告内部一致＋独立复核通过，但**委托项少一维（件质量）**、结论"件在装配点缺"被直接采纳，另查发现"件几乎不合格"。

## 0. 用在哪 / 不用在哪
| 用 | 不用 |
|---|---|
| 院方/第三方研究报告、对照研究、审计报告、评估报告 | 代码 PR（用 `pr-review`／四条件） |
| 任何"别人出的、你要据此决策"的文档类交付 | dev doc（用 `devdoc-gate-a`） |

## 1. 五步（顺序不可跳）
**第 0 步：先写验收计划（读报告之前）**
```
把委托书逐条抄成清单：委托项｜要求产出｜可核判据｜验收方法
清单没写完 ⇒ 不许打开报告（防被作者框架锚定）
```

**第 1 步：委托项 → 交付章节 100% 对照**
```
每项：交付里哪一节回答？证据是什么？→ 标 覆盖 / 部分 / 缺
任何"缺"或"部分" ⇒ 直接进 blocking（不许用"整体不错"抵消）
```

**第 2 步：抽样自核（≥10%，高风险项全查）**
```
 · 抽出的每条结论：自己跑命令/读代码/查源码，不采信报告转述
 · 高风险＝安全/数据/钱/交付闸门，一律全查
 · 每条记：我的命令＋原始输出＋结论（与报告一致/不一致）
```

**第 3 步：单列「件质量」验收（最易漏）**
```
对交付涉及的每个"件"（模块/文件/脚本/文档）单独判：
 合格 / 部分合格 / 不合格 ＋ 证据（file:line 或命令）
禁止用"缺装配/没接线"替代"件本身是否合格"——两回事
```

**第 4 步：独立复核的范围核对**
```
复核者是否独立（非作者）？其 range 是否覆盖委托项（不是只核报告内部一致）？
复核回执必须有：不一致处/无法核实处/跑不通处/能否据此决策
```

**第 5 步：判定（三态）**
```
 通过：委托项 100% 覆盖＋抽样自核一致＋件质量无不合格＋复核范围覆盖
 有条件：= 不通过（照创始人令），列必修项
 退回：缺维度/结论无据/件不合格
每条 blocking 必须带 file:line 或命令＋改法
 六件套缺任一 ⇒ 不通过（与"有条件＝不通过"并列）
```

## §1bis 出生证六件套（G1–G6）
### G1 可达 | 必贴证据：生产调用点 file:line ＋ WIRING 行 | 缺则退回 | 判据：`docs/authority/quality-standard-g1g6.md` G1:21
### G2 不静默 | 必贴证据：失败/降级可见化行 file:line ＋ 三态退出码实测 | 缺则退回 | 判据：`docs/authority/quality-standard-g1g6.md` G2:37
### G3 有判据 | 必贴证据：真实路径用例 file:line ＋ 改坏两态原始输出 | 缺则退回 | 判据：`docs/authority/quality-standard-g1g6.md` G3:52
### G4 边界 | 必贴证据：入参校验 file:line ＋ 出站 timeout／signal 行 | 缺则退回 | 判据：`docs/authority/quality-standard-g1g6.md` G4:68

## 2. 反模式（见到即判流程失败）
```
 ❌ 把"报告内部一致＋独立复核通过"当"委托达成"
 ❌ 采信结论层（"不是缺件是装配缺"这类框架句，本身就预设了件合格）
 ❌ 抽样自核=0（一条都没跑）
 ❌ 用"整体/方向性"掩盖缺项
 ❌ 复核者只核报告、不核委托
 ❌ "G1 只测不接"（测试绿但生产调用点为 0）
 ❌ "G3 用文本断言/空 expect 冒充行为"（无改坏两态）
```

## 3. 记录模板（贴 Issue／台账）
```
| 委托项 | 交付落点 | 覆盖 | 我的自核（命令/输出） | 件质量 | 六件套(G1–G6 缺项) | 证据三要素(命令/输出/merge sha) | 判定 |
（抽样≥10%；高风险全查；不合格件单列）
结论：通过/有条件(不通过)/退回 ＋ blocking 清单 ＋ 是否可据此决策
```

## 4. 与其它 skill 的关系
- `claim-verifier`：单条"声明是否成立"的核实口径（本 skill 第 2 步用它）
- `devdoc-gate-a`：dev doc 的六镜头评审（对象不同）
- `pr-review`：代码 PR 的合并前审查（对象不同）
- `dsh-code-standards`：代码标准与必复用约定的清单（本 skill 只引不复制）

## 5. 分场景补充（同一五步，按对象补检查项）

**A. 研究/审计/第三方评估**
```
 委托项 100% 对照；来源核（版本+file:line）；"件质量"单列；不可核清单
```

**B. 编码 session 完成（L2 交 L1 / L1 交 CTO）**
```
 ① 任务卡 Done 逐条对照（不是"代码写完"）
 ② 证据三要素齐：命令原文＋原始输出＋merge sha（在卡里可复跑）
 ③ 测试真跑：禁壳测试/恒真断言；抽跑关键命令（不采信 R2）
 ④ 写集：实际改动 ⊆ 声明写集；多出件须是门禁强制件
 ⑤ 代码标准：按 `dsh-code-standards` 清单逐条核（8 项代码标准 ＋ 4 条必复用约定）；本 skill 不重复计数
 ⑥ 四条件：CI 绿 pending=0／零重叠／独立复核／串行
 ⑦ 不替代：单卡通过 ≠ 模块通过；模块还需端到端（如 M9）
```

**C. 模块完成（M1–M10）**
```
 ① 每张卡证据在卡内（命令+原始输出+merge sha），body 不得仍"待填"
 ② 复核链：零上下文子代理 → CTO 抽核 → K3 终审（裁 319）；复核不替代 CI／集成测试／门禁，四道并存，不叠加会议
 ③ 端到端判据（M9）单独看，不能拿单卡绿替代
 ④ 有条件通过 = 不通过（列必修；不重开卡可，但必须有补正记录）
```

**D. 其他（合同/交付件/报告）**：套 A。
