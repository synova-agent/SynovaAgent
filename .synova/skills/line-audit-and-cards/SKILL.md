# 线级审计与卡面重写（CTO 方法）

> **谁用**：CTO（或 CTO 专项会话）。**产出**：① 审计报告 ② 重写后的卡面（含六字段＋§〇 七问）③ 批次划分 ④ 可转发的开工令。
> **为什么要有本技能**：新会话只看到"六字段""七问"这些**名词**会不知道是什么 ⇒ 本技能把每一问、每一字段**逐条写死并给范例**。

## 0. 开场三件事（不做这三件，后面全歪）

```
① **读权威**：院方《产品宪章.md》（最新版）—— 架构基准是 **§0.4 ＋ §4.1**（⓪ 连接器 / ① 循环 / ② 本体 /
   ③ 哨兵 / ④ 参数 / ⑤ 导航 / ⑥ 进化回环 / −1 运行时）。**不许用旧 L1–L5 当架构**（那是代码目录组织，见铁律 39）。
② **读机器真源**：`docs/synova/coordination/施工项登记.ts` 里**该块**的 items（id / title / paths / acceptance / dependsOn）
   与**块判据**（blockAcceptance）。
③ **读现状**：该块涉及目录的**实测状态**（下一节纪律），不是文档里写的状态。
```

**三条红线**（越界即停）：
```
· 不改门禁语义（那是 CTO 裁权，且要留 Note）
· 不 spawn 线负责人（常驻线负责人是独立 session；一次性任务组才可组队）
· 不许凭记忆断言 —— 一切"现状"必须带 file:line 或"命令 + 原始输出"
```

## 1. 第 0 步 · 定范围（"这条线应该覆盖什么"）

| 动作 | 具体怎么做 | 判据 |
|---|---|---|
| 列现状 | 登记件该块 items 逐条抄出：`id ｜ title ｜ status ｜ batch ｜ paths ｜ acceptance` | 条数与登记件一致 |
| 抄宪章 | 找到宪章里**管这块的条款号**（如 ② 本体层 = §0.4/§4.1；一致性 = §2.7） | 每条要求能指到**条款号** |
| 求交集 | 宪章要求 ∩ 现有 items ⇒ 得出 ① **漏项**（宪章要、卡里没有）② **冲突项**（卡里要做、宪章说不做）③ **重号/错归属** | 三类各出清单 |

**范例（K4，2026-10-11 实做）**：
```
现有 6 项：0-4 循环五阀映射指向已废止编号 ｜ 1-8 补 5 条预估值 ｜ 1-9 给 10 条边补 transfer_function
           3-5 作业单元缺两件 ｜ 3-11 专业包层（L1.5）机制 ｜ B2-GRAPH 图边查询 no such column: props
块判据：scripts/control-tower/check-ontology-fields.sh
🔴 冲突项：**3-11 专业包层 L1.5** —— 宪章 §0.7 明文把"L1.5 专业包"列为**延后**
🔴 待判：K4 块名"本体·因果边·循环编号"混了 **② 本体** 与 **① 循环** 两层 ⇒ 边界要重划
```

## 2. 第 1 步 · 事实采集（**量 ref，不量工作树**）

### 2.1 三条硬纪律（都是踩过的坑）

```
① **量目录/文件用 `git ls-tree <ref>`，不用 `ls`**
   事故：`ls -d src/*/` = 49（工作树） vs `git ls-tree origin/main src/` = **58**（真值）
② **一切"现状"必须带时间锚**：写 `as_of <commit>`；引用别人的数字前先复核
   事故：转述"回退后 28/32 变红" —— K3 实测 **8/32**（夸 3.5 倍）
③ **"已交付"二元化**：只许写「已推送 / 已合入(main)」，禁用"已交付"
   判据：`git merge-base --is-ancestor <sha> origin/main`
```

### 2.2 采集清单（按块定制；下面以 K4 为例）

| 维度 | 怎么采 | 交付形态 |
|---|---|---|
| 本体 | `git ls-tree -r origin/local-main -- extensions/ontology/` 全清单 + **跑块判据脚本拿原始输出** | 边类型/节点类型逐条 + 字段完整度 |
| 循环 | `cycles/*.cycle.json` 实际内容（**五阀映射指向什么**）+ `src/cycles/` 代码 | 每个 cycle 的映射链逐条 |
| 缺陷 | 报错**真实复现**（`no such column: props` 之类）| 命令 + 原始输出 + **影响面（哪些哨兵崩）** |
| 差量 | 宪章要求 vs 现有 | 缺哪类边/哪个字段/哪些是死引用 |

### 2.3 并行分工（若已组队）

```
队员各自领**互不重叠**的采集维度；Lead 汇总。
每份采集回执必须含：① 命令原文 ② 原始输出 ③ 结论 ④ 不确定项（不许猜）
```

## 3. 第 2 步 · 归属重定（按宪章，不按历史批次）

```
对手上每一项，逐条回答三问：
  ① 它在宪章里属于哪一块？（⓪①②③④⑤⑥/−1；旁参：§2.7 一致性 / §4.7 AI 化 / 4.3 参数层）
  ② 宪章条款号是什么？（**写出来**，不许凭感觉）
  ③ 结论：保留 / 改归属 / 撤销 / 拆卡？

冲突处理：
  · 卡里要做、宪章说"延后" ⇒ **标『撤销/延后』并写明宪章条款**（不许默默留着）
  · 卡里没做、宪章必须要 ⇒ **补成立项**
  · 一项跨两层 ⇒ **拆成两张卡**（归属单一化）
```

**范例**：`3-11 专业包层 L1.5` ⇒ 归属：⑤ 导航层（专业包）｜宪章依据：**§0.7 明文延后** ⇒ **结论：撤销/延后，不派单**。

## 3.5 第 2.5 步 · 🔴 横向查重（**不许只看自己这一块**）

> **创始人 2026-10-11 明令**：「注意一点，比如现在审计的是 K4，K4 审计的时候，**也要横向看其他的**，
> 否则就会出现 K12 那种，任务卡分散在其他模块。**如果不一起评估，就会重复造轮子**。」
>
> **实证（血的教训）**：K12-14「content-registry」整张卡**与 K10 的 EXT-WIRE 是同一件事**
> （同判据 `probe-content-registry.ts` ＋ 同写集 `src/deploy/content-registry.ts` ＋ 9 个 manifest）
> —— 因为当初只在本块内建卡、**没查重**。已撤销，活归 EXT-WIRE。
> **同源病**：K12 的 7 项是从别的块"移入"的（3-1/3-3/3-4/RB-01~04）⇒ 说明历史上就存在"同一件事散在多块"。

### 四道机械化查重（顺序做，都有命令）

```
① 写集重叠（同一文件被多块引用 ⇒ 冲突或重复）
   做法：把本块全部 paths 与**全仓所有块的 paths** 两两比对（前缀重叠判定）
   ⚠️ 坑：若本块用了**粗路径**（`src/l4/**` / `extensions/`）⇒ 会产出大量**假重叠**
        ⇒ 先做「**写集提精度**」：粗路径一律改精确（这是 Q2/写集字段的要求，也是查重的前提）
   判据：零重叠；有重叠必须显式声明「**串行：A 先 → B 后**」

② 跨块同判据（**最强信号**：同名脚本被多块引用 ⇒ 几乎必然是同一件事立了两次）
   做法：抽取全仓所有 acceptance[].run，按命令归组，看是否有**多块**引用同一命令
   实证输出：`K10/EXT-WIRE ｜ K12/K12-14 → npx tsx scripts/control-tower/probe-content-registry.ts` 🔴
   判据：跨块同判据 ⇒ **必须裁**（② 里那处就该并卡，不是串行）

③ 语义关键词（**本块主题词** 去全块标题/source 里搜）
   做法：列出本块的主题词（如 K4：边类型 / transfer_function / 五阀 / 循环 / 本体 / props），
        逐词统计全仓命中及其所属块
   实证输出：`「循环」→ K1:0-1 ｜ K4:0-4` 🔴 ⇒ 跨块同题，需合看
   判据：同词跨块 ⇒ **逐条判「同一件事 / 邻接但不同」** 并写结论

④ 同源（多个 item 的 source 指向**同一权威文档章节**）
   做法：source 归一化后按块分组，看是否跨块同源
   判据：跨块同源 ⇒ 判「同源不同事（正常）」还是「同源同事（重复）」
```

### 查重结论的三种处置（不许"看见了但不动"）

| 情形 | 处置 |
|---|---|
| **同一件事**（同判据＋同交付物） | **并卡**：保留先立的那张，另一张标「撤销·重复立卡」＋注明归谁 |
| **同一文件、不同事** | **串行**：显式声明「X 先 → 本卡后」，并写进两张卡的共写声明 |
| **邻接但不同事** | **写清边界**（本卡做什么、邻卡做什么），防未来撞车 |

### 为什么必须在这一步做（而不是等执行时）

```
· 等到开工才发现重复 ⇒ 已经写了码 ⇒ 返工或双份实现（K12-14 就是这样被发现的）
· 块内自查**查不出**跨块重复 —— 必须在**卡面冻结前**做，这是"防重复造轮子"的唯一时机
```

## 4. 第 3 步 · 卡面重写（**本技能的核心：六字段与七问逐项定义**）

### 4.1 卡面标准形态

```
# Task Brief: #<Issue号> → <块号>-<序号> — <一句话标题>
## 〇、为什么要做这个（通俗版 · 先读这一节）      ← 七问（见 4.3）
## Q0: 定位 — 项目拼图 + 文件审计                ← 字段 1
## Q1: 调研 — 业界/顶级团队/memory 教训           ← 字段 2
## Q2: 范围 — 做什么 / 不做什么（含路径）          ← 字段 3
## Q3: 验收 — 入口 → 交互 → 结果                  ← 字段 4
## 架构层: <宪章块号>                             ← 字段 5
## 写集: <精确路径清单>                           ← 字段 6
## Done 标准: <可机器判的完成标准>                ← 附加（但没有它卡不算成卡）
                 ⚠️ PR 正文须写 Closes #<本卡 issue 号>（门禁 check-board-truth 依赖此信号）
```

> **六字段** = Q0 / Q1 / Q2 / Q3 / 架构层 / 写集；**Done 标准**是第 7 项，缺它不准开工。
> **PR 正文必含**（CTO 裁定 011）：交付类 PR 必须在正文写 `Closes #N`（或 Fixes/Resolves）——
> 这是回填的上游信号。理由：门禁只能查「有引用却没关」，查不到「没引用」（没有信号 ⇒ 看不见）。

### 4.2 六字段逐个写细（每字段：**写什么 + 判据 + 反例**）

**字段 1 — Q0 定位（项目拼图 ＋ 文件审计）**
```
写什么：a) 本卡在**哪一块**（宪章块号）、该块现在是什么样的
        b) **文件审计**：本卡要碰的目录/文件，现在**已存在什么**（带路径）
        c) 结论：**新增 / 替换 / 扩展**（三选一）
判据：读完能回答"这张卡是往哪儿加、加在现有哪个东西旁边"
反例：写"本卡属于本体层"就完了 —— **没有文件审计 = 不合格**
```
**字段 2 — Q1 调研（三问）**
```
写什么：a) 业界最佳实践是什么  b) 顶级团队怎么做  c) **memory/ 里我们犯过的错**（同型事故）
判据：c) 必须**点名具体事故或铁律号**（如"铁律 0-2 接线失败 4 次"）
反例：写"参考了业界做法" —— 不点名 = 不合格
```
**字段 3 — Q2 范围（最简方案 ＋ 排除项）**
```
写什么：做什么（**最简**可行）／**不做什么（必须带文件路径）**
判据：排除项必须是**可判定的路径**（如 `不改 src/l4/**`）
反例：写"不改无关代码" —— **无路径 = 不可判定 = 会被门禁拒**
🔴 坑：**不要用 glob**（`probe-*.ts`）—— 门禁 G12 用 re.escape 字面匹配，glob 恒不中 ⇒ 全判"越界"
        正确写法：**逐条裸精确路径**（15 条就写 15 条）
```
**字段 4 — Q3 验收（入口 → 交互 → 结果）**
```
写什么：入口（从哪触发，命令/路由）→ 交互（中间发生什么）→ 结果（用户/调用方看到什么）
判据：**三环节都能指出具体位置**（文件:行 或 命令）
反例：只写"功能可用" —— 无入口无结果 = 不合格
```
**字段 5 — 架构层**
```
写什么：**宪章块号**（⓪①②③④⑤⑥/−1）—— 不许写 L1–L5（那是代码目录组织）
判据：块号必须与宪章 §0.4/§4.1 对得上
反例：写"L4 本体" ⇒ 用错体系（旧分层），要改写成 **② 本体层**
```
**字段 6 — 写集（精确路径清单）**
```
写什么：本卡**允许写的每一个文件路径**（逐条列）
判据：① 与其他卡**零重叠**（重叠必须显式声明"串行"并写先后）② 路径**精确**（不用 glob）
反例：写"src/ 下相关文件" —— 不合格，且会被门禁拦
技巧：先跑一遍**全块重叠检测**（把本块所有卡的 writeset 两两比对），把冲突提前消掉
```
**附加 — Done 标准**
```
写什么：**至少一条可机器判**的标准（能跑的命令 + 期望退出码）
判据：命令**现在跑得通**（哪怕结果是失败态，也要能跑）
反例：写"功能正确" —— 不可机器判 = 不合格
🔴 探针类任务必守：**未实现必须 exit 2**（0=通过 / 1=失败 / 2=未实现），**恒绿 = 交付失败**
```

### 4.3 §〇 七问逐个写细（**新会话最需要这段**）

> 目的（创始人 2026-10-11 原话）：「写这些的目的是，**写的时候就想清楚为什么要做这个模块，不做是不是也可以** ——
> 你写这个比代码本身重要；你不跑偏，执行 session 照着卡面做就不会有大问题。」

```
① 一句话 —— 是什么
   写什么：**大白话**说这张卡做什么（不许用内部术语堆砌）
   判据：非技术的人读完能复述
   范例：K12-21「给 21 张卡各配一把尺子，让"做完了没有"变成一条能跑的命令，而不是靠人复述」

② 解决什么问题
   写什么：**具体的痛**（带实测数据或创始人/院方原话）
   判据：能指出"现在哪儿疼、疼到什么程度"
   范例：K12-01「你的原话：每人岗位不同、给 agent 的上下文差异很大 ⇒ 产出没预期好；
                院方归因：根因不是员工不认真，是**没人告诉他们该带什么上下文**」

③ 做完对项目的推动
   写什么：对**宪章哪条优先级**的贡献（§2.7 一致性 / §4.7 AI 化 / 指标时序链…）
   判据：能指到条款号
   范例：K12-03「它是**信任引擎的供油管**——产出直接喂 K12-01 与 K12-12 ⇒ 一致性从'第一天'就成立」

④ 🔴 不做行不行（**这一问最重要**）
   写什么：明确结论（**不行** / **可以做但有代价**）＋ 理由
   判据：**禁令级 vs 欠账级**要分清 ——
          · 「不行」= 不做就塌（安全底线 / 结构缺口 / 前置缺失）
          · 「可以做但代价明确」= 欠账（体验/运维成本），**诚实标注它不是最先做的**
   范例：K12-15 reload「**可以做，但代价明确**：每次建档都要重启；不是安全底线，优先级低于上线闸」
         K12-09 多租户「**不行**：安全底线，且创始人已明确 DevMode 跨租户不可放行」

⑤ 现在有什么基础（**代码盘点**）
   写什么：✅ 已有的（**带路径，最好带行号**）／❌ 缺的
   判据：**每条都实测过**（as_of 某个 commit）
   范例：K12-05「✅ auth.ts:454 getPermissionFilter 真实现；knowledge.ts:59 真调用；21 处引用
                 ❌ 分层本身无载体：没有 extensions/knowledge-scope/；customer-config/ = 0 件」

⑥ 还需要做什么
   写什么：缺口清单（逐条可执行）
   判据：读完知道要建哪些文件/接线点
   范例：K12-01「建五件套 ＋ file-driven-loaders.ts +1 路 ＋ 测试 ＋ 探针」

⑦ DSH 借鉴方式（**三选一，必须写明借什么/不借什么/为什么**）
   写什么：
     · **照搬**：DSH 怎么做我们就怎么做（至今 **0 张卡**属于此类）
     · **参考自研**：借方向/原则，实现自己定（多数）
     · **自研**：DSH **无对应物** —— **必须诚实标注**（例：DSH 是单机单用户，没有"多租户/部门/权限模型"）
   判据：**必须给 file:line 证据**（如 `packages/compaction/compaction-basic/src/index.ts:114`）
   范例：K12-01「参考自研：借 DSH 的『按名声明、宿主满足』（`compaction-basic/src/index.ts:114` static inject=[...]）；
                 借『包自带判据、宿主只保证不生效就报错』（`dsh-invariants/lib/index.js:6-13`）；
                 ❌ 不借 Cordis 的生命周期/代际机制（我们内容是静态文件、boot 装配）」
   反面：写"借鉴 DSH" —— 不说**借哪个文件哪一行、借什么不借什么** = 不合格

⑧ 涉及代码文件（具体位置）
   写什么：交付物路径**逐条** ＋ 判据源路径
   判据：路径可在仓库中 ls-tree 命中（新建的也要写全路径）
```

### 4.4 卡面必带的另外两件（不写在正文里也要有）

```
· **共写声明**：若某文件被多张卡共写 ⇒ 在卡面显式声明「本文件与 X 卡共写，**串行：X 先 → 本卡后**」
· **来源标注**：卡面上注明 卡面来源 / 架构基准（宪章版本）/ 机器真源（登记件 id）/ 纪律（缺字段问 CTO，不许猜）
```

## 5. 第 4 步 · 批次划分（为什么要分批）

```
三条理由（结构决定，不是保守）：
 ① **依赖链**：A→B→C（前置未过，后置不可开工）
 ② **写集冲突**：同一文件被多卡共写 ⇒ **必须串行**
 ③ **上限即纪律**（DSH 原则 1）：一批摊太多卡 ⇒ 无主、无复核、无上限 ⇒ 必然烂尾

每批的内容 = ①本批卡清单 ②约束（依赖/串行）③批的**终点判据**（怎么算这批完了）
```

## 6. 第 5 步 · 开工令（**必须自足可复制**）

一份合格开工令必须含 **九节**（缺一节 = 未完成）：

```
一、仓库与账号      Gitea 地址（局域网＋本机）｜克隆 URL ｜CI/PR/看板 URL ｜推送账号 + 令牌路径
                    ＋ **三条硬前提**：从 local-main 起分支 / 合并只进 local-main（绝不进 main）/ 不许 --no-verify
                    ＋ **新分支必须直推**：`git push <url> <branch>`（中转脚本只支持已存在的远端分支）
二、卡面地址（三处）① 主仓 `.claude/task-briefs/…`（**为准·可版本化**）② 库外档案仓（汇总便于连读）
                    ③ 面板 issue URL（视图）＋ 声明「三处不一致时以主仓为准」
                    ＋ 架构基准（院方宪章版本）＋ 机器真源（登记件 id）
三、任务            做什么 + 写集 + 参照形状 + 明确的"不做什么"
四、agent team      要求：**按任务性质自建**（编制见 §10.2）+ shared task board + **写集互不重叠** + Lead 跑终验
五、独立复核        要求：复核者**只拿【交付物 + 一句话"核它与实测是否一致"】**（不给意图/结论/自查）
                    出四项：a 与实测不一致处（附命令）b 无法核实处 c 命令跑不通处 d 能否据此独立开工/决策
六、执行形态硬要求  契约/判据/exit code 语义 + 写集边界 + PR 流程（分支名 → base=local-main）
七、AGENTS.md 合规  先写 task brief（六字段）→ 答 task-start 4 问（含 Q4 契约与测试）→
                    交付时逐条答 Agent 自检 5 问（接线/异常/类型/测试质量/残留）
八、合并权 + 红线 + 回执 + 冷启动
                    合并权：满足四条件**自合并**（CI 全绿 pending=0 / 零写集重叠 / 已过独立复核 / 串行），
                    合并后发【PR 号 + CI 证据 + 四条件自检】**备案**；遇问题**停下报告**
                    红线：不改 X / 不碰门禁 / 不用 --no-verify / 不 spawn 线负责人
                    回执三信号：① 分支+commit+PR 号+自检 5 问 ② 判据原始输出 ③ 未决项
                    冷启动入口：AGENTS.md / 卡面 / 登记件 / 面板 / 活账 / 判例库
九、PR 正文必含     交付类 PR 必须在正文写 `Closes #N`（或 Fixes/Resolves）—— 这是回填的上游信号。
                    理由：门禁只能查「有引用却没关」，查不到「没引用」（没有信号 ⇒ 看不见）。
```

**写作纪律**：开工令**必须含地址与卡面路径**（漏了等于没派）；**同一会话内给出，不等对方问**。

## 7. 独立复核（交付前必做，写法固定）

```
① 派一个**没参与写**的复核者
② 🔴 **只给它【待交付文档 + 一句"核它与实测是否一致"】**
   —— **不得给**你的意图、结论、自查结果（否则它只会附和）
③ 要求它出四项：
   a 与实测不一致处（**附命令**）b 无法核实处 c 命令跑不通处
   d 总评：**能否据此文档独立开工/决策**（能／不能 + 理由）
④ 复核结论**必须回写**文档并重交；**不允许"复核了但没改"**
⑤ 无法修的：标「**已知不一致 + 原因**」（不许藏）
豁免：纯机械产出（须在交付里写明"未过对，因<类别>"）
```

**实证**：独立复核曾一次挑出 CTO 文档 **10 处**与实测不符（PR 数被 `--limit` 伪造 / 板不含 PR 却说"唯一活账" / "已交付"混入 4 项未合并 PR / L3 判据单向）⇒ **"我核过了" ≠ "别人核过了"**。

## 8. 常见坑（实测清单 · 每条都栽过）

```
① `--limit 100` **静默饱和给假数**（显示 100、实为 137）⇒ 一律 `--limit 1000`
② `gh` 脱离 git 仓 cwd 会 fatal ⇒ 一律加 `-R <owner/repo>`
③ **不要"看阻塞视图"**（GitHub/Gitea 无 API 可执行视图）⇒ 用字段复现
④ 板**只装 Issue 不装 PR** ⇒ PR 状态必须另查
⑤ 正则改文件**首匹配** ⇒ 撞号时会**改错对象**（实测：把别的块的项置成了 retired）
   ⇒ 改机器真源必须"解析 → 按 block+id 定位 → 改 → 复核（唯一性/引用完整性/**目标对象正确性**）"
⑥ posix `grep -E` **不支持 `\b`**（`git grep -E "\bL[1-5]\b"` 恒 0）⇒ 用 `L[1-5][^0-9A-Za-z]`
⑦ **推送前先验 commit 内容**（`git show --stat HEAD`）—— 实测犯过"推了空分支还当成功"
⑧ `--single-branch` 克隆里 `origin/<other>` 不存在 ⇒ 用 `FETCH_HEAD` 或显式 refspec
⑨ CI 断言**只看 `job.conclusion`**（`run.status` 会失真）＋ **等 pending=0** 才可断言
```

```
① 审计报告 → 库外档案仓（含 as_of commit）
② 卡面 → **主仓 `.claude/task-briefs/`**（为准）+ 面板回填 + 库外汇总

```

## 10. 🔴 组队规则（**本技能强制项**：按任务性质自建 agent team ＋ 独立复核）

> **创始人 2026-10-11 明令**：「执行这个任务要**自己根据性质建立 agent team 来执行**，**一定要有独立复核**。」
>
> ⇒ 这不是"建议"，是**准入条件**：本技能的任何一步，**都不接受"我一个人做完了"**这种交付。

### 10.1 三条强制项（缺一即视为未完成）

```
① **必须组队**（不许单干）—— 最小编制 = Lead ＋ 1 队员 ＋ 1 独立复核者（**复核者不参与写作**）
② **编制按任务性质定**（见 10.2 表）—— 不许"一刀切三个人"，也不许"人多好办事"
③ **必须独立复核**（写法见第 7 节）—— 复核结论**必须回写交付物**，不许"复核了但没改"
```

### 10.2 按任务性质定编制（四类典型，照表选）

| 任务性质 | 编制 | 每个角色的**终点判据**（怎么算干完） |
|---|---|---|
| **① 事实采集类**（多维度互不依赖，如 K4 的本体 / 循环 / 图缺陷三路） | Lead ＋ **N 个采集员**（1 人 1 维度）＋ 1 独立复核 | 每份回执必须含 **命令原文 ＋ 原始输出 ＋ 结论 ＋ 不确定项**（不许只给结论） |
| **② 重写 / 撰写类**（卡面、规格、开工令） | Lead（主笔）＋ **1 个挑战者** ＋ 1 独立复核 | 挑战者**必须找出至少 1 处不合格**；找不到要**说明为什么找不到**（不许"没问题"三个字结案） |
| **③ 审计 / 裁决类**（判"能不能派 / 是否重复 / 是否合规"） | Lead ＋ **2 名独立审计员（互不通气）** ＋ 1 独立复核 | 两份审计**各自独立成立**；结论冲突时**以实测为准**（不是以谁资历高为准） |
| **④ 混合类**（采集 → 重写 → 批次，如本次 K4 全流程） | **分阶段换编制**：采集阶段用 ①、重写阶段用 ②、交付前统一过独立复核 | 每阶段结束过一次门；**不许把三阶段压成一次交付** |

### 10.3 组队的硬要求（写开工令时照抄）

```
· 每个队员**写集互不重叠**；若重叠，**必须显式声明串行**并写清先后（谁先谁后）
· 用 **shared task board**：每张任务写清【目标 ＋ 验收判据 ＋ 写集 ＋ 依赖】
· **Lead 跑终验**：以**原始输出**为准（不看队员转述，不吃"我跑过了"）
· 组队规模守 **上限即纪律**（DSH 原则 1）：**一次不超过 4–5 人**；
  超了 ⇒ 说明该分批，而不是该加人
· 队员**不许越权**：不碰门禁语义、不改别人写集、不 spawn 线负责人
```

### 10.4 独立复核（**不是可选项**）—— 三句话记住

```
① **只给**复核者【交付物 ＋ 一句"核它与实测是否一致"】
   —— **不得给**你的意图、结论、自查结果（否则它只会附和）
② 它必须出四项回执：
   a 与实测不一致处（**附命令**）｜b 无法核实处｜c 命令跑不通处
   d 总评：**能否据此独立开工/决策**（能／不能 ＋ 理由）
③ 复核结论**必须回写**交付物并重交；**不许"复核了但没改"**；
   无法修的一律标「**已知不一致 ＋ 原因**」（不许藏）
```

**实证**：独立复核曾一次挑出 CTO 文档 **10 处**与实测不符（PR 数被 `--limit` 伪造 / 板不含 PR 却说"唯一活账" / "已交付"混入 4 项未合并 PR / L3 判据单向）
⇒ **"我核过了" ≠ "别人核过了"**：前者是口径，后者才是判据。

### 10.5 三种常见违规（见到即拒收）

```
❌ **单干**：「我一个人做完了」—— 本技能任何步骤都不接受
❌ **复核者兼作者**：自己给自己复核 = 等于没复核（且违反"独立"的定义）
❌ **只给一句"帮我看看"**：不给交付物、不给核对口径 ⇒ 复核者**无法**产出四项回执
```
