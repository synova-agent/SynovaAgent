# 线级审计与卡面重写（CTO 方法）

## 0. 开场三件事
① 读权威：院方《产品宪章》——架构基准 **§0.4＋§4.1**（⓪–⑥＋−1 运行时）；**不许用旧 L1–L5 当架构**（铁律 39）。
② 读机器真源：`docs/synova/coordination/施工项登记.ts` 该块 items＋块判据 blockAcceptance。
③ 读现状：**实测**，不是文档写的。
**三红线**：不改门禁语义（CTO 裁权＋留 Note）｜不 spawn 线负责人｜不凭记忆断言——现状必带 file:line 或「命令＋原始输出」。

## 1. 定范围
列现状（items 逐条抄 id/title/status/batch/paths/acceptance，条数一致）｜抄条款号｜求交集（⇒ ①漏项 ②冲突项 ③重号/错归属，各出清单）。

## 2. 事实采集（量 ref，不量工作树）
① 目录/文件用 `git ls-tree <ref>`，**不用 `ls`** ② 现状带 `as_of <commit>`，引他人数字先复核 ③ "已交付"二元化：只许「已推送／已合入(main)」；判据 `git merge-base --is-ancestor <sha> origin/main`。
采集：本体 `git ls-tree -r <ref> -- extensions/ontology/`＋块判据原始输出｜循环 `cycles/*.cycle.json` 实际映射＋代码｜缺陷**真实复现**（命令＋原始输出）｜差量。回执四件=命令＋原始输出＋结论＋不确定项。

## 3. 横向查重（不许只看自己这一块，卡面冻结前必做）
四道：① **写集重叠**（本块 paths × 全仓块 paths 比对；粗路径产假重叠 ⇒ 先提精度）判据：零重叠，重叠须显式「串行：A 先 → B 后」｜② **跨块同判据**（最强信号：抽全仓 `acceptance[].run` 按命令归组，多块同命令 ⇒ **并卡**）｜③ **语义关键词**（主题词逐词统计命中，同词跨块判「同一件事/邻接」）｜④ **同源**（source 归一化 ⇒ 「同源不同事/同源同事（重复）」）。
**处置**（不许"看见了但不动"）：同一件事 ⇒ **并卡**（标「撤销·重复立卡」＋归谁）｜同一文件不同事 ⇒ **串行**＋两卡共写声明｜邻接不同事 ⇒ **写清边界**。块内自查查不出跨块重复（K12-14 与 K10 EXT-WIRE 曾重复立卡）。

## 4. 归属重定（按宪章，不按历史批次）
逐项三问：① 宪章哪一块（⓪–⑥/−1；旁参 §2.7/§4.7）② 条款号（**写出来**）③ 结论：保留/改归属/撤销/拆卡。
冲突：卡要做而宪章"延后" ⇒ 标『撤销/延后』＋写条款（不许默默留着）｜宪章要而卡没做 ⇒ 补立项｜跨两层 ⇒ 拆两卡。

## 5. 边缺口审计（并入 edge-gap-audit）
> 拿**架构清单**逐层问「这一层的产物去哪了？」——**缺口常是静默的**（不报错、CI 绿、测试过，只是边半截）。
**三类断点**：① **断头路**（「读侧是谁？」答不出 ⇒ 有写无读）② **没记账**（「这个状态字段谁写它？」答不出 ⇒ 状态空转）③ **只覆盖一种**（「入参能表达几类？」只 1 类 ⇒ 覆盖面窄）。
**三步**：① 画边（谁产生/谁消费/回路闭了吗）② 扫状态字段（终态/标志位/结果对象逐个问「谁置位？」）③ 扫通用接口（"提案/事件/任务"容器逐个问「能表达几类 payload？」）。
**判据**：每个缺口 ⇒ 一条边（E 编号）＋一张卡＋一条"改坏即红"判据（**没有改坏即红的绿＝未证实的绿**）；**执行缺口**（有设计没实现）⇒ 可派单｜**架构缺口**（设计本身表达不了）⇒ **必须 CTO 裁定**（如 E9）。缺口＝清单有、实现无；"绿"≠"无缺口"。
**已验证**：E6/J5 ④台账只写不读｜🔴 0-2 总闸 `applied` 恒 0｜E9 ⑥只改阈值。
**反模式**：❌ 拿"CI 绿"当"无缺口" ❌ 只读代码找 bug ❌ 缺口直接派单（架构缺口派下去＝执行方自造语义＝越界）❌ 发现一条报一条（逐层扫完再报）。

## 6. 卡面重写（核心：六字段与 §〇 七问）
形态：`# Task Brief: #<Issue号> → <块号>-<序号> — 标题`＋§〇（七问）＋六字段＋Done 标准。六字段=Q0 定位/Q1 调研/Q2 范围/Q3 验收（入口→交互→结果）/架构层/写集；**Done 标准第 7 项，缺它不准开工**。PR 正文必含 `Closes #N`。
### 6.1 六字段（写什么｜判据｜反例）
- **Q0 定位**：哪一块＋现状；**文件审计**＝要碰的文件已存在什么（带路径）；新增/替换/扩展｜只写"属于本体层"=不合格。
- **Q1 调研**：业界最佳实践／顶级团队怎么做／`memory/` 我们犯过的错｜c 必须点名事故或铁律号｜"参考了业界做法"=不合格。
- **Q2 范围**：做什么（最简）／**不做什么（必须带文件路径）**｜排除项是可判定路径（如 `不改 src/l4/**`）｜"不改无关代码"=门禁拒｜🔴 **不用 glob**（`probe-*.ts`）——G12 用 re.escape 字面匹配，glob 恒不中 ⇒ 全判越界；写法：逐条裸精确路径。
- **Q3 验收**：入口（命令/路由）→交互→结果（谁看到什么）｜三环节都能指到文件:行 或 命令｜"功能可用"=不合格。
- **架构层**：**宪章块号**（⓪–⑥/−1），**不许写 L1–L5**｜与 §0.4/§4.1 对得上｜"L4 本体"=改 ② 本体层。
- **写集**：每个允许写的文件路径逐条列｜与其他卡零重叠（重叠须显式串行＋先后）＋精确不用 glob｜"src/ 下相关文件"=被门禁拦。
- **Done 标准**：至少一条**可机器判**（可跑命令＋期望退出码）｜命令现在跑得通｜"功能正确"=不合格｜🔴 探针类：未实现必须 exit 2（0 通过/1 失败/2 未实现），**恒绿=交付失败**。
### 6.2 §〇 七问
> 目的（创始人 2026-10-11）：写时就想清楚**为什么做、不做行不行**。
① **一句话**（能复述）｜② **解决什么痛**（实测数据/院方原话）｜③ **推动**（能指宪章条款号）｜④ 🔴 **不做行不行（最重要）**：结论（**不行**/**可以做但有代价**）＋理由；分清**禁令级 vs 欠账级**——「不行」=不做就塌（安全底线/结构缺口/前置），「有代价」=欠账（体验/运维成本）且诚实标注它不是最先做的｜⑤ **现有基础**（✅带路径行号／❌缺的，实测 as_of）｜⑥ **还需要做什么**（建哪些文件/接线点）｜⑦ **DSH 借鉴方式**（三选一：照搬／参考自研／自研（须诚实标注），写明借什么/不借什么/为什么；**必须给 file:line 证据**如 `compaction-basic/src/index.ts:114`；只写"借鉴 DSH"=不合格）｜⑧ **涉及代码文件**（路径可在 ls-tree 命中）。
### 6.3 另两件
**共写声明**（多卡共写某文件 ⇒「与 X 卡共写，**串行：X 先 → 本卡后**」）｜**来源标注**（来源／架构基准版本／登记件 id／缺字段问 CTO，不许猜）。

## 7. 批次划分
① 依赖链（前置未过，后置不开工）② 写集冲突（同文件多卡 ⇒ 串行）③ 上限即纪律（摊太多 ⇒ 无主无复核）。每批=卡清单＋约束＋**终点判据**。

## 8. 开工令（九节缺一=未完成）
① **仓库账号**：Gitea/克隆/CI/PR/看板 URL＋令牌；硬前提：从 local-main 起分支／只进 local-main（**绝不进 main**）／**不许 --no-verify**／新分支直推 `git push <url> <branch>`｜② **卡面三处**：主仓 `.claude/claims/`（**为准**）／库外档案仓／面板 URL｜③ **任务**：做什么＋写集＋不做什么｜④ **agent team**：编制见 §10＋shared task board＋写集互不重叠＋Lead 跑终验｜⑤ **独立复核**：见 §9｜⑥ **执行形态**：契约/判据/exit code 语义＋写集边界＋PR 流程（base=local-main）｜⑦ **AGENTS.md**：先写 task brief（六字段）→答 task-start 4 问（含 Q4）→交付时答 Agent 自检 5 问｜⑧ **合并权＋红线＋回执**：四条件自合并（CI 全绿 pending=0／零写集重叠／已过独立复核／串行），合并后发【PR 号＋CI 证据＋四条件自检】备案，遇问题**停下报告**；红线：不改 X／不碰门禁／不用 --no-verify／不 spawn 线负责人；回执三信号：① 分支+commit+PR 号+自检 5 问 ② 判据原始输出 ③ 未决项｜⑨ **PR 正文必含** `Closes #N`。
纪律：开工令必须含地址与卡面路径（漏了等于没派）；同一会话内给出，不等对方问。

## 9. 独立复核（交付前必做）
① 派**没参与写**的复核者 ② **只给【文档＋"核它与实测是否一致"】**，**不得给**意图/结论/自查 ③ 四项：a 与实测不一致处（**附命令**）b 无法核实处 c 命令跑不通处 d 总评**能否据此独立开工/决策** ④ 结论**必须回写**并重交（**不许"复核了但没改"**）⑤ 无法修的标「**已知不一致＋原因**」；豁免：纯机械产出（写明"未过对，因<类别>"）。

## 10. 组队规则（强制：按性质自建＋独立复核）
**三强制项**：① **必须组队**（最小 Lead＋1 队员＋1 独立复核者，**复核者不参与写作**）② **编制按任务性质定**（不许一刀切）③ **必须独立复核**＋结论回写。
**四类编制**：① 事实采集类（1 人 1 维度，回执四件=命令＋原始输出＋结论＋不确定项）② 重写/撰写类（Lead 主笔＋1 挑战者＋1 复核｜挑战者**必须找出至少 1 处不合格**，否则说明原因，不许"没问题"结案）③ 审计/裁决类（**2 名审计员互不通气**｜各自独立成立；冲突**以实测为准**，不以资历）④ 混合类（**分阶段换编制**｜每阶段过一次门，不许压成一次交付）。
**硬要求**：写集互不重叠（重叠须显式串行＋先后）｜shared task board（目标＋判据＋写集＋依赖）｜Lead 跑终验以**原始输出**为准（不吃"我跑过了"）｜**上限即纪律**：一次 ≤4–5 人，超了说明该分批｜队员不越权（不碰门禁语义/不改别人写集/不 spawn 线负责人）。
**❌ 三种违规即拒收**：单干｜复核者兼作者｜只给一句"帮我看看"（无交付物与口径）。

## 11. 常见坑（实测清单）
① `--limit 100` **静默饱和** ⇒ 一律 `--limit 1000`｜② `gh` 脱离 git 仓 cwd 会 fatal ⇒ `-R <owner/repo>`｜③ 不"看阻塞视图"⇒ 用字段复现｜④ 板**只装 Issue 不装 PR** ⇒ 另查 PR 状态｜⑤ 正则改机器真源**首匹配会撞号** ⇒ 解析→按 block+id 定位→改→复核（唯一性/引用/目标对象）｜⑥ posix `grep -E` **无 `\b`**（`\bL[1-5]\b` 恒 0）⇒ `L[1-5][^0-9A-Za-z]`｜⑦ 推送前 `git show --stat HEAD`｜⑧ `--single-branch` 无 `origin/<other>` ⇒ `FETCH_HEAD` 或显式 refspec｜⑨ CI 只看 `job.conclusion`＋**等 pending=0**。

## 12. 收尾（必须留痕）
① 审计报告→库外档案仓 ② 卡面→**主仓 `.claude/claims/`**＋面板回填 ③ 登记件新增项**必须带 issue 号**，命名 `<前缀>-<序号>` ④ 记账：活账追加一节 ⑤ 交接：回复带可复制开工令。
