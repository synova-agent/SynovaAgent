# squad-discipline — 小队行为纪律（门禁之外的部分）

## 为什么只有这些条款

原 `synova-dsh` persona 是 128 行铁律抄本；其中约七成（as any / 架构边界 / 桥接 / 契约 / 空壳测试 / 分支命名 / vitest 全绿 / pre-commit 组数）**已由 pre-commit 13 组 + CI + pre-push 硬执行**。重复它们有三个代价：噪音、数字漂移（M7）、以及"写了就当做了"的错觉。
**规则：门禁能拦的不写进技能；本技能只收「无人能拦、只能靠自持」的条款。**

## 一、防跑偏（创始人痛点，无任何门禁可抓）

1. **锚定三问，先于一切**：① 服务哪个真实用户场景？② 终态长什么样？③ 对齐 `PRODUCT-BRIEF.md` 哪一节？
2. **锚定不清 → 停下问创始人**（属产品方向，不是技术决策）；**禁止**带着模糊锚定开工。
3. 任务开始先**复述理解 + 确认 Done 标准**；歧义先问，禁假设共识（铁律 0）。

## 二、防自欺（声称 ↔ 证据）

4. **汇报格式 = 声称 ↔ 证据逐条对应**：每条"改了什么/接了什么"必须挂物理证据（grep 命中行号 / 测试结果 / `git diff --stat`），无自报项。
5. **数字必须来自命令原始输出**，禁手写；禁 `head` 截断关键输出（要"共 N 处"）。
6. **自检 5 问（写完必答）**：① 新 export 谁调用？② 每个 catch 有 log + degraded？③ as any = 0？④ 测试有断言且覆盖正常/降级/边界？⑤ 有死代码/旧引用残留？
   —— 门禁只查物理项；**"接线在正确调用链中"是语义判断，只能自持**。
7. **纪律不外包给 hook**：DSH 会话里 `.claude/settings.json` 的 hooks 不触发 → 流程靠自持 + git 门禁兜底。提交被拒先读原因修复，**禁 `--no-verify`**。

## 三、决策与升级（技术自决，不甩创始人）

8. **D333 四步**（第一性原理 / Anthropic 基线 / 开源实证 / 收敛检查）→ 记录**参考系**：`参考：Anthropic/DeepSeek/第一性原理 + 结论`（K3 可核）。
9. **技术决策一律自决**（工程方法/架构/实现/取舍）；只有**产品/业务**决策才问创始人。把技术问题甩给创始人 = 转嫁决策负担，禁止。
10. **同类错误第二次出现 = 防线系统性失效 → 立即升级创始人**（不看是谁犯的）。

## 四、审计免疫（闭环）

11. 收到 K3 发现：**先查台账是否已有同类**（M1–M8 模式）→ 同类则强化既有防线，不同类才加新机制（一类一机制，防臃肿）。
12. 归属三分：DSH 的错 → 台账 + 长成规则；控制塔缺陷 → 台账 CT 队列；**审计脚本/审计标准 → 只转达 K3，绝不改 `scripts/audit/`**（红线）。

## 五、隔离与环境（口径已更新 2026-09-23）

13. **一人一事一分支 + 独立工作树**：用 `.synova-wt-<任务>`（`git worktree add`），**不复用他人工作树**；主工作区 `/Users/wane/SynovaAgent` 只做同步与协调，任务 session 不在主树写。
14. 开工前 `git fetch --all`；**禁在 `[behind N]` 状态开工或 push**；禁 `git stash`（D312 事故）——要停就 commit 或换 worktree。
15. **取号必走分配器** `bash scripts/control-tower/alloc-task-id.sh "<任务名>"`，禁自编号（D382 撞车教训）。

## 六、待办与上限（与队长预设一致，避免两处漂移）

16. 成员 ≤4（队长 + ≤2 编码 + 1 自验）；**自验不得由编码兼任**；重型验证（vitest/全量门禁/黄金门禁）**串行**，同时 ≤1（机器 8GB）。
17. PR ≤12 文件 + 单域；超了拆 PR，不开口子。

## 七、团队机制（D931 接线；"小队是摆设"的根因）

18. **默认不会组队 —— 必须显式建成员**：DSH 只在被明确要求时创建队友；"成员 ≤4"是编制约束不是机制。
19. 队长**只协调不下场写码**；编制 = 队长 + ≤2 编码 + **1 独立自验**（自验不得由编码兼任）；`maxMembers=4` 已物理生效。
20. 派活走**共享任务**：正文含 **写集（逐文件）+ 验收命令 + 写者**；写集两两不重叠；热点文件单写者。
21. 交付回执必须含**团队成员运行记录**（成员名/状态/token/共享任务 id 与状态）；**只有队长在跑 = 退回**（M3 型）。
22. 成员在各自真工作树干活，不共用；重型验证串行 ≤1。

## 用法

- 队长与成员**开工时加载**；派单件写"按 squad-discipline 执行"即可，不复制条款正文。
- **本技能不含**门禁已覆盖条款——那些以脚本与 CI 为单一事实源（`bash scripts/pre-commit-check.sh` / `ci.yml` / `pre-push-check.sh`）。
- 修改本技能 = 治理产物 → 走 PR + K3 审（改纪律者不得自判通过）。

## 历史
- 2026-09-23：由 CTO 从 `synova-dsh` persona 提炼（创始人指令：取其可取、与控制塔不冲突者，给小队）。原 persona 同步精简，避免两处漂移。
