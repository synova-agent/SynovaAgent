# 决策: 最终分工方案（**可启动版**）—— 谁的域、改哪条路径、怎么验

状态: implemented
日期: 2026-10-02

## 一句话

**四条线各有其域、各改其路径、各由机器验其边界**；**CTO 只出锚与收口，不再碰线内操作。**

## 问题

三级制落地后，"谁该做什么"**散在院方研究件、CTO 岗位件、各线锚里**，没有一份**可启动的定稿**。后果已实际发生：

- **CTO 陷入线内操作**（逐 PR 解冲突、补写集声明、改号）⇒ **上下文被任务级内容灌满**（正是三级制要治的病）；
- **派单来源不明**（"X30 工程落地 session 给的"）⇒ 授权链断裂、事后无法追责；
- **归属靠记忆**（哪块谁负责没有机器可查的声明）⇒ 新人/新会话上手只能问人；
- **门禁语义变更无人裁** ⇒ 改门禁者可能自定阻断规则。

## 决定

## 一、**DSH 的做法（不是组织图，是"路径归属 + 标签强制"）** —— 我们照此对齐

实测 `dsh-v0.2.0-rc.2`：

| DSH 机制 | 实测 | 它替代了什么 |
|---|---|---|
| **`AGENTS.md` 分层声明归属** | **22 份**（`AGENTS.md`／`packages/AGENTS.md`／`.github/AGENTS.md`／`docs/AGENTS.md`／`apps/**`…） | **组织图**——"该动哪个包、谁支持这个改动"是**可查事实** |
| **无 `CODEOWNERS`** | 零命中 | 归属**不靠平台配置**，靠路径声明 + 标签 |
| **Issue 标签强制** | PR 必须：**≥1 同仓 Issue 引用**、**恰好一个 `kind/*`**、**≥1 个 `area/*`**、**至多一个 `p0`–`p3`** | **谁管哪块**——`area/*` 就是"域"的实体 |
| **Project 状态机** | 7 档（`Inbox/Backlog/Ready/In progress/In review/Done/No action`）；PR 事件驱动流转 | **人在哪一步**——不用问人 |
| **政策代码化** | `policy.mjs` + `rules.mjs` + `lifecycle.mjs` + **`policy.test.mjs`**；**策略取自默认分支** | **规则不靠自律**；且**PR 改不了自己的判据** |
| **`permissions:` 显式收敛** | 每个 workflow 都有（如 `{contents: read, issues: read, pull-requests: read}`） | 权限面最小化 |

**⇒ 结论**：**DSH 不分"人"，分"路径"**。归属写在**路径的 `AGENTS.md`** 里，执行由**政策代码**强制。

## 二、我方最终分工（**角色 × 域 × 路径 × 入口**）

> **我们用 DSH 的形状**（路径归属 + 标签强制），**但保留我们的三级制**（因为创始人无技术背景、记忆载体只能是仓库）。

| 角色 | **域** | **路径所有权（排他）** | **入口物** | **怎么验（机器）** |
|---|---|---|---|---|
| **CTO** | 宪法层与跨线 | `docs/synova/CTO-ROLE.md`｜`decisions/**`｜`docs/synova/STATE.md`｜`coordination/` 的**锚与回执**（库外）；**`ci.yml` 的"哪条阻断合并"＝唯一裁权** | 方向锚（A1–A8）／收件闸回执／当日裁决 | `cto-drift-check.sh`（6 条不变量）＋ 我的输出形态自查（件内无任务级内容） |
| **治理线** | 门禁·CI·控制塔·迁移·文档治理 | **`.github/**`**（workflows／ISSUE_TEMPLATE／issue-management）｜**`scripts/control-tower/**`**｜**`scripts/workflow/**`**｜`scripts/doc-system/**`｜`ownership.yaml`｜`.gitattributes`｜`docs/authority/DOCS-REGISTRY.yaml` | 全量门禁地图／文档治理清单 | 改坏即红夹具 ＋ 反例矩阵 ＋ **一致性门禁**（`check-required-contexts.py`） |
| **基座线** | DSH 契约与边界（**只出结论不出代码**） | `/Users/wane/src/deepseek-harness-020`（**只读**）｜契约台账（库外）；**`src/` 只读** | DSH 契约边界台账／范式结论 | 双侧 `file:line` ＋ **G1 守卫**（`grep -rn "@deepseek-ai" src/ packages/` 零命中） |
| **产品线** | 领域能力面＋照范式自研的运行时代码 | **`src/l3/**`｜`src/l4/**`｜`expert/**`｜`extensions/sentinels/**`｜`knowledge/**`｜`theory/**`** | 5 类扩展物生效判据／领域交付 | **三问机器可判**（加了吗／接上了吗／生效了吗）＋ 穿生产入口用例 |
| **Win 侧** | CTO 直配模块的**执行** | 仅**该模块明确列出的文件**（WIP=1） | 模块分配件 | 按 A7 三档出数；**验收归治理线/K3** |

**🔴 分界判据（一句话，遇争议照此判）**：
```
出【结论】（对账/登记/建议/范式）  ⇒ 基座线
出【代码/功能】（领域能力面）       ⇒ 产品线
出【规则/门禁/CI/迁移/文档治理】    ⇒ 治理线
出【方向/跨线裁决/线级对账】        ⇒ CTO
出【钱/风险/不可逆/红线】           ⇒ 创始人
```

**配套三条**：① 改"哪条检查阻断合并" ⇒ **治理线提案 → K3 过审 → CTO 裁**（不许线下自定）
② `ci.yml`／`ownership.yaml`＝**单写者热点文件**（改动须并入治理线窗）
③ 跨线写集冲突 ⇒ CTO **当日裁**

## 三、🔴 本决策**新增**的关键件：**每个能力面一份 `AGENTS.md`**（DSH 最值钱的一条，我们缺）

**我方现状**：只有**根级** `AGENTS.md`；DSH 有 **22 份**分层声明。

**⇒ 要求（**归属＝各线**，本决策只定"必须有"）**：

| 应有 `AGENTS.md` 的路径 | 归属（谁写谁维护） |
|---|---|
| `src/l3/AGENTS.md` | 产品线 |
| `src/l4/AGENTS.md` | 产品线 |
| `expert/AGENTS.md` | 产品线 |
| `sentinel/AGENTS.md`（或 `extensions/sentinels/AGENTS.md`） | 产品线 |
| `.github/AGENTS.md` | **治理线** |
| `scripts/control-tower/AGENTS.md` | **治理线** |
| `docs/AGENTS.md`（文档治理规则） | **治理线** |
| `docs/synova/coordination/AGENTS.md`（锚与回执的写法） | **CTO** |

**每份必须回答三问（可核）**：
```
① 这块是做什么的（一句话）
② 谁可以改（归属 + 越界找谁）
③ 改完怎么算完成（该面特有的判据；例：L3 的"生效了吗"怎么判）
```
**⇒ 它顺手治"不知道从哪下手"** —— 这正是"任务重"的一半来源。

## 四、三方交叉验证（**分工不靠人记得，靠机器**）

```
① 路径声明：每域有 AGENTS.md ⇒ 【谁的地盘】
② 条目分类：Issue 必带 kind/* + area/* + p0-p3 ⇒ 【这是什么、归哪个域、多急】
③ PR 准入：PR 必引 Issue（≥1 同仓、恰好一个 kind/*、≥1 area/*、至多一个 p0-p3）⇒ 【这活有出处】
```
**三者齐 ⇒ 任何一条在飞的工作，都能回答"谁在做、卡在哪、属于哪条线"**（不靠问人）。

## 考虑过的其他方案

**方案 B：按"工作性质"立线**（DSH 借鉴线 / 参考自研线）。
否决：① 四类清单（必须自建 37／用 DSH 14／参考自研 11／可裁剪 16）**是分类，不是建制**——
"借鉴"**穿在所有条目上**（参考自研 11 项分布在客户端/数据/部署），立线等于**每个域再切两半**；
② **"照范式自研"是常态**（运行时自建＋守 G1）⇒ 该线**永不退休**；③ CTO 上下文 ∝ 线数，加节点最贵。

**方案 C：按架构层（L1–L5）立线**。
否决：① L1–L5 是**代码依赖方向**（铁律 39），**不是交付单元**；② **铁律 1「垂直切片交付」反对按层横切**——
一个功能（如加一个专家）要穿 L3+L4+L5 ⇒ **5 条线各占一段，跨线协调爆炸**。

**方案 D：CTO 继续兼做线内操作（现状）**。
否决：CTO 上下文 ∝ **任务数**（不可封顶），而三级制的设计前提是 ∝ **线数**（可封顶）。
实证：2026-10-02 当日因逐 PR 操作**耗掉整轮上下文**，主线零推进。

**方案 E：照搬 DSH 取消三级制、只留路径归属**。
否决：**前提不同**（契约 §0 已写）——DSH 团队 20 人 + 人的记忆沉淀；**我们无技术背景创始人 + 几个 AI 助手，
记忆载体只有仓库**。⇒ **学 DSH 的形状（路径归属＋标签强制），保留三级制。**

## 影响

- **各线有排他路径所有权** ⇒ 写集冲突可事前判（不再靠事后解冲突）；
- **CTO 退回四件事** ⇒ `cto-drift-check.sh` 的 I1–I6 为机器守；
- **8 份 `AGENTS.md` 是新增长期承担**（各线自维；不进 CTO 上下文）；
- **不影响既有 248 件 `coordination/` 存量**（契约合规缺口另登记于本决策"待办"）。
