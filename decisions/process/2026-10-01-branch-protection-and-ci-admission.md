## 决策一 · 两套保护收口成一套 —— **同意**（带顺序硬约束）

**决定**：把 legacy 分支保护转成 ruleset（GitHub "Convert to ruleset"），使 main 的准入判据只有一个事实源。

**硬顺序（CTO 加）**：
1. **先落决策二**（在 legacy 上小步改 + API 读回复验）→ **再**做转换；
2. 转换窗口内**不合并任何 PR**；
3. 转换后必须用 API **逐字复验**：12 项必需检查名（转换前后逐字一致）、`enforce_admins`、`strict=false`、签名/线性历史/force push/deletion 四项；
4. 转换**不可逆** ⇒ 复验不通过 = **立即停手上报**，不许"先合了再说"。

**验收**：转换前后两份 API 快照的逐条对照表（文本 diff）；必需集逐字一致。
**否决的替代**：反向删 ruleset 留 legacy（不可取：legacy 是被取代机制）；两套都留只写文档（靠自觉，正契约要消灭的形态）。

## 决策二 · 必需面修正 —— ① **同意**；② **同意（附两条约束）**

**① Gate Integrity 进必需集：同意。**
- 新事实（CTO 实测）：该 job 在 main 最近 8 次 CI **全绿** ⇒ 挂上它**不会**立刻冻结队列；这是本次唯一的"加"，且它加回的是一道 **J2 级防绕过**能力。
- 名字必须**逐字**：`Gate Integrity (pattern sentinel + injection fixture + ci-reds)`。

**② `npm audit` 出必需集：同意，但去掉的是"阻断力"，不是"检查"。**
- 约束 A：该 job **继续运行、继续在 PR 上可见**（红不挡合并）。
- 约束 B：同批登记 P2 债「npm audit 改**增量判定**（diff 命中高危才阻断）」；改造完成后由 CTO 决定是否回归必需集。
- 依据：**决策镜头原则 4（机械问题与业务语义分离）**——"存量红"不是"本次改动的问题"，不该由本次 PR 承担阻断。

**③ 其余 10 项不动**（照提出件的红线）。

**验收**：API 读回必需集**含** Gate Integrity、**不含** npm audit；且 Gate Integrity 转红时确实阻断（构造/复用一次红的 run 验证）。

## 决策三 · `enforce_admins` —— **同意**（保留严 + 书面预案）

**决定**：保留 `enforce_admins = 开`；补**书面紧急预案**。
**CTO 加的要求**：预案必须写明 ① 谁有权临时关闭 ② 关闭的**判据**（例：CI 长期红导致无法合并修复，且没有替代路径）③ 关闭动作**留痕**（写台账）④ **恢复时限（24h）**；并写明与既有 `SYNO_ALLOW_MAIN_PUSH` 逃生舱的关系——**它需创始人逐次显式批准**（历史 D570 曾把逃生舱当常规通道用过，属违规）。
**依据**：原则 1（上限即纪律）＋ 既有铁律 0-3（禁直推 main）。

## 决策四 · CI 口径与瘦身 —— **同意，但口径按三档重定**（附 6 条判据）

> 🔴 **2026-10-02 口径更正（创始人裁）**：本决策原写「CI 瘦身 **≤25 min**」，并把 25min 当**验收判据** ——
> **该引用是错的**（属"启动令把两个数合并表述"造成的误引）。经核原文后重定如下，**原文出处并列**：
> · **≤15 min** ← 治理 05 **§I-4（验收判据）**：**"快层"跑完要多久** ⇒ **这是目标**
> · **>25 min** ← Q3 **R-1（反例节，不是判据）**：**若快层 >25min 就先别开 merge queue，先瘦身** ⇒ **这是闸**
> 两者**不是同一指标的两种说法，是两件不同的事**（一个是"应该多快"，一个是"能不能开队列"）。

**决定（三档口径，各归其位）**：

| 档 | 定义 | 目标/闸 | 现状实测（2026-10-02，#928 run） |
|---|---|---|---|
| **快层** | **不含 `Control Tower Gate Tests` 两条腿**（ubuntu + windows） | **≤15 min**（05 §I-4） | **≈12 min ✅ 达标**（Vitest 317s ＋ 其余合计 ≈370s） |
| **整轮** | 全 13 个检查名 | **>25 min ⇒ 不开 merge queue**（Q3 R-1） | **≈35–47 min ❌ 已饱和** ⇒ **merge queue 现在不开** |
| **CT 腿（单列）** | `Control Tower Gate Tests (windows)` ／ `(ubuntu)` | **单独立目标 + 先插桩归因** | **2106s（35.1min）／307s** —— **同一批测试，Windows 慢 6.8 倍，至今无归因** |

**CTO 加的判据（6 条）**：
1. 🔴 **"快层"必须写明其定义**（不含 CT 两条腿）—— 否则 15min 会被误读成"整轮"。
2. **CT 腿先插桩再动**：`simulate-ci.test.sh` 单条实测 **1891s**（占该 job 67%）—— **在归因出那 40%+ 未解释耗时前，不许砍**。
3. **不新增矛盾**：`simulate-ci.test.sh` 只跑 ubuntu 腿**能否把整轮压到 ≤25min 待算**（CT 腿即使降到 ≈925s，整轮仍可能 >25min）⇒ **不许把"方案 A 落地"当作"25min 达标"**。
4. 不改 job/step 显示名；不删测试（登记闸）。
5. timeout 基线**重取**（原 2816s 为旧值）。
6. 保留「**发布前在 Windows 上跑一次全量**」作补偿控制（登记为长期债）。

**验收**：三档各自出数 —— 快层实测 ≤15min（同一 run）／整轮实测数（用于判"能不能开队列"）／CT 腿插桩归因报告。**附改造前后 run id 对照。**

## 决策五 · 流程文件豁免 —— **同意**（附 4 条约束 + 1 处事实修正）

**决定**：`check-pr-budget.sh` 的计数**排除** `task-state/*.json`、`.claude/task-briefs/*`、`memory/notes/**`；**`MAX_FILES=12` 不变**（不动上限，只改计数口径）。
**约束**：
1. 实质文件计数、域检查、出库豁免（D1028 路径级）语义**一律不动**；
2. **不得扩大豁免范围**——`.claude/skills/**`、`decisions/**`、`docs/**`、`.claude/bypass.log` 等本次**不进白名单**（防范围蔓延）；
3. 新口径写进脚本注释 + README（**单源**）；
4. 显示口径修正：`soft_check` 的"N 处"是**输出行数**，须改为区分「**实质文件 N 件 / 流程文件 M 件 / 输出行数 K**」——否则每次对账都被误导。

**🔴 事实修正（影响验收口径）**：**裁掉预算 ≠ #908 能合**。CTO 实测该 job 另有 `❌ V5 平台敏感命令：scripts/control-tower/log-snapshot`（PR #908 新增脚本，1 处），CI strict 转硬阻断。工程线**必须同批处置**该条；否则"拆 2 个 PR 即过闸"的验收必然失准。
**数字口径**：本分支实测 **53/70 = 75.7%**（提出件写 51/70）；门禁自报"70 件增/改 + 白名单外 37 件"；三者须以**命令 + 排除项 + 截至时刻**统一。

**验收**：同一 PR 复跑后，输出能同时回答"实质文件数/流程文件数"，且不再报超限；含流程文件的 PR 不再红；**且** #908 的 V5 那条已消除或单独成卡。
