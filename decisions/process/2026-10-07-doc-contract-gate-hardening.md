# 决策: 文档契约闸 3 判据收敛 —— 补上 K3 复核测出的逃逸面（承接 D1203 整改）

状态: implemented
日期: 2026-10-07

> 本件承接并取代 `fix(D1203)` 的同主题整改（PR #1255，K3 verifier 判「通过但需整改」）：
> 其决定 1/2/3 与残余风险登记全部保留，另并入 K3 §R2 的第三类逃逸（X3）、§R3 的出口条件机器化与
> 存量动态派生；并修掉 verifier 抓出的两处 P3（错误用例标签引用 / 不存在的副作用声称）。
> 判据正确性仍须 **K3 独立复核**（红线 R-6：改门禁者不得自判通过）——本件不得自宣「已合规」。

## 一句话

把「闸 3 能被三条路绕开」补上：写成同名前缀的文件、用 `git mv` 搬进阻断区、在新目录播种 README 索引；
并把过渡表的出口条件从散文改成机器可判、存量从手写数字改成动态派生。

## 问题

D1193 把文档契约三闸接上线，并通过 K3 独立复核（CONDITIONAL PASS）。但 K3 自建夹具（不采信作者自测）
测出**两个 P1 逃逸 + 一个 P2 后门 + 一处 P1 可执行性缺口**：

① 阻断条目 `X/**` 只匹配子树 ⇒ 把内容写成同名前缀**文件** `docs/plans.md` 即放行（X1a）；
② 闸 3 取变更用 `--diff-filter=A`，而 `git mv` 被 git 记为 R(rename) ⇒ 把既有文档搬进阻断区可静默通过
（X2，K3 实测三闸 PASS）；
③ `**/README.md` 无同址约束 ⇒ 新建顶层 `reports/README.md` 放行，等于「用一份 README 在未授权目录开张」（X3）；
④ §9.1 出口条件不可机器判定、`transition_hits` 只打印不落盘；且「存量 214」在合并当刻实测即 215、次日 226
—— 违反本仓「引用纪律」（数量一律以脚本实况为准，不得写进定义）。

## 决定

1. 阻断条目启用**前缀闭包**：`X/**` 同时命中 `X.<ext>`；边界收紧到 `.`，因此 `X-archive/` 不误拦；
   **白名单不启用闭包**（否则 `docs/**` 会放行根级 `docs.md`）。
   **过渡例外不开闭包**（同名前缀文件不算 brief ⇒ 仍按阻断判，fail-closed）。
2. 变更集统一带 `--no-renames`：rename 被拆成「删除 + 新增」，新路径必然进入新增清单 ⇒
   `git mv <允许路径> <阻断路径>` 必被拦（回归断言见 `tests/doc-system/doc-contract-property.test.sh` 的
   **C3**（R→阻断区，`--staged`/`--base` 双腿）与 **C5**（R→同名前缀，X1×R 交叉））。
   ⚠ 事实边界（verifier 判定，本件更正）：**闸 1/2 的可观测行为不变** —— 其变更集本就用 `--diff-filter=ACMR`，
   R 已在集内且 `--name-only` 给出目标路径；`--no-renames` 只影响闸 3 的取数形态。**不存在**
   「闸 1/2 因此重核 lifecycle 目录」的副作用（D1203 决策件曾如此声称，实测不成立 ⇒ 已在两处改成事实）。
3. §9.1：删掉手写存量数字，出口条件改为**机器可判 DSL** `tracked-count:<路径模式>=<N>`（缺失/不可解析 ⇒ degraded exit 2）；
   存量**动态派生**（`git ls-files` × 模式，单源），声明值只作可选交叉校验（声明 ≠ 实测 ⇒ 任何模式判红）；
   `transition_hits` + 逐行台账追加落 `.claude/doc-contract-transition.log`
   （JSONL，`.gitignore:8 *.log` 已忽略 ⇒ **不是漏提交**）；落盘失败**显式 warn 但不阻断**
   （铁律 11：不静默；对账指标不是门禁）。
   「已达出口」在 `--baseline` 复审模式判红，逐 PR 模式只出 NOTE（台账是契约自身棘轮，不是每 PR 判据）。
4. X3（`**/README.md` 在新目录播种）**本轮修掉**：同址豁免须**同址有代码**（父目录含 ≥1 非文档文件）——
   这正是契约原意「包/目录自己的契约文档随代码走」。X1b（命名不同的同类目录 `coordinationX/`）
   **登记为残余风险**（契约 §9.2），类关闭走卡 #1261（把 `docs/**` 白名单收窄为正列表）。

## 考虑过的其他方案

- **无边界前缀匹配**（`rel.startswith("docs/plans")`）修 X1：拒绝 —— 会误拦 `docs/plans-archive/`，
  制造噪音 ⇒ 门禁被绕过（V3.9 教训）。**代价**：X1b（`coordinationX/`）不再被自动覆盖 ⇒ 登记残余风险 + 明文要求显式登记。
- **让匹配器猜同类名目录**（`coordination*`）：拒绝 —— 契约只点名具体路径，猜名字等于发明判据；
  改由 §3 明文要求「新增同类目录须显式登记阻断清单」。
- **X2 用 `--name-status` 解析 R 的目标路径**：可行（本件初版即此），但要为 `--staged` 与 `--base` 各写一遍解析；
  `--no-renames` 更短且不引入新解析面（最小改动优先）⇒ 采用后者。
- **X3 登记残余风险、先不修**（D1203 的读法）：拒绝 —— 其理由「机器判定『目录是否已存在』属新机制」在本件不成立：
  判据是**同址有没有代码**（父目录含非文档文件），属**判据收紧**而非新机制；
  且不修的代价（未授权目录用 README 开张）大于收紧的代价（同址无代码的目录不再放行 README）。
- **过渡条目也开闭包**（D1203 读法：`.claude/task-briefs.md` 也算 brief）：拒绝 —— 例外表应窄于它所例外的阻断条目，
  取 fail-closed 严格读法。
- **R3 把 214 更新成 226**：拒绝 —— 数字必然再腐；改为去数字 + 动态派生 + 落盘对账。
- **出口条件只写取数命令（散文）**：不足 —— 散文不可机器判「是否已达出口」；改为 DSL，不可解析即 exit 2。

## 后果

- **好的**：K3 §R2 三类逃逸（X1a/X2/X3）全部转红且有**性质断言矩阵**（边界路径 × A/R/M 变更形态 + 变异体反例，
  共 56 条断言：`tests/doc-system/doc-contract-property.test.sh`）；过渡对账有可取的数（JSONL 追加）；
  契约不再含会腐的手写数字；残余风险显式可查（§9.2）。
- **要长期承担**：① `--no-renames` 让大改动 diff 的路径清单变长（无内容开销）；
  ② 闭包把「同名前缀文件」视为同类过程件 —— 若确有合法的 `docs/plans.md` 类需求，须走契约修订而不是绕过；
  ③ **同址无代码的新目录不再能放 README**（如新建 `reports/README.md`）—— 若确有需求，走契约修订；
  ④ X1b 仍是已知未关闭面，直到 #1261 落地。
- **判据正确性仍须 K3 第二轮复核**（红线 R-6：改门禁者不得自判通过）——本件不得自宣「已合规」。
