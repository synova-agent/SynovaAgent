# 决策: 文档契约三闸接线 —— 判据修复（阻断优先 / 含 HTML / 契约动态解析）+ 提交端接线

状态: implemented
日期: 2026-10-07

## 一句话
把「文档契约三闸」从一句承诺变成真会拦人的门禁：判据修好，并接在提交端。

## 问题
契约 §3 写明「三闸（机器可核 —— 不靠自律）」，D1107 实测**全仓零执行体**（grep 0 命中 / 阳性对照 45）。
补齐执行体的 D1107 又声明**不接线**（接线归治理线），于是 D 层过程 md 继续入库：契约生效 10 天内
origin/main 新增 167 份 md，其中 **68 份不在白名单**（全部是 `.claude/task-briefs/`），验收判据②
「连续两周新增过程 md = 0」判 FAIL。首版判据另有三处实测缺口：
① 白名单前缀先命中 ⇒ §3 ❌ 点名的 coordination/、plans/ **永不触发**（阻断清单成死代码）；
② 闸 3 只认 `.md` ⇒ HTML 成侧门（实测漏网 `docs/synova/coordination/四问-64格.html`）；
③ 判据硬编码在脚本内，与 §3.1 自述「从契约文本动态解析」不符。

## 决定
1. **判据三处修复**：阻断清单**优先于**白名单；闸 3 判据对象扩到 `.md` + `.html`；白名单/阻断/过渡
   三块写进契约正文，执行体动态解析（块缺失 ⇒ degraded exit 2，fail-closed）。
2. **接线**：pre-commit 调 `check-doc-contract.sh`，位置在 **CT-34 纯文档早退之前**（否则永不点火）；
   本地软提示、CI `SYNO_CI=1` 转硬；CI 走 `--base origin/main`。
3. **过渡显式化**：`.claude/task-briefs/**` 进 §9.1 过渡表（带出口条件 + 责任线 + 存量），命中计数可见；
   其余阻断清单**不设过渡**。
4. **逃生舱** `SYNO_DOC_CONTRACT_ACK=1`（须给 REASON）只降级闸 3，且必须落 `degraded-events.log`。

## 考虑过的其他方案
- **A 只在 CI 加独立 job、不进 pre-commit**：拒绝。本地提交时看不见 ⇒ 反馈滞后；且与 D515/D516
  「本地软提示 + CI 权威」的双端语义不一致。
- **B 接在文末 D1/D2 旁（沿既有位置）**：拒绝。纯文档提交会在 CT-34 分支 `exit 0`，接在那里等于永不点火
  （本卡实测），正是 D1107 首版式「建成未接线」的翻版。
- **C 把 §3 ❌ 全部路径设为过渡放行**：拒绝。等于门禁没有牙齿，契约仍是承诺；且实测 plans/、audit-reports/
  近 7 天新增均为 0，直接阻断不造成活动受阻。
- **D 对全量存量判红**：拒绝。违背契约 §7「存量不返工」，且任一提交必红 ⇒ 必然 `--no-verify`（V3.9 教训）。
- **E 保留硬编码判据**：拒绝。契约 §3.1 自述「白名单从契约文本动态解析」，硬编码即漂移源。

## 后果
- **好的**：契约 §3 有了物理执行面；HTML 侧门关闭；过渡进度可计数；判据单一来源（契约正文）。
- **坏的 / 要长期承担**：① pre-commit 多一次 python 进程（<1s，已加「无文档变更则跳过」）；
  ② coordination/ 与 dispatch/ 的入仓路径被断，线路必须改走 PR 正文 / 卡 note / 库外档案仓
  （承接已存在，见契约 §11 与 STATE.md §8）；③ **判据正确性尚未过 K3 独立复核**（红线 R-6），
  复核前不得声称「已合规」。
- **已知缺口（只上报不代改）**：分配器 `scripts/control-tower/alloc-task-id.sh` 发号撞车 —— 本卡 dry-run
  发到 D1192，但 origin/main 上 D1192 已被 K6 任务占用（brief 文件名 + 4 个提交），且 `--check-id D1192`
  查不出（只查本地卡）。本卡改用 **D1193** 并人工全位置复核；分配器补「brief 文件名占用」面属另一张卡。
