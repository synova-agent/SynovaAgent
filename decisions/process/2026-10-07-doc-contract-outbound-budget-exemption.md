## 1. 问题

D1028 出库豁免的成立条件为 **a 暂存面无增/改（纯删除/重命名）** 且 **b 全部路径落 OUTBOUND_ALLOW_RE 白名单**。
而控制塔同时强制每个 PR 携带 task brief（新增件）⇒ a 对任何真实出库 PR **永不成立**；
b 的路径前缀是写死的，新建目录/根级遗留/vendor/死备份必然漏（D860 已论证「白名单必然漏 ⇒ 每次新任务都得改门禁」）。

## 2. 决定

新增 **S2.4 文档契约出库豁免**（并列于 D1028，不取代）：

- **判据源唯一** = docs/synova/DOC-CONTRACT.md 的机器可读块，经执行体 check-doc-contract.sh --files --json 判定；
- a' 剔除 D860 治理产物（brief/卡/Note/规格/证据）后，剩余变更全部为 D/R；
- b' 每个剩余路径都被判为**闸 3 违规**（契约 §7 的出库域 = 本就不该入库）；
- 二者同时满足 ⇒ 出库豁免生效，**不调高 --max-files**（上限 12 不动，禁调高）；
- fail-closed：执行体缺失 / 契约 exit 2 / JSON 不可解析 ⇒ 不豁免 + 显式说明。

## 3. 理由

1. **单源判据**：豁免跟随契约，扩出库域只改契约，不改门禁（治 D860 自证之病）。
2. **不放松真代码**：b' 只认契约判定的出库域；src/、scripts/ 等拒绝名单路径不属出库域，仍照常计预算。
3. **可审计**：生效时打印件数与判据源；未生效时逐条给原因，不静默。

## 4. 替代方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 调高 --max-files | 门禁明令禁调高，且会全量放开真代码 PR |
| 逐个把路径加进白名单 | D860 已证必漏；把「运行期产物」变成「每次改门禁」 |
| 拆成几十个小 PR | 契约 §7 存量 719 件 ⇒ 数百个 PR，成本不可接受；且 brief 必带使 D1028 依旧不适用 |
| 用「## 死代码清理声明」放行 | 该声明只对拒绝名单（src/scripts/.github/tests/extensions/expert）生效；根级/vendor 等不在其内，实测不改变计数 |
