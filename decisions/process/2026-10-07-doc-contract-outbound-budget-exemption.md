# 决策: D734 出库豁免契约化 —— 文档治理按 DOC-CONTRACT 出血口（S2.4）

状态: proposed
日期: 2026-10-07

> 卡号 #1296。创始人 2026-10-07 裁决：「门禁应该按照文档契约给你的文档治理提供豁免」。
> 本件与 D1028 路径级豁免**并列**（不取代）；S2.4 只把「出库域」的判据源从写死白名单换成契约执行体。
> 判据正确性须 K3 独立复核（红线 R-6：改门禁者不得自判通过）——本件不得自宣「已合规」。

## 一句话

把出库豁免的判据从「门禁里写死的路径前缀」换成「文档契约执行体的判定」：
契约判为出库域（闸 3 违规）的路径，纯删除时不占 PR 预算预算 —— 且不调高文件数上限。

## 问题

D1028 出库豁免的成立条件是 ⓐ暂存面无增/改（纯删除/重命名） ∧ ⓑ全部路径落 `OUTBOUND_ALLOW_RE` 白名单。
而控制塔同时强制每个 PR 携带 task brief（**新增件**）⇒ ⓐ 对任何真实出库 PR **永不成立**；
ⓑ 是写死前缀，根级遗留/vendor/novis-backup/synthesis/.codex 必然漏（D860 已自证「白名单必然漏 ⇒ 把运行期产物变成改门禁」）。

实测（`--diff-status` 注入缝）：白名单内纯删 99 件=PASS；同 99 件 + 1 brief 新增=FAIL（99 > 上限 12）；
白名单外 11 件=PASS、13 件=FAIL。⇒ 契约 §7 存量出库（实测 719 件）在一次大 PR 下必红；
历史 D1044-B1（294 件）/ D1050-B2（275 件）能过，是因为当时 D734 仍是旁路只打印，D1171 转 CI 硬阻断后第一次出库即撞墙。

## 决定

新增 **S2.4 文档契约出库豁免**（并列 D1028，不取代）：

1. **判据源唯一** = `docs/synova/DOC-CONTRACT.md` 的机器可读块，经执行体 `check-doc-contract.sh --files --json` 判定；
2. ⓐ' 剔除 D860 治理产物（brief/卡/Note/规格/证据，复用既有 `GOV_PREFIX_RE` ∧ `GOV_EXT_RE`）后，剩余变更全部为 D/R；
3. ⓑ' 每个剩余路径都被判为**闸 3 违规**（= 契约 §7 出库域，本就不该入库）；
4. 两条同时满足 ⇒ 豁免生效（N_FILES=0），**不调高 `--max-files`**（上限 12 不动）；
5. fail-closed：执行体缺失 / 契约 exit 2 / **输出 schema 漂移（缺 `gate3_inbound.violations`）** ⇒ 不豁免，并逐条显式打印原因（不静默）。

**K3 复核后收紧（#1299 CONDITIONAL PASS，创始人裁 B「先修后合」）**：

6. **根级件一律不豁免**（`^[^/]+\.(md|html|markdown|htm)$` 照常计预算）—— 根级 = 仓库门面/真相源区；
   类级堵住 K3 §② P1「任何未入白名单的、本应存在的文档可被零预算信号删除」（部分豁免：非根级豁免、根级计数）。
7. **不可豁免清单命中 ⇒ 绝不豁免（exit 1）**：A 层四件 + 根级真相/导航件（INDEX/START-HERE/CHRONICLE/LOOP/MEMORY/SPEC/TECH_DEBT/VERSION/CHANGELOG/LOOP-ENGINEERING-CHANGELOG/loop-run-log/PRODUCT-BRIEF/.codex VERSION）
   + 测试夹具点名件（3 份 audit-reports）。deny 方向硬编码可接受（同 D1028 DENY 名单语义）。
8. **拒绝名单路径不接管**：`src/`/`scripts/` 等归 D1028 封堵面，S2.4 跳过 —— 消除 K3 §④ P2「同帧打印 ✅豁免 与 ❌绝不豁免」的字面矛盾。

## 考虑过的其他方案

| 方案 | 否决理由 |
|---|---|
| 调高 `--max-files` | 门禁明令禁调高，且会全量放开真代码 PR |
| 逐个把路径加进白名单 | D860 已证必漏；把「运行期产物」变成「每次改门禁」 |
| 拆成几十个小 PR | 契约 §7 存量 719 件 ⇒ 数百个 PR 成本不可接受；且 brief 必带使 D1028 依旧不适用 |
| 用「## 死代码清理声明」放行 | 该声明只对拒绝名单（src/scripts/.github/tests/extensions/expert）生效；根级/vendor 不在其内，实测不改变计数 |

## 后果

- 正面：出库批次（契约 §7）可在单个 PR 内完成；扩出库域只改契约，不改门禁（单源判据）；
- 边界：`src/`/`scripts/` 等拒绝名单路径**不属**契约出库域 ⇒ 仍照常计预算，真代码不被放开；
- 可核：生效时打印件数与判据源；未生效时逐条给原因；
- 遗留：K3 复核点 4 条（夹带风险 / 契约白名单放宽的连带 / 输出截断 / 与 D1028 判据冲突）见 PR #1299。
