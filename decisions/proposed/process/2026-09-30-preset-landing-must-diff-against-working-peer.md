# 决策: 落位 Agent 预设必须与「可跑的同族包」做行集差集

状态: proposed
日期: 2026-09-30

## 一句话

新建一个 Agent 预设后，除了看它"形状对不对"，还必须跟一个**已经在正常跑的同类预设**比"少了哪一行"——少的那一行，就是它起不来的原因。

## 问题

2026-09-30 落位「📚 山河研究院·线研究员」预设（`shanhe-researcher`），GUI 里显示红标**加载失败**。
排查发现：它的**形状完全正确**（`- insert:` 行 ＋ config 五字段齐全）、引用的插件包 **21/21 全部存在于运行态**，
但仍然整包不可用。真正的原因是：**参考件本身缺一行 runtime** ——
`tool-workflow` 需要 `workflow-ptc` 作为 workflow 引擎，参考件里没有这一行；我们逐字复制，把缺陷一起搬了过来。

⇒ 痛点：**「形状对」不等于「能跑」**，而现有的建包检查只查形状。

## 决定

**建包/落位验收增加一条硬判据**：与一个**已验证能跑的同族包**做**行集差集**（比较两边的行 id 与插件包名），
差集非空即视为未完成。本次的对照物取 `synova-main-cto`（同为全量型预设，且已在运行）。
差集命令与预期已写入 `docs/synova/coordination/` 之外的过程件（库外档案仓 `2026-09-30-mac小队-记录-预设加载失败根因.md`）。

## 考虑过的其他方案

| 方案 | 为什么不选 |
|---|---|
| 只做形状校验（`- insert:` ＋ 五字段） | **已证不足**：本次形状全对而整包不可用 |
| 靠 GUI 红标事后发现 | 本次即如此；代价是一轮返工 ＋ 创始人先看到坏件 |
| 枚举所有 runtime 依赖关系（建依赖表） | 成本高，且上游每次发版都可能变；差集法用现成对照物即可 |

## 后果

- **好的**：建包一次装对；差集为空是可机器核的判据。
- **坏的 / 要长期承担的**：需要一个「已验证能跑的同族包」作为对照物；**该对照物本身失效时会误判**（须在对照物变更时重选）。
