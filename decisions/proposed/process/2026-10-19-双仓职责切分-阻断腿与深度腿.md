## 一句话

Gitea 是唯一账本和唯一拦人处；GitHub 只出"能不能跑"的信号、不出账 —— **他只需要打开一个地址**。

## 问题

**他要的两件事，今天都不成立。**

1. **"我该打开哪个页面？"没有答案。** 2026-10-18 实测 en0 从 `192.168.0.26` 漂到 `192.168.1.7`（今天又漂回）；
   Gitea 平台配置（`custom/conf/app.ini` 的 `DOMAIN` / `ROOT_URL`）与 handbook 十几件文档都写死了 IP
   ⇒ **换网段就全断**，他的唯一新入口反复失效（他只能听转述 —— 而那正是他不想要的）。
2. **"同一件事只在一处有未完成的账"不成立。** 实测（as_of 2026-10-19 00:55）：Gitea **134** open issue（含本件 #589 与清扫卡 #590）＋**15** open PR；
   GitHub **206 open issue＋141 open PR**，Project 板 10-04 起冻结 ⇒ **两套账并存**，
   我们在两个地方各看一半、各做一半，最后谁都不完整。

**并且两仓角色只有"施工面／生态面"的说法（裁定 115），没有回答"哪条腿负责拦、哪条腿负责证明能跑"。**
结果是：阻断性检查与慢的全量验证混在同一条腿里 —— 阻断腿被拖慢（历史病根：CI 又慢又重 ⇒ 超时 ⇒ `--no-verify` ⇒ 链全废），
慢腿的红色又没人处置（GitHub 全量 CI 在 10-15 有 3 个 job 红，无人建卡）。

## 决定

### 决定 1 · 他的入口只有一个：`http://MacBook-Pro-2.local:3000`

- **看进度／看历史／看门禁结论：同一个地址**（Gitea）。不再有第二个入口。
- **地址纪律三档**（本决策立，后续所有件遵守）：

  | 场景 | 用什么 | 例 |
  |---|---|---|
  | 给人（创始人／跨机） | **mDNS 名** | `http://MacBook-Pro-2.local:3000` |
  | 本机脚本／本机命令 | **loopback** | `http://127.0.0.1:3000` |
  | 🔴 任何地方 | **禁 `192.168.x.x`** | 换网段即断（今天已实测漂移） |

- 实测（2026-10-19 00:05 CST，本机）：

  | 项 | 命令 | 实测 |
  |---|---|---|
  | mDNS 解析 | `dscacheutil -q host -a name MacBook-Pro-2.local` | → `192.168.1.7`（另含 `127.0.0.1` / `::1`） |
  | 页面可达 | `curl -s -o /dev/null -w "%{http_code}" http://MacBook-Pro-2.local:3000/` | **200** |
  | 服务版本 | `curl -s -H "Authorization: token <token>" http://MacBook-Pro-2.local:3000/api/v1/version` | `{"version":"1.27.3"}` |
  | 当前 en0 | `ipconfig getifaddr en0` | `192.168.1.7`（**今天变过，勿依赖**） |

- 🔴 **平台层现状（复核后修正）**：`app.ini` 的 `DOMAIN = 192.168.1.7` ／ `ROOT_URL = http://192.168.1.7:3000/`
  （证据：`log/launchd.out.log` 2026-10-10 14:38 启动行 `AppURL(ROOT_URL): http://192.168.1.7:3000/`；进程此后未重启）。
  **但复核推翻了"它是打不开的根因"这个说法**：

  | 复核项 | 做法 | 实测结果 |
  |---|---|---|
  | API 绝对 URL 跟谁走 | 分别用 `127.0.0.1`／`MacBook-Pro-2.local`／`192.168.1.7` 请求 `/api/v1/repos/...` | `html_url`/`clone_url` **随请求 Host 变**（各自返回各自 Host） |
  | UI 链接形态 | `curl -s http://MacBook-Pro-2.local:3000/ \| grep -oE 'href="[^"]{0,60}"'` | 全部**相对链接**（`/assets/...`）；页内唯一绝对地址 = 请求 Host 本身 |

  ⇒ **结论修正**：打不开的根因 = **IP 漂移 ＋ 文档/命令写死 IP**，**不是 `ROOT_URL`**。
  把 `ROOT_URL` 统一成 mDNS **仍建议做**（影响邮件通知／webhook／OAuth 回调等非浏览器场景，**这几处未逐项实测**），
  但它是**口径统一**，不是"入口打不开"的根因。修法 = 两行 ＋ 重启（约 10 秒），**属平台层、不在 P10 写集 ⇒ 上报**。
- **Win 侧判据**：Win 上 `curl -s -o NUL -w "%{http_code}" http://MacBook-Pro-2.local:3000/` = 200；
  若不解析 `.local`，`hosts` 加一行兜底（**兜底不是常态**，否则又回到"换网段就断"）。

### 决定 2 · 两条腿：一条只管拦，一条只管证

| | **阻断腿 ＝ Gitea** | **深度腿 ＝ GitHub** |
|---|---|---|
| **角色** | 施工面 ＋ **唯一账本** | 生态面 ＋ **集成验证主场** |
| **跑什么** | 13 组门禁 ＋ 架构 ＋ 内容耦合 ＋ 增量测试（＋ 待搬：密封套件） | E2E 集成／全量 vitest／golden-case／Windows×2／定时 |
| **阻断合并？** | ✅ **required check（平台强制）** | ❌ **不阻断**（只出信号） |
| **产出** | **账**（Issue／PR／门禁结论） | **信号**（job 红绿） |
| **写入口** | **唯一**（写代码只经这里） | **只读**（单向镜像；禁直接提交） |
| **频率** | 每 commit／PR | 人为触发 ＋ 定时 |

**判定"新检查放哪条腿"四问**（依次问，任一命中即定）：

```
 ① 它红了，能不能 2 分钟内说清"哪里错、怎么修"？ ── 能 → 阻断腿
 ② 它是否"慢但重要／跨平台／端到端"？           ── 是 → 深度腿
 ③ 阻断腿是否已有等价门禁？                     ── 有 → 深度腿只留信号（不重复阻断）
 ④ 它红了要不要立刻禁止合入？                   ── 要 → 阻断腿；不要 → 深度腿
```

### 决定 3 · 阻断腿的真值 = "平台强制"，不是"我们自觉"

**required check 实测**（admin token）：受保护分支 `local-main`；`enable_status_check = true`；
`status_check_contexts = ['local-gates / gates (pull_request)']`；`required_approvals = 0`；`push_whitelist = []`。
⇒ 本地 `--no-verify` 绕得过提交端，**绕不过 required check**。这就是"阻断腿"的物理含义。

🔴 **阻断腿的物理风险（CTO 已点明，本件继承）**：runner = `runs-on: macos` **自托管** ⇒ **Mac 睡了 / Gitea 停了，谁都不能合**。
这是"快而硬"的代价；不得为了绕开它而关掉 required check（那就等于放弃阻断腿）。

**现状 8 步**（`.gitea/workflows/local-gates.yml`：单 job `gates`，`runs-on: macos`，硬上限 15 分钟）：

| 步 | 阻断 | 干什么 |
|---|---|---|
| 工作区／依赖 | 是 | 本机 clone ＋ **lock 哈希指纹**变了才 `npm ci`（防"旧树判红"） |
| ① **13 组门禁** | 是 | 唯一的组级阻断门（`scripts/pre-commit-check.sh`；🔴 自声明 13 组，**复核实测横幅 12 个、无组 11** —— CTO 2026-10-19 01:22 改判：**归 P4**（因 C2 是自指检查），本件不再列） |
| ①b 看板真值 | 是 | 交付未回填检测（`check-block-paths.sh`） |
| ①c **内容面耦合 CC1–CC4** | 是 | 存量棘轮／新增必拦（`check-content-coupling.sh`） |
| ② **架构边界** | 是 | 代码层 L1–L5 import 方向（`check-architecture.sh`） |
| ③ 增量测试 | 是 | `vitest --changed`（只测改动面） |
| ④ 门禁复现器自检 | **条件** | 变更集触碰工作流/复现器/夹具才跑，否则 <1s 跳过 |

**时长判据（目标 < 2 分钟）**：真值源 `/Users/wane/gitea/data/gitea.db` 表 `action_run`；
实测（as_of 2026-10-19 00:55）`status ∈ {success, failure}` 样本 **986 条**：**p50 = 9 秒**，`>120s` **仅 2 条**（144s／189s）。
（另 5 条 `cancelled` 不计；其中一条 79983s 是"取消后未正常结束"的异常记录，**不得当性能数据**）
⇒ **写成棘轮**：`≤120s` 常态；**新增 run `>120s` ⇒ 报警**（不许用平均值掩盖长尾）；`>15 分钟` = CI 故障。

🔴 **缺口（必须承认，不许当"已经做到"）**：**密封套件 `gate-integrity` 目前只在深度腿**
（`.github/workflows/ci.yml` 的 job `Gate Integrity`）；`scripts/pre-commit-check.sh` 与 `local-gates.yml`
**均未调用** `check-gate-integrity.sh`（grep 0 命中）⇒ 与"13 组 ＋ 架构 ＋ **密封套件** ＋ 内容耦合"差 1 件
⇒ 列入"必须阻断的搬进 Gitea（**密封套件优先**）"。

### 决定 4 · 深度腿：不阻断、不产出账、不重复阻断

- **六个 workflow**：`ci.yml`（13 job 定义／**14 job 实测**；Windows 2 条按路径触发 ⇒ 触发时 16）｜
  `dashboard-auto.yml`（push）｜`desktop-build.yml`｜`product-progress.yml`（每周五 09:00）｜
  `progress-freshness-watchdog.yml`（每日 01:30 UTC）｜`project-coordinates.yml`。
- **最近一次 main 全量**（run `38784123864`／2026-10-15）：**9 绿／3 红／2 跳**。
  红 = `Architecture Check`、`Gate Integrity`、`All Checks Passed`（聚合）；跳 = Windows×2。
  复跑：`gh run view <run-id> --json jobs`。
- **定时件现状**：`Progress Freshness Watchdog` 10-16／17／18 **连续 3 红**（产物过期 >3 天）。
- **成本事实（CTO 实测）**：GitHub 仓 **public** ⇒ Actions 分钟免费 ⇒ 深度腿"多跑"不花钱，这是"慢而重要的证明放深度腿"的经济前提。
- **三条铁律**：
  1. **不阻断合并** —— GitHub 侧没有"CI 必须绿才能合"的 required check；阻断只发生在 Gitea。
  2. **不产出账** —— GitHub 红了**不自动建卡**；由人（CTO／创始人）判"是不是真问题"，**真问题才在 Gitea 建卡**，
     卡的判据必须写"红在哪、怎么复现、期望是什么"。
  3. **不重复阻断** —— 同一检查已在阻断腿跑过，深度腿只留信号（"缩 GitHub"的依据）。

### 决定 5 · 待办只在 Gitea（唯一账本）

```
 ① 新待办唯一合法载体 = Gitea Issue（PR 也是待办，同规则）
 ② GitHub Issue/PR = 只读归档：不再新建、不在那里做新决策；存量按下面三动作处置
 ③ "这次红了要不要建卡"的决定，只在 Gitea 留痕（GitHub 上不辩论）
```

**存量处置三动作**（出自《创始人五项待办-2026-10-16》②）：

| 动作 | 判据 | 产物 |
|---|---|---|
| **已覆盖 ⇒ 关** | 内容已在 `local-main` 落地，或被 Gitea 卡覆盖 | 关闭 ＋ 一行指针（Gitea 卡／sha） |
| **仍要做 ⇒ 转卡** | 未落地且仍有价值 | Gitea 建卡（判据可机器判）＋ 关 GitHub 件 |
| **不再做 ⇒ 废** | 前提已不成立 | 关闭 ＋ 标 retired |

**完成判据**：GitHub `open PR = 0` ∧ GitHub 侧无"未完成"Issue ∧ 两仓 sha 差 = 0。

**对账五维**（CI 红／未合 PR／Issue／Project↔里程碑／主树）定义见《创始人五项待办-2026-10-16》② ——
🔴 **本件不复制那张表**（防双真源）；执行时逐维给"数 ＋ 处置 ＋ 谁做 ＋ 产出"。

### 决定 6 · 集成验证面（深度腿的主业）

**目的**：把"能跑"变成**持续被证明**的事（创始人语义：**"跑不起来，说啥都没用"**），而不是最后才发现。

| 证据类 | 既有载体（禁重复建设） | 腿 |
|---|---|---|
| 装配／端到端 | `scripts/integration/e2e-decision-roundtrip.ts`、`e2e-metric-readback.ts`；`tests/e2e/` 14 件 | GitHub |
| 契约 | `Integration Contract Check` job | GitHub |
| 行为金标 | `tests/fixtures/golden-cases/`＋`scripts/golden-scenarios`＋`Golden Case F1 Gate` job | GitHub |

**产出物**：一次人工全量触发 ⇒ **一张 job 红绿表**（每行：job／红绿／耗时／失败点摘要／真问题 or 旧判据失效）。
表是**信号**不是账 —— 红项处置回决定 5。

**分界**：阻断腿**不跑**全量 E2E／全量 vitest（历史病根：又多又慢 ⇒ 超时 ⇒ `--no-verify`）。
**慢而重要的证明放深度腿；快而致命的拦截放阻断腿。**

## 考虑过的其他方案

| 方案 | 为什么不选 |
|---|---|
| **A. 两边同一优先级（双活）** | 就是现状：两套账并存（GitHub 347 件未结账）⇒ 谁都不完整；且 GitHub 用个人 key/限流，不适合做施工面 |
| **B. GitHub 作唯一账本** | 他的实际入口在 Gitea（自建、无限流、可批量）；且 GitHub 侧身份/权限受组织策略制约（裁 113 ①） |
| **C. 只留 Gitea，弃 GitHub** | 弃掉"独立干净环境的第二意见"与"能跑起来"的证明场（创始人明确要 GitHub 承担集成验证，⑤） |
| **D. 双腿，但两条都阻断** | 阻断腿会被拖慢（历史病根：超时 ⇒ `--no-verify`）；且 GitHub CI 有外网抖动/限流，阻塞合入不可接受 |
| **E. 深度腿也建卡（自动开 Issue）** | 会制造"两边各挂一半账"的机器复现；且 GitHub 红多为旧判据失效 ⇒ 机器建卡 = 噪音 |
| **F. 地址一律换成当前 IP** | 今天已实证 IP 会漂（`192.168.0.26` ↔ `192.168.1.7`）⇒ 写死 IP 的方案本身就是病因 |
| **G. 地址一律换成 `127.0.0.1`** | 只对他本机有效；他是跨机（Win）使用者 ⇒ 必须 mDNS |

## 后果

**好的**

- 他**有一个能打开的地址**（mDNS 稳定），且"看进度／看历史／看红绿"是同一个页面。
- 账只有一处：GitHub 只出信号 ⇒ 不会再出现"两边各做一半"。
- 阻断腿**快而硬**（p50 9 秒、平台强制 required check）；慢的证明放深度腿，不拖累合入。
- "能不能跑"有了固定出口（集成验证面 ⇒ 红绿表），而不是最后才发现跑不动。

**坏的／要长期承担的**

- **两仓 + 两腿 = 两条链要维护**：镜像同步（单向快进）、身份（deploy key/GitHub App）、每日对账都要有人管。
- **平台层配置（`app.ini`）不在仓内** ⇒ 它的正确性靠人执行，不靠门禁 ⇒ 需一次执行 + 一次验收（并纳入每日对账）。
- **存量 GitHub 347 件要人工逐件判**（已覆盖／仍要做／不再做）—— 这是不可避免的人力成本。
- **阻断腿依赖 Mac 常开**：自托管 runner ⇒ Mac 睡了就不能合（CTO 已点明）；需在"Mac 休眠策略"或"runner 常开"上给一个工程解，否则会退化成"绕过门禁"。
- **H 类史料只能"加注不能改"** ⇒ 文档里会长期保留旧 IP（读者需读括注）。

**已知限制**

1. **Win 侧 mDNS 未实测**（本会话只有 Mac）。
2. `app.ini` 改动需重启 Gitea（约 10 秒不可用），且不在本包写集。
3. **已定因**：Gitea API 的 `html_url`/`clone_url` **随请求 Host**（三 Host 实测一致规律），不是读 `ROOT_URL`；UI 用相对链接。\n   仍未实测：邮件通知／webhook／OAuth 回调这三处是否写死 `ROOT_URL` ⇒ 改配置时一并验。
4. 深度腿 job 数：最近一次 main run 实体 14（Windows 2 skipped），触发 Windows 时 16 —— 不写死"15"。
5. 两仓 sha 差 = 0 目前**无人自动报警**（靠人查）⇒ 后续须补"每日校验 ＋ 不一致停同步"。
