# 体系总蓝图 v3（通盘设计）— 从"门禁治理"升级为"整个研发体系"

> 日期 2026-10-28 晚 ｜ 事实基准：`gitea/local-main = b8edf9860` 实测（不采信文档自述）
> 起因：创始人指出两条根因 —— ① 历史门禁 = 历史错误的映射；② **膨胀根源是"非技术创始人要安心"**。
> 本件回答三问：**V2 够不够？其他要不要全清？整个体系怎么通盘建？**

---

## 零、三问三答（先给结论）

### Q1：`门禁体系最终方案-V2` 够不够？满足了没有？

**必要但不充分。V2 只覆盖了 5 层里的第 3 层（治理层），而且它自己内部还缺 4 件，目前连 V2 自身都不成立。**

| 判定 | 依据（今晚实测） |
|---|---|
| V2 的**定位正确** | 三分类（P0永退/P1依数据退/P2取消）、强制力在服务端、能机器判定不人工举证 —— 方向对 |
| V2 **未达成** | 总闸 `verify-governance.sh` **文件缺失**；W6 三态归一 **pre-commit/CI 调用均 0**；W8 双预算未实施；W9 分支保护未完成 |
| V2 **覆盖不足** | 它只管"门禁自己怎么活"，不管：代码怎么生出来（源头层）、创始人怎么安心（呈现层）、DSH 品味怎么沉淀（学习层）、Gitea/GitHub 怎么分工 |

> 一句话：**V2 是"门禁的宪法"，但一个国家还需要民法典（模板）、政府（CI）、媒体（呈现）、教育（学习）。**

### Q2：其他的是不是要全部清除掉？

**不能全清，也不能不清。**

- ❌ **不能全清**：里面有 P0 安全判定（权限/跨企业隔离/Secrets/fail-closed）。全清 = 不可逆的安全敞口。且未建账就删，会删掉活件。
- ❌ **不能不清**：40 入册判据 + 29 probe + 18 根级 check + 16 CI 步 + 12 GH job + 190 测试件，**至今 `retired` = 0 条**（实测），零退役 = 只增不减。
- ✅ **正确做法**：先建账（`run_by`）→ 设**配额硬上限** → 按双轴标准分批退役（P2→P1→P0）。

### Q3：你点出的根源（创始人要安心）怎么解？

**解法不是多建门，是把"安心的来源"从 40 道门换成 1 个可信信号 + 1 个翻译层。**

- 旧逻辑：出一次事故 → 加一道门 → 创始人多一份安心 → 门越来越多。
- 新逻辑：**信号可信 ⇒ 单道门失去政治理由 ⇒ 才退得掉。**

所以"退役 ≥ 新增"要真正落地，前提是**先把总闸和防假绿三件套建成**——否则一退役，你的安心就没了着落，下次事故又会加回来。

## 一、五层体系蓝图（通盘）

```
┌─ L5 学习层  DSH 纪律/工程规范/代码品味 → 显性化、可迁移 ─────────┐
│     （把别人的好，翻译成我们的默认；不是抄代码，是抄品味）          │
├─ L4 呈现层  我的角色 + 周报 + 单一仪表盘 ────────────────────────┤
│     （创始人只读 1 个数 + 我的人话解读 + 标红风险）                │
├─ L3 治理层  W1–W10 + 总闸 verify-governance.sh ─────────────────┤
│     （身份/证据/诚实/成本/强制 —— 管住所有门，含它自己）           │
├─ L2 判定层  门禁本体：Gitea 权威腿 + GitHub 镜像腿 ──────────────┤
│     （做错了拦住；权威腿唯一判定权，镜像腿无独立阻断权）            │
├─ L1 源头层  系统提示词 / Skills / 模板 / 脚手架 ─────────────────┤
│     （生下来就对 —— 成本最低的合规，不做门禁，做默认）             │
└─────────────────────────────────────────────────────────────────┘
```

### L1 源头层（系统提示词 / Skill / 模板 / 脚手架）
| 项 | 现状 | 动作 |
|---|---|---|
| 模板 + 脚手架 | ✅ **真上线**（`templates/code` 3 件含三段契约、`new-file.sh`、`pnpm new` 别名） | 补核：三段契约兜底是否真接进 pre-commit（待 DSH 澄清） |
| 系统提示词 | ⚠️ 分散（`.claude`/`codex`/`codebuddy` 各自守则） | **统一收敛**：一份"工程纪律宪法"，其余引用它，禁各自为政 |
| Skills | ⚠️ 存在但无准入 | 建 **skill 准入**：新增 skill 须有 owner + 触发条件 + 反例，纳入配额 |
| 取证口径 | ⚠️ 之前分歧（console.log 计数口径不一） | 建 `evidence-collect` 统一取证技能 —— **一条口径，全体系复用** |

> **核心原则**：L1 是"不建门禁的合规"。能在源头默认对的，绝不在事后建门拦。

## 二、Gitea / GitHub 分工（明确，不再含糊）

| 平台 | 角色 | 判定权 | 现状问题 | 动作 |
|---|---|---|---|---|
| **Gitea**（内网 192.168.1.6） | **权威腿 / 真源** | ✅ **唯一判定权** | `default_branch` 仍指 `audit/k3-20260904-line1-desktop` | 迁回 `local-main`（admin） |
| **GitHub**（公开镜像） | **镜像腿**（集成 + 跨平台兼容性） | ❌ **无独立阻断权（✅ 2026-10-28 已批准）** | `ci.yml` 仅 `branches:[main]` ⇒ **哑腿**；ruleset 有 8 个 required context 却不触发 | ① **去判定权**（只报不阻断）；② 同步清理/降级 ruleset 的 8 个 required context，**禁留"名义 required、实际哑"** |

> **原则**：**一条权威腿 + 一条镜像腿，镜像腿不许有独立判定权。**
> 双重判定 = 双份成本 + 双份误伤，正是"应付门禁"的来源之一。

## 三、L3 治理层：V2 的 4 件硬缺口（必须补齐，否则体系不成立）

| 缺口 | 为什么它是命门 | 优先级 |
|---|---|---|
| **总闸 `verify-governance.sh`（G1–G10）** | 没有它，**没人能用一条命令回答"体系是否成立"**，安心只能靠口头汇报 ⇒ 膨胀根源复发 | **P0 第一** |
| **W6 三态归一接线** | `gate-assert.sh` 存在但 pre-commit/CI **调用均 0** ⇒ "128 不当 0、判不了归 2"在 40 判据里**一个都没生效** ⇒ **防假绿防线今天就是漏的** | **P0 第二** |
| **W8 双预算（刹车）** | 体系只加不限速；无耗时/举证成本上限 ⇒ 必然回归 122s→`--no-verify` 的老路 | P1 |
| **W9 分支保护** | 平台不拦 ⇒ 所有"绿"仍靠自觉 | P1（需你/CTO admin） |

> ⚠️ **重点提醒你**：W6 没接线这件事，意味着**你现在的"安心信号"本身可能掺假**（假绿无法被自动识别）。
> 在 W6 接上之前，任何"门禁全绿"的汇报我都会标注 **"诚实层未接线"** 字样。

## 四、L4 呈现层：你作为非技术创始人的**防线**（三件事）

这是我这一层要解决的核心 —— 你不需要读 40 个判据，只需要三样东西：

| 防线 | 内容 | 现状 |
|---|---|---|
| **① 单一可信信号** | 总闸输出 `x/y PASS` + `head_sha`。我每周只报这一个数 + 红在哪 + 为什么 | ❌ 总闸未建 |
| **② 信号不可伪造** | 防假绿三件套：**W4**（skipped/0测试不算过）+ **W6**（判不了归 2、128 不当 0）+ **W5**（旧树不许宣布通过） | ⚠️ **W6 未接线 ⇒ 此防线有洞** |
| **③ 变更对你可见** | 任何门禁**新增/退役/豁免**必须进周报；**P0 变更需你知会**；任何"通过"结论必须带 `head_sha` | ⚠️ 周报有，P0 知会未制度化 |

**我的角色定位（写死，避免漂移）**：
- ✅ **做**：独立核验（回仓库实测，**不采信任何文档自述**）· 翻译成人话 + 英文术语 · 盯单一信号 · 守"退役≥新增"配额 · 标红风险
- ❌ **不做**：不替你做技术决策 · 不替实施侧写代码 · 不把"未核实"说成"已通过"

## 五、L5 学习层：吸收 DSH 的纪律 / 工程规范 / 代码品味

你说得对：**DSH 源码就在我们开发机里，深浅不同地借鉴过，所以学它的纪律是必须的。**

| 学什么 | 怎么沉淀（进哪一层） |
|---|---|
| **代码纪律**（契约三段、三态退出码、禁静默降级） | → 写进**系统提示词 + 模板**（L1），让 AI 生出来就带 |
| **工程规范**（fail-closed、判不了归 2、不骗过判据） | → 固化成 **W6 + 总闸 G6**（L3），机器化 |
| **代码品味**（头注≤12行、不留 TBD、已知限制写脸上） | → 固化进**模板 + skill 准入**（L1） |
| **借鉴的模块** | → 逐模块登记"借鉴深度"（直接引用/改写/自研），进你的积木墙台账 |

> **关键区分**：学的是**纪律与品味**（可迁移、可机器化），不是抄代码。
> 借鉴深浅必须登记 —— 否则将来分不清哪些是自己的、哪些是借的，是法律与技术双重隐患。

## 七、收口顺序（建议）

1. **建总闸**（G1–G10）—— 安心的落点，第一优先
2. **接 W6** —— 补上防假绿漏洞（**否则前两步的信号不可信**）
3. **W1/W2 进 CI 硬腿**（或明确声明只做观测）
4. **落 W8 刹车 + W9 分支保护**（W9 需你/CTO admin）
5. **做减法**：`run_by` 建账 → 配额制 → 首批退役 P2/死件
6. **收敛系统提示词 + skill 准入 + evidence-collect 统一口径**（L1）
7. **Gitea/GitHub 分工落定**：`default_branch` 迁回 `local-main`；镜像腿去判定权并预演
8. **建 L5 学习层**：DSH 纪律沉淀 + 借鉴深度台账

> **贯穿原则**：每新增一道门，必须先退掉或合并掉一道。**先建账，再动刀。**
