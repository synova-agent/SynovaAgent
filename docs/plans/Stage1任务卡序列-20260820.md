```text
## Q0: 定位 — 借鉴 DSH 事件溯源范式，改造 Synova 会话存储
### a) 项目拼图
施工图 §4 能力映射第 1 行 + §5.3 自进化 E2 前置。补 C 线 S3-5（自诊断可信度）/ S0（信任建立）根因：
没有可回放的真相流。现状 SessionStore 是普通存储（src/store/session-store.ts:57 export class SessionStore，实证）。
### b) 文件审计
主要改动面：src/store/session-store.ts（658 LOC 目录）；消费方：ConversationEngine（src/agent/conversation-engine.ts）。
### c) 决策
借鉴理念自研，不引 DSH 代码。消费方接口不变（capability seam 思想：能力可换、消费方不动）。

## Q1: 调研 — 历史教训
a) 业界：DSH core/session（append-only SessionEvent log + deriveMessages 投影 + model-visible⟺logged 不变量，证据 H-05）。
b) 我们犯过的错：4 次接线失败——新机制必须从生产入口可触达；铁律 11 静默降级禁止。

## Q2: 范围 — 正确的最简方案
做什么：SessionStore 增加 append-only 事件流 + deriveMessages() 投影 + model-visible⟺logged 运行时断言。
不做什么：不动 ConversationEngine 对外接口；不动 routes/；不做 UI 回放视图（Trajectory 留到后续）；不引 dsh 包。

## Q3: 验收 — 入口 → 交互 → 结果
入口：生产链路 src/index.ts → SynovaAgent → 一次真实对话/诊断。
处理：会话全程事件落 log；kill 进程后从 log 重建模型消息历史。
结果：① 回放重建的消息历史与实际一致（测试断言）② model-visible 输入未落 log 时断言报警 ③ 集成测试走真实路由
契约：输入=会话事件流；输出=消息历史投影；降级=log 写入失败 → log.error + degraded: true（铁律 24/31）
测试：正常路径 + 降级路径 + 边界（空 log/半截事件）（铁律 48，非空壳）

## 架构层: L5（src/store/）→ 消费方 L2
## Done 标准: 回放一致 + 断言生效 + 集成测试真实路由 + 生产入口可触达 + pre-commit 全绿
```
