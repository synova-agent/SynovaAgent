## 背景：我们为什么会讨论这个问题

### 触发点

在Synova本体层v2.4的设计过程中，我们完成了一套覆盖16条因果边、10个实体、产业时钟、GPI增长潜力指数、三阶推理引擎的完整诊断体系。这套体系能够精准回答两个问题：

- "企业为什么增长停止了？"（7条防御边 + 7条增长动力边 + 2条横切边）
- "在当前的产业相位下，企业应该选哪条路？"（三阶推理引擎的三种战略原型——治疗/转换/跳跃）

但在一次讨论中，有人提出了一个看似简单却极其深刻的问题：

**"当所有人觉得电商没有机会的时候，拼多多杀出来了。当所有人觉得家电没有机会的时候，追觅杀出来了。当所有人觉得汽车没有机会的时候，特斯拉杀出来了。历史上类似的事情还有很多。我们的体系如何解释这类事务？"**

这个问题的背后，是一个更深层的追问：**当全世界的经验都指向"不可能"时，Synova凭什么能捕捉到那个"可能"？**

如果我们承认——且我们必须承认——商业史上充满了"非共识的成功"，那么一套宣称能诊断企业增长的体系，如果无法识别"非共识机会"，它就是残缺的。它只是一个"企业健康体检仪"，不是一个"范式转移探测器"。

### 为什么现有的理论工具不够用

我们首先考察了现有的理论工具：

| 理论工具 | 它能解释什么 | 它不能解释什么 |
|---------|------------|--------------|
| 颠覆性创新（克里斯坦森） | 为什么新进入者能击败现有者 | 无法判断"现在是那个时刻吗"——它只是事后描述 |
| 创造性破坏（熊彼特） | 为什么旧技术被新技术取代 | 无法区分"真颠覆"和"伪颠覆" |
| 技术-经济范式（佩雷斯） | 为什么某些时期会出现密集的创新浪潮 | 无法精确定位"这个具体的机会在哪里" |
| 产业生命周期 | 为什么产业会经历导入/成长/成熟/衰退 | 无法解释"为什么在衰退期还能杀出颠覆者" |
| 我们自己的三阶推理引擎 | 在给定的产业相位下选择最优战略路径 | 无法回答"如果存在一个被共识忽视的机会，它应该长什么样" |

**结论：这些理论都是"事后解释框架"，不是"事前判断工具"。** 它们能告诉你"为什么特斯拉成功了"，但不能在2010年告诉你"特斯拉可能是对的"。它们能告诉你"为什么柯达失败了"，但不能在2003年告诉柯达"你内部的某个信号正在被组织免疫系统过滤掉"。

我们需要一个可计算的、可嵌入本体的判断机制，让Synova能够在"共识认为没机会"的时刻，识别出"结构上可能存在机会"的信号。

### 我们怎么思考这个问题的

**第一步：定义"非共识"的物理本质。**

首先必须区分"非共识"和"反叛"——多数人反对少数人不叫非共识，那只是观点的对立。非共识的底层逻辑是：**主流共识基于"旧价值网络"的锚点，严重低估了一个"新价值网络"的潜在规模，因为该新网络的底层成本函数、用户行为、资产性质已经发生了不可逆的断裂式变化。**

用更精炼的话说：**非共识 = 主流共识的预测模型与底层物理现实之间的结构性脱节。**

三个经典案例验证这个定义：

| 案例 | 主流共识的盲区（旧锚点） | 非共识的底层物理现实（新锚点） |
|------|----------------------|---------------------------|
| 拼多多 | 认为"微信生态做电商质量低、不可能做大" | 微信流量边际获客成本趋近于零，"非标品+农产品"不受传统比价电商规则限制 |
| 特斯拉 | 认为"电动车续航短、充电难、永远是小众" | 电池成本年均下降18%（学习曲线远超燃油车），软件定义汽车重新定义了成本分摊 |
| 追觅 | 认为"戴森技术壁垒不可逾越，高速电机中国造不出来" | 中国供应链+算法能力让高速电机从奢侈品变成工业品，成本结构被彻底打碎 |

**第二步：推导出三个必要条件。**

通过对上述案例的交叉分析，任何一个"真非共识"都必须同时满足三个条件：

1. **认知偏离：** 主流共识的预期值与基于新技术的物理极限值之间存在显著差距（>2σ）。这确保了"这件事别人不看好"。
2. **成本断裂：** 新路线的成本函数不延续旧路线，而是出现了"架构级"的跃迁——不是优化，是重写。这确保了"这件事不是烧钱伪颠覆，而是有真实的经济基础"。
3. **价值网络错配：** 某种资产在旧系统中被视为"垃圾"或"负资产"，但在新系统中被视为"核心资产"。这确保了"这件事能重构产业格局，而非线性改进"。

三者缺一不可。缺少认知偏离，就是共识性机会（人人看得到，轮不到你）。缺少成本断裂，就是伪颠覆（烧钱换增长，不可持续——OFO是典型）。缺少价值网络错配，就是线性改进（无法重构产业格局）。

**第三步：确定"我们能做到什么，做不到什么"。**

NCI不是"占卜术"。它无法告诉你"下一个拼多多是谁"。它能做的是三件事：

- 识别"企业内部被组织免疫系统过滤掉的信号"。会议中提出的想法、一线反馈中的需求、老板随口一提的方向——这些信号在大多数企业里活不过一个月。Synova驻扎在企业内部，它能捕捉到这些信号、追踪它们的生命周期、检测它们是否被系统性地压制。
- 计算"这些信号和物理现实之间的结构性差距"。企业当前的成本结构 vs 新方向可能达到的成本结构。企业当前的资产估值 vs 新系统中该资产的估值。这些是企业自身的数据可以回答的——不需要外部研报。
- 输出一个结构化的判断："你的组织正在过滤掉一个至少值得认真讨论的可能。"不是"你应该立刻投入重注"——是"你应该至少把它从被忽略的状态中拉回来，重新审视"。

### 为什么选择这个工程方案

**不新增边、不新增实体。** NCI使用现有的16条因果边+10个实体。SENSING采集信号，SIGNAL_TRANSMITS检测信号是否被过滤，CUMULATIVE_LEARNING检测成本是否发生架构级断裂，ASSET_LOCKS检测资产在新旧系统中的估值差异，ASYMMETRIC_DEPENDENCY检测价值网络的错配。NCI只是把这些边的计算结果按一种新的组合方式重新组织——回答了"共识和现实的差距有多大"这个新问题。

**不依赖外部研报。** 认知偏离度不从券商研报获取"主流共识"——直接使用企业自身的行为数据。销售团队80%的时间投在旧渠道上、研发预算90%投向旧产品线的迭代——这些就是"组织共识"的最诚实表达。不需要外部分析师告诉你"行业怎么看"——企业自己的资源配置已经告诉了你最诚实的答案。

**分Phase递进，每分钟都有价值。** Phase 0先建管道——让Signal能被采集。即使NCI计算引擎还没上线，GA已经可以看到"过去30天内有哪些非共识信号被提出了"。Phase 1加上追踪——可以看到"哪些信号被提出了但从未被讨论"。Phase 2加上引擎——可以计算"这些信号和物理现实的差距有多大"。不是在最后一步才有价值——每一步都有独立的诊断价值。

### 预期达到的结果

**定性结果：**

- Synova不再是"企业健康体检仪"——它能检测到"组织免疫系统正在压制一个可能有价值的非共识信号"。
- 客户A的"年卡方案被提出但被忽略"这种事件，在Synova驻扎后可以被捕捉、追踪、在合适的时机重新激活。
- 对外宣传时，Synova可以说："我们不预测下一个拼多多。但我们确保你企业内部出现的'拼多多式想法'不会在无人察觉的情况下被组织免疫系统杀死。"

**定量目标：**

- Signal采集管道上线后，正常企业每天产生<50条Signal（不过度噪音）。
- 沉默检测：信号被提出后90天未被任何正式流程引用→自动触发警报。
- 重复沉默：同类型信号在12个月内≥3次被沉默→触发"系统性认知盲区"警报。
- NCI计算：Phase 2上线后，对已回测的案例（拼多多2015/特斯拉2010/追觅2018）的NCI得分≥70。

**诚实边界：**

NCI不适用于"全新型"的非共识——即没有任何历史数据、没有任何可比参照物的方向。对于这类信号，NCI只能标记为"待验证"，并告诉企业："这个方向无法量化评估。如果你选择探索，建议分配不超过X%的资源，并在Y个月内收集足够的数据以重新评估。"

## 1. Phase 0：Signal 实体与采集管道（5天）

### 1.1 Signal 实体设计

Signal 是一个轻量级的事件载体，存储在L4本体层。它不是10个核心实体之一——它是10实体的辅助观察层。

```typescript
interface Signal {
  id: string;
  source: 'im_message' | 'meeting_note' | 'ga_conversation' | 'sales_feedback' | 'founder_remark';
  content: string;           // 原始内容（文本摘要）
  key_themes: string[];      // LLM提取的关键主题标签
  involves_cost_structure: boolean;  // 是否涉及成本结构的讨论
  involves_new_business_model: boolean; // 是否涉及新商业模式的讨论
  contradicts_consensus: boolean;  // LLM判断：是否与当前企业的资源配置方向不一致
  timestamp: string;
  author_id?: string;        // 谁提出的（PERSON节点ID）
  related_activity_ids?: string[]; // 涉及的业务活动（Activity节点ID）
  lifecycle_stage: 'raw' | 'first_mentioned' | 'discussed' | 'budgeted' | 'adopted' | 'abandoned' | 'silenced';
  last_referenced_at: string;
  reference_count: number;
}
```

### 1.2 三条采集管道的具体实现

#### 管道A：IM信号采集（复用 src/routes/im.ts）

当前 im.ts 已有飞书/钉钉消息接收。扩展它的处理逻辑：

```
IM消息 → Webhook → im.ts 接收
  → LLM轻量分类（一个prompt，<200 tokens输出）：
    1. 这条消息是否涉及"成本结构"、"商业模式"、"新市场"的讨论？
    2. 消息中提出的方向是否与当前企业的OKR/资源配置方向不一致？
    3. 提取1-3个关键主题标签
  → 如果 (involves_cost_structure OR involves_new_business_model) AND contradicts_consensus:
    → 创建Signal节点，挂载到SENSING实体
    → lifecycle_stage = 'raw'
  → 否则：忽略（不创建Signal）
```

**LLM消耗：** 每条消息一个轻量分类prompt，预计每次调用<500 tokens。按每天500条消息、其中10%需要分类计算，每天约50次LLM调用。成本可控。

#### 管道B：会议纪要解析（新建）

不是所有企业都有结构化的会议纪要。最低可行方案：

```
会议纪要（飞书文档/钉钉文档/上传的文本文件）
  → 周期：每周解析一次（或GA手动触发）
  → LLM提取：
    1. 本次会议中提出的所有"新想法"或"新方向"
    2. 每个想法是否被讨论？是否有后续行动人？
    3. 本次会议和上次会议之间，有哪些之前提出但本次未被提及的主题？
  → 创建Signal节点：新出现的想法（lifecycle='first_mentioned'）
  → 更新已有Signal：之前提出但本次未提及的 → reference_count不加、last_referenced_at不更新（沉默累计）
```

#### 管道C：GA对话与企业主输入（新建）

GA和企业主的直接对话是最高质量的信号源。不需要LLM——GA可以直接标记：

```
GA在Synova对话中识别到一个"非共识想法"
  → GA手动调用: /signal/create { content, themes, contradicts_consensus }
  → 创建Signal节点（lifecycle='raw'）
  → GA标记此信号的重要性级别（1-5）
```

企业主也可以直接和Synova对话："我有个想法，我们能不能...？" → Synova自动识别并创建Signal节点。

### 1.3 Phase 0 验收标准

- 三条采集管道均可运行
- 每条管道产生Signal节点存储在L4本体层
- Signal节点挂载到SENSING实体（Signal作为SENSING的关联实体）
- LLM分类的准确率（GA人工抽查20条）：误判率<20%
- 每天产生的Signal数量：正常企业<50条（不会噪音泛滥）

## 2. Phase 1：信号生命周期追踪与沉默检测（3天）

### 2.1 信号生命周期追踪

Signal节点创建后，系统必须持续追踪它的"存活状态"。不是被动等待——是主动在每个周期扫描：

```
每周：
  1. 对所有 lifecycle_stage != 'adopted' AND lifecycle_stage != 'abandoned' 的Signal：
     - 扫描最近一周的会议纪要，检查该Signal的key_themes是否被提及
     - 扫描OKR/Goal的变化，检查是否新增了与该Signal相关的目标
     - 扫描预算分配的变化，检查是否有资源流向该Signal相关的Activity
     
  2. 更新 Signal.reference_count 和 Signal.last_referenced_at
  
  3. 判定生命周期阶段：
     - 7天内被提及 → lifecycle = 'discussed'
     - 30天内被提及+有预算分配 → lifecycle = 'budgeted'
     - 实际产生了新的Activity → lifecycle = 'adopted'
     - 90天未被任何正式流程提及 → lifecycle = 'silenced'
```

### 2.2 沉默触发器

当 Signal.lifecycle_stage = 'silenced' 时：

```
1. 检查这个Signal contradicts_consensus = true？
   → 是：触发"非共识信号沉默"警报（路由到strategy+org专家）
   → 否：标记为"自然淘汰"（正常——不是所有想法都值得追）

2. 如果这个Signal的 importance_level (GA标记) >= 4 且被沉默：
   → 触发"高价值非共识信号被组织免疫系统压制"警报
   → 自动检查同一时期被采纳的信号主题，对比差异模式

3. 如果同一类key_themes的信号在12个月内反复出现、反复被沉默：
   → 触发"系统性认知盲区"警报
   → 这不是单个信号被忽略——是组织对某个方向的信号有系统性免疫
```

### 2.3 Phase 1 验收标准

- 信号生命周期追踪每周自动执行
- 沉默触发器：信号被90天未引用时自动触发
- 重复沉默检测：同类信号12个月内≥3次被沉默时触发
- 延迟：从信号被标记为silenced到警报触发<24小时

## 3. Phase 2：NCI计算引擎（4天）

### 3.1 NCI的三层计算（重新设计——不依赖外部研报）

#### 维度一：认知偏离度（40%）

不再依赖券商研报。直接从企业自身的行为数据计算：

```
认知偏离度 = 组合计算：
  
  组件A (40%权重)：信号与资源配置的矛盾度
    计算：被沉默的Signal中，contradicts_consensus=true的比例
    数据源：Signal节点的生命周期数据
  
  组件B (35%权重)：企业效率曲线与物理极限的差距
    计算：CUMULATIVE_LEARNING边上的learning_rate vs ExternalBaseline的行业最佳学习率
    数据源：CUMULATIVE_LEARNING边 + ExternalBaseline实体
  
  组件C (25%权重)：外部先行者的存在性
    计算：AdversarialFrame中是否有竞争对手在类似方向上已有投入
    数据源：AdversarialFrame实体（GA手动维护或公开数据采集）
```

#### 维度二：成本断裂度（35%）

```
成本断裂度 = 组合计算：

  组件A (60%权重)：新路线的实际/估算单位成本 vs 旧路线的当前单位成本
    计算：如果Signal涉及具体的新技术/新模式，从CUMULATIVE_LEARNING边读取新旧路线的learning_rate差异
    如果learning_rate新 > learning_rate旧 × 2 → 成本断裂信号
    如果Signal没有具体数据（只是一个想法）→ 标记为"待验证"，成本断裂度=0
  
  组件B (40%权重)：成本下降的"突变性"
    计算：Pettitt突变点检测——新旧路线的成本序列是否存在统计显著的断点
    存在断点 → 架构级跃迁
    不存在断点 → 线性改进
```

#### 维度三：价值网络错配度（25%）

```
价值网络错配度 = 组合计算：

  组件A (50%权重)：资产在新旧系统中的估值差异
    计算：ASSET_LOCKS边上的asset_second_life_ratio
    如果某项资产在旧系统中的second_life_ratio < 0.2，但在新系统中 > 0.5 → 错配信号
    
  组件B (50%权重)：主流玩家与挑战者的配置权重差异
    计算：AdversarialFrame中主流玩家降低某类资产配置 vs 本企业提高配置
    差异 > 50% → 错配信号
```

### 3.2 NCI综合得分

```
NCI = 0.4 × 认知偏离度 + 0.35 × 成本断裂度 + 0.25 × 价值网络错配度

分类：
  NCI >= 70: 高非共识 — 推荐建立专门探索团队，投入不超过现金跑道的15%
  40-69: 中非共识 — 推荐小规模验证（<5%现金跑道），3个月后重新评估
  < 40: 低非共识 — 当前为共识性机会或数据不足以支撑判断
```

### 3.3 四层防御（与三阶推理引擎集成）

NCI得分再高，也需要通过四层防御才能进入最终推荐：

1. **数据支撑检查：** Signal是否有任何可量化的数据支持？无数据 → NCI降级为"待验证"。
2. **成本断裂真实性：** 单位成本下降是否结构性（learning_rate突变）vs 规模效应（产量增加自然下降）？
3. **生存底线检查：** 如果这个想法需要企业投入超过现金跑道的X% → NCI自动降低优先级。X根据企业规模阶段自动调整（小企业=10%，中型=5%，大型=3%）。
4. **三阶推理引擎冲突仲裁：**
   - 三阶推理引擎的推荐方向（治疗/转换/跳跃）和NCI的推荐方向是否冲突？
   - 如果冲突：根据E_m（执行动量）和S_r（结构冗余度）判断企业是否有余力同时处理两件事
   - 如果E_m < 0.3 且 S_r < 0.3：优先三阶推理引擎的推荐。NCI标记为"延后评估"。
   - 如果E_m > 0.5 或 S_r > 0.5：输出"NCI和三阶推理引擎的建议可以并行——建议分配一小部分资源探索NCI指出的方向"。

### 3.4 Phase 2 验收标准

- NCI三个维度均可独立计算（即使某个维度因数据不足返回0也不阻塞流程）
- NCI综合得分可计算
- 四层防御全部通过后才能进入最终诊断报告
- 与三阶推理引擎的冲突仲裁逻辑可运行

## 专家修正附录：六项修正（v1.0 -> v1.1）

### 修正一：认知偏离度的双因子张力模型

原方案：认知偏离度仅检测信号是否与企业内部资源配置方向不一致。

问题：2010年的特斯拉，内部极度一致（all-in电动车），外部极度看空。按原方案会给出低NCI得分。

修正：NCI的认知偏离度 = 内部共识强度 x 外部共识逆强度。内部共识从企业资源配置方向提取，外部共识从AdversarialFrame + ExternalBaseline提取。只有当内部极度看多、外部极度看空时，NCI认知偏离度才达到峰值。

### 修正二：僵尸信号检测

原方案：90天未被引用定义为沉默。

问题：哇呢的年卡方案可能被频繁讨论但从未有预算分配——只说不做的僵尸状态。

修正：增加决策-行动比监控。reference_count > 5 但 resource_allocation_delta = 0 -> 触发决策瘫痪警报，而非沉默警报。

### 修正三：第一性原理断层扫描

原方案：Signal没有具体数据时，成本断裂度=0。

问题：真正的非共识恰恰发生在没有历史数据的地方。拼多多2015年没有社交电商成本曲线数据。

修正：当成本断裂度因数据缺失无法计算时，不归零——触发第一性原理断层扫描。基于物理/经济下限计算理论最小成本。如果理论下限 < 当前行业成本 x 0.3 -> 直接赋值70分，标记为第一性原理级非共识。

### 修正四：规模-风险弹性系数

原方案：所有企业统一适用投入不超过现金跑道的X%。

问题：用大企业的风控逻辑套创业公司。

修正：员工<20人取消硬性上限，改为可行性实验设计。员工20-100人动态上限。员工>100人维持10-15%上限。

### 修正五：GA驳回机制

原方案：LLM判断contradicts_consensus。误判会反复触发警报。

修正：GA可手动标记某个Signal为低质量想法。后续来自同一提出者或同一类内容的信号，NCI自动降权（权重x0.3）。

### 修正六：背水一战模式

原方案：生存底线检查统一适用。

修正：增加背水一战触发条件——现金跑道<6个月 AND NCI>=70 AND 三阶推理引擎推荐ROI<1。触发时系统不设上限，输出死亡概率和非共识机会不对称回报率的对比。

### 修正后的验证标准

- 双因子张力模型：特斯拉2010模拟数据——内部一致+外部看空->NCI>=70
- 僵尸信号检测：哇呢年卡方案——多次讨论、无预算->触发决策瘫痪
- 第一性原理断层：拼多多2015模拟数据——无历史曲线->第一性原理计算->NCI>=70
- 规模弹性：5人公司和500人公司同一信号——上限建议显著不同
- GA驳回：手动标记低质量想法->同一提出者后续信号NCI降权
- 背水一战：现金跑道<6月+NCI>=70+治疗ROI<1->不设上限
