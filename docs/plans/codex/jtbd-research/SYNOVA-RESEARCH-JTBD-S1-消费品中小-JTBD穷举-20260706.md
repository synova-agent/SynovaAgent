> 数据环境：电商后台+聚水潭ERP+金蝶财务+有赞私域+钉钉+Excel。

---

## 研究说明

本文件穷举场景1下中层管理者需要完成的所有决策型JTBD。JTBD不按角色分——先穷举所有中层需要完成的决策，再标注哪些角色执行它。

**核心句式**：我需要[做什么决策]，但我不确定[什么信息]。

**关键约束**：
- 决策动词优先——"分析/了解/掌握"不是JTBD
- 聚焦中层频率最高的决策场景——非仅战略级/老板级
- 不预设数量上限

**标注字段说明**：

| 字段 | 含义 |
|------|------|
| **JTBD类型** | 预测型 / 诊断型 / 干预型 |
| **执行角色** | 哪些中层角色执行此JTBD |
| **频率** | 实时 / 每日 / 每周 / 每月 / 每季度 |
| **重要性** | 1-5（5=决策错误会导致重大损失） |
| **中层可控性** | 0=无权改变 / 1=可影响 / 2=可调整 / 3=可直接决策 |
| **可行动性** | 知道信息后，中层能做什么具体动作 |
| **数据可得性** | 自动可得 / 需GA手工采集 / 需企业补充数据 |

## 研究过程说明

1. **穷举起点**：从客户A中层管理者每天/每周/每月"实际在做什么决策"出发，而非从"数据盲区"出发。
2. **覆盖范围**：覆盖了11个决策域——电商运营、品牌市场、产品、渠道、生产供应链、财务、人力资源、客服体验、跨角色协同、第二曲线探索、数据基础设施。
3. **角色覆盖**：8个中层角色全部覆盖，电商运营经理和财务负责人因"线上渠道为主+数据整合中枢"的角色特征，参与的JTBD最多。
4. **盲区验证**：每个JTBD的信息缺口与场景基础画像中列出的5大盲区进行了印证。6个盲区对应类（单品利润/竞品/客户/产能/新业务/数据整合）均在JTBD中被拆解为具体的决策场景。
5. **未穷举说明**：以下JTBD类型有意识排除——纯粹的"汇报准备"（如"准备周报需要的数据"——不是决策型JTBD）、"信息检索"（如"查找某客户联系方式"——不是决策）、"流程审批"（如"审批请假"——信息完整无需判断）。
