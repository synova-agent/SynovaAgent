## 1. 我们在做什么（速读）

**SynovaAgent** = 组织数字孪生诊断 + 持续增长导航系统。
**核心问题**：这家企业的增长卡在哪里？现在该做什么？
**形态**：独立 Agent 进程（HTTP + MCP），驻扎企业，持续观测 → 主动发现 → 自动诊断 → 行动建议 → 跟踪执行。**不是 ChatBot**。

## 7. 组织：**三级制**（创始人裁定）

> 创始人原话：「之前所有任务都经过 CTO 这个节点……导致这个节点的任务非常多非常分散，容易导致上下文混乱、记忆稀释，很多问题就是 CTO 本身制造的……**CTO 只对线负责人说话，不对执行者说话。**」

```
创始人 → CTO → 线负责人 → 执行者
```

| 层 | 角色 | 职责 | 载体 |
|---|---|---|---|
| **人** | **创始人** | 方向／最终裁决／开线负责人会话 | —— |
| **第一层** | **CTO**（【Synova-主CTO】） | **只做四件事**：① 方向锚＋边界声明（每线每窗一件）② 跨线裁决（当日）③ 治理三件事（每日审计处置／周 bypass 对账／方向复盘）④ 线级周对账 | 常驻 session |
| **第二层** | **线负责人** | 本线域内**派单权**（写派单件／pre-dispatch／线内收件／接执行者回执） | **每线一个独立常驻 session**（由创始人开） |
| **第三层** | **执行者小队** | 执行 | **Agent Teams**（`spawnTeammate`） |

**「线」= 常驻建制（基座／治理／产品）＋ 战役（门禁线·文档线·积压线，挂线下做第一批工单）＋ 小队（执行者编制）**

⛔ **CTO 不做**：不写派单件／不做 pre-dispatch／不做线内收件／不接执行者回执／**不 spawn 线负责人**

**理由（有物理依据）**：subagent 默认派发深度受限 ⇒ CTO 的子代**派不动**两级小队；且一次性子代无 mailbox／无持久身份 ⇒ M3 型事故形态。
