核心命题

"这家企业的增长卡在哪里？现在该做什么？"

Synova 不是 ChatBot。它是驻扎在企业内部的 AI Agent——持续观测，主动发现，自动诊断，给出行动建议，追踪执行效果。它的产品形态是独立的 Agent 进程，通过 HTTP API + MCP 对外服务，不依赖任何前端或桌面端。

一、产品定位与愿景

1.1 Synova 是什么

Synova 是一个驻扎企业的 AI 诊断 Agent + 持续增长导航系统。它不是给老板生成一份 PDF 诊断报告然后离开——它驻扎在企业内部，持续观测企业的经营数据，主动发现异常，自动诊断根因，给出可执行的行动建议，追踪执行效果，并在执行偏离时自动调整。

Synova 的核心洞察来自一个第一性原理：企业是一个将输入资源（资本、人力、信息）通过一系列转化活动变为对外部更有价值的输出，并从输出中捕获价值回注到输入的正反馈循环系统。这个循环的净溢出，就是利润。企业增长停滞的根本原因，是这个循环在某个环节断裂——而 Synova 存在的全部意义，就是找到这个断裂点，并帮助修复它。

👔

企业老板 / CEO

使用频率：每月1-2次（诊断报告 + 溢出仪表盘）

核心需求："我的企业增长卡在哪里？应该往哪个方向投入？"

五、关键模块深度分析

5.1 本体层因果体系（42条边 + 15节点池）

定位：整个 Synova 大厦的地基。定义了企业增长的完整因果传导网络。

设计哲学：从第一性原理出发——企业是一个闭环价值循环系统，在五个位置可能断裂（获取/配置/转化/交付/回流）。每个断裂位置的每种断裂方式对应一条因果边。42条边不是"我们认为重要"的归纳——是"逻辑上只存在这几种断裂方式"的演绎推导。

四层分离：表达层（因果链，自然语言解释）→ 编排层（Playbook + Skill）→ 计算层（42条边 transfer_function）→ 存储层（15节点池 + GraphStore）。每层只与相邻层通信。

硬度测试：每条边标注参数覆盖率（≥80%参数有客户A数据支撑 → hard），确保工程团队知道哪些边可以直接实现为 compute 函数。

5.2 哨兵系统（50哨兵 + 61 compute）

定位：Synova 的"眼睛"——持续扫描企业的7个维度，检测异常信号。

设计哲学：哨兵不绑定特定专家。哨兵 Finding 不预设由谁解读——由主Agent（L2编排层）根据诊断上下文路由给合适的专家。每个哨兵定义它的 JTBD（要完成什么诊断任务）、消费的42边参数、调用的 compute 函数、严重度阈值。

方案级哨兵：增长导航系统中的 Goal 注册后自动创建方案级哨兵——追踪特定 Goal 的执行效果。方案级哨兵有独立的生命周期（Goal关闭→30天归档→60天物理删除），不污染全局哨兵阈值。

5.3 专家系统（8位专家 + 主Agent）

定位：Synova 的"大脑"——8位领域专家各自在自己的推理域内做 ReAct 推理 + 交叉验证，主Agent负责任务分解、专家路由、冲突仲裁和收敛合成。

专家推理域核心问题
战略专家竞争位势/市场定位/护城河"方向对不对？对手在哪？机会在哪？"
组织专家决策集中度/协作效率/人才密度"组织能不能执行增长战略？"
财务专家资本配置/成本结构/现金流"钱够不够？哪里漏了？增长有没有财务支撑？"
技术专家技术架构/系统可靠性/AI投资回报"用对工具了吗？技术在帮企业还是拖企业？"
营销专家客户获取/留存/定价/品牌"客户怎么看你？获客效率能更高吗？"
行动专家方案可行性/执行追踪/优先级排序"所有诊断不变PPT，变成谁该做什么"
商业模式专家收入结构/价值循环/利益相关者对⻬齐"你的商业模式本身有没有结构性缺陷？"
知识专家知识提取/模式识别/跨企业学习"从每次诊断中学到了什么？"

主Agent（L2编排层）：不是专家。是专家的调度者和仲裁者。负责任务分解（判断需要哪些专家）、专家路由（单专家80%/多专家20%）、冲突仲裁（基于证据强度，非投票）、收敛合成（综合所有专家结论生成统一诊断报告）、推理成本预算（轻量模型日常+深度模型关键诊断）。

5.4 增长导航系统

定位：Synova 的"手"——诊断报告的输出不是终点。将诊断建议转化为可执行 Goal，追踪执行过程，检测偏离，触发调整，闭环验证。

完整链路：诊断报告 → Proposal（三选一确认）→ Goal 注册 → 方案级哨兵自动注册 → 执行追踪 → 三因子偏离检测 → 轻量级再诊断 → 全量诊断升级 → Goal 闭环验证。

中层工作台：每天 3-10 次使用。activeGoals + 告警列表 + nextAction 智能推荐 + 免打扰规则引擎。

六、与传统咨询的对比

核心差异：从"给你一份报告"到"驻扎在你的企业里"

传统咨询是项目制——咨询顾问来企业做2-4周诊断，写一份报告，离开。老板看完报告，可能执行也可能不执行。三个月后报告过时了。Synova 不是项目制——它驻扎在企业里，每天都在看数据，自动发现异常，主动推送给老板和中层，追踪执行效果。它不是"给你一份报告"——是"成为你企业的一部分"。

维度传统咨询（麦肯锡/BCG模式）Synova
诊断频率一次性（2-4周项目）持续（快诊周级、中诊月级、全诊季度级）
数据覆盖面依赖顾问手动收集，覆盖有限42条因果边 × 50哨兵 × 61 compute 全面覆盖
诊断一致性与可复现性依赖顾问个人经验——同样的企业给两个顾问可能得出不同结论基于数学化的 transfer_function——同样的数据输入，同样的诊断输出
执行追踪无——报告交付即结束Goal注册→方案哨兵→偏离告警→轻量级再诊断→闭环验证
企业历史积累每次咨询从零开始PKB持续积累——企业的每次诊断、每次执行结果都在知识库中
专家经济学资深咨询顾问年薪200万+，能服务的客户数量有限AI专家7×24运行，边际成本趋零；GA（人类咨询顾问）借助Synova服务更多客户
成本一次诊断项目 30-300万年度订阅 5-50万（按企业规模分级）
中小企业可及性几乎不可及——费用远超预算核心目标客户——价格设计为中小企业可负担

七、市场竞争格局

7.1 竞争定位

竞争者定位与 Synova 的关系
传统咨询（麦肯锡/BCG）高端项目制咨询。客单价 100 万+。一次性交付。互补 大型企业仍需要战略级咨询。Synova 聚焦中小企业——这是传统咨询无法服务的长尾市场。GA 合作伙伴可以是咨询顾问——用 Synova 放大他们的服务能力。
Palantir Foundry企业数据集成平台。本体层建模+数据管道的工业级方案。异构同层 Palantir 解决了"数据集成"，但没有解决"因果推理"和"增长导航"。Synova 在 Palantir 的本体层之上增加了因果诊断和行动闭环。Palantir 服务的是政府和大企业，Synova 服务的是中小企业。
零一万物（Yi-Large等）大模型创业公司。可能从AI应用层切入企业服务。潜在竞争者 大模型公司可能增加企业管理功能。但 Synova 的壁垒不在AI本身——在 15份权威文档背后的领域知识（本体层+管理经济学+因果边推导+行业模板）。大模型可以快速复制一个对话界面，但无法快速复制覆盖七部门的因果诊断体系。
传统BI工具（Tableau/PowerBI）数据可视化。被动呈现数据，不主动发现问题。替代+互补 BI工具是"数据看板"，Synova 是"诊断+导航"。BI告诉你"销售额下降了15%"，Synova 告诉你"为什么下降了、该做什么、做了之后怎么追踪效果"。
ERP+管理软件（金蝶/用友）企业管理软件。管流程，不管诊断。互补 ERP 是 Synova 的数据源之一。Synova 消费ERP的数据做诊断。不是竞争关系。

7.2 Synova 的竞争壁垒

壁垒不是AI。是领域知识 + 因果体系 + 行业模板。

  1. 15份权威规范文档：从第一性原理推导的完整因果诊断体系——42条边、50哨兵、8专家、增长导航、循环溢出。这是一个完整的"企业增长操作系统"的设计蓝图。任何竞争对手要复制，需要同样的研究深度和时间投入。
  2. 管理者经济学工程化：博弈论、行为经济学、信息经济学的学术理论被工程化为27个可执行的compute函数。这不是"加一个盈亏平衡计算功能"——是系统性地将经济学推理嵌入诊断引擎。
  3. 池-阀-流-溢出模型：从企业价值循环的最不可约简模型出发，推导出所有可能的断裂点。这个模型是领域知识，不是模型能力。
  4. 行业模板库：18个行业的循环配置模板（餐饮连锁/零售/SaaS/制造/建筑/物流等）。每新增一个行业的经验，整个模板库的价值增加。
  5. 本地部署 + 数据不出企业：中小企业对数据安全的敏感度不亚于大企业。本地Agent = 零数据泄露风险。
  6. 两端进化：企业内部的中层驱动进化+跨企业的联邦学习。系统使用的企业越多，诊断越精准——形成数据网络效应。

十、总结

Synova 不是又一个 AI 产品。它是企业的 AI 免疫系统。

在 Synova 之前，中小企业的增长诊断依赖三种方式：老板的直觉（凭经验拍脑袋）、财务软件（只告诉你发生了什么，不告诉你为什么）、传统咨询（太贵、太慢、不可持续）。

Synova 提供了第四种方式：一个驻扎在企业的 AI Agent，持续观测，主动发现，自动诊断，给出行动建议，追踪执行效果。它不是给你一份报告然后离开——它成为你企业的一部分。

它背后的15份权威规范文档、42条因果边、50个哨兵、8位专家、增长导航系统、循环溢出引擎、中层驱动进化——这些不是为了造一个更聪明的ChatBot。这些是为了回答一个简单的问题，一个每个企业老板每天都在问的问题："我的企业增长卡在哪里？现在该做什么？"
