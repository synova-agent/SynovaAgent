## 1. 已固定方向，不重开

### 1.1 产品目标

Synova 是组织数字孪生诊断与持续增长导航系统。诊断是手段，目的是帮助企业识别增长瓶颈、形成行动并记住结果。

首个客户不以“伙伴云销售表→四总数→销售分析”为主线，也不预设“唯一首问”。首次入口是**中性企业扫描与问题梳理**：先取得企业材料，理解事实、结构、业务循环和人的说明，再形成有证据的瓶颈假设与方向。

### 1.2 首个客户闭环

```text
企业建档与中性扫描范围
→ ⓪ 业务系统／授权本地文件／上传文档／人的说明
→ 来源、版本、权限、证据与三类核对
→ ② 每客户对象、关系、目标与计划
→ ① 业务循环快照；③ 确定性观测；④a 指标时序
→ ⑤ 结合②结构与④依据形成解释、建议与任务
→ 人作决定；经⑤→③追加④b
→ 到期取得实际结果；经③追加④c
→ ⑥ 比较预期与结果，经验证、批准后进化能力
```

### 1.2.1 🔴 ⑤与②①③④产品契约入口

本轮产品决策记录见[`decisions/proposed/product/2026-11-15-goal-navigation-enterprise-context.md`](../../decisions/proposed/product/2026-11-15-goal-navigation-enterprise-context.md)；完整产品图景见[`docs/synova/产品宪章-v8.5-修订稿.md`](产品宪章-v8.5-修订稿.md)。创始人已于 2026-11-15 裁定**产品宪章以 v8.5 为当前执行版本**；院方原件同步另行完成，不回改 v8.4 历史镜像。

施工侧必须遵守其核心约束：⑤是目标驱动的持续经营导航；②①③④共同构成企业上下文与验证核心；事实关系、因果假设和已验证关系必须分层；岗位界面共享同一企业状态；决策历史不得覆盖；缺失不得补零；图连通不得冒充根因；跨模型增益须用同模型 A/B 实测，不作自动变准承诺。

**⑤当前代码差距（2026-11-15 只读结构核查；不是运行时验收结论）**：已有 Goal、目标分派、②目标分解边、偏离哨兵、决策记录、追加式修正及通用 `metric_readings` 等零件，但尚未组成上述闭环。目标分解边的生产写入、Goal 激活到哨兵绑定、目标持续时序与证据、正负向偏差语义、真实决策创建入口和“原决策→推翻→新决策→结果”全链均未证明接通；旧目标生命周期还存在未接线、覆盖当前值及缺失实际值补零风险。现有“导航循环”主要是状态与完成率统计，不等于持续经营导航。岗位右侧栏最终可见交互仍需专项核实。后续施工必须审计复用合格零件，不得以“已有 Goal 模块”宣称本契约已完成。

**链式召回施工契约**：以 Goal／KR 或 Decision 为入口，支持向前、向后沿显式引用逐跳读取；每跳返回摘要、稳定关联 ID 和续读入口，全文只在需要时读取。召回沿用②图关系、④a时序与④b/c确定性查询及其版本链，不新建向量数据库、平行事实账本或第二套因果权威。每跳执行同一企业与用户的可见范围检查，保留来源、业务期间、版本、事实／推断／未知及因果验证状态；不可见对象不得经摘要、计数或关联 ID 泄露；缺链显式报告，禁止模型补造。按当前问题裁剪召回范围，禁止默认灌入整库。**召回链只证明引用可回放，不证明因果成立。**

首个纵向验收使用“1000 万目标→招聘 50 人→4 个 KR→行动与持续观测→50 改为 30→新行动与结果”：从新决策向后还原旧决策当时依据，从旧决策向前看到变更与双方结果；权限、缺链、全文按需展开和确定性改坏必红均须实测。

### 1.2.2 ②①③④当前技术与代码缺口（只读核查）

- **②结构载体存在，语义校验未闭环**：有 `extensions/ontology/`、`src/l4/ontology-loader.ts` 和 SQLite 图存储；loader 仍以 `label` 做端点和参数查询，与 v2.11 的 `$id` 契约存在差距。边定义仍有 `TBD / unknown`，不得把已存图内容直接当作企业真值。
- **①有动力学字段，未形成真实因果传导**：`CycleConfig` 有 `polarity / delay / weight / mapping`，但 `src/cycles/overflow-compute.ts` 的核心计算未消费 `cycle.edges` 做状态传导；`src/agent/loop-handlers.ts` 的生产调用传 `currentNodeValues: {}`，存在退回初始值的路径。cycle 中固定系数与初始值不得冒充客户标定参数。
- **③调度、事件与④a读写基础真实存在，但覆盖和业务时态不足**：有 `SentinelRunner`、`metric_readings`、统一 writer／reader、趋势 API 和结构化 `metrics` 落盘；指标级覆盖仍需逐哨兵核验。通用 writer 固定 `confidence='medium'`，loader 以写入时间作 `observedAt`，既有现金流哨兵仍有 `Number(...) || 0`，均不得进入可信归因而不处理。
- **④b/c/d尚未组成经营回验**：`src/l4/decision-capture.ts` 有追加式修正和 `correctsRowId`，但主要是特定节点的确认／驳回／修正；未证明通用“决策→观察期→实际结果→偏差”生产闭环。`calibrateThresholds()` 仍返回 `not_implemented`。
- **LLM企业上下文供给未证明接通**：`ConversationEngine` 当前只保存 `ReportGraphAdapter` 引用，未找到实际读取调用。`ReportGraphAdapter.getCausalChains()` 仅连接遍历边，却统一设置 `rootCause: true` 并称“因果链”；这是必须阻止的结构化幻觉风险。
- **施工顺序**：不以补全所有边类型为前置。先用“一个公司目标→一个岗位 Goal→一个 KR→两条明确标注的因果假设→持续指标→一次人工调整→一次结果回验→同模型有无上下文 A/B”证明价值，再按真实使用扩展。

### 1.3 不得改变的产品边界

- `proposal_only`；系统不自动执行客户经营动作。
- 决策人与闭环负责人均为创始人；实际客户使用中仍须保留人的确认、责任和历史。
- 不预设销售、免单、退款、交付或任何其他问题就是客户瓶颈。
- 不把任何单一来源或人工看板直接当成真值。
- 不让模型负责最终算术、猜数、消灭冲突或编造因果。
- 不上向量数据库、独立图数据库平台、Kafka、Kubernetes、复杂多租户控制面或通用 Runtime Bridge。
- 不首版建设完整企业本体、通用文档解析平台、复杂 RBAC 编辑器或全量知识平台。
- 不全量迁移旧 Synova，不按对象、文档、哨兵、专家或 PR 数量证明价值。

### 1.4 技术选型

- DSH 版本选型本轮锁定 **`0.2.2-rc.2`**，后续升级另立任务。
- 版本选型锁定不等于十项探针通过、官方安装完成或《DSH 锁版记录》已形成。
- Node 采用该发行包实际携带的 **24.21.0**。
- 完整 DSH 官方发行包作为独立 Sidecar；不裁剪为模型调用器，不自研通用 Agent 内核。
- Synova 领域资产不绑定 DSH 内部 API，不随运行时升级重写。

## 2. Synova、CompanyOS 与 DSH 的关系

| 对象 | 是什么 | 负责什么 | 明确不负责 |
|---|---|---|---|
| **Synova** | 面向客户的企业诊断与增长导航产品 | ⓪–⑥、企业事实、证据、权限、决策、任务、结果、客户 UI 与离线交付 | 不重建通用 Agent 内核 |
| **CompanyOS** | 长期企业组织 AI 化与共创体系；当前也可提供研发协同 Hub／Mandate 能力 | 研发任务协调、授权和组织层的长期共创 | 不替代 Synova 领域层，不拥有 Synova 客户事实与经营决策 |
| **DSH** | 固定版本完整通用 Agent 运行时 | 会话、模型、工具循环、上下文、权限审批、技能、插件、存储与恢复 | 不替代①②③④⑤，不直连领域 DB，不成为领域权威账本 |

### 2.1 代码、数据与交付边界

- Synova 与 CompanyOS 的代码、数据、部署和计费分离，只共享明确批准的契约、Schema 或通用运行时经验。
- CompanyOS Hub／Router 不进入客户 Synova 部署包。
- 客户唯一交付物是 **Synova 离线部署包**：Synova API/UI Host＋领域内容包＋固定 DSH 官方发行包＋自有插件＋安装／启动／备份恢复脚本。
- 客户只面对 Synova 的合同、UI、账号、数据、运维和升级；不自行升级 DSH。
- 保留 DSH 许可证与版权声明，首次交付前核查实际协议文本。
- DSH SessionRef 只是对话恢复引用，不是企业事实、权限、任务或决策 ID。

### 2.2 研发账本边界

- 不在 Win 建第二套 Hub、Router、SQLite、Excel 或其他任务数据库。
- Hub 可正常服务时使用唯一 CompanyOS Hub 凭证。
- Hub 不可用时，可按已执行机制使用 Gitea 权威过渡 Mandate，并明确 `Hub Assignment / epoch / lease = NOT_ISSUED`；不得伪造凭证，也不得因此永久阻塞离线施工。
- Gitea Issue 与固定评论是产品票、契约和证据入口；聊天记忆不是任务账本。

### 2.3 Cordis 口径

- 完整 DSH 内部使用 Cordis，Synova 运行 DSH 时间接使用其官方插件与生命周期机制。
- `synova-sidecar` 可使用官方 profile／preset／`cordis.patch.yml`。
- Synova 领域代码不直接依赖 Cordis；不使用 Cordis 替代 Synova 内容宿主、权限或领域账本。
- 不建立第二套 Cordis 容器，不让领域内容包调用 DSH／Cordis 内部 API。

### 3.1 完整分层图与图例

│      ↓ 带来源／版本／权限／业务时态的事实、断言与证据                       │

│ ⑥ 进化：经验证、批准后新增／停用／撤回①②③④⑤的定义与能力；不改历史事实       │

└───────────────────────────────┬─────────────────────────────────────────────┘
                                │ 官方 ACP／回环 MCP 薄适配
┌───────────────────────────────▼─────────────────────────────────────────────┐
│ −1 DSH 完整通用运行时 Sidecar（固定 0.2.2-rc.2）                             │
│ 会话／模型／工具循环／上下文／事件／审批／技能／插件／存储与恢复               │
│ 不直连领域 DB，不拥有①–⑥，不成为企业事实、权限、任务或决策的权威账本          │
└─────────────────────────────────────────────────────────────────────────────┘
```

**读图规则**：⓪–⑥是产品宪章的领域架构，不是代码 import 层号，也不是施工 PR 的顺序；−1 是运行时支撑。①②可并行被③读取，⑤可用②作必要结构上下文，但经营判断的依据仍须落④。证据、权限与数据边界横切所有层。

### 三条领域硬契约

1. 只有③能写④，包括④b决策与④c结果；
2. ⑤进行经营判断时只能以④为判断来源，可读取②结构作必要上下文；
3. 只有⑥能改变①②③④⑤的定义与能力，运行中的模型不得自行修改。

### 数据与对象边界

- ②自然键为 `(graph, type, businessKey)`，`graph` 承担企业隔离。
- `$id` 是稳定内部引用，不替代自然键。
- ②身份继续使用现有权威载体；不得建立与②平行的通用 Fact 账本。
- 证据工作流 `confirmed / pending / conflict / stale` 与②实例七态 `measured / derived / estimated / partial / stale / conflict / missing` 分开保存。
- ④a测量时序先于④d标定；没有真实依据时不创建假参数。
- 所有关键确认、决策和结果追加历史，不覆盖成“系统一直正确”。

### 3.2 MOVO：参考实现，不是 Synova 新平台或新依赖

2026-11-15 只读核查了 [MOVO Community Edition README](https://github.com/himovo/movo)、[`runtime-host/package.json`](https://github.com/himovo/movo/blob/main/services/chat-api/dsh/runtime-host/package.json)、[`Dockerfile`](https://github.com/himovo/movo/blob/main/services/chat-api/dsh/runtime-host/Dockerfile)、[`docker-compose.yml`](https://github.com/himovo/movo/blob/main/docker-compose.yml) 及启动／版本／备份脚本。它是“DSH 负责 Agent Runtime、MOVO 负责企业产品层”的参考实现；其 Runtime Host 当前也固定使用 DSH `0.2.2-rc.2`。这里只确认所读文件中的做法，不声称已验证 MOVO 产品或其全部 Runtime Host 源码。

**可借鉴并转成 Synova 验收项**：

- 依赖清单＋lockfile 固定版本，构建时比对声明与实装版本，运行时输出实装版本；
- Runtime Host 独立进程／容器、内部 token、健康检查、依赖就绪等待、日志与停止隔离；
- 预构建或离线发行物、显式版本切换、稳定数据卷／目录标识、初始化引导；
- 备份含版本、校验和与所需数据对象，恢复前校验，恢复后重新做健康检查；
- 组织、模型、审计、Skills／MCP 等按明确能力契约逐步开放，而非首版全装。

**明确不照搬**：不引入 MOVO 整套 12 服务、MongoDB／Redis／Weaviate、完整企业知识平台或第二套控制面；不复制其模型／工具网关来取代已批准的 Synova 薄适配；不把 MOVO Desktop 当开源资产。MOVO Community License 对多租户 SaaS、OEM、白牌及去品牌有额外限制，任何代码或资产复用前必须单独核协议，不因“能读到源码”而默认可用。

**升级与可选能力**：DSH 继续固定 `0.2.2-rc.2`，不自动跟随 DSH 或 MOVO。后续升级一律走“固定候选版本→隔离探针→回归与恢复验证→主动切换”；MOVO 更新只作参考输入。可选能力通过 Synova 内容／能力包、支持矩阵、权限与审批逐项增加，未开放能力不得进入客户默认面。

### 3.3 一致性部署：沿既有方向审计、加固，不重做分布式架构

- 一个客户一套实例、最少进程；SQLite＋受控文件对象存储，固定发行包、依赖清单、独立 Sidecar profile 与 Synova 离线包。
- 先盘点并验证既有启动、健康、日志、备份恢复、导出和升级回滚实现；合格才复用，不合格在相同架构内修复，不顺手换技术栈。
- 同一版本在干净机器上得到相同目录、配置、权限和迁移结果；开发机 profile、凭据、缓存与危险权限不得进入客户包。
- 启动／停止／健康／日志、备份恢复、导出与回滚均须有实机证据；不能因 MOVO 调研把单客户部署扩展成分布式平台。

## 8. 数据、安全与运行时契约

### 8.1 身份与权限

- `enterpriseId / userId / runId / scope` 由服务端从认证上下文注入，不信任模型输入。
- 首版少量角色不自动等于全量数据权限；逐次检查可见范围。
- 可见证据与值版本先过滤，再进行对账、聚合和报告；不得生成全量报告后遮盖。
- 跨企业、跨可见范围、伪造证据／路径、未登记工具和跨用户幂等必须有反例。

### 8.2 文件与证据

- 原始文件只读，不默认扫描磁盘，不接受模型传任意路径。
- 本地读取与模型外发分别授权；实际外发内容可查看。
- 路径规范化、授权根、`..`、符号链接与目录替换均须检查。
- 文件预检后变化、同大小替换、链接替换和目录替换有反例；不承诺阻止提交后外部修改。
- 原始证据、版本、哈希、期间、来源、责任与适用范围可追溯。

### 8.3 事务与幂等

- better-sqlite3 事务全同步，共用同一连接，事务函数内禁止 `await`。
- 未授权、不支持格式和解析失败不得留下半批对象。
- 业务冲突是正常领域结果，保留双方与 `conflict`，不是系统异常。
- 幂等约束企业、操作、创建人和规范化载荷指纹；同键不同载荷拒绝且零写入。
- 不依赖纯内存幂等冒充持久约束；跨用户同键不得泄露原响应。

### 8.4 Sidecar 安全

- 独立 `synova-sidecar` profile，不继承 desktop 的 `danger-full-access / approval: never`。
- 默认 read-only＋approval ask，最小工具开放；Shell、任意路径、Web、第三方 MCP 和经营写入默认关闭。
- 回环 HTTP MCP 仅监听 `127.0.0.1`，随机端口、一次性 token、运行结束撤销。
- `close` 不等于进程停止；启动、停止、健康、日志和恢复均须有证据。
- 不自动升级；客户不继承开发机 profile、插件、凭据或危险权限。

→ Mandate：base／branch／写集／验收／有效期
→ 独立 worktree
→ 历史资产与现状核验
→ 契约／测试→实现→真实接线
→ 定向＋集成＋反例＋改坏必红
→ lint/typecheck／相关与全量测试
→ commit／push／PR
→ base/head/compare／CI／六字段回执
→ 零上下文独立复核
→ 串行集成与合并纪律
→ 阶段验收
```

### 执行纪律

- 不在 main 直接施工，不 force push，不 `--no-verify`，不自动 merge／close／deploy。
- 固定 base 后不擅自 rebase；共享写集重叠登记并串行集成。
- 写集变化必须显式批准并更新 claim；不得先写代码再补票。
- 每票只使用合成资料，直到真实数据／外发／部署被单独批准。
- 独立复核者只读，发现问题退回实现者，不自行修复后批准。
- CI 未绿不能因本地通过而合并；环境问题交所属线，不削弱安全断言或给例外。
- 软提示不被用作无限扩写集理由；主线不接管其他门禁任务。

### 六字段回执

1. 实际改动；
2. 真实入口验证；
3. 测试与失败路径结果；
4. 与 DEV DOC 的偏差；
5. 未验证项；
6. 需要 CTO 裁定的问题。

附 base／head、compare、命令、退出码、原始输出、CI run／job 和 `UNVERIFIED / NOT DONE`。

## 10. 首个客户最终验收矩阵

| 维度 | 必须证明 | 不能用什么冒充 |
|---|---|---|
| 中性扫描 | 多来源资料进入同一证据体系，形成企业脉络、缺口与候选方向 | 预设唯一问题、通用 LLM 分析 |
| 证据与真值 | 来源、版本、期间、状态可追溯；冲突并列、缺失不补零 | 对账一致＝业务真实 |
| 领域纵向薄片 | ②符合固定目标规范；真实②对象与关系、①快照、③Finding、④a时序 | 通用 Fact 表、散文或拿规范声称代替实现 |
| 哨兵时序 | SentinelRun 与测量值持久化；同输入／版本可复算；历史不覆盖 | 只显示当前计算值、失败时伪造结果 |
| 建议质量 | ⑤建议引用②③④与公司上下文，包含不确定性和回滚 | 模型猜数、相关性当因果 |
| 多用户 | 至少两个用户围绕同一②对象、任务和决定协作，权限实测 | 各自会话复制企业事实 |
| 决策结果 | 一次真实管理决定经⑤→③入④b，到期结果经③入④c；归因含替代解释 | 只有建议，没有责任与结果 |
| 运行时 | 固定 DSH 完整 Sidecar；失败、恢复、外发和权限经过实测 | 旧版本证据、静态 dump、空成功 |
| 领域独立 | DSH 停止后领域计算与内容校验仍通过 | 领域层 import DSH／Cordis |
| 内容进化 | 一个实际能力新增、停用、撤回和回滚，不改通用引擎 | 文件复制、假热更新 |
| 部署恢复 | Synova 离线包干净安装、重启、备份恢复、导出、回退 | 开发机可运行＝客户可部署 |
| 客户价值 | 真实用户使用并形成行动与结果回验 | 测试数、文档数、功能数 |

任一“真实”验收未执行，必须保留 `NOT DONE`，不得改写成开发测试已覆盖即客户通过。

## 12. 何时升级给主线会话／创始人

### 12.1 主线会话接入

- 跨层权威、领域契约或 Synova／CompanyOS／DSH 边界需要变化；
- 需要修改共享核心 Schema、权限模型、导航主流程或既有 compute 契约；
- DSH 升级、替换、内核 patch 或官方能力无法满足固定架构；
- 两个执行线出现无法调和的技术方案或验收结论；
- 复杂文件／事务／权限／运行时问题经实际复现仍无法收敛；
- 阶段集成需要重新划分垂直切片；
- 需要总体验收支持。

### 12.2 创始人裁定

- 产品目标、首个客户范围、`proposal_only` 或中性扫描方向变化；
- 真实客户数据、真实模型外发、生产部署或客户经营动作授权；
- 客户安全、合同、许可证、交付或商业模式出现新边界；
- 需要停机窗口、真实安装或生产资源操作；
- 需要扩大首版为完整知识平台、复杂权限平台或其他新方向。

### 12.3 不升级

写集内实现选择、普通 bug、测试修复、常规 PR 评论、依赖版本与声明不一致的本地排查、CI 重跑和已有契约内的实现争议，由 Win CTO 闭环。
