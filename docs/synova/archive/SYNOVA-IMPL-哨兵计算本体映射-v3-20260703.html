1.3 Financial 节点的当前问题：怪物节点

当前 Financial 节点承载了 17 个 optionalProps，被 6 个诊断层全部依赖。当 compute 函数问"这个企业的自由现金流是多少"时，它做的是 store.queryNodes('Financial') → .props.operatingCashFlow——本质是把 Financial 当成一个巨大的 KV 读写器。

必须拆分成多个有明确语义的子节点。每个子节点有自己的时间戳和来源，哨兵通过遍历边来消费它们。

// ✅ 新模式：沿边遍历图
function computeKzIndex(store: GraphStoreReader, teamId: string) {
  // 第1步：找到 Financial 节点
  const finNode = store.queryNodes('Financial', { teamId })[0];
  
  // 第2步：沿 GENERATES 边找到现金流子节点（带时间戳和来源）
  const cashFlowNodes = store.traverse(finNode.id, ['GENERATES'])
    .filter(n => n.type === 'CashFlowStatement');
  
  // 第3步：沿 STRUCTURED_AS 边找到资本结构子节点

    .filter(n => n.type === 'CapitalStructure');
  
  // 第4步：在正确的子节点上提取字段
  const cf = cashFlowNodes[0].props.operatingCF;   // ← 来源清晰：最近一期的经营现金流
  const debt = capStructNodes[0].props.totalDebt;   // ← 来源清晰：资本结构子节点
  // ... 代入 KZ 公式
}

2A.1 增长动力学核心公式

增长 = 外部机会(External Opportunity) × 价值捕获(Value Capture) × 内生创造(Endogenous Creation) − 增长成本(Growth Cost)

其中每一项都是一个向量，由多个哨兵指标组成。
增长停滞发生在任何一个向量降至临界阈值以下。

对应关系:
  外部机会  → 环境层 E1-E6（PEST-CC框架驱动）
  价值捕获  → 界面层 I1-I13（生态位理论 + 战略7力 + 商业模式）
  内生创造  → 内部层 O1-O10（演化经济学 + 杨三角锚点）
  增长成本  → 资本层 F1-F5（公司金融理论）+ I11-I13（交易成本 + 边界决策）
  
校准器:
  技术层 T1-T9 和 匹配层 S1-S3 不直接进入增长公式，而是作为"调节器"：
  - T1-T9 评估"人+Agent混合组织的生产力基础"
  - S1-S3 评估"战略方向与组织能力的匹配度"

2A.2 环境层的数据输入框架：PEST-CC

PEST-CC 框架（杨国安教授在传统PEST基础上加入两个C）：政治(P) + 经济(E) + 社会(S) + 技术(T) + 竞争态势(C1) + 客户需求变化(C2)。PEST原始框架来自Aguilar (1967)《Scanning the Business Environment》。这是环境层E1-E6的数据采集和分析框架——不是哨兵本身，而是"这6个维度各有什么信号"的输入框架。PEST-CC的分析结果映射为6个诊断哨兵（E1-E6）。每个哨兵附带一个techno-economic-phase校准参数（源自佩雷斯Perez, 2002），根据企业所处的AI革命阶段调整阈值。

2A.3 交易成本理论的AI时代修正（关键）

科斯 (Coase, 1937) 提出交易成本理论时背景是1930年代的工业经济——默认生产单位是人。在2026年AI时代，Agent正在成为新的生产单位，交易成本的计算逻辑必须修正： 三个局限:
  1. 生产单位从"人"变为"人+Agent"混合体——科斯框架没有预见到Agent可以作为独立生产单位。当Agent编码一次后可以无限复用（边际成本趋近于0），"自制vs外购"的决策逻辑根本改变。
  2. 信息处理成本成为独立的约束维度——科斯讨论的是治理成本（合同、监督、谈判），但没讨论信息处理成本。在AI时代，信息处理能力（Shannon信道容量）正成为比治理成本更重要的增长约束。本体系通过O6（组织信道容量）和O7（信息失真率）覆盖这一维度。
  3. 协调成本从人-人扩展到人-Agent和Agent-Agent——传统的层级协调（Arrow衰减p^n）不再适用。I13哨兵专门评估"人+Agent混合边界效率"，使用第一性原理推导的计算公式。 参见白皮书§7.8（I11哨兵）中"科斯框架AI时代修正"的完整论述。

2A.4 第一视角测试规则（已注入所有专家）

第一视角测试（First-Person Test）：任何专家在给出诊断建议之前，必须先回答"设计者有没有把自己放进最终用户的身体里？最脆弱的时刻能否通过信任测试？" 举例（客户A案例）： - 战略专家提出"到家月子照护"建议 → 必须回答"如果你是刚生完孩子的母亲，你会让宝宝晚上被带到酒店外另一个空间吗？" - 这条规则阻止了表面上"正确"但根本无法通过用户信任测试的建议。 - 已在 strategy/business_model/marketing 三个专家的RULES.md中注入，并附带哇呢案例作为教学案例。

2A.5 品牌评估前置规则（已注入）

在评估任何品牌哨兵（I4）之前，必须先判定"这个品类在消费者心智中是否存在？" 如果品类不存在（如手脚模纪念品）：品牌溢价和忠诚度计算的结果不应被解释为"品牌弱"，而应解释为"品类尚未建立，品牌评估不适用"。 判定标准：一个品类要进入消费者心智，需要整个产业链（上游+中游+下游）多年的共同推动，不是靠任何单一企业可以完成的。例如钻石（上游De Beers+中游零售商+下游婚庆产业链）、儿童摄影（上游摄影器材+中游影楼连锁+下游影像留存文化）。 已注入 strategy/business_model/marketing 的RULES.md。

2A.6 决策偏见审计（已退级）

行为经济学的偏见检测（Kahneman & Tversky, 1979 前景理论）——损失厌恶、沉没成本、确认偏误——这些是增长最隐形的杀手。但是偏见检测需要精心设计的对照实验，不适合自动化哨兵。已退级为专家定性判断维度（由org专家和strategy专家在诊断过程中以启发式方式评估），不设独立哨兵。如果未来有足够的纵向行为数据（决策记录+结果反馈），可以考虑重新设计为有监督学习哨兵。

2A.7 组织双环学习理论（O8的理论根源）

Argyris & Schön (1978) 双环学习： - 单环学习（Single-loop）：修表面——发现了问题，改了操作方法，但没问"为什么会产生这个问题" - 双环学习（Double-loop）：改根因——发现问题是治理变量（目标、政策、假设）本身有问题，修改的是底层逻辑 O8哨兵"组织修复能力"的诊断核心：不是看"修了多少次"，而是看"修的是表面还是根因"。compute-problem-action-cycle通过"同类问题复发率"来区分单环（高复发）和双环（低复发）。

compute-saas-usage-score

/**
 * 软件资产利用率 — T1哨兵核心compute函数
 * UtilizationRate = ActiveTools / TotalAuthorizedTools
 * OverlapRate = OverlappingToolPairs / TotalToolPairs
 * ShadowITRate = UnauthorizedTools / TotalActiveTools
 * 
 * 本体映射: Tool::status(''active''|''idle''|''deprecated''), Tool::authorization(''authorized''|''unauthorized'')
 * 边: PROVIDES → Capability (检测功能重叠，两个Tool提供相同Capability=重叠)
 */
function computeSaasUsageScore(tools: Array<{
  status: string; authorization: string; providesCapabilities: string[];
}>): { utilizationRate: number; overlapRate: number; shadowITRate: number; healthScore: number } {
  const total = tools.length;
  if (total === 0) return { utilizationRate:0, overlapRate:0, shadowITRate:0, healthScore:0 };
  const active = tools.filter(t => t.status !== 'idle' && t.status !== 'deprecated');
  const authorized = tools.filter(t => t.authorization === 'authorized');
  const unauthorized = active.filter(t => t.authorization === 'unauthorized');
  
  // 功能重叠检测：两个Tool提供同一个Capability
  let overlapCount = 0;
  const capMap = new Map();
  for (const t of active) {
    for (const cap of t.providesCapabilities) {
      if (!capMap.has(cap)) capMap.set(cap, []);
      const users = capMap.get(cap)!;
      if (users.length > 0) overlapCount++;
      users.push(t.authorization);
    }
  }
  
  const utilizationRate = active.length / total;
  const totalPairs = total * (total - 1) / 2;
  const overlapRate = totalPairs > 0 ? overlapCount / totalPairs : 0;
  const shadowITRate = active.length > 0 ? unauthorized.length / active.length : 0;
  const healthScore = utilizationRate * 0.4 + (1 - overlapRate) * 0.3 + (1 - shadowITRate) * 0.3;
  
  return { utilizationRate, overlapRate, shadowITRate, healthScore };
}
// 阈值: utilizationRate < 0.7 → 资源浪费 | shadowITRate > 0.2 → 失控风险 | overlapRate > 0.3 → 重复订阅

/**
 * 数据完整率 — T3哨兵核心compute函数
 * CompletenessRate = 1 - (Nodes_MissingRequiredProps / TotalNodes)
 * PII_Rate = PII_Containing_Nodes / TotalNodes
 * 
 * 本体映射: 全部graph_nodes (props完整性检查), PII字段敏感检测

function computeDataReadinessScore(nodes: Array<{
  id: string; type: string; props: Record; requiredFields: string[];

  if (total === 0) return { completeness:0, piiRate:0, healthScore:0, degraded:true };

    n.requiredFields.some(f => n.props[f] === undefined || n.props[f] === null)

  const piiNodes = nodes.filter(n =>

compute-scale-economy

/**
 * 规模经济指数 — 单位成本随产量变化的弹性
 * η = d(log Cost) / d(log Q)
 * 来源: 管理经济学(托马斯) Ch7, Helmer (2016) 7 Powers Ch3
 * 
 * 本体映射: Financial::cogs, Financial::revenue 按产量Q时序
 * 边: COST_DRIVEN_BY → Process(生产流程)
 * 
 * 判定:
 *   η < -0.1 → 显著规模经济（产量翻倍，单位成本下降>10%）
 *   η ≈  0   → 无规模经济
 *   η >  0   → 规模不经济
 */
function computeScaleEconomy(costVolumePairs: Array<{cost:number; volume:number}>): 
  { elasticity: number; signal: string } {
  const n = costVolumePairs.length;
  if (n < 4) return { elasticity: 0, signal: 'insufficient_data' };
  // 对数线性回归: log(Cost) = α + η × log(Q)
  const sumLogQ = Σ log(Qi); const sumLogC = Σ log(Ci);
  const sumLogQ2 = Σ(log(Qi))²; const sumLogQLogC = Σ log(Qi)·log(Ci);
  η = (n·sumLogQLogC - sumLogQ·sumLogC) / (n·sumLogQ2 - (sumLogQ)²);
  return { elasticity: η, signal: η < -0.1 ? 'strong' : η > 0.05 ? 'diseconomy' : 'neutral' };
}

 * SwitchingCost_Ratio = Σ(切换投入_i) / ACV
 * 切换投入包括: 数据迁移成本、重新培训成本、集成重做成本、流程调整成本
 * 来源: Helmer (2016) 7 Powers Ch5
 * 
 * 本体映射: Client::tenure, SELLS_TO::annualContractValue, SELLS_TO::penetration
 * 
 * 判定:
 *   SwitchingCost_Ratio > 0.5 → 高切换成本（客户被锁定）
 *   SwitchingCost_Ratio < 0.15 → 低切换成本（客户可随时离开）
 */
function computeSwitchingCost(clients: Array<{acv:number; tenure:number; dataVolume:number; integrationComplexity:number}>): 
  { switchingCostRatio: number; signal: string } {
  const avgSwitchingCost = clients.reduce((s,c) => 
    s + (c.dataVolume * 0.3 + c.integrationComplexity * 0.4 + c.tenure * 0.3), 0) / clients.length;
  const avgACV = clients.reduce((s,c) => s + c.acv, 0) / clients.length;
  const ratio = avgACV > 0 ? avgSwitchingCost / avgACV : 0;
  return { switchingCostRatio: ratio, signal: ratio > 0.5 ? 'high' : ratio < 0.15 ? 'low' : 'medium' };
}

compute-process-power

/**
 * 流程优势 — 企业产出效率 vs 行业标杆
 * Efficiency_Ratio = 企业单位产出投入 / 行业标杆单位产出投入
 * Process_Age_Premium = 1 - e^(-λ·years)  (流程积累的时间价值，λ≈0.2)
 * Process_Power = Efficiency_Ratio × (1 + Process_Age_Premium)
 * 来源: Helmer (2016) 7 Powers Ch6
 * 
 * 本体映射: Process::efficiency(产出/投入比), Tool::status, DEPENDS_ON 边
 * 
 * 判定:
 *   Process_Power > 1.0 → 流程优势
 *   Process_Power < 0.7 → 流程劣势
 */
function computeProcessPower(processes: Array<{efficiency:number; yearsActive:number; industryBenchmark:number}>): 
  { processPower: number; signal: string } {
  const avgEfficiency = processes.reduce((s,p) => s + p.efficiency, 0) / processes.length;
  const efficiencyRatio = avgEfficiency / (processes[0]?.industryBenchmark || 1);
  const avgYears = processes.reduce((s,p) => s + p.yearsActive, 0) / processes.length;
  const agePremium = 1 - Math.exp(-0.2 * avgYears);
  const power = efficiencyRatio * (1 + agePremium);
  return { processPower: power, signal: power > 1.0 ? 'advantage' : power < 0.7 ? 'disadvantage' : 'parity' };
}

compute-counter-positioning-slm

/**
 * 反定位 SLM 公式 — 挑战者的战略杠杆利润
 * SLM = Om × (OP/NP) × δ
 * Om = 在位者旧业务利润率(通常>0.5意味着高利润暴露)
 * OP/NP = 在位者价格/挑战者价格(>1表示挑战者有价格优势)
 * δ = 蚕食率 = |Δ旧业务销量| / 新业务销量
 * 来源: Helmer (2016) 7 Powers Ch2, 数学推导见白皮书§7.3
 * 
 * 本体映射: Financial::grossMargin(对手), COMPETES_WITH边
 * 
 * 判定:
 *   SLM > 0 且 applicable=true → 反定位战略可行
 *   当 δ=0（在位者认为新模式不影响旧业务）→ SLM=0 → 反定位不成立
 * 
 * 边界条件（必须同时满足）:
 *   1. profitExposure: 在位者旧业务利润率 > 50%
 *   2. modelConflict: 新模式与在位者旧模式冲突
 *   3. sizeAsymmetry: 挑战者规模 < 在位者规模的5%
 *   4. windowOpen: 在位者已在认知偏见/代理问题上陷入困境
 */
function computeCounterPositioningSlm(params: {
  incumbentMargin: number; incumbentPrice: number; ourPrice: number;
  ourRevenue: number; incumbentRevenue: number;
}): { applicable: boolean; slm: number; conditions: Record } {
  const { incumbentMargin, incumbentPrice, ourPrice, ourRevenue, incumbentRevenue } = params;
  if (incumbentRevenue === 0 || ourPrice === 0) 
    return { applicable: false, slm: 0, conditions: {profitExposure:false,modelConflict:false,sizeAsymmetry:false,windowOpen:false} };
  const profitExposure = incumbentMargin > 0.5;
  const sizeAsymmetry = ourRevenue / incumbentRevenue < 0.05;
  const priceRatio = incumbentPrice / ourPrice;
  const delta = priceRatio > 1.5 ? 0.8 : (priceRatio > 1 ? 0.5 : 0.2);
  const conditions = { profitExposure, modelConflict: true, sizeAsymmetry, windowOpen: true };
  if (!profitExposure || !sizeAsymmetry) 
    return { applicable: false, slm: 0, conditions, confidence: 0.3 };
  const slm = incumbentMargin * priceRatio * delta;
  return { applicable: true, slm: Math.round(slm * 100) / 100, conditions };
}

  const last = sorted[sorted.length - 1];

/**
 * Bass 扩散模型 — 新惯例在组织内的采纳速度
 * F(t+1) = F(t) + p × (1 - F(t)) + q × F(t) × (1 - F(t))
 * p = 创新系数(外部影响: 培训/命令/咨询)
 * q = 模仿系数(内部影响: 同事采纳后跟风)
 * 来源: Bass (1969), Management Science
 * 
 * 判定: q < 0.1 → 惯例扩散靠外部推动(不可持续) | q > 0.3 → 自驱动扩散(健康)
 */
function computeBassDiffusion(adoptionTimeline: Array<{t:number; cumulativeAdopters:number}>): 
  { p: number; q: number; peakTime: number } {
  // 非线性回归估计p和q(Bass模型的S形曲线拟合)
  // 简化: 取最后两个数据点计算增长率
  if (adoptionTimeline.length < 3) return { p: 0, q: 0, peakTime: 0 };
  const n = adoptionTimeline.length;
  const last = adoptionTimeline[n-1]; const prev = adoptionTimeline[n-2];
  const growthRate = (last.cumulativeAdopters - prev.cumulativeAdopters) / (prev.cumulativeAdopters || 1);
  const q = Math.min(growthRate, 0.5); // 估计模仿系数(上限0.5)
  const p = Math.max(0.01, growthRate - q * last.cumulativeAdopters / 100);
  return { p, q, peakTime: q > 0 ? Math.log(q/p) / (p+q) : 0 };
}

/**
 * Altman Z-Score — 企业破产预测
 * Z = 1.2×(WC/TA) + 1.4×(RE/TA) + 3.3×(EBIT/TA) + 0.6×(MVE/TL) + 1.0×(Sales/TA)
 * 来源: Altman (1968), Journal of Finance
 * 
 * 判定: Z < 1.81 → 破产风险 | 1.81-2.99 → 灰色地带 | > 2.99 → 安全
 */
function computeAltmanZ(fin: {
  workingCapital:number; totalAssets:number; retainedEarnings:number;
  ebit:number; marketValueEquity:number; totalLiabilities:number; sales:number;
}): { zScore: number; signal: string } {
  const z = 1.2*(fin.workingCapital/fin.totalAssets) + 1.4*(fin.retainedEarnings/fin.totalAssets)
    + 3.3*(fin.ebit/fin.totalAssets) + 0.6*(fin.marketValueEquity/fin.totalLiabilities)
    + 1.0*(fin.sales/fin.totalAssets);
  return { zScore: z, signal: z < 1.81 ? 'distress' : z < 2.99 ? 'grey' : 'safe' };
}

compute-pert

/**
 * PERT 三点估算 — 任务工期的不确定性评估
 * Expected_Duration = (O + 4×M + P) / 6
 * Variance = ((P - O) / 6)²
 * O = 乐观估计(Optimistic), M = 最可能估计(Most Likely), P = 悲观估计(Pessimistic)
 * 来源: US Navy Special Projects Office (1958)
 */
function computePert(optimistic: number, mostLikely: number, pessimistic: number): 
  { expectedDuration: number; variance: number; stdDev: number } {
  const expected = (optimistic + 4 * mostLikely + pessimistic) / 6;
  const variance = Math.pow((pessimistic - optimistic) / 6, 2);
  return { expectedDuration: expected, variance, stdDev: Math.sqrt(variance) };
}

compute-becker-hc-roi

/**
 * 人力资本 ROI — 培训投入的回报率
 * HC_ROI = (Training_Productivity_Gain - Training_Cost) / Training_Cost
 * 来源: Becker (1964) Human Capital
 * 
 * 用于O10人才密度补充——不仅看"有多少高绩效员工"，还看"投资在人与上的回报"
 */
function computeBeckerHcRoi(trainingCost: number, productivityGain: number): 
  { hcRoi: number; signal: string } {
  const roi = trainingCost > 0 ? (productivityGain - trainingCost) / trainingCost : 0;
  return { hcRoi: roi, signal: roi > 0.5 ? 'strong' : roi > 0 ? 'positive' : 'negative' };
}

compute-agency-cost

/**
 * 代理成本 — 委托-代理理论的企业治理成本
 * AC = Monitoring_Cost + Bonding_Cost + Residual_Loss
 * 来源: Jensen & Meckling (1976), Journal of Financial Economics
 * 
 * Monitoring_Cost: 监督成本(审计、董事会、KPI体系的运行成本)
 * Bonding_Cost: 约束成本(管理层主动接受约束的支出)
 * Residual_Loss: 无法消除的剩余损失(即使最优合约也无法避免)
 */
function computeAgencyCost(monitoring: number, bonding: number, residualLoss: number): 
  { totalAgencyCost: number; costRatio: number; revenue: number } {
  const total = monitoring + bonding + residualLoss;
  return { totalAgencyCost: total, costRatio: total / (revenue || 1), revenue };
}

compute-evpi

/**
 * EVPI 期望完美信息价值 — "等待更多信息"的决策价值
 * EVPI = |EV_with_Perfect_Info - EV_with_Current_Info|
 * 来源: 管理经济学(托马斯) Ch14, 决策理论
 * 
 * 当EVPI > 信息获取成本时，应该"等待"而不是"立即行动"
 */
function computeEvpi(evPerfect: number, evCurrent: number): 
  { evpi: number; shouldWait: boolean; infoCostThreshold: number } {
  const evpi = Math.abs(evPerfect - evCurrent);
  return { evpi, shouldWait: evpi > 0, infoCostThreshold: evpi };
}

compute-dupont

/**
 * DuPont 三因子分解
 * ROE = Profit_Margin × Asset_Turnover × Equity_Multiplier
 *      = (NetIncome/Revenue) × (Revenue/TotalAssets) × (TotalAssets/Equity)
 * 来源: DuPont Corporation (1919), 公司理财(罗斯) Ch3
 */
function computeDupont(netIncome: number, revenue: number, totalAssets: number, equity: number): 
  { roe: number; profitMargin: number; assetTurnover: number; equityMultiplier: number } {
  const pm = revenue > 0 ? netIncome / revenue : 0;
  const at = totalAssets > 0 ? revenue / totalAssets : 0;
  const em = equity > 0 ? totalAssets / equity : 0;
  return { roe: pm * at * em, profitMargin: pm, assetTurnover: at, equityMultiplier: em };
}
