#### A1.5 【P0-1】门禁的"计划哈希"真相源绑在**提交者本地工作树**，在真 main 上状态定性反转

**机制**：`check-dispatch-gate.sh` → `pre-dispatch-check.sh:68-76` 的 ⑩ 项，用 `shasum -a 256 "$PLAN"` 算**工作树里那份**计划文件的哈希，与派单文档里的 `依据计划: v1.2@<hash>` 比对；不符 → `FIND=1` → 门禁 exit 1。

**实证 1（本机独立复算：派单声明"v1.2@4e46603f"实为 sha256 前 8 位，不是 commit）**

```
$ git cat-file -p cdeba8e9:docs/synova/coordination/整体推进计划-主线-20260913.md | shasum -a 256 | cut -c1-8
4e46603f        ← 与批次五派单锚定一致 ✅（F4 的语义已在 §A2 得到确认）
$ printf '# 派单：D998 锚定测试\n依据计划: v1.2@4e46603f\n...' > <派单-锚定反向测试.md>
$ cd aw5-pr574 && SYNO_PRE_DISPATCH_DOCS=<该文件> bash scripts/control-tower/check-dispatch-gate.sh
  ❌ ...: 复核未过 (exit 1)——逐项点名:
       ⚠️ 派单引用的计划哈希与当前不符（当前 v1.2@8d331729）——计划已更新，重读后再派
GATE RC=1
```

**实证 2（根因定位，两处哈希来源）**

| 位置 | 计划文件 sha256 前 8 位 |
|---|---|
| `origin/main`（= cdeba8e9 树） | **4e46603f** ← 真值 |
| PR #574 head 树（ce1d9469） | **8d331729** ← 其分支基线早于计划变更提交 `93eff3b9`（`git merge-base --is-ancestor 93eff3b9 ce1d9469` → **NO**） |

→ **一份锚定完全正确的派单文档，在 PR #574 这棵树里必红**；同一份文档在 main 上则是绿的。
→ 该门禁一旦合入 main，任何"分支落后于计划变更"的提交者都会吃到假红。这与编码指令 §一.3 自己列的已知病（「工作树落后 main 时…假红/假绿」）是**同一个病**，而 D778 的解法只把它写进了 skill 规则（要求人在同步的 worktree 里跑），**没有修门禁本身**。

**P1-1（测试覆盖盲区，解释"为什么 23/23 全绿仍漏掉 P0-1/P0-2"）**

`tests/control-tower/check-dispatch-gate.test.sh:35-37`：

