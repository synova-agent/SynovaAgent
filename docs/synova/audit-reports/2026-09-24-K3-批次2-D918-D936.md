### ① D937（P0，待开卡）：组 7a `grep -Ev "^+++"` 是否非法 ERE → 检查恒过？

**定位**：`scripts/pre-commit-check.sh:991`

```bash
NEW_DIAG=$(echo "$GIT_CACHED_DIFF" | grep "^+.*DiagnosticModule" | grep -Ev "scripts/pre-commit-check.sh|.md|.html|//|@deprecated|import type|^+++|hard_check|禁止新 DiagnosticModule|不要再使用 DiagnosticModule" || true)
```

**结论：证实，且比派单所问更糟——两个平台两种死法，全部恒过。**

**复现 1（派单原文，macOS BSD grep）**：
```
$ echo test | grep -Ev "^+++"
exit=2
grep: repetition-operator operand invalid
```
BSD grep 判 `^+++`（锚点后跟重复算符）为非法 ERE → exit 2、输出为空。

**复现 2（CI 侧，ubuntu-latest = GNU grep 3.11，源码自编译实测）**：
```
$ echo test | ./grep -Ev "^+++"        # 自编译 GNU grep 3.11
exit=1                                  # 无输出——模式命中了 "test"
$ printf 'abc\n+++\n' | ./grep -E "^+++"
abc
+++                                     # 两种行都命中 → ^+++ 在 GNU 下匹配一切行
```
GNU 对行首 `+` 打 warning（`+ at start of expression`）并按退化语义处理——**`^+++` 匹配每一行** → `-v` 排除每一行 → NEW_DIAG 恒空。

**复现 3（端到端，真实脚本 + 真实违规）**——在 main 检出中暂存含 `export const m: DiagnosticModule = ...` 的违规新增行，跑真实组 7：
```
$ SYNO_CI=1 bash scripts/pre-commit-check.sh 2>&1 | sed -n '/组 7\/13/,/组 8/p'
── 组 7/13: 架构合规 ──
grep: repetition-operator operand invalid        ← 错误就打在旁边
  ✅ 禁止 DiagnosticModule: 新模块须实现 Sentinel 接口   ← 依然放行
```
（探针文件已当场清理，未提交。）

**控制流证据**：全脚本无 `set -o pipefail`（`grep -n pipefail` 零命中），管道中第二 grep 的 exit 2 被吞；`|| true` 再兜底；`soft_check()`（pre-commit-check.sh:105-124）见空串即打 ✅ 并 `log_gate miss`。CI 侧（ci.yml:12 runs-on ubuntu-latest，:87 SYNO_CI:"1"）走 GNU 分支 → 同样恒空 → **CI strict 权威门禁对该检查同样失效**。

**影响面**：
- 引入点：`git log -L 991,991` → b8e1eb20（D520，2026-08-24）——失效已 **31 天**，期间本地与 CI 无任何提交被 7a 拦过。
- 波及范围仅组 7a 一处：组 1（:492）的 `grep -v '^+++'` 是 BRE（`+` 字面量），合法且工作正常；全仓 `grep -Ev … ^+++` 同型仅此一条（scripts/+tests/ 扫描零其他命中）。
