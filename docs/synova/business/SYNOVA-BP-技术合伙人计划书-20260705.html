Synova
企业增长导航系统 — 技术合伙人计划书

2026年7月 · 不融资 · 只讲技术和商业逻辑

一句话：Synova是一个驻扎在企业内部的AI系统。它7x24小时持续观测，自动诊断增长瓶颈，告诉企业"增长卡在哪里、现在该做什么"。它不是ChatBot——它是有因果推理能力的组织数字孪生。

1. 我们在做什么

1.1 问题

中国有超过500万家成长型企业。它们大多数请不起麦肯锡（一个项目200-500万），也养不起专职的战略团队。它们遇到增长瓶颈时，靠的是老板的直觉、朋友的推荐、或者被收了几十万但效果不明的咨询公司。

更根本的问题在于：企业增长最大的敌人不是竞争对手——是"没人知道问题在哪"。 诺基亚在2007年全球市场份额49%，但中层管理者因为传递坏消息而被"杀死信使"。柯达发明了数码相机但胶片的70%毛利率锁死了转型。恒大的审计/风控/合规全部归集到董事长办公室，没人敢在会议上问"万一房价跌20%会怎样"。

这些问题不是"数据不够"——数据一直都在。是"没有人把数据组织成因果判断"。财务报表只告诉你利润下降了，不告诉你为什么下降。咨询公司只能待8周、访谈20个人、看到企业愿意给他们看的东西。

1.2 我们的方案

Synova驻扎在企业内部。不是ChatBot——是24小时运行的诊断引擎。它持续做三件事：

建模：把企业的ERP、CRM、财务数据、IM通讯记录、会议纪要，转化为一张"企业因果图谱"。不是"企业里有什么东西"的关系图——是"钱从哪来、花到哪去、谁在做什么活动、这些活动产生了什么结果、结果有没有回流成新的资源"的因果链。

诊断：沿着16条因果边持续扫描。不是查"财务报表的数字对不对"——是查"数字背后的因果链健不健康"。比如：融资约束不是看"钱够不够"，是看"利润有没有回流成可融资的资产"。组织修复不是看"问题解决了没"，是看"同一个问题是不是反复出现"。

导航：当多条边同时报警时，三阶推理引擎按时间顺序追溯根因，给出三种战略方向（治疗/转换/跳跃），以及每种方向的ROI估算。不是平铺问题清单——是给出方向。

2. 为什么是我们

2.1 不可复制的壁垒

壁垒说明为什么别人抄不了
本体层10个实体 + 16条因果边 + 4个调节因子。这不是"企业数据模型"——是从16个企业死亡案例（Nokia/Kodak/恒大/Enron等）中反向推导出来的因果结构。这个设计过程花了4个月、7位外部专家评审、5轮迭代。不是工程师能凭直觉建的。
产业时钟自动判定企业所在产业的"相位"（导入/成长/成熟/衰退/转折）。同一个毛利率20%，在成长期是危险的保守，在成熟期是健康的效率。需要10项基础设施的渗透率阈值数据——这些基准数据需要积累。
NCI非共识检测识别"被组织免疫系统过滤掉的非共识信号"——拼多多、特斯拉式的机会在被证明之前往往先被组织内部的共识压制。只有驻扎在企业内部的系统才能捕捉"被过滤的信号"——外部咨询师永远看不到。
进化体系三层进化：会话内学习→组织自适应→全局进化。不是"定期人工改规则"——系统从每一次与企业人的交互中自己学习。需要有持续运营的企业客户数据积累。先发优势随客户数增长而加强。

2.2 已验证的准确度

第一个正式客户（婴儿手足纪念品企业，全国细分第一）的诊断结果：准确判断了"砍掉低产客户群=年亏134万"——而客户管理层和外部收几十万的咨询师都认为应该砍。核心发现获得客户"比外部咨询更精准"的评价。这是没有哨兵参与计算、仅靠理论体系+上下文注入就做到的。

3. 技术架构

3.1 技术栈

层技术说明
本体层(L4)图数据库(SOG) + JSON Schema企业知识图谱。10实体+16条因果边+4调节因子。节点=池(存量)，边=阀(流量+因果参数)
洞察层(L3)TypeScript + 哨兵+Cron46个哨兵，92个compute函数。不是读KV做算术——是沿因果边做图遍历
专家系统Markdown文件驱动 + ReAct推理9位专家(战略/组织/财务/技术/营销/商业模式/行动/知识/Host)。文件驱动——新专家=新建目录+5个Markdown文件
LLMDeepSeek + OpenAI + Gateway多模型路由。非结构化信号提取用轻量prompt(<500 tokens)
存储(L5)SQLite + 文件系统图数据+扩展JSON+专家Markdown+行业模板
交互(L1)HTTP API + MCP + TUI独立进程，不依赖前端

3.2 架构原则（Anthropic工程标准）

  • 一次性切换，零兼容层。 不做"新旧并存"的过渡——用自动化验证器确保切换后输出不变，切换后立即删除旧代码。
  • 只新增文件，不修改存量代码。 NCI哨兵和进化触发器都是新增模块，挂载到现有体系上。
  • 文件驱动扩展。 新行业=新JSON文件。新专家=新Markdown目录。新哨兵=新目录+manifest.json。不修改TypeScript代码。
  • 五层物理隔离。 L1-L5每层只与相邻层通信。pre-commit物理阻断跨层import。

6. 为什么现在是时候

AI基础设施已经就绪。 DeepSeek V3的API成本已经降到可以支撑"每条消息<500 tokens分类"的经济模型。Agent框架正在成熟——企业内部的AI不再只是"问问题的ChatBot"，而是"能自主执行任务的Agent"。

中小企业咨询市场有巨大的价格鸿沟。 麦肯锡一个项目200-500万。中小咨询公司几万到几十万但质量参差不齐——而且他们都做不了"驻扎在企业内部、24小时持续观测"。Synova年费3-6万，价格是传统咨询的1/100，但持续性是不可替代的。

先发优势随数据积累而加强。 每接入一个新客户，ExternalBaseline的行业数据就更准。每多一个企业验证NCI的判断，模型的信度就更高。这不是"软件"——这是"数据和模型的双重飞轮"。

7. 对技术合伙人的期待

我们不是要找"帮我写代码的人"。我们的技术架构已经足够清晰——16条因果边、10个实体、92个compute函数、9位专家、三阶推理引擎、NCI非共识检测——这些都是已经设计完成并正在工程化的。

我们需要的是能理解这套体系的技术深度，并且能在以下方向之一独立带领团队的人：

  • 因果推理引擎的持续进化。 16条边不是"写完了就完了"——需要不断从新的企业死亡/增长案例中提取新的因果模式，验证现有边的正交性，检测新的参数组合。这需要同时具备系统动力学和软件工程的背景。
  • 非结构化数据管道的工程化。 NCI的Signal采集管道需要连接飞书/钉钉/企业微信，需要会议纪要的LLM解析，需要信号生命周期的跨时间追踪。这是工程深度极高的工作——不是"调一个API"。
  • 进化体系的实现。 当前代码只有30%完成度。需要从单体文件拆分为6个独立模块，实现企业行为自动检测、外部数据自动聚合、哨兵-诊断矛盾检测。需要扎实的分布式系统和时序数据处理经验。
  • 产品化和商业化。 被动模式（企业日常AI大脑）的产品设计、GA陪跑版的标准化流程、行业模板库的建设。需要懂企业服务、懂SaaS产品、懂AI产品的人。
