## §6 口径陷阱（本窗实证，建议进纪律）

| 陷阱 | 实证 | 纪律 |
|---|---|---|
| **run 级掩盖 job 级** | 同一对象 run=`cancelled` / job=`failure` | 读结论**取 check-run 级**；且**先重列 run**，不复用上批 run id |
| **`skipped` 的必需 context** | `Golden Case F1 Gate => skipped` 在 10+ 支 PR 上作为"REQ-RED"出现；main 上 `Checker Review (maker/checker) => skipped`（因 `ci.yml:622` 的 job 级 `if` 在 push→main 为 false） | "红/绿"三态须写全：**success / failure / skipped / cancelled / null** 分别列 |
| **`cancelled` 算不算红** | `check-ci-stale-red.sh:53` 与 `check-gate-integrity.sh:718` 均严格 `== 'failure'`；而 `ci-red-baseline.txt` 段头**宣称** 5 类算红 | 文档口径宽于实现口径 ⇒ `concurrency.cancel-in-progress: true` 下 **"取消"是事实上的静默绕过通道** |
| **`git ls-tree -- '*.html'` 静默假零** | 该写法在 git 2.50.1 返回 **0 且 exit=0**；`ls-tree -r 全量 \| grep '\.html$'` = **257** | 凡通配匹配用 `git ls-files '<glob>'` 或全量 grep；**静默 0 最危险** |
