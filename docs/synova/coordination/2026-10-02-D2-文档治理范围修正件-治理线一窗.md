## 4. 层归属（含 E/F 定义与交叉引用）

```
A 入口      → 不变（README/AGENTS/CLAUDE/STATE）
B 决策      → 不变（decisions/**；.html 不适用——决策件只能是 md）
C 长期      → 新增承载：活载体 + 文档面 .html（类 1/5/6）
D 过程      → 不变（不入库）
E 生成      → 新增承载：生成物快照 .html（类 2）；仍适用「三条件同时满足方可入库」
F 出库面    → 【本件新增定义】在库但已出役：归档冻结（类 4）+ 一次性报告（类 3）
              · 判据：路径命中 /archive/ 或根级一次性报告命名
              · 语义：**只读** + 可出库（出库不丢历史：出库前记 sha256 + 出库目标）
              · 与 B 层 archived 的区别：B-archived 是「决策已冻结但仍有指导价值」；
                F 是「已出役的记录」，**不再指导未来**，仅保历史
              · 与 D 层的区别：D 层要求不入库；F 是**已在库**的存量，处置=归档/出库，不是删除
```

**归属的可核判据**：本件 §3 的 6 类 → 4/5 层映射表即判据；实现方式（登记字段 `layer:`）见 §6-C。

## 6. 三闸覆盖面（含与 #931 执行体的逐行对照）

### 6-A 实测：#931 执行体对 `.html` 的行为（本窗实跑）
```
python3 <pr931:validate_doc_contract.py> --repo-root <main树> --files app/new-page.html
  → 闸 3 · 入库闸（核 0 件）；结论: ✅ 三闸全过
同上喂 docs/report/new.html / app/index.html / src/x.ts → 均为「核 0 件 / 三闸全过」
```
⇒ 根因**不是**白名单没写 `.html`（若如此会走 `docs/` 前缀放行、`app/**` 判红），
而是 `gate3_inbound()` 第一行就 `[f for f in files if f.endswith(".md")]` —— **非 md 根本不进判据面**。
**⇒ 纯加白名单解决不了问题**；必须先扩**扫描面**，再加白名单分支。

🔴 **补一层根因（本窗新证，doc-sys 实测 + 我复核）**：#931 的 docstring 写「白名单**从契约文本动态解析**」
（`validate_doc_contract.py:42`），实现却是硬编码常量 `:69 WHITELIST_PREFIX = […]`，全文件 5 处
`DOC-CONTRACT` 全是注释、**从未读契约文件**。⇒ 因此：
1. **在 #931 上直接把 `.md` 扩成 `.html` 是危险的**——因为 `WHITELIST_PREFIX` 里含 `"docs/"`，
   任何 `docs/**.html`（含生成物、含 `coordination/` 过程痕迹）都会命中前缀放行；
2. 这与契约 §3「❌ coordination/ 一律阻断」**自相矛盾**（#931 的 `BLOCKED_HINTS` 只在白名单**之后**才被检查，
   被 `docs/` 前缀先吃掉）。
⇒ **W2 的前置条件**：先让 #931 的白名单**真的从契约解析**（或至少把 `coordination/` 判红提到白名单**之前**），
再谈 `.html` 扩面。**这一条不满足，C-2 不得落地。**

### 6-C 我定的判据（**形态**，不是实现）

**C-1 闸 3 扩扫描面**：`gate3_inbound` 的候选文件集从 `*.md` 扩到 `*.md + *.html`；
**`.yaml/.yml` 暂不并入**（另有登记门禁管；并进来会与 `doc-registry-gate.sh` 重复判据 ⇒ 两套真值源）。

**C-2 `.html` 白名单（闸 3 分支）**——按 §3 分类落判据：
```
✅ 放行: ^docs/.+\.html$                       （C 层文档面；类 5/6）
✅ 放行: ^app/.+\.html$ 且非时间戳命名          （类 1 活载体：产品运行资产）
✅ 放行: ^electron-renderer/.+\.html$
⚠️ 条件放行: ^app/.+-\d{8}-\d{6}\.html$         （类 2 生成物）⇒ 须命中 E 三条件，
                                              否则阻断（这是"生成物不入库"的机器化）
🔴 阻断: 根级 *.html（类 3）⇒ 必须先进 docs/synova/archive/ 或出库
🔴 阻断: 其余路径 *.html
```

**C-3 登记门禁扩面**：扫描面 `\.(md|yaml)$` → `\.(md|yaml|html)$`；**但**：
- `app/**` 与 `electron-renderer/**` 的活载体**免登记**（它们是运行资产，登记台账只收文档）；
- 免登记须以**显式排除规则**落地（不是靠不扫）；
- 同时补 **M-5**：`id` 与 `path` **全局唯一**（含跨分支，见下）。

**C-4 层/出口登记字段**：登记条目建议增 `layer: C|E|F` 与 `exit: keep|archive|outbound|delete`（可为空=keep）。
理由：三层判据（§3/§4/§5）若只在文档里，**无法机器复查**；登记台账是唯一现成的机器面。

**C-5 跨分支 id 撞号的实测（M-5，本窗新证）**：
```
origin/main                    42 条   max=DOC-0123
origin/pr931                   44 条   max=DOC-0133
origin/docs/D1110-…            46 条   max=DOC-0136
origin/docs/D1106-…            46 条   max=DOC-0131
⇒ 同一 id 段（0124…0136）被多个未合并分支并行占用
```
⇒ 现有门禁**只查单文件内唯一**，**不查"已被别的分支预定"**。判据建议：
① 单文件内 `id`/`path` 唯一（本窗实测：main 上 42 条**无重复** ⇒ 此项加严零存量红）；
② 取号参考 = `max(DOCS-REGISTRY.yaml 的 id ∪ origin/main ∪ 未合并分支)`（同 D# 取号器 CT-36 的做法）；
③ 撞号时**拒绝并点名冲突位置**（不是静默复用）。
