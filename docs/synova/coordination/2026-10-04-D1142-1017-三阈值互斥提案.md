## 一、互斥性（实测构造，机器可复现）

```

bash scripts/control-tower/check-pr-budget.sh --files "$FILES"
```

三条棘轮对**同一件事**（"这批变更要不要全部写进声明"）给出**相反**要求：

| 棘轮 | 位置 | 要求 | 方向 |
|---|---|---|---|
| **D708** merge_writeset_gate | `scripts/control-tower/merge_writeset_gate.py`（声明源 = task-state `write_set` ∪ dev doc ∪ brief Q2，取并集） | **声明写集 ⊇ 变更集全集** | 声明**越全越容易过** |
| **G12** Task Scope | `scripts/pre-commit-check.sh:1259-1392`（Q2 include 认领制） | **brief Q2 ⊇ 变更集** | 声明**越全越容易过** |
| **D734** PR 预算 | `scripts/control-tower/check-pr-budget.sh`（默认 `--max-files 12`；`GOV_PREFIX_RE` 路径级豁免） | **变更集 ≤ 12 文件**（治理簿记类路径除外） | **声明全了就超限** |

⇒ 对"同构大批量、零逻辑改动"的变更（例如本体边类型 55 个 JSON 补同一字段，或文档/注册表批量归一），
**遵守 D708/G12 就必须列全 N 个文件，而列全即触发 D734** ⇒ **越守规矩越红**。实测受害：**#948**（1 个 PR，非 13 个）。

**不是"阈值定错了"**：三条各自都合理 —— D708/G12 管**授权与诚实**（防夹带、防越界），D734 管**冲突概率**（大 PR + 长存活分支 = 冲突源）。
缺的是一条**"低风险大批量"的显式通道**：把"同构、零逻辑改动、零新增"这一形态从预算里**有条件**放行。

## 二、提案：路径级口径（三条件，全部机器可判）

命名：**归集型 PR**（batch-normalization PR）。声明段落 `## 归集声明`（PR 正文 + brief 双落，语义同 D1028 `## 死代码清理声明`）。

### 条件 A — 同构 ≥10 文件 且 零逻辑改动
- **同构**：全部变更路径落在**同一仓库前缀**（或同一扩展名类）内 —— 由声明段首行 `- 同构前缀: <path/ 或 *.json>` 指定，机器判 `变更集 ⊆ 该前缀`。
- **零逻辑改动**（可判代理，两条取一）：
  - A1 非代码文件（`.json/.md/.yaml/.yml/.txt`）：逐文件 `git diff --numstat` 的 `added+deleted ≤ 20`（数据/文档类批量改写）；
  - A2 代码文件（`.ts/.tsx/.js/.sh/.py`）：逐文件 `added+deleted ≤ 5` **且** 新增行中不含 `function ` / `=>` / `if (` / `for (` / `class ` / `import ` / `export `（"零逻辑"的最低可判边界）。
  - 任一文件越界 ⇒ **例外不生效**（回落 D734 原判定）。
- **≥10 文件**：`变更集文件数 ≥ 10`（低于 10 件的"小归集"本来就 ≤12，不需要本通道）。

### 条件 B — 零新增文件
- 变更状态**全部为 `M`**：`A`（新增）/`D`（删除）/`R`（重命名）/`C`（复制）**各 = 0**。
- 理由：新增文件是"新写集"（最容易夹带新逻辑）；删除/重命名另有 D1028 逃生口（`## 死代码清理声明`），不混线。

### 条件 C — 完整清单进 PR 正文 + brief（**声明 ⊇ 变更集**，缺一条即不生效）
- PR 正文含 `## 归集声明` 段，逐行 `- <精确相对路径> — <同构依据>`；
- brief 同段落（pre-commit 可读源，复用现有 `--decl-file` / `SYNO_DR_DECL_FILE` / brief 链解析，**不新造机制**）；
- 声明路径集 ⊇ 实际变更集（少一条 ⇒ 不生效 ⇒ D734 原判定 + D708 夹带判定照旧红）；
- 声明中含**不存在**的路径 / 带通配符的条目 ⇒ 不生效（防"写一条洗全场"，同 D1028 语义）。

### 附加收敛（防开大口子）
- **硬上限**：豁免仅解除"12 件封顶"，仍需 `≤ 40 件`（超过 ⇒ 必须拆 PR）；上限写进脚本常量，改动须 CTO 批。
- **路径级而非规则级**：只解除 D734 的计数，**D708/G12/D734 的其余判据（单域、声明一致、Q2 认领）一条不减**。
- **例外必须显式**：无 `## 归集声明` ⇒ 一切照旧（**不静默放行**）。

## 三、让步序（优先级序，显式登记 —— 谁让步，白纸黑字）

```
优先级 1（永不让步）  D708 merge_writeset_gate —— 授权口径：声明 ⊇ 变更集。
                      让步 = 允许夹带，属 M2 族事故（#449 夹带 51 文件 / #442 夹带 6 文件）。
优先级 2（不让步）    G12 brief Q2 范围 —— 提交粒度声明完整性。
                      它对本场景**可满足**（把 N 个文件写进 Q2 即可），故无让步必要；
                      只是它逼着声明全，从而与 D734 对撞。
优先级 3（唯一让步者）D734 check-pr-budget —— 且仅对满足 A∧B∧C 的归集型 PR 让步，
                      让步范围 = 仅解除 12 件封顶（仍 ≤40），其余判据全保留。
优先级 4（本提案不动）三阈值本体（12 / 声明语义 / Q2 语义）—— 卡面 Done 硬要求，一字不改。
```

**为什么让步的是 D734 而不是别的**：D734 的立法目的 = 降低合并冲突概率（`冲突概率 ∝ 改动大小 × 分支存活时间`），
而同构大批量的**风险形态不同**：文件多但每文件改动极小、无新增文件、且全部显式声明 ⇒ 冲突面被"同构 + 零新增"收敛；
D708/G12 的目的（诚实与授权）与"批次大小"无关，**一旦让步就改变门禁性质**。

## 七、送审点（K3）与裁决点（CTO）

**K3 过审**：① 条件 A 的"零逻辑改动"代理判据是否足以防"用归集通道夹带逻辑"；② 条件 C 的"声明 ⊇ 变更集"是否真的拒绝洗白式声明（要求反例）；③ 让步序是否与 D708/D734/D1028 既有语义冲突。

## 八、边界与风险（如实登记）

1. **不是"放宽预算"**：例外只对 A∧B∧C 三条件同时成立者生效；无声明 ⇒ 一切照旧。
2. **代码文件的"零逻辑"是近似可判**：A2 用行数 + 关键字代理，不能证明语义无逻辑 —— 故 A2 阈值取到最紧（≤5 行）；若 K3 认为不够，可把代码文件整体排除在通道外（只允许数据/文档类），**这一档由 CTO 选**。
3. **同步风险**：本提案不解决"长存活分支"本身（D734 的另一半）——归集型 PR 仍应尽快合并。
