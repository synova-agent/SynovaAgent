## 三、裁决选项（三条路线，含推荐）

### 甲案（推荐）出库 + 证据上移到**提交自身**
- **新载体**：commit trailer，由 `synova-commit` 在**门禁通过后、commit 之前**写入消息体：
  `Synova-Evidence: pre-commit PASS gate=13 sid=<sid> tree=<git write-tree 的树对象 sha>`
- **对账闸门改线**：`check-bypass-log.sh` 判据改为 —— `<base>..HEAD` 的非 merge 提交，**必须**
  (a) 带 `Synova-Evidence:` trailer，**或** (b) 命中**冻结历史账本**（出库前最后一个 commit 的 `.claude/bypass.log`，经 `git show <freeze-ref>:.claude/bypass.log` 读）。
  两者皆无 ⇒ exit 1（与现状同强度）；不可判（git/ref 不可用）⇒ exit 2（沿用现状 fail-closed）。
- **为什么 tree 绑定**：现状"每提交有 HASH 行"能抓 amend（amend 后 HASH 变、账本无记录）；
  trailer 若只写 sid+时间戳，amend 会**保留** trailer ⇒ 漏拦。绑定 `tree=<index-tree-sha>`（commit 前即可算出）
  ⇒ amend 改了内容 ⇒ 树变 ⇒ trailer 与 `git show -s --format=%T HEAD` 不符 ⇒ **红**（强度 ≥ 现状）。
- **本地 24h 绕过窗口**：读 per-session 账本 union（`.sessions/*/bypass.log`），本地语义不变。
- **代价**：改 3 个脚本 + 6 个测试；跨机证据链**更强**（证据随提交走，不依赖各机本地文件）。
- **已知缺口（如实登记）**：裸 `git commit`（不经 synova-commit）无 trailer ⇒ 红（**与现状等价**：现状裸提交也无 COMMITTED 行）。

### 乙案 保留 tracked，但"每会话一文件"（`.claude/bypass/<sid>.log`）
- ❌ **不推荐**：① 同会话跨机仍冲突（Win/Mac 同分支同名文件）；② **PR 仍会带运行期产物变更**（每个 PR 新增自己会话的日志文件）⇒ 不治根；
  ③ 出库的收益（消影子提交 / 消审计噪音）一分都拿不到。

### 丙案 出库 + **CI 对账降级**（不看证据链，仅本地有账本时对账）
- 代价：D331 的初衷（发现 amend / 裸提交）在 CI 层**失效**，属地地道道的**审计降级**；
- 仅在 CTO 认为 "D331 价值 < 改线成本" 时选它。若选丙，`verify-d703.sh:105-114` 的 DS8a 也必须同步（否则假绿）。

## 八、残留不确定性（如实登记，不掩盖）

1. **GitHub 侧的"直接证据"仍缺一格**：本件用"本地带驱动干净 + 无驱动必冲突 + 交集恰为该文件"三条推出服务端行为，
   **未**取得 GitHub 自己的冲突文件清单（API 不暴露）。若要直接证据，可在 CTO 授权下做一次**受控实验**：
   开一个只追加一行 `bypass.log` 的临时分支 → 观察 PR 是否 DIRTY → 立刻关闭（成本 = 一次 CI 触发）。
   **治理线不擅自开实验 PR**（本卡未授权，且属共享仓库噪音）。
2. **#1001 的 DIRTY 未能解释**（交集为空）⇒ 存在至少 1 个与本文件无关的冲突源，登记备查。
3. **`gh pr list --json mergeable` 会返回陈旧值**（#1006 实测：初查 CONFLICTING、续查 MERGEABLE）——
   本条同时是对**任何基于 list 接口的统计**的告警：此前"66 对互合"等口径若用 list 数据，需按此复核。
4. **`merge=union` 的语义边界**：union 驱动只保证"行级并集"，两行为同一 HASH 的重复行需靠"每行含唯一 HASH"约定去重；
   出库后该约定随之退役（不再有跨分支行级合并需求）。
