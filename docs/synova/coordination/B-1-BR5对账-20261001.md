> CTO 已复核到确切行：`src/agent/tool-loop-executor.ts:244` `pruneForPrompt(JSON.stringify(execResult))`、方法签名 `(text: string)`（`:78`）。

### 11.1 触发窗口（可算）

| 量 | 值 | 来源 |
|---|---|---|
| `PRUNE_MARKER` 长度 | **39** 码点 | 我方 `:23`（与 rc.2 `config.ts:7` 逐字节一致） |

### 11.2 🔴 真实形状输入的实测结果（**可复现**）

复刻我方切法（`Array.from` = 码点，`:134-137`），喂**真实工具返回的形状**（`read_document`，`builtin-tools.ts:152-183`，返回 `{documents,count,totalDocs,orgId}`）：

```
输入 : {"documents":[{"type":"doc","name":"N"*40,"docType":"pdf"}, …], "count":…, "totalDocs":…, "orgId":…}
       长度 = 7023 码点  ⇒ 落在触发区间 [5159, 8192] ✅ 触发
输出 : head(4096 码点) + MARKER + tail(1024 码点)，长度 5159

🔴 json.loads(输出) 失败：JSONDecodeError: Expecting value: line 3 column 2 (char 4099)
   切点处 = ...'docType": ' + '\n\n[... tool result middle pruned ...]\n\n' + '"docType": "pdf"}, {"type": "doc", "name"'...
```

**两条独立的破坏**：
1. **不是合法 JSON** —— 切点落在 JSON **字符串字面量内部**（`"docType": ` 之后），marker 被塞进一个**未闭合的引号里** ⇒ 任何 `JSON.parse` 该 `content` 的下游/复读器直接抛错。JSON 没有自描述边界，**码点硬切必然可能切在字面量内**。
2. **语义自相矛盾**（即使忽略第 1 条）—— tail 从 `"docType": "pdf"` **中途**开始，于是输出里 **`"docType"` 出现两次**（head 段一个被截断的、tail 段一个完整的）。模型看到的是**同一份文档对象里一个字段说了两遍且互相冲突**。

### 11.3 为什么回归测试没抓住（**断言面选错，非断言少**）

`tests/llm/tool-result-pruner.test.ts` 的输入全是**合成重复串**（`makeLongText`、`'😀'.repeat(6000)`），断言的是长度上界 / marker 出现一次 / 头尾逐码点相等 / 无孤立代理对。
⇒ **`grep -c "JSON.stringify"` = 0：没有任何一条用例喂过真实结果形状，也没有任何一条断言"输出仍可被 `JSON.parse`"**。
**结论**：这正是「测试通过 ≠ 生产路径正确」——用例覆盖的是**我实现的切法**，不是**生产喂进来的数据形状**。

### 11.4 影响范围（按确定性分级，**不夸大**）

| 级别 | 断言 | 证据强度 |
|---|---|---|
| ✅ **确定** | 凡 `total ∈ [5159, 8192]` 的输入，修剪后**不是合法 JSON**；切点落在字面量内时还会产生**重复/冲突字段** | **已实测复现**（本节 10.2） |
| ✅ **确定** | 我方栈当前**无** `ContentBlock` / 多模态工具结果 ⇒ "富块被吃"**不成立**（我 §二-2 的原表述已更正） | `providers/types.ts:10,46` + 零命中 grep |

### 11.5 最小修复方向（**本卡不改，仅给方向**）

1. **按形状感知**：`pruneForPrompt` 接 `ContentBlock[]`（rc.2 `pruneContent` 形状），只切 `text` 块；
2. **或至少按字段感知**：在 `JSON.stringify` **之前**对**已知大字符串字段**施加预算，保证输出仍是合法 JSON；
3. **补一条"输出可 parse"断言**：凡修剪发生，`JSON.parse(out)` 必须成功（或显式声明输出为非 JSON 的文本协议）；
