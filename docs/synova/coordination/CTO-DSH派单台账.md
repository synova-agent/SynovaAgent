## 二、派单第二问：架构能不能这么设计？（`01-可扩展架构`★ 宪章级）

**三类可直接否决**：❌ 只能我们改、客户不能改的扩张点（除非内核层）❌ 注册成功但不验证生效 ❌ 让客户扩展 import 内核实现
**三层能力**：可扩展 → 免编程 → **可验证（命门）**
**每个扩展点三问（必须机器判定）**：① 加了吗（存在性）② 接上了吗（生产调用点）③ **生效了吗（端到端跑一次、结果里有它）** —— **判据要"穿生产入口的用例"，不是 grep 命中**
**五个"能注册但没生效"的实测**（派单时当作反面清单）：专家 6/6 degraded ｜ 边写库零校验（可写 `NONEXISTENT_EDGE`）｜ 字段映射 0/8 命中本体 ｜ `loadCycles` 目录缺失静默返 0 ｜ 哨兵 20/45 不查 store
**五条约束**：分层（谁能扩展）｜三问可机器判定｜非技术用户三护栏（语法/语义/**影响预告**——第三道最值钱）｜内核与扩展**物理可见**（`extensions/`+`expert/` vs `src/`，客户物不许 import 内核）｜一切可扩展物**版本化+可追溯**（定义改动留痕 + 诊断产物记录所用版本）
**一句话**：能加，但加完必须能证明生效；能改，但改完必须能回答"上次为什么不是这样"

## 三、派单第三问：涉及"多人用同一套 agent"吗？（`02-一致性保障`★ 宪章级）

**五层**：知识一致 ／ 上下文一致 ／ 标准一致 ／ 目标一致 ／ **反馈一致（★ 本文补，连决策闭环）**
**四机制**：① **角色预设包（Role Pack）** ② 知识分层（四层，不是"一个统一库"）③ **输出契约（可机器校验）** ④ 培训替代
**前提纠正**：一致性 ≠ 相同输出 ⇒ 目标 = "每个岗位在各自标准下产出**可预期、可复核**"
**四个症状的真实归因**：全不是"agent 不聪明"，是"环境没配好"（知识供给缺失／上下文没显式化／缺输出标准与复核）
