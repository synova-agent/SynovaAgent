## 一、两侧分工（**唯一差异 = CTO 角色**）

| 环节 | Mac 侧 | Win 侧 |
|---|---|---|
| CTO 角色（派单·规格·收件闸·合并 PR·台账·双仪表盘） | **Mac-CTO** | **Codex** |
| 开发 | DSH 小队（同构） | DSH 小队（同构） |
| 独立审计 | K3（独立仓） | K3（**Win 侧独立仓**，maker 无写权） |
| 体系/门禁/文档事实源 | **Mac 侧唯一** | 只读 + 提请求卡 |

**域归属唯一源 = `docs/synova/coordination/ownership.yaml`**（42 条 glob、顺序求值最后匹配者胜、`**` 宽兜底 + Mac 例外在后、`domain_neutral` 豁免、退出码 0/1/2 fail-closed）。
现行模型：**win = 兜底**（`src/**` 未命中例外者 + `extensions/**` + `packages/**` + `synova_worker/**` + `docs/plans/**`）；**mac = 例外集**（哨兵线 `src/{sentinel,cron,mcp}` + 控制塔/流程 `scripts/*` + 协调与规范文档 `docs/synova/{coordination,product-lines,dispatch,authority,research,project}` + 工程面 `.github/workflows`/`VERSION.md`/`.claude`/`.dsh`/`electron*`）；**k3 = `scripts/audit/**` + `docs/synova/audit-reports/**`**。
⚠️ **不得在未读该表的情况下另写一份归属表**（2026-09-24 已犯过一次）。

## 二、开发模式（**两侧同构，硬要求**）

1. **必须用 Agent Teams 小队**：队长 + ≤2 编码 + **1 独立自验**（自验不得由编码兼任）；**队长不下场写码**；`maxMembers=4`。
2. **严禁用子代理代替小队**：子代理无共享任务板/mailbox/持久身份 → 无法独立自验、无法留运行记录 = 作者自判通过（M3 型事故）。
   判定：只队长在跑 / 成员未运行 / 无共享任务 id / 写集未逐人拆 / 自验由编码兼任 → **退回**。
3. **先 plan 后执行**：开工第 0 步进 plan 模式产出六项（依赖图／逐文件写集／三路径+变异体夹具设计／失效条件／前置冻结清单／可复制验收命令），**停下等 CTO 复核放行**再动手。
4. **WIP=1**：每侧同一时间只允许 1 张在制代码卡；**前一张未过收件闸不放行下一张**；退回只退那一张。
5. **回执必含「团队成员运行记录」**（成员名 · 状态 · token · 共享任务 id 与状态）。

## 三、验收链（执行方一律不判"通过"）

```
成员独立自验 → 队长出「自验结论」→ CTO 收件闸（四判据）→ K3 终审
```
**收件闸四判据**：① 锚定三问回答 ② 声称↔证据逐条对应（命令 + 原始输出）③ **反例夹具"改坏即红"** ④ 团队成员运行记录。
**有条件通过 = 未通过**。

## 四、五条口径纪律（2026-09-23/24 血的教训，逐条都有实例）

1. **负面断言必须写明搜索范围**（"零命中"= 在什么范围内零命中）。
2. **判断面用 `git ls-files`，grep 限定 `src/`**（`lib/` 被 gitignore：工作树干净 ≠ 没有产物）。
3. **计数必须带「命令 + 排除项 + 截至时刻」**（同一对象出现 710/307/711 三个数的教训）。
4. **路径写全**（DSH 源码树是 `packages/<组>/<包>/…` 两层）。
5. **引用必须可核验**：`path:line` + 原文片段；**被引文件 mtime 晚于引用者 → 该引用自动降级"待复核"**。

## 五、红线（违反=事故）

不碰 `scripts/audit/**`、不写审计标准、禁止自我审计；禁 `--no-verify`／`git stash`／force push 共享分支；
任务一律在 `.synova-wt-*`（**名字带侧前缀防撞号**：`cto-` / `squad-`）；**主工作区只做同步与协调**；
K3 独立仓 maker 侧（含 CTO）无写权；**同类错误第二次出现 → 立即升级创始人**。
