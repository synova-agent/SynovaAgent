## 二、新发现（本批实测，需处置）

### P0-1 `.claude/bypass.log` + GitHub 不执行 merge driver → 全员 PR 恒冲突（treadmill）
- **现象**：push 成功、PR head 已更新，但**完全没有 CI run**（`check-runs=0`、`actions/runs?branch=` 无新条目）；`GET /pulls/N` 返回 `mergeable_state=dirty`。
- **根因**：`refs/pull/N/merge` 造不出来（冲突）→ `pull_request` workflow 不启动。而冲突**唯一来源**是该账本文件：
  ```
  merge-base 两侧都改的文件 = 仅 .claude/bypass.log（我方 16 文件 / main 4 文件，交集就它）
  ```
  仓内 `.gitattributes` 有 `merge=union`（本地合并干净），**GitHub 服务端不执行自定义 merge driver** → 只要两侧都动过它就判 conflict；且每个 session 的 post-commit hook 都在追加它 ⇒ 必然两侧都动。
- **代价**：本批为此空转 4 轮（close→reopen 无效、API 重算无效、`merge-tree` 干跑证明零冲突也没用），只有"再并一次 main"能临时解除，main 每次推进即复发。
- **止血**（已用）：把该文件整体对齐 main 侧（`git checkout origin/main -- .claude/bypass.log`）**并对齐后不再提交它** → 我方相对新 merge-base 零改动，main 单侧继续变不再冲突。物理确认：`HEAD` 与 `origin/main` 该文件 sha 逐字节相同。
- **根治（待派）**：bypass.log 按 session 分片 或 移出 git 跟踪；同时修 `synova-commit` 不再把它卷进提交。

### P0-2 `merge_writeset_gate.py` 两处判据缺陷
- **(a) `DID_RE = [Dd]\d+` 从任意文本贪婪取号**：实测把 GitHub 自动 merge 提交 SHA 的子串当任务号 —— `Merge e5164463…bd90144212…` → **"D90144212"**；另一轮 → **"D957"**。→ `find_declaration_files` 找不到声明 → 声明写集为空。
- **(b) 降级分支短路豁免**：`merge_writeset_gate.py:381-390` 在 `declared` 为空且变更含源码时，**在豁免判定之前 `return 2`** → **PR 正文 `## 写集豁免` 通道（门禁自称的修复方式③）在该路径完全不可达**。实测：PR #768 正文写了 9 行精确豁免，CI 仍报"degraded 阻断 + 7 文件夹带"，且输出里连"豁免 N 条"都不打印。
- **临时绕开（未改门禁）**：给卡正式发号 D1007 并让**分支名携带 D#**（`branch` 是推断第一优先级）→ 实测 `D# 推断来源: branch → D1007`、`✅ pass`。
- **根治（待派，须过 K3）**：排除自动 merge/shadow 提交；DID 需词边界；降级路径应先消费豁免通道再判定。

### P1-1 `synova-commit` 内建 auto-push，无 `--no-push`
- 派单要求"不推送、等 CTO 审 diff"，工具在 commit 成功后**自动 push 分支**（D307 只对 `session/<sid>` 跳过）。
- 后果：① 工具替执行方越过收件闸；② 它把 post-commit 的 bypass.log 噪声带上分支，直接促成 P0-1。
- 修法：`--no-push` 开关 + worktree 默认不推 + 账本文件不进提交。
