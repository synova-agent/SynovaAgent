## A2v2-3. 🔴 方法论产出（比功能本身更值得留）

### (1) 「拆一道护栏仍绿」≠「保护有效」——必须测**承重路径**
verifier 的 M5 变异体实测：**仅**去掉 DENY_EXACT 收紧块（`:501-505`）**不会**让 `B12` 变红 —— 因为 DENY_EXACT **单独**命中时被**另一条分支** `:491 elif [ "$DR_DENY_RE_N" -eq 0 ]` 挡住。
⇒ 实现实际上有**两道独立护栏**；只有构造 **`B19`（DENY_RE + DENY_EXACT 混合）** 让 `:491` 不成立，收紧块才成为承重，M5 才被抓住。
**通用教训**：判"保护有效"必须**逐条拆护栏并测承重路径**；只拆一条得绿，不能推出保护有效。

### (2) 变异体的判别可能**不在出口码**，而在**输出判据**
实现者自建的第 3 个变异体（去掉 DENY_EXACT 判据）**出口码仍是 1**（该夹具本就跨域）⇒ 判别落在「旁路封堵行是否存在」。**只断言 exit code 的变异体会漏判这一类。**

### (3) 自验员自查出 **9 条自己的夹具缺陷**（FIX-1..FIX-9），最典型两条
- **`seq -w 1 5` 对个位数不补零**（产出 `mod1` vs 声明侧 `mod01`）⇒ **10 条夹具假红**。若不做非冻结预跑，就会在冻结样本上报 10 条"不通过"，**全是假警报** —— 而假警报会让人开始怀疑真警报。
- **原因提取器「空 == 空」= 假 PASS / 假 FAIL**（已修 + 加空提取守卫）。
⇒ **非冻结预跑是必要环节**；且需在结论里明确标注"预跑不是结论"。
