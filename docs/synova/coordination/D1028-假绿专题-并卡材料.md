## 二、本卡可并的三条（**逐条原始输出，已独立复现**）

### A. P6 —— `check-pr-budget.sh --base <ref>` 在 `HEAD == ref` 时恒空（**检查未执行==检查通过**）
**发生场景**：沙箱里 `HEAD` 停在 `main` 分支，跑 `--base main` ⇒ `git diff main...HEAD` 为空 ⇒ `✅ ① 变更文件数 0 ≤ 上限 12` + `✅ PASS` + `exit 0`。
**原始输出**（`docs/synova/product-lines/evidence/D1028-A2/00-前提冻结实测-原始输出.txt`，末尾留撤回说明）：
```
### 场景1: 纯删 src/** 14 件（判据① 的形态） ###
$ git diff --name-only --diff-filter=ACMR $B...HEAD
   → 行数: 0
$ bash scripts/control-tower/check-pr-budget.sh --base main
   ── PR 预算门禁（D734）: 基线=main 上限=12 文件 / 落后阈值=20 ──
     ✅ ① 变更文件数 0 ≤ 上限 12
     ✅ ② 无变更文件 → 域校验跳过
     ✅ ③ 落后 main 0 个提交 ≤ 20
   ✅ PASS PR 预算内（0 文件）
   => exit code: 0
```
（该批数据**已被队长判定无效并撤回**，因为沙箱 `HEAD == main`；修正版见 `01-P6-修正版-判据①②前提实测.txt`，每个沙箱先 `git checkout -b feat`。）
**为什么算假绿**：报的是"变更文件数 0"（一个数字），**不是**"未取到变更集"。**执行方看不出自己没被检查**。同一命令在分支离开 base 后**真跑**（本卡收口时实测 `--base origin/main` → `ⓐ 不满足 / ✅ 3 ≤ 12 / EXIT=0`）。
**可并的判据**：`--base` 解析成功后必须**显式断言**"变更集非空 或 明确标注'相对 <ref> 无差异（可能 HEAD==ref）'"，不得静默输出 0 文件通过。

### B. L1-b —— `brief_parser.parse_q2` 的 exclude 臂**恒空**（写 `###` 就失效）
**根因**：`:90` / `:94` 只认**行首** `不做什么` / `做什么`；`### 不做什么` 不命中 ⇒ `in_exclude` 永不置位 ⇒ 所有排除项被当 include 收进去，**排除机制静默失效**。
**独立复现（队长亲自跑，两个探针文件只差一个 `###`）**：
```
$ python3 scripts/control-tower/brief_parser.py --q2-exclude /tmp/q2probe.md    # 含 ### 不做什么
  → exclude 行数: 0
$ python3 scripts/control-tower/brief_parser.py --q2-exclude /tmp/q2probe2.md   # 无 ###
scripts/audit/**
  → exclude 行数: 1
```
**为什么算假绿**：G12 的"排除项禁止修改"那一臂**看起来在跑**（有 ✅ 输出），实际对采用 `###` 层级的 brief **恒过**。本卡 brief 初稿即为此形态（附录 §C.3 已认领）。
**可并的判据**：解析器必须对"有 `不做什么` 语义但未被识别"给出**非零告警**（例如：Q2 段内出现 `不做什么` 字样却 `exclude` 为空 ⇒ 显式 ⚠️/红）。

### C. L7 —— D2 登记门禁在"已提交"状态下**输入恒为 0**（CI 上恒 no-op）
**根因**：`doc-registry-gate.sh` 只扫 `git ls-files --others`（untracked）∪ `git diff --cached --diff-filter=A`（staged 新增）⇒ **文件一旦 commit，两个集合都空**。
**独立复现（队长亲自跑，本工作树已提交状态下）**：
```
$ bash scripts/doc-system/doc-registry-gate.sh
── 汇总: 检查 0 个文档，0 个未登记 ──
  ✅ 登记门禁通过
EXIT=0
```
**为什么算假绿**：这是"**本地软提示 + CI 转硬**"（D515/D516 分层）承诺的**落空**——本地能拦（staged 时），CI 侧**没有输入可判**，于是 CI 上的 ✅ 是"没检查"而非"检查通过"。
**可并的判据**：CI 侧必须改为"扫**本次 PR 变更集**里的 `*.md|*.yaml`"（而不是 untracked/staged），否则该门禁在 CI 上永不可执行。

## 三、结构性建议（供专题卡取舍，**不是结论**）

1. **给"跳过"一个独立标记**：`⏭ SKIP`（附原因）与 `✅ PASS` 必须是**两种输出**。本卡三条的共同点正是"跳过被渲染成 ✅"。
2. **给每条 ✅ 附"检查对象计数"**：`✅ 检查 N 个对象`。N=0 时必须降级为 SKIP 或 ⚠️。这一条能一次性覆盖 A/B/C 三条（本卡 P6 的 `变更文件数 0` 已经是计数，缺的是"N=0 时不得判过"）。
3. **判别性夹具准入**：凡新增/修改的检查，必须附"**换成必然违规的样本仍必须红**"的夹具；只有正向绿样本的检查不得入库。（本卡 v1/v2 已按此办：变异体 4 个 + 声明夹具 6 条。）
4. **禁 grep 计数当验收判据**（本卡实锤 INJECTED-RED 自指反例）：需要"零残留"断言时，必须限定**可执行口径**（如 `--include='*.sh'`），或改用"执行该对象必然报错"的行为判据。
