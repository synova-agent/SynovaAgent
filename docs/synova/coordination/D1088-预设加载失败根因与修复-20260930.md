# D1088 · 预设「加载失败」根因与修复（2026-09-30）

> 触发: 创始人做 T8 空会话测试时，设置 → Agent 预设 里「📚 山河研究院·线研究员」显示红标**加载失败**（同屏 `liangshen` 也失败）
> 结论: **研究员那条是我建包时的缺陷，已修**；**liangshen 是存量坏件，与本次改动无关**

---

## 一、机制：UI 的红标从哪来（源码实证）

1. 客户端字典 `@deepseek-ai/dsh-client-ui-agent-preset/lib/client.js`：`brokenBadge: "加载失败"`，渲染条件 `row.broken !== void 0`。
2. 宿主 `@deepseek-ai/dsh-agent-preset-registry/lib/index.js`：
   - `list()` 对每个预设调 `await this.diagnostic(record)`，非空则并入 `{ broken }`；
   - `async diagnostic(record)`：`audit = auditRows(tree)` → 返回 `[...audit.failed, ...audit.pending].join("\n")`；
     **即：预设挂载树里「失败」或「挂起(pending)」的行，就是 broken 的原因**。
3. ⇒ 红标＝该预设的某一行**没能挂上**，不是「预设没注册」（注册表 `listConfigs` 里它一直在，19 个 preset）。

## 二、研究员的根因：`tool-workflow` 缺它的 runtime

**对照实证（全 15 个已装 @local 预设）**：

| 预设 | `tool-workflow` | `workflow-ptc` | 状态 |
|---|---|---|---|
| **shanhe-researcher** | ✓ | **—** | ★ 加载失败 |
| liangshen | ✓ | ✓ | ★ 加载失败（另有原因，见 §四） |
| 其余 13 个（含 synova-main-cto / shanhe 四线 / securities-research 等） | ✓ | ✓ | 正常 |

⇒ **本件是全部预设中唯一「有 tool-workflow、无 workflow-ptc」的一个**，也正是两个失败件之一。
`workflow-ptc`（`@deepseek-ai/dsh-workflow-ptc`）是 `tool-workflow` 的 workflow runtime；缺它则该行挂起 → 整包判 broken。

**修复**（2026-09-30 已执行）: 在 `delegation` 组内、`tool-workflow` 之前补一行
`- id: workflow-ptc / name: '@deepseek-ai/dsh-workflow-ptc' / config: { provider: spawn }`，
写法逐字对齐主 CTO 包。

**验证**: 修后 `delegation` 组行集与 `synova-main-cto` **完全一致**（`tool-subagent-control / -list-agents / tool-subagent / -fork / workflow-ptc / tool-workflow`，差集为空）。
安装件是**软链**（`profiles/desktop/node_modules/@local/dsh-preset-shanhe-researcher → /Users/wane/src/dsh-preset-bundles/shanhe-researcher`），改源即生效，无需重装。

**待确认**: 刷新「设置 → Agent 预设」后红标应消失（`list()` 每次重新 diagnostic）。**若仍在 → 报我**，说明还有第二处 pending 行。
