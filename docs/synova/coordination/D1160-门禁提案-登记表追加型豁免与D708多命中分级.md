## 一、豁免提案：`docs/authority/DOCS-REGISTRY.yaml`「追加型」

### 1.1 病根（第一性原理）

- **现象**：D708 `merge_writeset_gate.py` 把"共享文件"按**互斥**处理 ⇒ 多 PR 同改一张登记表即判"写集重叠"，只能串行。
- **本质**：**登记/清单类文件是追加型数据结构**（append-only log）——两个 PR 各自**追加一条**在语义上**可交换**（commutative），不构成语义冲突；门禁把"同文件"误当"同语义面"。
- **收益面**：`#1114` 写集重叠 **14 处、14/14 全部只撞该表（独占）** ⇒ 该表是它的**唯一**阻塞源；`#1079` 全量重叠 **30 处**（13 撞该表 + 17 撞 `ci.yml`）。
- **代价实证（撞号面）**：本席实测 **6 个在飞 PR 各自独立认领同一批 `DOC-` 行键**（`#1132`/`#1114`/`#1000`/`#948`/`#945`/`#794` 均含 `DOC-0144`；**最高已认领到 `DOC-0185`**）⇒ 无"行键求交"机制时，台账合并后必产生**重复 id**（§1.5.3 即为解法）。

### 1.3 五条硬约束（CTO 定稿措辞）+ 技术前置

1. **① 只允许追加、禁改既有行**
2. **② 不得插入任何历史节块内部** —— **绿条件（正例）：新增节点 / 新条目落点 ∈ EOF 或最新节块尾部**（**CTO 2026-10-05 已裁 = 路线 ㈠**；见 §1.4.a / §1.4.b）
3. **③ 冲突时编号小者先 rebase**
4. **④ 只对登记/清单类追加生效，不得用于语义行改动**
5. **⑤ 只对 `docs/authority/DOCS-REGISTRY.yaml` 生效，不得外推**（**每次外推须重新举证实测 numstat 纯追加**）

**技术前置（CTO 采纳）**：**`NUMSTAT` 删除数 = 0** 才豁免（"纯追加"是**前置条件**，不是假设）。
依据 N2：15 个触达 PR 中 **2 个含删除**（`#948` `-4`、`#794` `-1`）⇒ 追加型**不是该表当前全貌**。

**K3 判定**：`D1160 / #1146 = CONDITIONAL PASS`；**P1 = 豁免三条件可绕** —— 追加**第二个顶层 `documents:` 键**时：**零删除 ✅**（① 过）、**无 `id` 冲突 ✅**（③ 过）、**落点合法 ✅**（②/㈠ 过），但在 **PyYAML last-wins** 语义下**整体覆盖既有登记** ⇒ **静默丢失全表**。

**为什么原三条判据抓不到**：① 只看 `NUMSTAT`/hunk（"新增一个键行"满足 `deletions==0`）；② 只看**落点**（EOF 追加合法）；③ 只看**行键 `id:` 求交**（新块内 `id` 与 base 不重复）⇒ **三者皆为"行面"判据，均不审视"结构面"**。

**新增断言 ⑥（本件采纳；落地卡必须实现，本件不实现代码）**

| # | 断言 | 机器判据（**零依赖，行级**） | 失败行为 |
|---|---|---|---|
| ⑥-1 | **顶层键集合不变** | 取 `BASE-REF-TEXT` 与 head 的**顶层键序列**（正则 `^[A-Za-z_][A-Za-z0-9_-]*:`，**列 0**）⇒ 两者**集合相等** | `exit 1` + 点名 `key-set-change` |
| ⑥-2 | **无重复键** | 同一层级**同名键只许出现一次**（同一检测器输出的序列**无重复**；实测复现：非法样例序列 = `['documents','documents']`） | `exit 1` + 点名 `duplicate-key` |
| ⑥-3 | **语义键交集为空** | 新增条目的语义键取值（`path` / `name`）与 base 既有取值**交集为空** | `exit 1` + 点名 `semantic-key-collision` |

**问题**：执行方见 `exit 2` 会理解成"**门禁自身坏了**"，而本例实为"**你的号被占了**（可修）"⇒ **三态语义被误用**。

### 4.2 分级规则（CTO 裁决，核心）

对多命中候选集合 `C`，逐条以 `git cat-file -e <merge-base>:<relpath>` 判其是否存在于 **base**：

| 情形 | 判定 | 退出码 | 语义 |
|---|---|---|---|
| `C` 中存在**来自 base** 的候选 | 「**号码已被占用**」= **你的问题** | **`exit 1`** | 可修：改号/让号（走 `alloc-task-id.sh --check-id <D#>` 只读校验） |
| `C` **全部来自本分支** | 本分支自造同号多声明 ⇒ 检查/分支状态异常 | **`exit 2`** | fail-closed：收敛为一份 or 修夹具 |
| `\|C\| == 1` | 单命中 | 走**现行**语义（0/1 依声明对账） | 不变 |
| `\|C\| == 0` | 零命中 | 走**现行**"声明源为空"诊断路径 | 不变 |

**base 口径**：以 `--base` 解析出的 **merge-base commit** 为准（现行输出已打印 `merge-base <sha>`），**不是** `origin/main` 字面——避免 `--base` 指向他处时判定漂移（遵 §0.2 H1：**判据只读 git 对象，禁读工作树**）。
