## 〇、一句话

一个 PR 从「它声称的写集」到「真正进入 main 的文件集」之间不许出现夹带；出现即**红并逐文件点名**。

## 一、立项依据（M2 族三次实证）

| 事件 | 事实 |
|---|---|
| PR #449 | 夹带 D603，共 51 个文件进 main |
| PR #442 | 夹带 6 个文件进 main |
| D593-FIX | 声称已提交，实际未提交（反向：声称做了实际没做） |

三次的共同结构：**「作者声称的变更范围」与「实际变更范围」不一致，而现有门禁都看不见这一格。**

## 二、触发点（spec Q1）

**选：合并前（PR job），`merge-base(origin/main, HEAD)..HEAD`。**

| 方案 | 语义 | 为什么不是它 |
|---|---|---|
| 合并后（main push job 对账 squash 结果） | 事后发现已污染的 main | **只能报告，不能阻止**。与目标「夹带文件**进不了** main」直接矛盾 |
| 合并前（PR job，merge ref / merge-base） | 在进入 main **之前**判定 | 选它。可与 GitHub 必需检查绑定，物理阻断合并 |

**与现有 gate 的边界（严禁重复造）**：`ci.yml` L51-57 的 `verify-parallel --ci-pr` 已做「**本 PR 变更集 × 已合 PR 的写集**」——那是 **inter-PR**（两个 PR 撞同一批文件）。本 gate 做的是「**本 PR 变更集 × 本 PR 自己的声明**」——**intra-PR**（本 PR 里混入未声明文件）。两者正交，触发点同为 PR job，**共存不替代**。

顺带：`main` / `master` push 时本 gate **跳过**（此时 PR 语义已消失，且 `docs_only` 判定在 main push 上通常已跳过本步骤）。

## 三、声明源与权威顺序（spec Q2）

| 序 | 源 | 解析方式 | 特点 |
|---|---|---|---|
| S1 | `task-state/<D#>.json` 的 `write_set` 数组 | 直接读 JSON | 结构化、机器可读（新可选字段） |
| S2 | dev doc `docs/plans/codex/implementation/SYNOVA-IMPL-*<D#>*.md` 的写集表 | **复用** `devdoc_writeset.py --extract` | 已有解析器，零新代码 |
| S3 | task brief `.claude/task-briefs/*<D#>*.md` 的 Q2「做什么」 | **复用** `brief_parser.py --q2-include` | 已有解析器，零新代码 |

**多源同时存在 → 取并集**，并逐条打印「该条目由哪个源收录」（输出里可审计）。
理由：三者都是**作者自己的声明**。取交集会把「在 S2 声明、S3 未列」判成夹带，属对声明语义的误读。

**D# 推断**：分支名 `fix/D708-…` 优先 → 回退最近提交 subject 的 scope（`chore(D705):`，D328 本来就强制）。

**缺失时怎么办**：
- 三源皆无声明 **且** 变更含源码文件 → **fail-closed（exit 2）** + 修复指引
- 三源皆无声明 **但** 变更全在豁免范围（`docs/` `\.claude/` `memory/` `task-state/` `*.md`）→ **skip + 降级登记**（不阻断纯文档 PR）

理由：把「无声明」默认放行，等于给夹带留一条零成本通道（摘掉 brief 即可）——那就不是 gate。

## 四、判定与豁免（spec Q3）

**夹带定义**：变更集（`--no-renames` 的 A/M/D/R）中，不匹配任何声明条目、也不命中任何豁免的文件。

**逐类判定（A/M/D/R 一律同规则）**：
- **新增(A)**：最典型的夹带形态（#449/#442 即此）→ 必判。
- **修改(M)**：改动他人文件的语义与新增等同 → 必判。
- **删除(D)**：**同样必判**。删除写集外文件是对仓库的破坏性变更，且删除项正是 D706 暴露的高危形态（删除可能被静默丢弃）——不能因为「只是删了」就豁免。
- **重命名(R)**：本 gate 用 `--no-renames` 把重命名拆成 D+A 两条，两条各判。
- 需要删除写集外文件时，走 `## 写集豁免` 显式声明理由（如「清理已废弃脚本」）。

**匹配语义**（与作者书写习惯对齐）：精确相等 / 目录前缀（`scripts/control-tower/` 覆盖其下全部）/ 含 `*?[` 时走 `fnmatch`。

**豁免必须显式，且逐条打印理由**：

| 类 | 内容 | 理由 |
|---|---|---|
| 分支级 | `auto/**` | CI 自动生成的仪表盘分支，无写集语义 |
| 分支级 | `main` / `master` | 合并后 push；本 gate 触发点在合并前 |
| 路径级内置 | `.claude/bypass.log` | post-commit hook 每次提交追加的证据账本，属运行期产物，与写集无关 |
| 声明级 | 声明文件里的 `## 写集豁免` 段落，每行 `- <路径> — <理由>` | 作者显式声明 |

**声明的豁免条目缺理由 → 不生效**（防止「写个路径就绕过」）。这条有专门的反例测试。

## 五、fail-closed 语义（spec Q4）

沿用 D328 三态：`0` = 无夹带 / `1` = 夹带（业务阻断）/ `2` = **无法判定**（同样阻断）。

exit 2 的触发条件：取不到 `merge-base` / git 调用失败 / 声明源解析异常 / 三源无声明且含源码变更。
**绝不静默放行为「通过」**（铁律 11），且每次 exit 2 都写 `.codex/control-tower/logs/degraded-events.log`。

## 六、诊断质量（spec Q5）

参考 DSH `dsh-hook-protocol/lib/index.js` 的 `matcherDiagnostic`（matcher 拒绝时必须给出可读理由）与 `lib/invariant.js` 的「判定 / 状态推进分离」。拒绝时输出：

```
❌ 结论: block — 检测到 1 个写集外文件（夹带）
   任务: D708 | 分支: fix/D708-…

     · scripts/control-tower/        ← S1:task-state.write_set
   豁免 1 条（显式，逐条打印理由）:
     · .claude/bypass.log  ← [builtin] post-commit hook 每次提交追加的证据账本（…）
   夹带文件 1 个（不匹配任何声明项）:
     - src/b_smuggled.ts
   修复指引（三选一，禁止静默忽略）:

     ③ 显式豁免: `## 写集豁免` 段落，每行 `- <路径> — <理由>`（无理由不生效）
```

另有 `--json` 机器可读输出（`component/status/smuggled/declared/exempt/warns`），供上层聚合。

## 七、回滚方式

- 首选：revert 引入本 gate 的提交（CI 配置 + 脚本在同一 PR，一并回滚）。
- 不设 `SYNO_*` 逃生舱——逃生舱本身会成为绕过通道（V3.9：软机制 0% 有效）。
- 若需灰度：可先只加 `--json` 上报不阻断（把步骤改为 `|| true` 并**显式注释降级理由**），但**本 PR 不提供**该形态。

## 八、三个历史实证的回放（spec 验收要求逐条说明）

| 事件 | 本 gate 若在，能否抓到 | 抓到后输出什么 |
|---|---|---|
| **#449**（夹带 D603，51 文件） | **能**——那 51 个文件必然不在该 PR 的 brief/dev doc 声明内 | 列出 51 个夹带文件逐条；声明源标注；提示「它们可能属于另一个任务（D603）」 |
| **#442**（夹带 6 文件） | **能**——同上，6 个未声明文件 | 同上（6 条） |
| **D593-FIX**（声称提交实未提交） | **不能**——这是「声称做了但没做」，变更集**小于**声明，不是夹带。本 gate 只管「变更集 ⊄ 声明」这一侧 | 诚实的边界声明：反向不一致（声明多、实际少）需要另一类 gate（如 dev doc DS 项 × 实际 diff 的**覆盖**校验）。**已登记待派**，不在本任务范围 |

> 第三条是本设计**主动声明的能力边界**：本 gate 只防「多了」，不防「少了」。把两者混为一谈会让 gate 名不副实。

## 九、验收（物理可复现）

| 项 | 方式 |
|---|---|

## 十、风险与已识别的反对意见

1. **误伤面**：声明不完整（例如新增了一个测试文件但没写进 Q2）的 PR 会由「静默通过」变成「红」。
   - 这是**有意**的：声明与事实一致是 D329/D534 已确立的纪律，且修复成本是「补一行声明」。
   - 缓释：修复指引明确给出三选一；纯文档 PR 走降级放行不受影响。
2. **单点误判风险**：`--branch` 取 `GITHUB_HEAD_REF`，fork PR 下语义需实测（本仓为单人仓，暂无 fork PR）。
3. **不覆盖「少了」**（见 §八第三条）——已在设计里显式声明，避免能力被高估。

### 阻塞项：D# 推断大小写敏感 + 回退链误抓登记提交（已修）

**复核实测证据**（主 CTO 复现命令）：

```
parse_did('feat/win-d702-write-op-no-swallow')            → None      ← 小写 d702 不匹配 D\d+
parse_did('docs(d702): …')                                → None
parse_did('chore: bypass COMMITTED 登记 (auto hook, D521)') → 'D521'  ← 影子提交带历史 D#
```

第三条最危险：post-commit hook 生成的「登记影子提交」**经常就是 HEAD**，其 subject 里带一个
**历史 D#**（真实值 D521）。旧回退链直接读 `git log -1` → 写集错配到 D521。
现场核验：本分支 HEAD 的 subject 正是该登记提交，若分支名不含 D# 即会误配。

**修法（三条，全部落地）**：

| # | 修法 | 实现 |
|---|---|---|
| ① | 大小写不敏感并归一化大写 | `DID_RE = re.compile(r"[Dd]\d+")`；`parse_did` 返回 `m.group(0).upper()` |
| ② | 回退链跳过自动登记提交 | 新增 `infer_did()`：分支名优先 → 否则向前遍历 ≤20 条提交，**跳过 subject 含「bypass COMMITTED 登记」的提交**，取第一个带 D# 的非登记提交；返回值附来源（`branch` / `commit-subject`）供诊断审计 |
| ③ | 用真实输入补回归断言 | 测试 ⑩（parse_did 真实输入 4 例）/ ⑪（登记影子提交地形 + 分支名不含 D#）/ ⑫（PR 正文声明源） |

**红灯验证（去掉修法即红）**：用 `HEAD` 版（修复前）的 gate 跑扩展后的测试：

```
❌ ⑩ BAD:feat/win-d702-write-op-no-swallow->None,docs(d702): 补文档->None
❌ ⑪ 回退链错配: 'D521 None degraded'（期望 'D712 commit-subject pass'）
❌ ⑫ PR 正文声明源未生效: rc=1
结果: 22 通过, 4 失败   → exit 1
```

修复后：**26 通过, 0 失败 → exit 0**。

> ⑪ 的地形设计要点：分支名必须**不含任何 D#**（`feat/win-write-op-no-swallow`），否则
> branch 分支优先命中、回退链根本不会被走到 —— 第一版断言就因此假绿（分支名带了小写 d712，
> 被大小写不敏感的新 `parse_did` 直接命中）。这本身也是一次「断言没打到目标路径」的自纠。

### 可选建议（已做，单独说明）

## 补记（#1284 / D1222，2026-10-07）：豁免源「事件体读取」的重跑陷阱 + `--pr-body` 实接线

### 陷阱（实测，非推断）

`resolve_pr_body_text()` 取 PR 正文只有两条路：① `--pr-body <文件>`；② `GITHUB_EVENT_PATH` 的事件体。
而 **`ci.yml` 从不传 `--pr-body`**（历史 `grep -c 'pr-body' ci.yml` = 0）⇒ 只能走事件体。

🔴 **GitHub「Re-run」重放的是原事件体快照，不会重抓 PR 正文** ⇒ **「编辑正文 → 点重跑」对豁免机制永远无效**。
实证（#1273）：正文 13:45:56 加入 `## 写集豁免`，重跑 attempt 2 读到的仍是 13:31 的旧正文；
日志里「豁免」出现 3 次，逐条核过**全是门禁自己的修复指引模板文案**，**没有一条是解析到的豁免**。

### 契约（现行，三条并列）

| 声明源 | 载体 | 重跑是否刷新 | 适用场景 |
|---|---|---|---|
| S1/S2/S3 文件式 | `task-state/*.json` write_set · dev doc 写集表 · brief Q2 | ✅ 随 commit 一起被重放（内容即代码） | **必须可判**的场景（推荐） |
| ④ PR 正文 | `--pr-body`（**已接线**，取当前正文） | ✅ `gh pr view` 实时取 | 过渡期/一次性放行 |
| ④' PR 正文（旧路径） | `GITHUB_EVENT_PATH` 事件体 | ❌ **重跑不刷新**（快照） | 仅首次运行时等同于① |

**结论（写死，避免下一个人再踩）**：PR 正文里的 `## 写集豁免` **必须配合新 commit 或已接线的 `--pr-body`** 才生效；
只改正文不推 commit、然后重跑 = **无效**。

### 接线实现（ci.yml，D1222）

D708 step 前：`gh pr view "$PR_NUMBER" --json body --jq .body > "$RUNNER_TEMP/d708-pr-body.md"`，
再传 `--pr-body "$RUNNER_TEMP/d708-pr-body.md"`。三态显式：
- 取到 ⇒ 日志打印 `正文来源: gh pr view #N —— 当前正文（re-run 亦刷新）`，并**逐条打印解析到的豁免行**（原样进日志，供审计）；
- 取不到 ⇒ `::warning title=d708-pr-body::…`（**显式降级**，回退事件体快照，禁静默）；
- `merge_group`/`push`（`event.pull_request` 为空）⇒ `::notice` 显式说明「正文豁免段在此路径不适用」（非静默跳过）。

判别夹具：`tests/control-tower/d708-pr-body-wiring.test.sh`（7 用例）—— 从 ci.yml **提取真 step 正文执行**，
以 `gh`/`python3` 双桩录制 argv，证明 `--pr-body` **真被喂到 python 调用**（而非"代码里有该分支"）、
正文含豁免段时日志出现解析行、取数失败/无 PR 号两态显式、以及**去掉接线的变异体必红**。
