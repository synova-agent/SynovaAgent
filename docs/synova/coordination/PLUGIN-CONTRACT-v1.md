## 〇、通用部分（五类共用，**必须先读**）

### 0.1 基座边界判定问句（对任何候选能力问它）
> **"把这个能力拆掉，系统还能不能'安全地坏、响亮地坏'？"**
> 能 ⇒ **插件**；不能 ⇒ **内核**。
> （DSH 实测：真不可卸载的只有三样 —— Loader/组装机制、进程级 fail-loud 守卫、沙箱 fail-closed 契约）

### 0.2 四问的**机器判据**（每类插件都要能答，且不许靠 grep）
| 问 | 判据 | 反例（必须红） |
|---|---|---|
| **① 加了吗** | 清单里能查到该插件（注册表/清单文件） | 从清单删除 ⇒ 系统必须显式报"缺失"，不得静默 |
| **② 接上了吗** | **从生产入口可达**（静态图 `reaches` 判定，见 06） | 只被 tests/ 引用而生产入口不可达 ⇒ **判"没接线"**（4 次接线失败的签名） |
| **③ 生效了吗** | **生产入口冒烟 + 事件链断言**（`04` 四层范式：兼容闸门 → schema dump → **invariant** → **证据文件夹具**） | 组件被调用时必须产生可对账的账本事件；缺失即 fail |
| **④ 删干净了吗** | 删除后：清单无残留、无生产引用、**无孤儿测试** | 任一项有残留 ⇒ 红 |

### 0.3 故障隔离（**坏插件不许拖垮别人**）
- 每个插件在**独立失败域**运行；失败**分类**：**新引入 vs 既有**、**必需 vs 可选**
- 汇总处**只对"本 PR 新引入或行为变化"的失败置红**；既有失败输出为诊断清单**不阻断**
- **逃逸到进程级的失败一律致命**（fail-loud），但**不许把他人拖红**

### 0.4 版本化（稳定面红线）
- **一旦发布，永不改**：**① row id ② config 键形状 ③ provider/服务名字符串**
- 包名、内部模块结构 **均视为实现细节**（可改）
- 契约版本载体（三域分治）：**peerDependencies semver**（能否共存）｜**JSON Schema dump**（配置形状，keyless，可被 bash 校验）｜**数据 format 版本链**（落盘读不读得动）
- **兼容闸门先于加载**：只读 `peerDependencies` 判定，**不 import 插件代码**

### 0.5 跨栈约束（TS ↔ bash）
> **bash 门禁只能验"进程退出码"，验不了"契约形状"** ⇒ 跨栈契约一律降格为
> **文件证据 + JSON Schema 双端共享**（否则 bash 侧永远在测代理而非本体）

## 一、哨兵插件契约（v1 冻结）

### 1.1 注册（加了吗）
- 位置：`extensions/sentinels/<哨兵名>/`
- 必需文件：`manifest.json`（**唯一注册入口**）
- `manifest.json` 必填字段：`id`（**row id，一旦发布永不改**）｜`name`｜`version`｜`layer`｜`entryPoint`｜`computes[]`｜`degradedPolicy`

### 1.2 接上（接上了吗）
- **可达性判据**：`src/**` 生产入口 → 加载器 → 该哨兵必须有静态可达路径（dependency-cruiser `reaches`）
- **禁**：只被 `tests/**` 引用的哨兵（那是"没接线"）

### 1.3 生效（生效了吗）
- **必须**：连续两次运行的结果**可对比**（时序落盘）
- **必须**：每次运行产生**证据文件**（含 `run_id` + `input_digest`）
- **降级契约**：任何失败 ⇒ 返回 `degraded: true` + `reason`（**禁静默**）

### 1.4 删干净（删了吗）
- 删除后 grep 零残留：清单、生产引用、孤儿测试
- **删除走已有通道**（feature-flag 审计），不发明新流程

### 1.5 反例与失效条件
- ❌ 注册成功但**从未被生产调用** ⇒ 不算"接上"
- ❌ 只跑通单测 ⇒ 不算"生效"
- **会推翻本条的证据**：若发现某哨兵**只能**通过动态变量路径加载（无法静态判定），则 1.2 需补"运行时注册表 diff"

## 二、compute 插件契约（v1 冻结）

### 2.1 签名（**不可改**）
```
(store: GraphStoreReader, teamId: string) => ComputeResult
```
- `store` 提供三原语：`queryNodes` / `queryEdges` / `traverse`（**compute 不许自己找数据，沿边走过去**）
- **新 compute 必须先定义契约（JSDoc 输入/输出/降级）再实现**（铁律 47）

### 2.2 输出契约（`ComputeResult`）
- 必需：`value`｜`degraded`（boolean）｜`reason`（degraded 时必填）｜`inputsDigest`
- **禁**：`undefined` 冒充"无数据"（须显式 `null` + reason）

### 2.3 测试契约（铁律 48）
- 三路径覆盖：**正常 / 降级 / 边界**
- **必须有 `expect()` 断言**（空壳测试 ⇒ commit 阻断）

### 2.4 生效判据（与哨兵同）
- **生产入口冒烟**：真起进程跑一次 ⇒ 该 compute 必须被执行（覆盖率 diff 证明）
- ❌ 反例：`vitest` 覆盖率绿 ≠ 生效（它测的是测试，与"生产入口触达"**正交**）

### 2.5 反例与失效条件
- ❌ `transfer_function` 声明在**边数据**里而**生产 TS 零读取** ⇒ 判"没生效"（**已知实例**）
- ❌ `requiredProps` 只在**节点类**有读取点、**边类**零消费 ⇒ 口径须限定（**已知实例**）

## 附：本契约的失效条件（什么会推翻它）
1. 若基座采用非"注册表 + 可达性"的加载范式（如纯运行时发现）⇒ 0.2 的判据需重写
2. 若插件方（Win 侧）在 mock 开发中发现**契约表达不了**某个必要能力 ⇒ **走 migration + 双签**（不许私自扩）
3. 若"独立失败域"在当前 CI 拓扑下不可实现 ⇒ 0.3 退为"分进程执行 + 分类汇总"
