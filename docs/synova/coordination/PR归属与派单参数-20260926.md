### 1.1 为什么改（实测代价）
旧规则「PR 由 CTO 开」是 CTO 自加，**非 DSH 实践、非行业实践**。
实测代价：**D962 阶段 2a 交付 15:09 完成 → 到 CTO 处理已过数小时**，期间 CTO 带宽被治理/事故/复核占满 ⇒
**交付全部滞留在单点**。该由**门禁 + 模板 + CI**保证的事（写集/红线/判据），不该由「谁点按钮」保证。

## 二、派单模板参数更正（FIX-010，CTO 自造缺陷）

**错误**：此前派单件写 `merge_writeset_gate.py --repo .`。
**实测**（`scripts/control-tower/merge_writeset_gate.py:361-366`）：**参数是 `--repo-root`，不存在 `--repo`**。
⇒ **正确用法**：
```bash
python3 scripts/control-tower/merge_writeset_gate.py --repo-root . --branch <分支>
```
⇒ 后续派单件一律以此为准；历史派单件中的 `--repo .` 按此更正。

## 三、为什么 R1–R4 不直接改 `派单模板.md`（FIX-011 的活实例）

`D328` 门禁按「**暂存文件 → 已声明卡**」反查归属。实测：
- `派单模板.md` 出现在 **D931 / D943** 的声明中
- `.github/workflows/ci.yml` 出现在 **D954** 的声明中
⇒ 任何**新卡**直接改这些**共享文件**都会被判「**疑似并行劫持**」并拒绝提交（CTO 本轮亲历 **3 次**：D954、D940、D931/D943）。

**⇒ 结论（记入 FIX-011）**：共享治理文件需要一条**显式的多卡共享声明机制**（或改为一对象一文件）。
**在此之前**：新规则落**新文件**（本件），**不动**有历史归属的共享文件。
