## 三、设计决策（CTO 自决项，供审计判断合理性）

| 决策 | 理由 | 潜在争议点 |
|---|---|---|
| Win 卡"合并≠完成"（无审计报告→running） | 与 Mac 侧 impl_done→running 口径统一，防假完成 | 审计报告按内容 grep \bD#\b 判定，可能漏判（报告未提编号但实际审过）→ 偏保守，可接受 |
| Win 窗口 ≥D328（194 个远古 D# 不上板） | 防噪音；--since-d 可配置 | D1-D327 历史不可见（但 DASHBOARD-CN 全历史可查） |
| 降级轮零删除（而非按域过滤） | Win 卡与 Mac 卡同为 D# 格式无法区分；误删破坏性 > 漏删 | 降级期间真僵尸会残留一轮（derive 恢复后自愈） |
| todos 自写 YAML 解析器（非 PyYAML） | 系统 Python 3.9 无 PyYAML，插件环境不引依赖 | 仅支持 aggregate-todos.py 已知 schema；schema 变更需同步——已在脚本头注释声明 |
| fetch 到 refs/remotes/origin/main（不碰工作区） | 根治 D501 工作区滞后；只动 remote-tracking ref | 并发 git 操作的锁竞争未显式处理（git 自身串行保护） |

## 四、已知限制（诚实降级，非缺陷隐瞒）

1. derive 依赖 git fetch 网络（失败 → 用本地旧 origin/main，记 errors，snapshot 头部 degraded=true）
2. index.js spawnSync python3（180s 超时）——插件环境无 python3 时永久走工作区直读（console.warn 可见）
3. profile 部署是 cp（非 pnpm 托管）——插件升级需手动重拷（install.sh 方式①可替代，未在本任务执行）
4. L00 总览 pct 直读 product-progress.json 的 product_progress_pct 字段，不重算加权
