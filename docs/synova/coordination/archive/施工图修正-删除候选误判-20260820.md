## 一、修正结论（一句话）

施工图 §3.5 把 `src/infra` + `src/locale` 列为"⚫ 删除候选（复核零引用后删）"，但 **grep 实测两者都被生产代码真实引用**——应从删除候选移出，改为"保留"（或"评估合并入邻近模块"）。

## 二、代码证据（可复核）

### 1. `src/locale/` — 被文件驱动加载体系引用（不是零引用）

```bash
# src/init/file-driven-loaders.ts:24-27（文件驱动加载器，部署链路在用）
src/init/file-driven-loaders.ts:24: const { loadLocale, t, reloadLocale } = await import('../locale/locale-loader');
src/init/file-driven-loaders.ts:25: const { locale } = loadLocale();
src/init/file-driven-loaders.ts:27: void reloadLocale; // 备用热加载 — 接线
```

- `file-driven-loaders.ts` 是 L0 初始化/加载器，被 `src/init/` 启动链路调用
- locale 是**文件驱动本地化体系**（`extensions/locales` 的加载器）——施工图 §5.2 扩展点 #13 恰好把"语言/本地化"列为"品牌表层 ✅ 已可插拔"，**locale-loader 就是那个扩展点的实现**，删了扩展点 #13 就断
- 结论：**保留**（它是 §5.2 #13 的实现载体，不是死代码）

### 2. `src/infra/` — command-lanes 被主 Agent 运行时引用

```bash
# src/agent/synova-agent.ts:252-255（L2 主 Agent，生产入口）
src/agent/synova-agent.ts:252: // Phase 4.3: CommandLanes — 工具执行路径隔离（高风险工具走独立 lane）
src/agent/synova-agent.ts:254: const { CommandLanes } = require('../infra/command-lanes');
src/agent/synova-agent.ts:255: const lanes = new CommandLanes({ defaultTimeoutMs: 60_000 });
```

- `command-lanes.ts` 是工具执行路径隔离（高风险工具独立 lane，60s 超时）——**这是安全机制**，被 L2 主 Agent 运行时 require
- 施工图把 infra 归"各仅 2 处提及"→ 误判零引用，但**动态 require 是运行时接线**，静态 grep 数引用少 ≠ 死代码（施工图 §2.2 自己写过这条原则："静态零引用 ≠ 死代码，删除前必须复核"——这里违反了）
- `trace-context.ts` 暂未查到生产引用（可单独复核，但整个目录不该整体删）
- 结论：**保留**（command-lanes 是安全机制，在运行中使用）

## 三、为什么是误判（根因）

施工图 §3.5 的删除候选判断用了"**grep 引用次数少 → 疑似零引用**"的启发式，但：

1. **静态 grep 数引用 ≠ 死代码**——`require()` 动态加载、`await import()` 异步加载，静态 `grep "src/infra/"` 数不到（引用是相对路径 `../infra/`，不是 `src/infra/`）
2. **文件驱动加载器**（file-driven-loaders）会动态扫描目录，更不可能被静态引用计数覆盖
3. 施工图 §2.2 自己写的原则被 §3.5 违反：**"静态零引用 ≠ 死代码，删除前必须复核"**
