# 每周自检对齐任务（2026-08-25 创始人定）

> 背景: AGENTS.md/CLAUDE.md 停在 V4.5.1，控制塔演进 V5.1.1 期间文档冻结 → 门禁语义/版本/定位严重漂移（AGENTS.md 对齐教训，2026-08-25）。
> 机制: CTO 每周自检对齐——用脚本检测文档 vs 代码漂移，发现即安排对齐。

## 自检脚本

`scripts/control-tower/weekly-selfcheck.sh`

**检查项**（漂移检测）：
1. AGENTS.md / CLAUDE.md 版本 vs 控制塔 VERSION.md（应 V5.x 一致）
2. pre-commit 语义（软提示 vs 实际 pre-commit-check.sh）
3. pre-push 语义（门禁 0-5 vs 实际 pre-push-check.sh）
4. 专家数（AGENTS.md 声称 vs expert/ 目录实测）
5. 桌面端定位（AGENTS.md 是否含）
6. 技能双轨同步（.claude ↔ .dsh，sync-dsh-skills --check）
7. cto-handover 派单规范（§〇b DSH 借鉴核查）

**输出**: `[OK]`（零漂移，exit 0）/ `[DRIFT] <文档> <差异>`（有漂移，exit 1）/ degraded（exit 2）

## 定时方式（已落位 — launchd 系统级，2026-08-25）

**`com.synova.weekly-selfcheck`**（`~/Library/LaunchAgents/com.synova.weekly-selfcheck.plist`）：
- **每周日 08:00** 自动执行（StartCalendarInterval Weekday=0 Hour=8 Minute=0）
- 命令: `bash scripts/control-tower/weekly-selfcheck.sh --report`
- 输出: `docs/synova/CTO-HEALTH.md` 追加「每周自检」段（[OK]/[DRIFT]）+ `/tmp/synova-selfcheck-launchd.log`
- 全程无人值守（系统级自动，DSH 常驻由 com.synova.dsh-web launchd 管理，同先例 backup-db）

**触发后的人工动作**（仅当有 [DRIFT]）：CTO 读 CTO-HEALTH.md 自检段 → 对齐 → 提交 PR → 重跑确认 [OK]。

**DSH 原生备选**（调研结论）：dsh-task-board cron（Host 级，GUI 创建）+ dsh-schedule（session 级）——如需 agent session 参与（非纯脚本），可后续在任务看板补一个 cron 触发 CTO session 做对齐修复。
