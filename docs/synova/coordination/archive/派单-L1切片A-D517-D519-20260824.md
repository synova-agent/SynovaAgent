## D517：安装包可产出（验证点 1-1）

**目标**：`electron-builder` 配置完整，CI 可复现打出双平台安装包产物（.dmg Mac / .exe Win）

**spec 必答题**：
1. electron/package.json 的 electron-builder 配置：appId/产品名/目录（files 白名单：main.cjs/preload/renderer-dist/server 启动）/双平台 target（mac: dmg+zip, win: nsis）——给出完整配置骨架
2. **构建产物验证**：本地 `npx electron-builder --dir`（mac 可跑）产出 release/mac/ 可执行 app——spec 的 Done 必须是"产物存在 + 大小 + 可启动"物理证据（禁止 grep 配置冒充——D510 F1 教训）
3. CI 接入：product-progress.yml 或新 workflow 加"push main → electron-builder 构建（双平台矩阵）"——CI 无 GUI 如何验证（mac runner 可跑 --dir，win runner 交叉构建或跳过）
4. renderer 构建链：electron-builder 前需 vite build 渲染进程（electron-renderer/）——构建顺序与产物路径契约

**验收**：`ls release/mac/ 含 .app 且可启动（open 后进程在）`；CI job 绿且产物 artifact 可下载

## D518：安装引导单一入口（验证点 1-5）

**目标**：npm run dev 与安装包双引导收敛——用户只有一条路径"双击装→开窗"

**spec 必答题**：
1. 现状盘点：开发引导（npm run dev 起后端+渲染）vs 生产引导（安装包→spawn 后端+loadURL）两条路径的入口差异
2. 收敛策略：生产入口为主，dev 入口标记为"开发模式"（环境变量区分）；装包后 main.cjs 的 SERVER_URL 如何指向本机实例（spawn vs 外连）
3. 后端 spawn 契约：electron/backend-spawn.cjs（D504 已交付）的启动/健康检查/端口冲突/退出回收——spec 需验证它真被 main.cjs 调用（WIRE CHECK）
4. 安装包"开窗即用"：装完双击 → 后端自动起 → 首诊页可达（不碰命令行）的链路图

**验收**：装包后双击打开即进首诊（无命令行操作）；dev 模式可测（文档标注）

## D519：Mac 安装包实测（验证点 1-3）

**目标**：Mac 本机真实打 dmg → 安装 → 启动 → 出窗（物理实测，非模拟）

**spec 必答题**：
1. 实测步骤清单：本地 electron-builder 打 dmg → 挂载安装 → 从 /Applications 启动 → 断言进程 + 窗口（用 `osascript` 或日志）——给出可执行的验证脚本

**验收**：evidence/ 含 dmg 产物的 ls+md5+启动日志；founder-demo checklist 可执行
