## DSH 借鉴清单（不重复造轮子 — 施工图 DOC-0114/0115 对齐）

> 依据：`docs/synova/research/DSH迁移施工图-20260820/DSH迁移施工图-20260820.md`。Electron 壳 = 🟢 死守自研（§3.1 品牌表层），但"进程生命周期管理"范式可借鉴（§4 能力映射表"安全边界 sandbox 长期借鉴不引代码"同类）。

### 红线（三条，spec 必须遵守）

1. **借鉴 = 读 DSH 代码思路 → 在 backend-spawn.cjs 自己实现**，不 copy DSH 代码、不 `npm install @deepseek-ai/dsh`（Stage 3 前零 DSH 依赖，施工图 R1）
2. Electron 壳（electron/ 目录）自研，不借 DSH 壳（DSH 无 Electron——它是 Node 服务 + 浏览器 UI，非桌面应用）
3. 验收含接线审计（施工图 R4）

### 借鉴对象 1：进程生命周期管理（D522 必答 5 退出回收）

文件：`~/.nvm/versions/node/v24.19.0/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-subprocess-local/lib/index.js`

| DSH 函数 | 行号 | 借鉴点 |
|---|---|---|
| `signalTree(platform, pid, sig, child, taskkill)` | L757-768 | 跨平台信号树：Win 用 `taskkill /T /F`，POSIX 用 `kill(-pgid)`，失败回退 `child.kill(sig)` |
| `taskkillTree(pid, force)` / `taskkillProcessTree(pid)` | L102 / L742 | Win 进程树终止，幂等 teardown（缺 taskkill 二进制/非零状态不破坏幂等） |
| `windowsProcessTree()` | L17-19 | Win 进程树遍历（Toolhelp32 snapshot，shell pid 作伪进程组） |
| `linuxProcessGroupHasLiveMembers()` | L322-333 | POSIX 进程组存活检查 |
| SIGTERM→SIGKILL 升级 | L548-556 | 优雅退出失败后强制升级 |

### 借鉴对象 2：优雅退出（D522 必答 5）

文件：`~/.nvm/versions/node/v24.19.0/lib/node_modules/@deepseek-ai/dsh/lib/profile-boot-DG5t9aNs.js`

| DSH 函数 | 行号 | 借鉴点 |
|---|---|---|
| `createProcessShutdown(async () => fiber.dispose())` | L225-227 | shutdown 控制器（dispose → 回收，不静默） |
| `process.on("SIGTERM", () => interrupt(0))` | L231 | SIGTERM → 优雅退出 exit 0 |
| `process.on("SIGINT", () => interrupt(130))` | L234 | SIGINT → exit 130 |

### 关键差异（dev-doc 要写进 spec）

- Synova `backend-spawn.cjs` 现在的 `stop()` 是**朴素 SIGTERM**（`child.kill`），**没有**进程组 / Win taskkill 树 / SIGTERM→SIGKILL 升级。借鉴 DSH 补齐这三块，D522 的"退出回收无孤儿"才有 Win 侧保证。
- DSH 探活用 Cordis fiber 机制，Synova 用 HTTP healthz 探活（`ensureBackend` 已实现）——**探活不借鉴，只借鉴 teardown**（避免把 DSH 的 Cordis 生命周期硬套进 Synova 的 spawn+healthz 模式）。

## D522：服务自启开窗即用（验证点 1-4）

**目标**：双击应用后，后端服务自动拉起、健康检查通过、开窗即见首诊页——整条链路物理可复现，无命令行操作。

**依赖**：无（backend-spawn.cjs + main.cjs 接线已在 main）。本 D 独立可做，不等切片 A。

**spec 必答题**：
1. **ensureBackend 全链路实测**（backend-spawn.cjs 是纯 Node 模块，可无头单测）：探活失败→spawn→轮询→健康→stop 回收，五段各写集成测试（铁律 48 非空壳，正常+降级+边界三路径）
2. **WIRE CHECK 物理证明**：grep 证明 main.cjs 真调用 ensureBackend（L121 调用点 + L186 before-quit 回收 + degraded 分支有 log.error）——D504 已接线，本 D 需把"接线真闭环"变成测试断言，禁止只 grep 冒充（D510 F1 教训）
3. **端口冲突安全网**：已有服务在跑（reused=true）时不重复 spawn——写测试覆盖"预起一个假服务→ensureBackend 返回 reused 不 spawn 第二个"
4. **降级诚实**：spawn 失败/重启超限/ENOENT → 返回 degraded=true + log.error，不静默（铁律 24/31）；测试覆盖降级路径
5. **退出回收**：before-quit → stop() → SIGTERM 子进程，无孤儿（测试断言子进程 pid 已死）——**借鉴 DSH `signalTree`/`taskkillTree`（见上方 DSH 借鉴清单）：Win 走 `taskkill /T /F`、POSIX 走进程组 `kill(-pgid)`、加 SIGTERM→SIGKILL 升级**

**验收**：`npm test` 覆盖 backend-spawn 五段链路（正常+降级+边界）；`grep ensureBackend electron/main.cjs` 有调用点；无孤儿进程残留

**目标**：Windows 上双击安装包（切片 A D517 产物 NSIS .exe）→ 安装 → 启动 → 出窗见首诊，全程无命令行。

**依赖**：切片 A 的 D517 安装包产物（NSIS .exe）。**编码阶段必须显式声明前置依赖已满足，否则退回待命**（防空转）。

**spec 必答题**：
1. Win 实测步骤清单：NSIS 安装 → 开始菜单/桌面快捷方式 → 双击 → 进程启动 → 窗口出现 → 首诊页可达（用日志/截图/进程断言，给出可执行验证脚本）
2. 双平台承诺口径：Mac 侧（D519 切片 A）已承诺，本 D 只做 Win 侧——但 spec 需声明 Win 侧实测的证据形态（进程名 + 窗口标题 + 首诊 URL 可达）

**验收**：Win 实测 evidence 含安装包 md5 + 进程/窗口断言 + 首诊 URL 可达；founder-demo checklist 的 Win 侧 4 步可执行
