## Spec 1：D504 Electron 桌面端一体化（GS-01 前置，L1 桌面端 0/8 → 可装可跑）

### 背景（CTO 已读透，dev-doc 写 spec 前复核）

| 项 | 内容 |
|---|---|
| 落地对象 | `electron/main.cjs`（153 行）+ `electron/preload.cjs` + `electron/package.json`（无 electron-builder 配置）+ `electron-renderer/`（36 文件雏形） |
| 现状 | main.cjs 有 BrowserWindow/Tray/Menu/Notification，SERVER_URL 硬编码 localhost:18790；**无 spawn 后端服务、无开机自启、无打包配置** |
| 补缺口 | L1-1~L1-6（安装包能打出来 / Windows 双击安装→出窗 / Mac 版可用 / 服务自启开窗即用 / 安装引导单一入口 / 30 分钟从安装到可诊断） |
| 验收 | GS-01 场景转绿（exit 0 + 证据入库）+ L1 验证点 ≥4 项 verified |
| ⚠️ 归属 | electron/ + electron-renderer/ 归 Mac DSH ✅；**服务端 src/server 归 Win**——服务自启方案不得改 src/（用 spawn `npm run dev` / 独立进程管理 / launchd 注册，避开 Win 写集） |

### dev-doc 必须回答的问题（spec 的核心）

1. **服务自启方案**：Electron 主进程 spawn 后端（cwd 定位 + 崩溃重启 + 退出回收）vs 系统服务注册（launchd/Windows 服务）vs 打包内嵌服务进程——三选一或组合，给出契约（生命周期/端口冲突/日志）。
2. **打包方案**：electron-builder 配置（mac dmg/zip + win nsis），双平台产物路径；`electron/package.json` 需要什么字段。
3. **安装引导收敛**：双引导（npm run dev vs 双击安装包）如何收敛到单一入口（L1-5）。
4. **首诊旅程接线**：开窗后从哪进首诊（renderer 调用后端 /api/diagnosis/consult 的路径），30 分钟承诺的假设条件。
5. **与 GS-01 脚本的接口**：GS-01 场景如何驱动 Electron（CI 环境无 GUI 如何验证——headless 断言后端 + 打包产物存在性？）。

### 写集建议（dev-doc 定稿，需与编码 session 核对）

- `electron/main.cjs`（服务自启 + 生命周期）
- `electron/package.json`（electron-builder 配置 + 脚本）

- `scripts/golden-scenarios/GS-01-first-diagnosis/`（场景脚本增强）

## Spec 2：D505 哨兵自诊断可信度（S3-5，L22 自诊断与稳定性）

### 背景（CTO 已读透，dev-doc 写 spec 前复核）

| 项 | 内容 |
|---|---|
| 落地对象 | `src/sentinel/sentinel-service.ts` + `src/cron/CronScheduler` + `src/agent/sentinel-service.ts`（哨兵调度核心） |
| 现状 | 哨兵体系 45 文件已工作（GS-03/05 绿、GS-07 绿），但 **self-check 实现 0 处**——哨兵自身挂了（loader 失败/适配器崩溃/scheduler 停摆）无人知晓 = S3-5 自诊断可信度断裂 |
| 补缺口 | S3-5（自诊断可信度）+ T-22-02（GS-07 已绿但自诊断本身是独立缺口）|
| 验收 | 哨兵自检：loader 失败/适配器异常/调度空转 → 显式 degraded 信号 + 日志/工单；GS-07 不回归 |
| ⚠️ 归属 | src/sentinel/ + src/cron/ + src/agent/sentinel-service 归 Mac DSH ✅ 纯领地 |

### dev-doc 必须回答的问题（spec 的核心）

1. **自检面**：什么算"哨兵体系健康"——loader 注册数 vs 预期？适配器 run 失败率？scheduler 心跳？给出健康指标清单 + 阈值。
2. **信号形态**：degraded 信号如何传播（复用铁律 31 的 degraded 传播到哪一级）——log？SentinelFinding？工单？FDE 警报？对齐既有 evidence/collector 管线。
3. **与 watchdog 的关系**：自检是进程内（sentinel-service 自测）还是进程外（独立 watchdog cron）？给出选型。
4. **误报控制**：阈值怎么定才不打扰（哨兵偶发失败 vs 系统性停摆的区分）。
5. **验收可测性**：如何用场景脚本/单测证明"哨兵挂了自己能发现"（注入故障 → 断言 degraded 信号）。

- `src/agent/sentinel-service.ts`（如涉及调度健康）
