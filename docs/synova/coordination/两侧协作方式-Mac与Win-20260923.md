# 两侧协作方式（Mac / Win）— **唯一差异：CTO 角色由 Codex 执行**

> 本件是两侧协作的**唯一事实源**。Mac 与 Win 在"开发模式 / 预设 / 技能 / 验收链 / 归属规则"上**完全同构**；
> 差异**只有一处**：CTO 角色（派单、规格、收件闸、合并、台账）在 Mac 由 Mac-CTO 执行，在 Win 由 **Codex** 执行。

## 一、共同部分（两侧完全一致，不得各搞一套）

### 1. 开发模式 = **Agent Teams 小队**（**严禁用子代理代替小队**）

| 项 | 规定 |
|---|---|
| 组队方式 | **Agent Teams**（预设已挂 `agent-team` + `tool-agent-team` + `ui-agent-team`，`maxMembers=4`） |
| 编制 | **队长 + ≤2 编码 + 1 独立自验**（自验**不得**由编码兼任）；**队长不下场写码** |
| 派活 | 每成员一份**共享任务**，正文含「**写集（逐文件） + 验收命令 + 写者**」；写集两两不重叠；热点文件单写者 |
| 并发 | 重型验证（vitest／全量门禁／黄金门禁）**串行 ≤1** |
| 回执 | **必须**含「团队成员运行记录」：成员名 · 运行状态 · token · **共享任务 id 与状态** |

**为什么严禁子代理代替小队**：子代理**无共享任务板、无 mailbox、无持久身份** → 无法"独立自验"、无法留运行记录 → 结果是**作者自判通过**。这正是已发生过的 M3 型事故（"小队是摆设"：面板里队伍建了，活是 4 个子代理串行干的，烧 3.1M/30.4M/38.6M/7.4M token 却无一条成员运行记录）。

**判定与退回（物理判据，不看解释）**：
- 只队长在运行、成员未运行 → **退回**
- 无共享任务 id、写集未逐人拆 → **退回**
- 自验由编码成员兼任 → **退回**
- **同类第二次 → 立即升级创始人**（红线）

### 3. 验收链（两侧同构，只有执行者不同）

```
成员（独立自验）→ 队长（出「自验结论」）→ CTO 收件闸（四判据）→ K3 终审
```
**收件闸四判据**：① 锚定三问回答 ② 声称↔证据逐条对应（命令 + 原始输出）③ **反例夹具"改坏即红"** ④ **团队成员运行记录**。
**执行方一律不判"通过"**；**有条件通过 = 未通过**。

### 4. 归属规则 = **一个模块只归一边**（见 `模块归属-MacWin-20260923.md`）
整目录/整包归属；owner 负责该模块全部改动类型；跨模块任务拆两张卡串行；同文件同时只有一个写者。

### 5. 跨机红线（两侧同规）
不碰 `scripts/audit/**`；禁 `--no-verify`／`git stash`／force push 共享分支；任务在 `.synova-wt-*`，**主工作区只做同步与协调**；计数与引用必须带「**命令 + 口径 + 截至时刻**」；K3 独立仓 **maker 侧（含 CTO）不得有写权**；保留各自机器身份不匿名。

## 二、唯一差异（就这一处）

| 环节 | Mac 侧 | Win 侧 |
|---|---|---|
| **CTO 角色**（派单/规格/**收件闸**/合并 PR/台账/双仪表盘） | **Mac-CTO** | **Codex** |
| 开发 | DSH 小队（同构） | DSH 小队（同构） |
| 独立审计 | K3（Mac/K3 独立仓） | K3（**Win 侧独立仓**） |
| 体系/门禁/**文档事实源** | **Mac 侧唯一** | 只读 + 提请求卡（不单方面改） |
| 模块归属 | 见归属表 | 见归属表 |

**Codex 作为 Win 侧 CTO 角色的同规约束**：不写产品代码；不碰 `scripts/audit/**`；不判自己派单的通过（终审归 K3）；派单必带「执行形态」硬字段（见 §一.1）；**派单前必须查板 + 报号段**（避免两侧撞号）。
