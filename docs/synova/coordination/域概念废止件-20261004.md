## 二、废止什么（精确边界）

### ✅ 废止
```
① **域作为【任务分配机制】** —— 不再有"某块归谁"、"跨域 PR"、"域主"这些概念
② **域作为【阻断依据】** —— 任何门禁不得因"跨域"而阻断（D1062 已对一处做了，本文凭废其余）
③ **域作为【组织架构】** —— 不再有"Mac DSH / Win Claude 的领地"语义
④ **块与域绑定的做法** —— 我此前问"K5 块归谁"= 该做法的产物，一并废止
```

### ❌ 不废止（保留的替代物，各司其职）
```
① **文件级互斥**（防两个 AI 会话同时改同一文件）
   ⇒ 由**派单方（CTO）在派单时保证**：一张卡一个写集，卡与卡写集不重叠
   ⇒ 不再需要 ownership.yaml 的 321 条路径规则来"推导域"
② **署名溯源**（谁改的）
   ⇒ 由 commit author（`synova-cto` / `Synova-Win` / …）+ `SIGN-OFF` 承载
   ⇒ 这是**记录**，不是**分配**
③ **K3 审计红线**（`scripts/audit/**` 其他角色禁碰）
   ⇒ 依据是**审计独立性**（铁律 0-5），与"域"无关 ⇒ 以"K3 独立仓 + 不碰审计脚本"表述
```

## 三、为什么可以废止（第一性推理）

```
域这个概念的原始用途（TASK-ROUTING.md 原文）：
  「两个人各管一块地…… 互不踩线」—— 两个**人**，在两台**机器**上

现在的实情（实测）：
  · ownership.yaml 里三个域 → **同一个 GitHub 账号** @tangbaobao520
  · 真正区分它们的只是**会话署名**（synova-cto / Synova-Win / synova-mac / Kimi K3）
  · 近 30 天提交：552 账号合并 / 439 synova-cto / 111 Synova-Win / 50 synova-mac / 4 K3
  · 🔴 而 `scripts/audit/**` 声明"k3 独占"，实际最近 20 次提交全是 **ClawOrg**

⇒ **域在人/机器这一层已经不存在了。剩下的只是一组路径规则 + 一堆引用它的门禁。**

而**新模型**（创始人 2026-10-04）：
  一个派单方（CTO）→ 若干执行者
  ⇒ 执行者之间**不需要**领地划分 —— 派单方保证写集不重叠就够了
  ⇒ 模块 = 独立包/插件/模块，**开发好与基座接上**
  ⇒ **不存在"怎么分配"的问题**
```

## 五、新模型（替代域的机制）

```
① **派单方 = CTO**，唯一。所有任务由我分派。
② **分配单位 = 模块**（一个包 / 一个插件 / 一个模块），不是"域"，不是"块"。
③ **不冲突的保证 = 写集互斥**（在派单时裁定：一张卡 = 一个写集；卡与卡不重叠）。
④ **接上基座 = 该模块的完成标准**（跑一次真实流程，断言它产生了数据/被消费 —— 穿生产入口）。
⑤ **署名溯源 = commit author**（记录谁改的，但不用于分配）。
⑥ **K3 独立性** = "K3 不碰 `scripts/audit/**` + 用自己独立仓"，与域无关。
```
