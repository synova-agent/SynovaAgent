## 一、一句话定义

> **一个「执行点」= 树上一个会自行点火、且能产出可判定结论（三态）的检查调用点**；
> 计数单位是 **call site（调用点）**，不是"检查项"、不是输出行数、不是日志里出现过的门禁名、不是文档宣称。

**含（计入）**：
1. 提交端 git hook 内**被实际调用**的检查（`pre-commit` / `commit-msg` / `post-commit` / `pre-push`）；
2. CI 中**会自行点火**的 job（每个 job 计 1；矩阵展开**不重复计**，避免"改矩阵 = 刷数字"）；
3. 平台层**配置型硬约束**（ruleset / branch protection / CODEOWNERS 生效规则 / ownership 语义——**仅当它真能阻断**）；
4. 自动触发的独立脚本（被 hook 或 CI 调用者）。

**不含（不计）**：
- **advisory / 顾问腿**：`continue-on-error: true` 的 job 或 step（它产结论但不阻断）；被移出必需集且仅"按路径触发"的腿——**单列不上账**；
- **纯提示项**：`opt_check` / `note_check` / `bypass_run` / 只打印不判定的旁路（它们的失败不进入任何阻断路径）；
- **只含 miss 的历史门禁名**：日志里出现过但树上无执行体的（幽灵载体，G9 那类）；
- **手工触发**的脚本（如 `verify-incremental.sh`、`baseline-check.sh`：D1146 后无自动登记点 ⇒ 不是执行点，是工具）；
- **文档/台账里的自称**（含 CHANGELOG、AGENTS.md 表格、brief 里的清单）。

**三条"不"（来自本波次实测教训，直接写进口径）**：
1. **不得用 grep 单独充当计数**：`grep` 只能回答"这个串出现过吗"（V-02）。
   凡计数命令，必须**同时**给出其**枚举源**（哪个文件、哪一行段、什么匹配规则），且该枚举源能被第二人复跑得到同一数字。
2. **不得跨载体比数**：本件实测——同一份命令在 `origin/main@13b294013` 与主仓 `c/docs/D1115…@c3edaedab` 上得出
   `密封面未登记 77 vs 78`、`密封面 136 vs 132`（载体差 1 个提交即漂移）⇒ **任何执行点数字必须带 `as_of` SHA**。
3. **不得把"具名调用点去重数"当"执行点总数"**：它只覆盖 hook 内部一层（本件 E1 的三列即为此设计：
   `去重 56 / 去掉沙箱夹具标签 55 / 非注释行 56`——**同一个口径可以有 3 个差 1 的值**，不标规则即不可比）。

**契约（path-1 简要）**：输入 = 可选载体目录（默认当前 git 仓根）｜输出 = `as_of` + E1..E9 + E10 探针｜

**为什么是"组合"而不是新建 `scripts/control-tower/check-execution-points.sh`**（CTO 明裁二选一中的"或"）：
1. **口径未裁前落地 = 先给数后定口径**，正是 CTO 明令禁止的顺序；
2. **自指污染**：新脚本会落进它自己统计的 `scripts/check-*.sh` / G5 分母（E6 = 28 → 29），
   即"加一个计数器就改变被计数的集合"——这类自指必须在口径里预先声明（本件以 E0 回避之）；
3. **新执行体而无归属判据**：口径未定 ⇒ 三态无意义（判什么？）；且按治理线纪律，**新增执行体须先有替代与退出条件**（自繁殖对冲）；
4. **密封面棘轮**：新脚本若配 `.test.sh` 夹具，会撞 `check-gate-integrity` 的"基线外新增"（见
   `未登记密封面清单-20261005.md` §三）⇒ 形成"新脚本永久红等另一个 PR"的循环依赖。

⇒ **待口径裁定后**再落 `check-execution-points.sh`（草案契约见 §五）。

## 五、`check-execution-points.sh` 契约草案（**未落地 —— 待 CTO 裁定口径后再开卡**）

```
【用途】按 CTO 裁定后的口径，一次打印全部"执行点"面值与 as_of；只读、不阻断。
【输入】$1 = 载体目录（默认 git 仓根）；$2 = 可选 --json
```
