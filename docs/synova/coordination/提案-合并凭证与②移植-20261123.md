## 2. 现状证据（真机原始输出；本机 Windows）

### 2.1 凭据三级全空、真 token 在 GCM（甲类根因；已修）

```
== 前三级来源现状（只看是否有值，不打印值）==
GITEA_TOKEN=(empty)
SYNO_GITEA_TOKEN=(empty)
HOME/gitea/.win-push-token=missing
```

`git credential fill`（`GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=never timeout 10`）对 `host=127.0.0.1:3000` **可非交互取到** `password`（探针只输出 `HAS_PASSWORD=yes`，不打印值）。

### 2.2 ② 在 Git Bash 恒 exit 2（真机原始输出）

`bash scripts/control-tower/check-merge-conditions.sh --pr 1461 --repo-root <本仓>`（Git Bash，token 已可取到）：

```
① CI 全绿 pending=0 ......... ok (state=success total_count=1)
MERGE-COND: degraded ①=ok
degraded: ② 对手集缺失/为空（prs.tsv）——判不了，禁 ok(比对 0 对)
[stderr]
Traceback (most recent call last):
  File "<stdin>", line 8, in <module>
FileNotFoundError: [Errno 2] No such file or directory: '/tmp/syno-mc.EpUFTT/pulls_p1.json'
degraded: ② 对手集缺失/为空（prs.tsv）——判不了，禁 ok(比对 0 对) [code=E_OPENPRS_EMPTY]
```

**根因（实测，非推断）**：MSYS 只对**命令行 argv** 做路径转换，**不转换文件内容/环境变量**。

```
python= C:\Users\Administrator\AppData\Local\Programs\Python\Python313\python3.exe
argv[/pulls/100]= 'C:/Program Files/Git/pulls/100'      ← argv 被转换
argv[/pulls?state=open]= '/pulls?state=open&limit=50&page=1'  ← 含 ?/& 时不转换
argv[/tmp/x.json]= 'C:/Users/ADMINI~1/AppData/Local/Temp/x.json'  ← argv 被转换
文件内容里的 /tmp/... → python 看到原样 POSIX ⇒ FileNotFoundError（上条 traceback）
```

⇒ `scan_open_prs`（`gitea/main` L350-393；甲类改动后 L415-458）把 `$WORK/pulls_p1.json` 的 **POSIX 路径写进 `pulls_parts.txt`**，再交给 **native Windows python** ⇒ 打不开 ⇒ 合并步失败。

**附带的静默吞错**（铁律 11）：`scan_open_prs` 的合并 python 调用**未检查返回码**（函数尾恒 `return 0`）⇒ 真因（FileNotFoundError）只留在 stderr，判定层看到的是 `E_OPENPRS_EMPTY`（"对手集为空"）——诊断被引偏一层。本次真机输出即此形态。

### 2.3 同一坐标缺陷的另一面：Git Bash 的 `--selfcheck` 恒 A 红（**既存**，与甲类改动无关）

| 运行壳 | `--selfcheck` | 主配对测试 |
|---|---|---|
| WSL（`/mnt/d/...`，默认 `bash`） | `SELFCHECK-OK: 13/13` | `结果: 14 通过, 0 失败` |
| Git Bash | `SELFCHECK-FAIL: A`（A 用例 `HTTP 500 on /pulls/100`） | `结果: … 12 处 ❌`（A/B/C/D1–D4/E/F/G/H/J） |
| Git Bash ＋ **base 原脚本**（对照组） | `SELFCHECK-FAIL: A`（**同一条**） | **同 12 处 ❌** |

原因：fixture 模式下 `fixture_get` 把 **API 路径**当 **argv** 交给 native python（`fixture_get "$path" "$out"`，`gitea/main` L228-283／甲类后 L293-348）。`/pulls/100` 被 MSYS 转成 `C:/Program Files/Git/pulls/100` ⇒ 正则 `^/pulls/(\d+)$` 不命中 ⇒ `sys.exit(1)` ⇒ `api_get` 读成 500 ⇒ A–J 全崩。**注意 `/pulls?state=open&...` 因含 `?`/`&` 反而没被转换** —— 这解释了为什么只有部分调用坏。

> 结论：**「文件路径」与「API 路径」必须分开处理**。一刀切"全改 argv"会修好 ②、却把 fixture 模式反向弄坏（API 路径本不该被当文件路径转换）。

## 3. 乙类提案 A：② 移植修复（推荐方案）

### 3.1 推荐实现（最小面，两处）

**A-1 `scan_open_prs`：页文件路径改走 argv（+ 检查合并步返回码）**

- 现状（`gitea/main` L355-391）：`printf '%s\n' "$WORK/pulls_p${page}.json" >> "$WORK/pulls_parts.txt"` → `python3 - "$WORK"`（python 从文件读路径）。
- 改为：用 bash 数组收集页文件（bash 3.2 支持普通数组），`python3 - "$WORK" "${parts[@]}"`；python 侧 `sys.argv[2:]` 即页文件列表，**不再读 `pulls_parts.txt`**（该文件可保留作调试快照，或一并删；建议删，防两套坐标系）。
- **必须同时加返回码检查**：`if ! python3 - ...; then die_degraded "E_OPENPRS_JSON: open PR 列表合并失败（fail-closed）"; fi`（复用既有 `E_OPENPRS_JSON`，**不新增码**）。否则本次这种"合并失败 → 空集 → E_OPENPRS_EMPTY"仍会复现，只是换成别的坑。

**A-2 `fixture_get`：API 路径改走**环境变量**（不被 MSYS 转换）**

- 现状：`fixture_get "$path" "$out"` → `python3 - "$FIXTURE" "$1" "$2"`，`$1` = `/pulls/100` 被转换成 `C:/Program Files/Git/pulls/100`。
- 改为：`SYNO_MERGE_COND_FIXTURE_PATH="$path" python3 - "$FIXTURE" "$out"`，python 读 `os.environ["SYNO_MERGE_COND_FIXTURE_PATH"]`；**文件路径（夹具/输出）仍留 argv**（需要被转换）。
- 该项**不改变生产路径**（fixture 仅测试/自检），但它决定"三平台回归能否用同一套 selfcheck 判据"。

**备选（不推荐）**：`cygpath -w` 归一所有路径再交给 python。缺点：要在写文件前知道谁会读、`cygpath` 在非 MSYS 平台不存在需 `command -v` 分支、Windows 反斜杠/空格进 TSV 文本会引入新的转义面；且**API 路径仍会被 argv 转换**，A-2 照样要做。故仅作为 A-1 不可行时的兜底。

### 3.2 契约变化（写进脚本头）

- `@cross_platform` 补：**「跨 MSYS↔native 边界：文件路径走 argv（MSYS 转换），API 路径走环境变量（MSYS 不转换）；禁把任一者写进文件再交给 native 解释器」**。
- `scan_open_prs` 头注释补：合并步失败 ⇒ `E_OPENPRS_JSON`（禁 `E_OPENPRS_EMPTY` 掩盖真因）。
- **退出码不变**：0/1/2 三态语义一字不改；`E_OPENPRS_EMPTY` 断言**保留**（对手集真空仍是 exit 2）。

### 3.3 风险

| 风险 | 处置 |
|---|---|
| 假绿：修完仍拉到空集却判 ok | `E_OPENPRS_EMPTY` 断言**不动**；再加"合并步 rc≠0 ⇒ exit 2"双保险 |
| argv 长度上限（Windows 32767 字符） | `MAX_PAGES=20` × 单页路径（~60 字符）≪ 上限；不构成风险，写进限制说明 |
| 普通数组在 bash 3.2 的行为 | 仅用 `parts=()` / `parts+=("$p")` / `"${parts[@]}"`（3.2 均支持）；macOS 回归必跑 |
| 页文件顺序 | 数组按页序追加，`seen` 去重逻辑不变 ⇒ 与现状同序 |
| 删 `pulls_parts.txt` 影响既有测试 | `grep` 全仓该文件名（测试未引用）；若保留则明确"只是快照、不再被读" |

### 3.4 回滚

单文件 `git revert`（`scan_open_prs` 与 `fixture_get` 两块可独立回滚；A-2 回滚后 Git Bash 的 selfcheck 回到既存 A 红，但 ② 生产路径不受影响）。

## 4. 乙类提案 B：`E_NO_TOKEN` 降级码

- **触发条件（窄口径，三条同时满足）**：① `TOKEN` 为空；② HTTP ∈ {401, 403}；③ 响应体含 `Only signed in user`。
- **行为**：`die_degraded "E_NO_TOKEN: 无凭据（GITEA_TOKEN/SYNO_GITEA_TOKEN/$HOME/gitea/.win-push-token/git credential fill 四级全空）——补凭据后重跑"` ⇒ **仍 exit 2**（与现状同退出码，只把"凭据缺失"与"API 故障"分开）。
- **落点**：`resolve_pr`（`/pulls/<n>`）、`cond1_ci`（`/commits/.../status`）、`scan_open_prs`（`/pulls?state=open`）三处 `*) die_degraded "E_*_HTTP: ..."` 分支前加一次 `api_auth_hint` 判定；④ 次级 CI 不 degrade（现状即"不绿"），不改。
- **真机依据**：无 token 直连 API 得到
  `{"message":"Only signed in user is allowed to call APIs."}`（当前脚本把它吞成 `E_API_HTTP: HTTP 403`）。
- **风险**：响应体嗅探是"内容约定"，Gitea 改文案即失效 ⇒ 失效后**退回现有 `E_API_HTTP`**（不新增失败模式）；必须"TOKEN 为空"才嗅探，避免把"token 过期"误报成"没配 token"。**不得**因此新增 exit 3/0 之类退出码。
- **回滚**：删 `api_auth_hint` 与三处分支即为现状。
