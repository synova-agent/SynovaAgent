## 一、现行判据（**不合格**，要换掉的那条）

原卡（#987/#988，batch0b 五支，已合 `4a35bd7cc`）Done 里写的是：

```
grep -rl "action_effect_lag" extensions/ontology/edge-types/ | wc -l   ⇒ 55
# 以及等价的形式：WITH_FIELD_NONEMPTY=55
```

**为什么不合格（判据纪律 B：修复前 baseline 上必须红）**：
- 该判据只问「键**在不在** / 值**非不非空**」。`"unknown"` **非空** ⇒ 满足。
- 于是它**分辨不出**「时滞值已定」与「显式写了个 unknown」——
  **而后者恰好是本批 55 条里的 50 条**（实测：`unknown` 50 · 5 条有值）。
- 换句话说：这条判据**在被测物什么都没修好时也会绿**（只要有人把 `"unknown"` 写进去）。
  ⇒ 它不是判据，是**格式检查**。

**实测证据（main `4a35bd7cc`）**：
```
$ git grep -h '"action_effect_lag"' origin/main -- extensions/ontology/edge-types/ | sed 's/.*: //' | sort | uniq -c
  40 "unknown",      ← 40 + 10 = 50（40/10 的拆分是 CRLF 行尾差异，非两个值）
  10 "unknown",
   2 "3-6_months",
   1 "immediate",
   1 "1_month",
   1 "1-3_months",
```

## 二、提案判据（**待裁**）

### 2.1 主判据：**落在权威枚举内的条数 > 0**

权威枚举（源：权威文档15 第一章 §3.4，**六个值，不含 `unknown`**）：
```
immediate | 1_month | 1-3_months | 3-6_months | 6-12_months | >12_months
```

**可复跑命令（v2 · 按 K3 审计 B3/B4 重写：单遍文本管道 + 有 exit 码 + 与拼写锁捆绑）**：

```bash
#!/usr/bin/env bash
# 判据 · W3 时滞「有值 vs 未知」—— 两检查同脚本，缺一即开洞（K3 P1-8：2.1 单独可被 JSON 重复键绕过）
# 基线必须钉 sha，禁用「batch0b 前」这类浮动表述（K3 P1-7）；真起点 = c9b365590^
REF="${1:-origin/main}"
vals=$(git grep -h '"action_effect_lag"' "$REF" -- extensions/ontology/edge-types/ \
        | sed -E 's/.*: *"([^"]*)".*/\1/' | sort -u)          # CRLF 免疫（引号内捕获）
# (1) 主判据：落在权威枚举内的条数 > 0
IN_ENUM=$(printf '%s\n' "$vals" | grep -cxE 'immediate|1_month|1-3_months|3-6_months|6-12_months|>12_months' || true)
[ "$IN_ENUM" -gt 0 ] || { echo "FAIL: IN_ENUM=0"; exit 1; }
# (2) 拼写锁：非枚举值必须逐字 == unknown
BAD=$(comm -23 <(printf '%s\n' "$vals") <(printf '%s\n' unknown immediate 1_month 1-3_months 3-6_months 6-12_months '>12_months') | grep -x . || true)
[ -z "$BAD" ] || { echo "FAIL: 非法值: $BAD"; exit 1; }
echo "PASS: IN_ENUM=$IN_ENUM"
```
🔴 **K3 P1-9 修复点**：v1 的 `echo "IN_ENUM=$IN_ENUM"` **永远 exit 0** ⇒ 照抄入仓即违反 [#1137]。本版**两条检查各带 exit 1** 且**捆绑在同一脚本内**。
**实测现值（🔴 2026-10-05 实跑本命令后纠正 —— v1 写的 5 与命令实际打印不符）**：

本命令的 `IN_ENUM` 是 **枚举值「种类数」**（`sort -u` 去重后计数），因为第二检查（拼写锁）需要去重值集。
实跑两态（原样跑件内命令）：
```
$ bash w3-check.sh origin/main        # ⇒ PASS: IN_ENUM=4   exit 0
$ bash w3-check.sh c9b365590^         # ⇒ FAIL: IN_ENUM=0   exit 1   ← 真基线红 ✓
```
| 口径 | 值 | 说明 |
|---|---|---|
| **种类数**（本命令打印） | **4** | `immediate` · `1_month` · `1-3_months` · `3-6_months` |
| **条数**（K3 审计口径） | **5** | 同上，其中 `3-6_months` 出现 **2** 次 |
⇒ 两者都 `> 0`，**判据等价成立**；但**落登记件时必须写清用哪种计数**，否则「现值 5」与命令打印的「4」又是读数≠判据。
**原 v1 表述**：（`immediate` 1 · `1_month` 1 · `1-3_months` 1 · `3-6_months` 2）

### 2.2 分辨力证明（**§三-B 承重**）

| 状态 | `IN_ENUM` | 判据 |
|---|---|---|
| **修复前**（batch0b 合并前，字段整个不存在） | **0** | 🔴 **红** |
| 修复后（`4a35bd7cc`） | **4 种类 / 5 条** | 🟢 绿（实跑本命令 = 4） |
| **反例：只写 `"unknown"` 不写任何枚举值** | **0** | 🔴 **红** ← 现行判据在这一点上会**假绿** |

⇒ 新判据**分辨得出**「有人只填 unknown」这种形态 —— 这正是它要防的。

### 2.3 附加条款：**未知必须是 `unknown`，不许是 `TBD`**

目的：禁止用不同拼写绕过"未知"的识别。🔴 **已并入 §2.1 的同一脚本（K3 P1-8）** —— 单独使用会漏掉「JSON 重复键」绕过面：
`{"action_effect_lag":"TBD","action_effect_lag":"immediate"}` 下 `python json.load` **静默取最后一个重复键**
⇒ 纯 2.1 判绿而文件里躺着 `TBD`；文本检查能看到两行 ⇒ **两条必须捆绑，缺一即开洞**。
**现值**：唯一非枚举值是 `"unknown"` ✅
