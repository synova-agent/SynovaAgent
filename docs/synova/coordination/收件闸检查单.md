# 收件闸检查单（CTO 验收唯一载体，D943）

> **每次验收必须逐项打勾并附原始输出**；缺项 = 未通过；**有条件通过 = 未通过**；执行方一律不判"通过"。

## 〇、断面与口径（D943 新增，**先查这项**）

- [ ] **断面一致**：`python3 scripts/control-tower/check-dsh-anchor.py --repo .` → **`DSH-ANCHOR: OK`**
      （若 `DEGRADED`＝树已移动或事实源坏 → **不得验收**，先更新断面源并重取引用）
- [ ] **未引作废口径**：对照 `docs/synova/coordination/已作废口径表.md`，交付物未把作废口径当现状引用
- [ ] **单一事实源**：交付物所依据的权威文件已写明路径（不是"我记得"）

## 一、锚定三问

- [ ] 本卡要我解决什么？**卡面/派单件**在哪？（给路径）
- [ ] 交付物改了哪些文件？（`git diff --name-only`；与写集一致，零夹带）
- [ ] 与在飞工作是否冲突？（热点文件单写者：`ci.yml`／`pre-commit-check.sh`／`ownership.yaml`／`派单模板.md`）

## 二、声称 ↔ 证据逐条对应

- [ ] 每条判据都有「命令 + 原始输出」，**不是结论句**
- [ ] 计数带「口径 + 排除项 + 截至时刻」
- [ ] 负面断言写明搜索范围

## 三、反例「改坏即红」

- [ ] 变异体矩阵：每条"改坏 N 处 → 对应夹具必须红"，**贴原始输出**
- [ ] 复原后必须绿（同批证明）
- [ ] **红证不得残留仓库**（`grep -rc INJECTED-RED` 须 0）

## 四、团队成员运行记录

- [ ] 成员名 · 运行状态 · 共享任务 id 与状态
- [ ] **自验不得由编码兼任**；写集两两不重叠
- [ ] token 不可得时**以 model 替代并说明来源**（**禁编数字**）
- [ ] 只有队长在跑 / 无共享任务 id / 自验由编码兼任 → **退回**

## 五、机制在场性（D943 新增）

- [ ] 交付的机制能回答三问（消费者是谁／在哪一层／哪条命令证明在跑）
- [ ] 门禁类交付：**CI 清单已登记 + CI 上真跑通**（附 CI 原始结论；不许"先入列再修"）

## 六、K3 与合并

- [ ] 门禁/治理类改动 **必须过 K3**（执行方与 CTO 均不得自判通过）
- [ ] 合并顺序符合依赖（栈式 PR：base 先合）
- [ ] 既有红：允许带红合并，**但必须在 `ci-red-baseline.txt` 登记**（未登记即违规）
