## 〇、这份文档为什么存在

创始人的原话：「**我要的不是凭借记忆，而是你真的能做到遵照你写出来的这些原则行事。**」

本文档把"原则"变成**可检查的约束**：每条原则 → 一个机器消费点（门禁/脚本/门禁字段）→ 违反即阻断。
**凭记忆 = 每天重新决定一次要不要遵守**；本文档 = 把决定固化一次。

## 一、主线定义（唯一口径，不因谁吵得响而变）

**产品主线 = 让产品成立的最小可信闭环，三件事：**

| 主线支柱 | 含义 | 对应验收 |
|---|---|---|
| **① 能被装起来用** | 桌面端线 1 走到 100% | 线 1 的 1-1…1-8 全部 verified |
| **② 报告可溯源** | 证据链接通（采集→落库→引用） | 一条诊断报告能溯源到 ≥1 条原始证据 |
| **③ Agent 能主动** | D-1 状态驱动通知模型落地 | 8-6 契约 + loader + 通知链跑通 |

**判据（每次派单前必答）**：
> **这件事让 ①/②/③ 中的哪一项前进？** 答不上来 → **标为 `infra:<理由>`**，且计入基础设施工时。

**非主线的都是支撑**（控制塔、门禁、看板、审计吞吐）——**它们合法，但不许超 25% 产能**。

## 三、三阶段推进（退出条件写死）

### 阶段 1｜止血：事实可见 + 清空欠账（T+0 ~ T+3 天）
- 看板真相源三层修复（线级状态派生 + verdict 维度 + 失败可见）
- CTO 健康看板修复（崩溃 + FAIL 判定）
- D738 基线棘轮（CI 转绿）
- D735 Stage 2（bypass 出库切换）
- 早期队列 PR 全部收口（无 open 积压）
- 批 C：merge queue（`merge_group` + 一键回滚）
**退出条件**：仪表盘数字 = 真相源数字；**零 PR 积压**。

### 阶段 2｜主线攻坚：线 1 → 100% + 证据链接通（T+3 ~ T+10 天）
- 1-5 双引导收敛实施（Win，spec 已在 main）
- **1-4 重打新产物 + 证据落盘（D747，Mac，CTO 亲做）**：重打包 → 安装实测 → `[preload-check] OK` 原始日志 + 渲染层 API 实测请求**双双落 git 证据文件**（贴命令与输出）
- 1-2 / 1-6 Win 环境阻塞补测（人工桌面会话）
- 1-8 复验（K3，绑新产物）
- **D728 + D729(Win 部分) 证据链接线**（Win，一次扩写集 + 中间态护栏）
**退出条件**：**线 1 = 100%**；报告能溯源到 ≥1 条原始证据（贴命令）。

### 阶段 3｜产品闭环（T+10 ~ T+20 天）
- D-1 通知模型落地（8-6）
- 哨兵真实数据流（表建了但空着 → 真实数据）
- L1 未闭合项 9 → 0
- 技术债按域清（57 处 locale、测试 hermetic 等）
