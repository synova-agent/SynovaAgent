## 附一 · 🔴 本窗新增：**散落门禁体系归一**（创始人点名）

**创始人原话**：「**我们研究院也有过研究，我们不同的门禁体系散落各处。**」

**我实测到的"散落"形态（供你起手，不是清单）**：

| 时机 | 载体 | 我实测到的例子 |
|---|---|---|
| 写代码前 | PreToolUse hook | `hook-block-write`／`hook-check-task-scope` |
| 提交时 | `pre-commit` 13 组 | 类型安全/测试/秘密/接线/架构/brief/契约/文件驱动/范围/技能同步 |
| 提交声明 | `commit-msg` | Conventional Commits + **D328 一致性强阻断**（`resolve-commit-brief` 拿**暂存文件**匹配 brief 写集） |
| 推送时 | `pre-push` 0-5 | 多机同步／secrets／golden-case／vitest --changed／tag |
| CI | `ci.yml` 13 job（矩阵展开） | 与 pre-commit **大量重叠**（本地软提示 / CI 权威） |
| 服务端 | ruleset `main-protect` + legacy protection | **两套保护并存**，必需集 12 项**只在 legacy 一处** |
| 提交后 | post-commit | bypass 检测 + 外部审计器 + 决策建议 |
| 文档 | `doc-registry-gate` / `check-doc-contract` / DOC-CONTRACT 三闸 | 我实测的 `DOCS-REGISTRY.yaml` 撞号与冲突 |
| 认领/号源 | `alloc-task-id.sh` + 水位表 + task-state | **我今天实测：水位表滞后 146 号** |
| 密封面 | 棘轮基线（`ci-red-baseline.txt`／`required-checks-baseline.txt`／`gate-integrity-baseline.txt`） | **三张基线表** |

**⇒ 本窗要求（范围，不是任务）**：
**出一份"全量门禁地图"**：**哪条在哪个时机、拦什么、是否重复、是否可并、缺口在哪、总条数趋势**，
并给出**归一方案**（合并重复 / 补缺口 / 退役死项 / 明确单写者），**配套 G′3 净新增季度复审口径**（院方 §2.4.2）。
