### 3.2 判定：**并入 PR #1079（同一支），不另开卡**

**理由（顺序性，非偏好）**：
- **同一支**：ratchet 是**逐树求值**的（`all_ci_face` 来自该树 `tests/`）。夹具与登记若不在同一棵树，就是两个半成品：
  - 先合 #1079（无登记）⇒ 该 PR 的 `Gate Integrity` **红**；且该红 check-run 会落 main tip ⇒ 按 #1077 §四 的跨机制实测
    （`run_ci_reds` 统计 base 上**全部** `failure`，**不问是否必需**）⇒ **把下一个 PR 的 `Gate Integrity` 拖红**（C 段"未登记 CI 失败"）。
  - 先合"登记"（夹具还没进树）⇒ `ci.yml` 里一条**指向不存在夹具**的路径 = 幽灵登记（G9 同型），且不产生任何密封面收益。
- **不另开卡**：这不是"缺一件"，而是**#1079 自身缺一行**（同一 PR 内补 = 一次提交解决，另开卡 = 制造"红等另一个 PR"的循环依赖
  —— #1107 正文 §五.4 已把这个反模式写下来过）。
- **责任面**：`ci.yml` 属 **T3 / Lead 域**（治理线红线：本席**不改** `ci.yml`）⇒ 本件的产出是"判定 + 证据 + 精确插入位置"，**执行不在本席**。

### 3.3 插入位置与形式（给执行者）

- **推荐形（真跑）**：把两行加入 `ci.yml` 的 canary 密封清单 `for t in \` 块（`:499` 起，`tests/control-tower/*.test.sh` 清单）。
  **前置条件**：两夹具必须 hermetic（不依赖本机 git 历史/网络）。**未核**——本席只读，未跑这两个夹具；**请执行者先跑一遍再登记**。
- **退让形（登记但不跑）**：写进同 job 的注释块（`ci.yml:491-492` 已承认注释形计登记）。
  **代价**：**登记 ≠ 执行**（这套 matcher 的根本弱点）——必须同时在注释里写明"未在 CI 执行，原因 X"，否则就是假登记。
