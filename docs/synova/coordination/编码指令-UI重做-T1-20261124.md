## 2 · 本任务目标

在**必需 CI 上下文**内建立客户可见字符串的禁用词 ratchet：

1. 一个**提取器**：从 `electron-renderer/src/**/*.{ts,tsx}` 取出客户可见字符串（范围见 DEV DOC §5.4）。
2. 一个**判定器**：拿《词典》§1 规则（**只对 §1.1 M 级做阻断**，H 级只输出复核清单）判违规。
3. 一份**允许清单**：把现状全部违规登记为可销账条目，键＝`(path, rule, normalizeText(text))`。
4. **四条硬断言**（DEV DOC §5.4）：零清单外违规／清单不腐化／覆盖面不缩水（文件数==43、每文件候选>0）／总量不塌（==实测冻结基线数）。

**关键**：允许清单是**债单**，不是豁免。每批 T2–T6 修掉一条就必须删一条；留着旧条目也会红。

## 5 · 关键契约（照抄，不得自创）

### 5.1 提取器

- 扫描根：`process.env.UI_REDO_SCAN_ROOT ?? 'electron-renderer/src'`（**必须支持该环境覆盖**，反例 T1-D 靠它）。
- 被扫：`.ts`/`.tsx` 的**字符串字面量**与 **JSX 文本节点**。
- 不扫：`className`／`data-*`／`data-testid`／`style` 值、import 路径、`console.*` 参数、注释与 JSDoc。`aria-label` 计入客户可见但**不进 allowlist 销账口径**。
- 导出：`extractVisibleStrings(root): Array<{path, line, text}>`。

### 5.2 归一化（键的确定性依赖它）

```ts
export function normalizeText(raw: string): string {
  return raw.normalize('NFKC').replace(/\s+/g, ' ').trim();
}
```
两侧（源码提取物、allowlist 的 `text`）**必须共用这一个实现**。

### 5.3 允许清单

- 条目＝`{ path, rule, text, why, lineHint }`。
- **键＝`(path, rule, normalizeText(text))`**；`lineHint` 仅展示，**不得参与判据**。

### 5.4 四条硬断言

| # | 断言 | 红条件 |
|---|---|---|
| 1 | 零清单外违规 | 任何 M 级命中不在清单内 |
| 2 | 清单不腐化 | 清单条目的 `(path, rule, normalizeText(text))` 在源码中**不再出现** |
| 3 | 覆盖面不缩水 | 被扫文件数 ≠ **43**；或任一被扫文件候选数 == 0 |
| 4 | 总量不塌 | 候选字符串总数 ≠ 你在本任务实测并写死的基线数 |

> 断言 4 的基线数必须由你实测产出，并在回执里给出**命令与原始输出**；写死后只能因有序删除而更新，不得随手调小。

## 7 · 失败与回退 · 停点

**失败与回退**
- 提取器误报多（把内部常量当客户面）⇒ **只能收窄"提取规则"**（哪些不算客户面），**不得收窄禁用词表**。

- 完全无法区分 ⇒ 停，退回 CTO。

**停点（出现即停，回来找 CTO）**——编号与 DEV DOC §6.1「停点」逐条对齐

1. 《词典》某条规则会误伤真实客户数据（如客户表名本身含下划线命名）。
2. 需要改 `electron-renderer/**` 才能完成。
3. 需要新增 CI job、改 `scripts/ci/**` 或改门禁判据。
4. 「技术详情」的开放范围会影响扫描口径（属产品口径，非实现细节）。
5. 发现《词典》§1.1/§1.2 之外还有**有串无级别**的泄漏点（分级表有漏），**不要自行定级**，报上来。
