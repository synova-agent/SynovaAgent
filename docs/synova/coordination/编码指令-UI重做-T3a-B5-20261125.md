## §3 目标行为（**骨架＋文案**，真值留接口）

### 3.1 状态位骨架（前端只表达，不推断）
定义**展示层**的四个空态分支（不新增业务真值）：

| 分支 | 触发条件（**本批可用的判据**） | 客户可见文案 |
|---|---|---|
| `insufficient_data` | 已有 `hypothesis.invalid` 且 `reason.code === 'INSUFFICIENT_CONTEXT'`；或 `synova_context_get` 返回 `count === 0` | **数据不足，无法形成瓶颈假设** ＋ 缺什么／怎么补 |
| `invalid_output` | `hypothesis.invalid` 存在但 code 非 `INSUFFICIENT_CONTEXT` | **输出未按约定成型** ＋ 技术详情入口 |
| `no_output` | `run.completed` 但无 `hypothesis.structured` 也无 `hypothesis.invalid` | **本轮未产出假设** |
| `unknown` | 以上都不满足，但 `outcomeStatus` 字段**尚未存在** | **暂无法判定本轮结果**（**不得**冒充完成或失败） |

> 🔴 **重要**：`unknown` 这一支就是"真值未到"的诚实表达。**不允许**用现有零散事件拼出"成功/失败"。

### 3.2 空态渲染规则
1. **不渲染**「瓶颈假设」四要素占位（对象/关系/依据/不确定性一律不填占位散文）。
2. 改为：**一句话结论（数据不足）** ＋ **缺什么**（列表）＋ **怎么补**（动作建议）＋ 技术详情入口。
3. `missing[]` 若为空 ⇒ 显示「未提供具体缺口」（兜底入 §2.7-K，本批可加）。

### 3.3 与技术详情
```tsx
<TechnicalDetails items={[{ label: '状态', value: reason.code }, …]} />
```
默认收起；`reason.code`／原始 message 只在这里出现。
