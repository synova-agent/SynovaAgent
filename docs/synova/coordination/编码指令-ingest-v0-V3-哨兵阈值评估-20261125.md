## §3 目标行为

### 3.1 正常路径（入口 → 操作 → 结果）
```
[入口] node scripts/ingest-v0/sentinel.mjs --db <隔离库> --org <orgId> --period <YYYY-MM> [--out <json>]
[操作] ① 打开隔离库：`new Database(dbPath, { fileMustExist: true })`（**可写**，因为要写事件；**不得**调 `reconcileSchema`，那会写 schema）
      → ② 预检 `metric_observations` 存在 → ③ 枚举本企业本期的对象（含 sales.target 或 sales.performance 任一）
      → ④ 逐对象校验并计算（§5.2 守卫）→ ⑤ 判定 §5.3 三态
      → ⑥ 经 appendSentinelEvent 写 run_completed ＋（未达成的）finding
      → ⑦ 用 replaySentinelEvents 读回自检，打印摘要（可选写到 --out 的**人类可读摘要**，非唯一产物）
[结果] 退出码 0/1/2；`sentinel_events` 新增行；`GET /api/sentinel/findings` 可见未达成项
```

### 3.2 判定三态（③ 只算，不评级越权）

| 状态 | 条件（全部满足才算"可判"） | 产出 |
|---|---|---|
| `achieved`（达成） | 守卫全过 ∧ `performance / target >= 1` | **不写 finding**；在 run_completed payload 计数 |
| `below_target`（未达成） | 守卫全过 ∧ `0 ≤ performance / target < 1`（**含 0**：目标为正而业绩为 0 就是未达成，不存在 0 态空洞） | 写 **1 条 `finding`**，`severity='warning'`，payload 带 §5.4 全部追溯字段 |
| `insufficient_data`（数据不足） | 守卫任一不过（§5.2） | **不计算、不告警、不写 finding**；原因逐条进 run_completed payload |

- 🔴 **绝不输出 `critical`**：我们只有"客户目标"一个判断点，标不出两档；编第二档就是伪造（裁定四）。
- 🔴 `insufficient_data` **不得**降级成 `below_target`，也不得当成"正常"。

### 3.3 数据缺失／失败时
| 情况 | 表现 | 退出码 |
|---|---|---|
| 缺参数／未知开关 | `E_BAD_ARGS`，不写任何事件 | 2 |
| 库不存在／不是 SQLite | `E_DB_UNREADABLE` | 2 |
| 缺 `metric_observations` 表 | `E_TABLE_MISSING`（提示先跑 V2） | 2 |
| 本企业本期无任何相关指标行 | `status:"no_data"`；不写事件 | 1 |
| 有行但全部 `insufficient_data` | 写 1 条 `run_completed`（含原因计数），不写 finding | 1 |
| 单轮（org+period）观测行 **> 10000** | `E_OBSERVATIONS_TRUNCATED`；**不写事件**（禁止静默截断凑数）；需要时应另立分页票，不是本票扩范围 | 2 |
| 写事件失败 | `SentinelsEventError` 原样上报（含 code/phase/retryable），不吞 | 2 |
| 读回自检为空（写了却读不到） | `E_SELFCHECK_READBACK`（**不许报成功**） | 2 |

### 3.4 禁止的假象
❌ 用 `info` 冒充"未达成"或"数据不足"｜❌ 把 `target` 猜出来／用 `performance` 反推 target｜❌ `target=0` 时算除法得 `Infinity` 当达成｜❌ 把 `insufficient_data` 计成"达成"｜❌ 只写 `--out` JSON 不写事件表（那正是裁定三禁止的脚本演示）｜❌ 在 finding 里填 `critical`。

## §5 关键契约

### 5.1 读原语（追加）
```ts
export interface MetricObservationScope { orgId: string; period?: string; objectId?: string; metricId?: string; limit?: number }
export interface MetricObservationPage { rows: MetricObservationRow[]; truncated: boolean }
export function listMetricObservations(db: Database.Database, scope: MetricObservationScope): MetricObservationPage
```
- 校验（**不复用四键校验**，那是全键必填）：`orgId` 非空；可选字段出现时必须非空；`objectId !== '*'`；`limit` 整数 1..10000（缺省 1000）。
- `truncated = 命中行数 > limit`（读侧 `LIMIT limit+1`，只返回前 limit 行）。
- `READ_FAILED`：查询失败；**只 select**；`WHERE org_id = @orgId` 必带；`ORDER BY period, object_id, metric_id`。

### 5.2 守卫（每条都要有独立用例）
对同一 `(orgId, period, objectId)` 的两行 `sales.target` / `sales.performance`：
1. 两行**都存在**（缺任一 ⇒ `insufficient_data`，`reason:'MISSING_METRIC'`，写明缺哪个）；
   > 可达性说明：V2 对**空单元格不落行**（`facts.mjs` 只在解析出有限数时产事实）⇒ 真实数据上"缺业绩"表现为**该行不存在** ⇒ `MISSING_METRIC`。`PERFORMANCE_MISSING` 只在**行存在但 `value=NULL`** 时触发（本票的防御性守卫，**只能由单元测试构造**，V2 数据产不出来）。
2. `target > 0`（≤0 或 NULL ⇒ `reason:'TARGET_NOT_POSITIVE'`）；
3. `performance` 为有限数（行在但 NULL/NaN ⇒ `reason:'PERFORMANCE_MISSING'`）；
4. **同 org、同 period、同 object**（四键已保证，仍须断言 `org_id===orgId && period===period`）——违约 `reason:'SCOPE_MISMATCH'`；
5. **同单位**：两行 `unit` 都非空且相等（不等 ⇒ `reason:'UNIT_MISMATCH'`；任一为空 ⇒ `reason:'UNIT_MISSING'`）；
6. **都有原始来源**：两行 `source_id`/`evidence_ref` 至少各有一项非空（否则 `reason:'SOURCE_MISSING'`）；
7. `target` **只能取自库内观测行**——禁止由 `performance`、模型或行业默认值推断（代码层面：函数只接受读到的 `target` 值）。

### 5.3 计算与评级
```
achievementRate = performance / target          // 仅守卫全过时计算
achieved      : rate >= 1
below_target  : 0 ≤ rate < 1  ⇒ severity 'warning'  // 阈值来源＝客户自己的目标（真实阈值，非伪造）；含 rate=0
insufficient_data: 守卫不过   ⇒ 不计算
thresholdSource = 'customer_target'             // 逐字使用创始人给的取值
```
🔴 **永不产出 `critical`**。定级口径已经创始人裁定（2026-11-26）：未达成 ⇒ `warning`；**coding 不得自行改评级**（改判须先改本件）。

### 5.4 事件契约（**逐字对齐 `persistRunEvents` 投影形状**）
```jsonc
// 事件 1：run_completed（每轮 1 条）
{
  "event_type": "run_completed",
  "sentinel_id": "sales-achievement",
  "aggregate_id": "sales-achievement@<checkedAt ISO>",
  "payload": {
    "sentinelId": "sales-achievement",
    "sentinelName": "销售目标达成",
    "checkedAt": "<ISO>", "durationMs": 0, "ok": true,
    "error": null, "degraded": false, "cronJobId": "",
    // 本票追加的审计字段（投影忽略未知字段）：
    "orgId": "<orgId>", "period": "<YYYY-MM>", "runId": "<runId>",
    "thresholdSource": "customer_target",
    "counts": { "objects": 0, "achieved": 0, "belowTarget": 0, "insufficient": 0 },
    "insufficientReasons": [ { "objectId": "…", "reason": "MISSING_METRIC" } ],
    "sources": [ { "objectId": "…",
                   "target":      { "metricId": "sales.target",      "sourceId": "…", "evidenceRef": "…" },
                   "performance": { "metricId": "sales.performance",  "sourceId": "…", "evidenceRef": "…" } } ]
  }
}
// 事件 2..N：每条 below_target 一条 finding
{
  "event_type": "finding",
  "sentinel_id": "sales-achievement",
  "aggregate_id": "sales-achievement@<同一 checkedAt>",
  "payload": { "finding": {
    "id": "sales-achievement:<objectId>:<period>",
    "severity": "warning",
    "title": "销售目标未达成（达成率 82.5%）",
    "description": "本期目标 1,200,000，实际 990,000，达成率 82.5%（阈值来源：客户目标）。",
    "evidence": ["metric_observations:<objectId>/sales.target@<period>", "…sales.performance@…"],
    "suggestion": "核对目标口径与在手机会，安排下期追平计划。",
    "detectedAt": "<ISO>", "status": "open"
  } }
}
```
- **追溯六项必须落在字面键上**（裁定四，逐项可断言）：企业=`payload.orgId`｜期间=`payload.period`｜指标=两行 `metric_id`（`sources` 与 evidence 串）｜来源=`payload.sources[].target/performance.sourceId/evidenceRef`（**值取自库内观测行，逐字相等**）｜阈值来源=`payload.thresholdSource`｜运行 ID=`payload.runId`。
- `sources[]` 覆盖**每个被评估对象**（含 insufficient 的），值直接来自 `MetricObservationRow.source_id`/`evidence_ref`；子项必须带 `metricId` 字面量（`sales.target`/`sales.performance`），**对象缺某指标行时该子项取 `null`**（不省略键，形状稳定）。
- **不写 `sentinel_tickets`**、不改任何 CHECK ⇒ 不触碰 §2.2 的 severity 域问题。

### 5.5 `--out` 摘要契约（**只是摘要，不是产品产物**）
`--out` 落盘 JSON 单对象（`schemaVersion:1`）：
```jsonc
{ "schemaVersion": 1, "kind": "sales-achievement.summary", "generatedAt": "<ISO>",
  "orgId": "…", "period": "…", "runId": "…",
  "counts": { "objects": 0, "achieved": 0, "belowTarget": 0, "insufficient": 0 },
  "warningCount": 0, "criticalCount": 0,
  "insufficientReasons": [ { "objectId": "…", "reason": "…" } ] }
```
- `criticalCount` **恒为 0**（本哨兵永不产出 critical；该字段存在只是为了让"没有伪造"可被机器断言）。
- `warningCount === counts.belowTarget`（同一事实两处出现，必须相等；不相等即实现错）。
- **产品产物是 `sentinel_events` 的事件**；`--out` 不写库、不被 ⑤/UI 消费（这不是旁路：旁路指"只写脚本格式而不写产品表"，本票两者都写，且产品表是主）。

### 5.6 退出码与 stdout
`0`=写了 ≥1 条 finding ｜ `1`=已执行但无 finding（`no_data` 或全 `insufficient_data`）｜ `2`=判不了（§3.3 各失败码，含 `E_OBSERVATIONS_TRUNCATED`）。
stdout 恰一行：`sales-achievement: org=<id> period=<p> objects=<n> achieved=<n> belowTarget=<n> insufficient=<n> events=<n>`。
