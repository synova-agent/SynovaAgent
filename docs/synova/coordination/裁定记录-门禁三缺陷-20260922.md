## 缺陷① D708：`infer_did` 扫到「并入的 main 历史」→ 取错 D# → 误判夹带

### 复现（CTO 亲跑）

```
$ python3 scripts/control-tower/merge_writeset_gate.py --base origin/main \
    --head origin/chore/ingest-institute --branch chore/ingest-institute
❌ 结论: block — 检测到 10 个写集外文件（夹带）
   任务: D811 | 分支: chore/ingest-institute          ← 任务是 D849，不是 D811
```

`任务: D811` 是错的。逐条按 gate 自己的规则走一遍 commit subject：

```
$ git log --max-count=20 --format=%s origin/chore/ingest-institute
9cce8b87 Merge remote-tracking branch 'origin/main' into rs-674   → no-D#
1d8dcab6 feat(D811): 未合 PR 队列收口… (#673)                      → HIT D811   ← 这是 main 的历史
544bb535 chore: bypass COMMITTED 登记 (auto hook, D521)            → skip(登记)
bf325e51 docs(D849): 研究院 8 份交接文档入库…                       → 真正的任务在这里
```

**根因**：分支名 `chore/ingest-institute` **不含 D#** → `infer_did()` 回退到「向前扫 20 条 subject」；
HEAD 是 merge 提交（无 D#），下一条就是**被并入的 main 的提交** → 取到 D811。
于是拿 `task-state/D811.json`（队列收口写集）当声明源 → 本 PR 的 10 个真交付文件全判「夹带」。

### 反证（同一 commit，只换分支名）

```
$ ... --branch docs/d849-ingest-institute
✅ 结论: pass — 提交文件集 ⊆ 声明写集（无夹带）
   任务: D849 | 声明写集 2 条: docs/synova/research/研究院交接-20260918/ · task-state/D849.json
```

### 同类次数

- **第 1 次**：#694（当时根因归为「PR 正文写集豁免写法模糊」——**那个归因是错的**，真因就是本缺陷）
- **第 2 次**：本件（#674/#675）
- 另：#685（`chore/dsh-decisions`，分支名无 D#）CI 失败步骤同为 `Merge write-set reconciliation (D708)`
- 反证：`docs/squad-lead-preset`（#697）在合并 main 后也被 infer_did 取了 **D870**（同样是 main 历史里的号），只因变更全在文档范围才侥幸降级放行

**判定：防线系统性失效 → 升级创始人（红线：同类错误第二次出现）。**

## 缺陷② D733/D734 域门禁无「代行」概念 → win 离线期一切 win 文件改动恒红

### 复现（CTO 亲跑，用 PR #696 的真实 merge commit）

```
$ git fetch origin refs/pull/696/merge:refs/tmp/pr696m && git worktree add /private/tmp/w696m refs/tmp/pr696m
$ cd /private/tmp/w696m && python3 scripts/control-tower/check-ownership.py \
    $(git diff --name-only origin/main...HEAD)
win  tests/agent/expert-file-loader.integration.test.ts
win  tests/circular-dependency.test.ts
win  tests/e2e/p0-client-a.test.ts
❌ FAIL 跨域: 变更落在 2 个域 ['mac', 'win'] —— 单个 PR 只许一个域（无归属 0，域判定豁免 6）
EXIT=1
```

CI 侧一致（日志原文）：`❌ ② 变更跨域 —— 一个 PR 只许一个域（D733 ownership.yaml）`。

### 根因

`docs/synova/coordination/ownership.yaml` 的兜底规则是 `glob: "**" → owner: win`，
其 `territory` 注释写的是 win 领地（`src/**` / `extensions/**` / `packages/**` / `synova_worker/**` / `docs/plans/**`）。
**未登记的路径一律落 win** —— 包括 `tests/agent/**`、`tests/e2e/**`、顶层散装 `tests/*.test.ts`。
而创始人 **2026-09-20 已下令**：win 机器不在线，所有 `domain:win` 任务一律 Mac 代行。
**门禁不知道这条口令** → 任何"Mac 修 win 文件"的 PR 恒红。

### 同类次数（都打了同族补丁，本件第 4 次）

| 次 | 触发 | 补丁 |
|---|---|---|
| 1 | D782 PR-2/PR-4 | ownership.yaml 加 `tests/doc-system/**` 派生规则（注释自陈「CI 实测落兜底误判 win」） |
| 2,3 | D793/D795 新建 `tests/project/**` | 再加一条派生规则（注释自陈「漏补本表」） |
| **4** | **D861（#696）** | **本件 → 不再打补丁，改机制** |

**判定：同族第 4 次 → 打点补丁的路走不通，须给「代行」显式开关（单点、可逆、逐条打印）。**

## 缺陷③ D749/G12 与 D708 写集口径互斥 + 判据随运行日漂移

### 3a 口径互斥（同一 PR 过一个必倒一个）

- **D708** 接受**三源并集**：S1 `task-state/*.json:write_set` ＋ S2 dev doc 写集表 ＋ S3 brief Q2（`merge_writeset_gate.py` 契约原文）。
- **D749 G12** 只认 **brief Q2** 单一源。

#696 的实测结果：D708 **过**（其 `task-state/D861.json` write_set 含 `tests/**`），G12 **倒**：

```
❌ G12: task brief Q2 范围一致性（写集单一事实源，D749）: 8 处  [硬阻断]
     scripts/control-tower/check-pr-budget.sh (不在 Q2 范围内)
     …
```

Q2 里写的是文件名（`check-pr-budget.sh`），G12 要的是**路径**（`scripts/control-tower/check-pr-budget.sh`）。

### 3b 判据随运行日漂移（fail-open）

`scripts/pre-commit-check.sh` 组 12 用 **文件名日期前缀 ±1 天**挑「今日 brief」：

```
DAY_WINDOW_RE=$(python3 -c "... t + timedelta(days=k) for k in (-1,0,1) ...")
ALL_TODAY_BRIEFS=$(today_files_by_prefix "$ROOT/.claude/task-briefs/" | sort)
[ -z "$ALL_TODAY_BRIEFS" ] && [ -n "$CUR_BRIEF_PATH" ] && ALL_TODAY_BRIEFS="$CUR_BRIEF_PATH"
if [ -n "$ALL_TODAY_BRIEFS" ] && [ -n "$STAGED_ALL" ]; then … fi   # 空 → 整段跳过 → fail-open
```

**同一个 commit，今天跑红、后天跑绿**（brief 掉出窗口 → `ALL_TODAY_BRIEFS` 空 → 整段 soft_pass）。
门禁判据必须对运行时刻不敏感。
