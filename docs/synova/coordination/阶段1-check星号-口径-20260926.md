- **判定**：`n > 48` ⇒ 新增了 `check-*` 文件（需解释）；`n = 48` 或下降 ⇒ 未新增。
- **边界（负面断言写范围）**：

  - 文件面 ≠ 门禁面：`check-*` 文件不全是门禁（也有一次性检查脚本），门禁也不全叫 `check-*`。

### 7.2 三条可复跑命令（`<ref>` = 被检 ref，base 固定 `origin/main`）

**P1 · 主判据：`scripts/**` 新增一律点名（不只 `check-*`）**

```bash
git diff --name-status origin/main..<ref> -- scripts | awk '$1=="A"{print $2}'
```
判定：**输出为空 ⇒ PASS**（无新增 `scripts/` 文件）；非空 ⇒ 逐条进 P3。

**P2 · 判定点：门禁面被改动点名（改已有文件也可能加判定点）**

```bash
git diff --name-status origin/main..<ref> \
  -- scripts/pre-commit-check.sh scripts/pre-push-check.sh scripts/control-tower/ .github/workflows/
```
判定：为空 ⇒ 门禁面未动；非空 ⇒ 逐条人工判"**是否新增判定点**"（本报告不自动判，只点名）。

**P3 · 身份判别：每个新增文件的"可执行位 + 是否被门禁入口调用"**

```bash
for f in $(git diff --name-status origin/main..<ref> -- scripts | awk '$1=="A"{print $2}'); do
  mode=$(git ls-tree <ref> -- "$f" | awk '{print $1}')
  entry=$(git grep -n -F "$(basename "$f")" <ref> \
            -- scripts/pre-commit-check.sh scripts/pre-push-check.sh .github/workflows 2>/dev/null | head -2)
  printf '  %-58s mode=%s  entry_refs=%s\n' "$f" "$mode" "${entry:-NONE}"
done
```
判定：`mode=100755` + `entry_refs` 命中门禁入口 ⇒ **真·新门禁（点名）**；`entry_refs=NONE` ⇒ 未被门禁入口调用的检查器/数据/配置（仍需记录，但不构成本判据的"新增判定点"）。

### 7.5 残余边界（诚实登记，负面断言写范围）

1. **P1 只看"新增文件"**：在**已有**文件中加入判定点 → 由 **P2 点名**，但 P2 只报"面被改动"，**是否新增判定点仍需人工判**（本判据不是全自动）。
2. **git 差异面**：未入 git 的本地文件（未提交脚本、本地改的 hook）**不在测量面内**。
3. **入口清单是固定的**：P3 的 `entry` 路径写死 `pre-commit-check.sh` / `pre-push-check.sh` / `.github/workflows`；**新的入口类型**（如未来新增的 hook 或外部调度器）不在面内 —— 入口清单本身需要随架构变更维护。
4. **"`scripts/**` 新增 = ∅"≠"无新增门禁"**：门禁也可能以**非文件**形态出现（CI 内联 `run:` 步骤、规则数据）。**该判据比 `check-*` 强，但仍是充分条件的一部分，不是全部** —— 完整判定 = P1 ∅ **且** P2 无新增判定点（人工确认）。
