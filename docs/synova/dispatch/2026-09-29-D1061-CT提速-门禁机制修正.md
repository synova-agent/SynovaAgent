## 〇-b、实测新发现（卡面未载，直接改变方案）

**N1 · windows 腿的真实成本在「递归重跑」，不在"套件太多"**

|---|---|---|

| `gate-failopen-net.test.sh` | 120s | 7.4% |
| `alloc-task-id-lock.test.sh` | 99s | 6.1% |

| （中间 34 个 <5s/个，未逐一列） | | |

机制（代码级）：`tests/control-tower/simulate-ci.test.sh:37,47,52` 三次调 `bash "$SIM"`；`scripts/control-tower/simulate-ci.sh:49-64` 每次把 ci.yml 提取的密封清单（**44 条，排除自身**）**全量重跑一遍** → CI 里嵌套 44×3 = **132 次**内层执行。
⇒ **这是 windows 腿的头号杠杆**；单靠"变更路径选择器"不动这一条，目标 ≤8min 达不到。

**N2 · “main 门禁病拖红全部 PR”的真因（实测）**
`TypeScript + Lint + Iron Laws` job 的红**不是 tsc**，而是 `merge_writeset_gate.py`(D708) fail-closed：

```
⚠️ 结论: degraded — 无任何写集声明（S1 task-state.write_set / S2 dev doc 写集表 / S3 task brief Q2 三源皆空）且变更含源码文件 → fail-closed 阻断
   任务: D09 | 分支: fix/injection-residue-exclude-docs
   D# 推断来源: commit-subject → D09

```
`D09` 来自 merge SHA 里的 hex 片段 `…fca238bd09e02…` 被 D# 正则命中。**每个含源码的 PR 都踩这条**（PR #878 的唯一红项即此）。
