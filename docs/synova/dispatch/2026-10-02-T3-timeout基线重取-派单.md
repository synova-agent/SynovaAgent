## §1 采样方法（**两个过滤器缺一不可**，否则基线算歪）

```bash
GH=gh; REPO=synova-agent/SynovaAgent
# ① 只取 success 的整轮 run（口径原文）
$GH run list --repo $REPO --workflow ci.yml --status success --limit 60 \
    --json databaseId,createdAt,headBranch,headSha > runs.json
# ② 逐轮取 job + step 级时间戳
for id in $(jq -r '.[].databaseId' runs.json); do
  $GH run view "$id" --repo $REPO --json databaseId,createdAt,updatedAt,jobs > "jobs-$id.json"
done
```

**过滤器 A：剔除 docs-only 轮次**。docs-only 的 run 里各 job 只跑 10~30s，混进来会把中位数压到 11s。
判据：`TypeScript + Lint + Iron Laws` 该 job 耗时 `< 60s` ⇒ 判为 docs-only，整轮剔除。

**过滤器 B：CT 腿必须按「碰/不碰」分层**。D1039 让 CT 重活只在"碰控制塔路径"时跑：
不碰的 run 里 CT 腿只要 18~30s，碰的 run 要 1336~2413s ⇒ **双峰分布**，混算无意义。
判据：CT job 耗时 `< 300s`（windows）/ `< 60s`（ubuntu）⇒ 判为"未跑重活"，剔除。

> 2026-10-02 实测：60 个 success run 里，同时满足过滤器 A 的 **14 轮**；
> 其中 CT 重活样本 windows 10 / ubuntu 10。
