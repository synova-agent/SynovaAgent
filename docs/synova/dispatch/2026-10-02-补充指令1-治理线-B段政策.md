## §1 目标（一句话）

> **把「任务从哪来、谁在做、卡在哪」从散件变成 GitHub 原生事实** —— 即 **PR 挂 Issue**、**状态随事件自动流转**。
> **不是**为了"再加一道门禁"；**是为了让门禁不再需要人去盯**。

## §5 三条**顺序硬约束**（**本条是本件最该守住的东西**）

### ① 门禁**先软后硬**（不许一次性设必过）
```
第 1 步：作为【非必过 / 信息性】上线，先把全仓在飞 PR 跑一遍，出"会拦谁"的预演报告
第 2 步：把预演结果报我 → 我裁"何时转必过"
第 3 步：转必过（并入必需集需走你的送审链：你提案 → K3 → 我裁）
```
**理由**：新增必过 job 会**同时影响所有 open PR**。今天存量红已实证这个代价（6 个 PR 被卡）。
**判据**：转必过之前，必须有**预演报告**（会拦多少 PR、拦的是哪一类）。

### ② **`permissions:` 显式收敛**（**我方现在完全没有**）
DSH 每个 workflow 都写 `permissions:`；我方 `ci.yml` **零显式块** ⇒ **权限面比 DSH 宽**。
**要求**：新增/改动的 workflow **必须**带 `permissions:`（最小集）；**是否给现有 `ci.yml` 补**＝你评估后给我一个建议（**属安全面，我裁**）。

### ③ **策略代码来自默认分支**
DSH 的 `checkout` 固定 `ref: ${default_branch}` ⇒ **用主分支上的策略校验 PR**，PR 改不了自己的判据。
**要求**：照此形态（否则"改策略让自己过"是必然漏洞）。

## §6 链路（**不许跳**）

```
你提案（含：触发面 / 拦什么 / 预演报告 / 改坏即红夹具 / 反例矩阵 / 权限最小集 / 策略来自默认分支的证据）
  → K3 过审（≤24h）
  → 我裁（"哪条检查阻断合并"的变更，只能我裁）
  → 你执行
  → 预演报告 → 我裁"何时转必过"
  → 转必过 → 复核
```

## §8 回报（指针式，随你的 R1–R5）

除既有 R1–R5 外，本件额外要三项：
1. **预演报告**：非必过状态下，全仓在飞 PR 里"会拦多少 / 拦哪一类"
2. **权限最小集**：新增 workflow 的 `permissions:` 逐项列出（并给"为何这一项必需"）
3. **策略来源证据**：证明策略代码取自默认分支（不是 PR 自带）
