## 1 安装方案

### 1.1 载体事实（先取证，再设计）

| 事实 | 证据 |
|---|---|
| DSH 支持 CC 方言 hooks | 包 `@deepseek-ai/dsh-hooks-claude-code`（`app.asar:/dsh/node_modules/@deepseek-ai/dsh-hooks-claude-code/`） |
| **只有 exit 2 阻断**，stderr 即原因 | `dsh-hook-protocol/lib/index.js:63` `const BLOCKING_EXIT_CODE = 2;` ；`:111-115`（exit 2 → reason=stderr；exit 0 → 解析 JSON） |
| 支持事件 | `UserPromptSubmit` / `PreToolUse`（`dsh-hooks-claude-code/lib/index.js:16-17`）—— 正是派单点名的两种 |
| payload 字段 | `UserPromptSubmit` → `.prompt`；`PreToolUse` → `.tool_name` + `.tool_input`（同文件 `promptPayload` / `preToolPayload`） |
| matcher = 工具名（正则或字面备选） | 同文件 `:88` 起；非法正则 → **整份配置被拒**（`SyntaxError`） |
| 配置**进程启动时只读一次** | `README.zh.md:71`「一份配置应用于整个进程：启动时只读取一次」 |
| 本 profile **当前未挂**该桥 | `grep -c hooks-claude-code ~/.dsh-trial-017/profiles/desktop/cordis.patch.yml` = 0（2026-10-06 实测） |

### 1.2 登记点（`hooks.json` 写法）

模板即 `docs/synova/gates/hooks.json`（原样可复制），核心两段:

```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command", "timeout": 20,
        "command": "bash \"${CLAUDE_PROJECT_DIR}/scripts/control-tower/gate-hook-entry.sh\" receipt || exit 2" } ] }
    ],
    "PreToolUse": [
      { "matcher": "send_message|team_task_create|spawn_teammate|write|edit|bash",
        "hooks": [ { "type": "command", "timeout": 20,
        "command": "bash \"${CLAUDE_PROJECT_DIR}/scripts/control-tower/gate-hook-entry.sh\" dispatch || exit 2" } ] }
    ]
  }
}
```

三个写法要点（都有实证依据）:
- **`|| exit 2`**：登记点在而闸脚本缺失时，bash 返回 127 = **非阻断失败**（协议规定除 2 外一律不阻断
  ⇒ 门禁会**静默消失**）。加 `|| exit 2` 把「入口不存在」也抬到阻断位。入口内另有同义判定（见 1.3）。
- **`$CLAUDE_PROJECT_DIR`（不带 `:-` 回退）**：桥会把 `${CLAUDE_PROJECT_DIR}` 在解析期替换成配置里的
  `projectDir`（`substituteCommand`，同文件 `:33-38`）；带 `:-$PWD` 会被替换成 `<路径>:-$PWD}` 而语法崩坏。
  未配 `projectDir` 时该变量由桥**每 hook 进程注入**（= 会话工作区）。两条路径都通，故只用裸 `${CLAUDE_PROJECT_DIR}`。
- **`timeout` 单位是秒**（`hook.timeout` → `timeoutSec`），闸脚本最快路径 <100ms，20s 是兜底。

### 1.3 入口脚本为什么存在

`gate-hook-entry.sh <receipt|dispatch>`：闸名合法性 + 闸脚本存在性 + `exec`。缺任一项 ⇒
`GATE-ERROR` + **exit 2**（fail-closed，不静默放行）。契约: 0 通过 / 2 阻断 / 3 缺件（同样阻断）。

### 1.4 前置条件（缺一不装）

| # | 条件 | 校验命令 | 不满足的后果 |
|---|---|---|---|
| P1 | D1163 PR **已合 main** | `git -C <repo> ls-tree origin/main scripts/control-tower/receipt-gate.sh` | 每个动作撞 GATE-ERROR ⇒ CTO 收发全停 |
| P2 | `python3`（或 `python`/`py`）可用 | `python3 -c 'import sys'` | 桥无法解析 payload ⇒ 闸 fail-closed 阻断**一切** |

## 2 闸 1 · 收件闸判据（receipt-gate）

**事件**：`UserPromptSubmit`（收件发生在"提示词到达"这一刻；`PreToolUse` 看不到收件内容）。

### 2.1 判据

| 项 | 判据（机器可判） |
|---|---|
| 触发面 | 文本**声称是回执**：① 任一行归一化后**行首**为 `回执` ② 任一行 ≤80 字且**行尾**为 `回执`/`回执】` ③ 六个标签命中 ≥2 |
| 必备六行 | `流前缀: / 基线 ref: / 项清单: / 状态: / 例外清单: / 在飞-卡数:`，**标签锚行首**（允许 `#`/`>`/`-`/`**`/反引号前缀，归一化后判定） |
| 值非空 | 标签后须有非空值（仅 `/`、`-`、`—`、`|`、空白视为空）——空值等于没填；无内容写「无」 |
| 通过 | 六行齐且值非空 ⇒ `exit 0` |
| 违规 | 缺任一行 / 值空 ⇒ `exit 1`（cli）或 `exit 2`（hook 阻断位），stderr 逐条点名缺项 |
| 自身失败 | payload 不可解析 / 文本源不可读 / 无 python ⇒ `exit 2` + `GATE-ERROR`（fail-closed） |
| 留痕 | 每次判定追加一行 jsonl 到 `${SYNO_GATE_LOG_DIR:-${TMPDIR:-/tmp}/synova-gates}/receipt-gate.jsonl` |

### 2.2 两处细化（本卡决定，**可被 CTO 覆盖**）

| # | 细化 | 理由 | 代价（我认领） |
|---|---|---|---|
| R1 | 触发面 = 「声称」而非「出现"回执"二字」 | 派单 §0 明说输入是**声称是回执的文本**；正文里聊到回执不该被拦 | **漏拦形态**：回执若既无标题又只有 ≤1 个标签，闸看不见（不触发）⇒ 该形态靠"聊天里提到"兜不住，属已知洞 |
| R2 | 值必须非空 | 空值 = 没填，`例外清单:` 留空正好掩盖"我没做到的" | **误拦形态**：确实想留空的写手会被拒 ⇒ 明文规定**无则写「无」**（夹具 `receipt-empty-exception.txt` 钉住该语义） |

### 2.3 已知限制（如实报告，不是待办美化）

- 🔴 **UserPromptSubmit 被拒时，stderr 原因不回传模型**：桥在 `dsh-hooks-claude-code/lib/index.js:240`
  `if (merged.decision === "deny") return { kind: "reject" };` —— 与 `PreToolUse`（`:251-258` 会把 reason 交给模型）
  不同。⇒ 「把缺的哪几行喂给 CTO 看」的落点是 **hook/result 会话日志**（桥会持久化 stderr 摘要）
  **+ 本闸的 jsonl 留痕**，而非对话上下文。若 CTO 要求"拒收理由直接进对话"，需改桥（红线外，须另立卡上报）。
- 🔴 **配置是进程级的**：一份 `hooks.json` 管**整个 DSH 进程**里所有会话（`README.zh.md:71`），
  不只 CTO 那个 session ⇒ 其他线收到的回执同受此闸约束。若不接受，唯一办法是给 CTO 单开一个 DSH 进程/档案。

## 3 闸 2 · dispatch 闸判据（dispatch-gate）

**事件**：`PreToolUse`，matcher = `send_message|team_task_create|spawn_teammate|write|edit|bash`。
**取文规则**：`send_message.message` / `team_task_create.subject+description` / `spawn_teammate.prompt` /
`write|edit`（仅当目标路径含「派单」或落在 `…/coordination/`、`…/gates/`）/ `bash`（仅当命令含 `gh issue|pr create|comment|edit`）。
其余工具与目标 = 不适用（放行）。

### 3.1 触发面

指令形态 = 含 `#编号` 或 `D####` 任务号，或含指令词（派单/派活/写集/红线/Done 标准/验收命令/执行以下/接单/开工）。
**不触发 ⇒ 直接放行**（状态汇报、日常对话不拦）。

### 3.2 四类判据（CTO 指定，不许加更多）

| # | 判据 | 机器口径 | 违规输出 |
|---|---|---|---|
| ① | 仓库内路径存在性 | 抽取 `src|scripts|tests|docs|packages|extensions|electron|electron-renderer|task-state|memory|.github|hooks` 下的路径；`git cat-file -e origin/main:<p>` 或工作区 `-e` 命中即过；**同行**标「新建/尚未存在/待创建」⇒ 豁免 | `① 路径不存在且未标「新建」: <路径>` |
| ② | 外部件五元组 | (a) 含 `外部件` 的行须同带 `断面/形态/版本/坐标/时刻`；(b) 外部主机 URL（放行 `github.com/synova-agent`、`api.github.com`、`localhost`、`127.0.0.1`）须 URL 内钉 sha/语义版本，或 ±3 行内五元组齐 | `② 外部件缺五元组（行 N…）` / `② 外部引用未钉版且无五元组: <url>` |
| ③ | 单流 | 指令正文（**排除**代码块、以及标题含"回执/证据/复现/现状/为什么/背景/实测/实证/输入/症状/根因/验收记录"的段、`「」` `""` 反引号内）内出现的流前缀去重 ≤1 | `③ 非单流: 指令正文出现 N 个前缀（…）` |
| ④ | 点名分支/PR 真伪 | 分支 `git merge-base --is-ancestor origin/<b> origin/main`；PR 查 `origin/main` 提交标题 `Merge pull request #N` 或 `(#N)` | `④ 声称 PR #N 已合，origin/main 无合并痕迹（行 N）` / `④ 声称 …在飞，实已入 main（状态陈述过期）` |

流前缀词表 = `scripts/control-tower/stream-prefixes.txt`（现含 CTO/DSH/GV/IM/BT/CL/K1/K3/PL/SQ，可增删；
线退役即删，棘轮只减不增）。

### 3.3 三处细化（本卡决定，**可被 CTO 覆盖**）

| # | 细化 | 理由 | 代价（我认领） |
|---|---|---|---|
| R1 | 触发面 = 指令形态（非"所有 send_message"） | 误拦 = 指令发不出去，代价最大；日常对话含 `#1234` 的概率低 | 漏拦：不带任何任务号/指令词的"口头派单"不被查 |
| R2 | ④ 判「**声称**」的真伪，不是"点名即在 main" | 按字面「点名的分支/PR 必须在 main」会拦掉**一切在飞引用**，而派单正文引用在飞 PR 是常态（例：CTO 今日派单自身就点名 `PR #948`）。**本条的判据目的**（K3-P1-2「派单前置失实」）是禁"把未合写成已合"，故对偶判定：声称已合→必须在 main；声称在飞→必须不在 main（后者顺手抓"状态陈述过期"） | 漏拦：只提及不声称的真伪不拦（**打印事实行**，不阻断） |
| R3 | ③ 排除"证据/回执段"与代码块 | CTO 今日派单 §0 就列了 6 个前缀（DSH-/IM-/K1-/BT-/GV-/CL-）。若按全文计，**这条派单自己会被自己的闸拦掉** = D734 式"越守规矩越红" | 漏拦：把两个流前缀写进"为什么/证据"段可绕过 ⇒ 由 ④/① 与人工复核兜（已明写在案） |

- 「指令里引了不存在的路径」⇒ 红：夹具 `tests/control-tower/fixtures/gates/dispatch-bad-path.txt`
