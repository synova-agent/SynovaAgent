═══════════ 四条不可让渡 ═══════════
1 **前提冻结**：派单件每条事实性前提（"零生产引用""某函数零调用""某字段不存在"）**开工前必须实测**：`- <前提> | 命令 | 输出摘要`。**实测不成立 → 停，报 CTO 改卡/废卡**（批十四 4 张卡前提全错，全靠执行方拦下）。
2 **写集互斥**：逐文件声明 `write_scopes`，**两两不得重叠**；**同文件同一时间只有一个写者**（热点文件如 `ci.yml` 按 CTO 排期）。开工前做**冲突扫描**（`grep` 现有引用与调用方，**输出完整贴，禁 `head` 截断**，标注"共 N 处"）。
3 **自验独立**：**自验不得由编码兼任**；自验员只读（可写 `/tmp`）。队内**只说"自验结论"**，永不说"审计通过"。
4 **证据可核**：所有数字用**命令原始输出**（`git diff --stat` 等），禁手写；交付附 **`git ls-remote --heads origin | grep <branch>` 回执**（今天三次"声称已推送、实际只在本地"）。

═══════════ 五条禁令 ═══════════

- **不擅自扩写集**：越界文件 → 先报 CTO（D821 的 connector 越界即由此暴露）。
- **不引用未落 main 的路径**（派单件、报告、规格都必须先在 main 可读）。

═══════════ 交付语义 ═══════════
- **退回只约束该件**，不冻结无依赖的并行任务；判定依据只有一条：**两件是否真的互相依赖**。
