## 〇、为什么要立这一节

本批同一个**错误族**连续出现 4 次：**断言与它测量的「时点 / 对象」脱钩** ——
「delta=0」沿用改前读数、把「编辑中途快照」当稳定态、用默认编码读文件读出满屏乱码差一步误判、
`Out-File -Encoding utf8` 自加 BOM 造出假差异。
每一条都不是能力问题，而是**工具使用纪律**问题 ⇒ 可写成清单，**逐条可核**（有判别动作 + 有反例）。

## 一、清单（9 条）

### 1. 文本管线与 BOM：字节级比较**禁经** `Out-File` / `Set-Content`
- **症状**：同一个 blob，经 PowerShell 抽一次就"多了 3 字节"；`git diff` 显示 `-﻿/**` → `+/**`。
- **实测**（Windows PowerShell **5.1**）：`Out-File -Encoding utf8` 会**写入 BOM** ⇒ 8498 B → 8657 B；
  `*>` 重定向产 **UTF-16LE**（git 判 `Bin`，`git diff --stat` 显示 `Bin 0 -> N bytes`）。
- **判别动作**：`node -e "…readFileSync(p).slice(0,3)"` 看前 3 字节（`EF BB BF` = BOM；`FF FE` = UTF-16LE）；
  或 `git diff --stat` 看到 `Bin` 即报警。
- **正确做法**：取 blob 用 `cmd` 重定向或 `git cat-file` **直读**；比较用 `git hash-object` / `git diff <sha> <sha>`。

### 2. 等长替换**禁用**长度断言
- **症状**：替换前后"字节数没变"被当成"内容没变"。
- **判别动作**：**长度相等 ≠ 内容相同** ⇒ 判据只能是**内容级**（blob sha / `hash-object` / `git diff`）。
- **反例**：本批注释改动恰好 **+36 B** 还能看出；若换成等长串（如把 `#1424` 换成 5 位其它号）则长度完全不动。

### 3. 行数必须写**口径**
- **症状**：同一文件"行数"报出两个值（`wc -l` / `Measure-Object -Line` / `Get-Content | Measure-Object`）。
- **原因**：末行是否有换行、是否含 BOM、是否按 CRLF 切。
- **判别动作**：报行数**必须带口径**（命令原文 + 是否含空行/末行）。

### 4. glob 空结果 **≠** 不存在
- **症状**：`glob(tests/store/**/*.ts)` 返回 "No files found"，据此判"文件不存在"。
- **实测**：同一路径 `Get-ChildItem -Recurse` 列出 11 个文件 ⇒ **是工具面（路径解析/沙箱）问题，不是事实**。
- **判别动作**：空结果必须用**第二条独立命令**（`ls`/`Get-ChildItem`/`git ls-tree <ref>`）复核后才可下"不存在"结论；
  且"存在性"一律以 **`git ls-tree <ref>` / `git grep <ref>`** 为准（**禁用工作树**量现状）。

### 5. 表面相同 **≠** 机制相同
- **症状**：两处"红"被当作同一件事；两处"绿"被当作同一件事。
- **判别动作**：必须看**断言文本 / 错误类 / 栈顶文件**，不能只看结论色。
- **反例**：本批 CI 红的两件 —— 一件是存量（`ReactCurrentOwner`，另一分支同红），一件是环境依赖（真 LLM 文本）；**色同因不同**。

### 6. 零改动判据 = **内容 sha256**（不是 mtime）
- **症状**：`-shm` / `-wal` 的 mtime 变了 ⇒ 被判"写库了"。
- **判别动作**：SQLite 的 `-shm`/`-wal` 由引擎管理（只读打开也会触碰共享内存）；
  **零写入的判据 = 数据本体（如 `data/synova.db`）的 sha256 前后一致**（本批实测 `771f0677…` × 2，一致）。
- **加固**：只读读数优先 `immutable=1`；不可用时用 `readonly + PRAGMA query_only=1`（并记录为何不可用）。

### 7. 对照前**先核同构**
- **症状**：拿 A/B 两边差异做归因，但两边并不同构（不同 commit / 不同依赖 / 不同解包完整度）。
- **判别动作**：对照前先证明三件：**同 commit 来源**、**同依赖面**、**提取完整**（解包器报错即视为不完整）。
- **反例**：本批基线对照用 `git archive`（`tar` 报 `Invalid empty pathname` ⇒ 非全量解包）；
  结论成立的前提是"被测文件确实解出且未受缺失影响"—— 这必须**写进结论**，不能默认。

### 8. 命令报错时，输出**不是**数据
- **症状**：把管道里的报错文本当业务输出（PS 5.1 把 native stderr 包成 `RemoteException`；`$LASTEXITCODE` 与 `$?` 不同义）。
- **判别动作**：先看 **exit code**，再看 stdout/stderr 分流；管道吞错（`2>&1 | …`）必须显式声明。

### 9. 🆕 声称「相同」必须写**两个对象 sha** + **当点现测**
- **症状**：「delta=0 / 逐字节一致 / 无差异」这类表述，**对象与时点全都不写**，且常沿用**改前**的读数。
- **实测反例（本批）**：注释改动落地后，仍沿用改前 `hash-object` 读数声称"逐字节一致"；
  现测才是 `e47568b663…`(8498 B) ↔ `46e255d554…`(8534 B)，**+36 B / +1 行**。
- **判别动作（硬格式）**：凡声称相同，必须写成
  `对象A:<ref>:<path> sha=<…> (<N> B) ↔ 对象B:<ref>:<path> sha=<…> (<M> B) | 差=<±bytes/±行> | 现测于 HEAD=<sha>`，
  并**当场重跑**判据命令；**禁止**引用上一次的读数。
