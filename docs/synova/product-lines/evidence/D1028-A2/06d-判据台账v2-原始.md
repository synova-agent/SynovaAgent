## 〇、本棒的核心风险（决定夹具设计）

CTO 裁定把 v1 的「纯 D/R 无条件 FAIL」保留，但开了逃生口。⇒ **新的攻击面 = 逃生口本身**。
两个最容易写错的地方（本台账定向盯这两条）：

| # | 风险 | 为什么危险 | 本台账判据 |
|---|---|---|---|
| R-A | **「放行」被写成「豁免」** | 若声明生效顺手把路径从 `N_FILES` 剔除，则**任何规模的 src 删除都能靠一份声明过闸** —— 逃生口变成后门 | **A3 / C3**（声明完整 + 纯删 `src/**` **13 件** → **必须 exit 1**，计数 13 > 12） |
| R-B | **覆盖判据被弱化**（前缀/后缀/大小写/通配匹配） | 写一条 `- src/ — …` 或 `- mod01.ts — …` 就能"洗全场" | **A6 / B4 / B5 / B16**（通配、同名不同层级、大小写、前缀） |

## 〇-b、声明语义的等价实现自由度（先声明判据，避免事后找理由）

规格 §2 只说「逐行 `- <路径> — <铁律37依据>`」。以下**未规定**，本台账按「**不得静默放行未声明语义**」这一更高判据处理，并**并列记录实测**：
- 前导 `./`、首尾空白、重复条目、空行、注释行 → 如果被**规范化/忽略**（等价语义）→ 可接受；如果**导致整段失效**→ 也算 fail-closed，可接受；**不可接受**的只有「错误地覆盖了未声明的路径」。
- `--decl-file` 指向仓库外（/tmp）→ 规格未限制，记录行为。

## 〇-c、硬约束（沿用 v1 实测坑，已写进 harness2.sh）

1 真 git 夹具必须在 `feat` 分支变更（否则 `main...HEAD` 恒空 = 假绿）。
2 TARGET 必须落 `<ROOT>/scripts/control-tower/` 镜像布局（否则 `check-ownership.py:45/67` → 域校验 exit 2）。
