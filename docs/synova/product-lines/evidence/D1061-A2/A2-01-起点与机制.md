## 2. 并行安全审计（先证不 flaky，再动手）

**问题**：并行 = 多条测试同时跑；若它们共用固定路径（`/tmp/...`）或同时写仓库，就会互相踩。

**实测方法**：对密封清单 55 条逐条 `grep -oE '/tmp/[A-Za-z0-9._/-]+'`，剔除 `mktemp` 模板（`.XXXXXX`），
按路径聚簇看**是否有跨测试共用**：

```
$ （逐条提取固定 /tmp 路径 → 路径→使用者聚合）
/tmp/d384-alloc-tests → tests/control-tower/alloc-task-id.test.sh   （仅 1 条测试）
/tmp/dsh-anchor-t.out → tests/control-tower/check-dsh-anchor.test.sh（仅 1 条测试）
/tmp/k3t.out          → tests/control-tower/check-k3-report.test.sh （仅 1 条测试）
/tmp/il-ct            → tests/control-tower/incident-loop.test.sh   （仅 1 条测试）
/tmp/x                → tests/control-tower/verify-claims-table.test.sh（仅 1 条测试）
/tmp/scratch.md       → tests/doc-system/doc-registry-gate.test.sh   （仅 1 条测试）
/tmp/ct-out.log       → tests/control-tower/d956-failmsg.test.sh（夹具自身的提取锚点，非执行路径）
```

**结论：无任何固定 `/tmp` 路径被两条以上测试共用** ⇒ 并行不因 `/tmp` 冲突而 flaky。
（`mktemp` 模板一律 `.XXXXXX`，天然隔离。）

**仓库写入面**：粗筛显示仅 `post-commit-marker.test.sh` 会写 `$REPO/.claude/` 下的固定文件；
该文件在同一 job 内只被这一条测试写 ⇒ 无并发写者。**登记为已知单点**（若未来新增写者须复查）。

## 3. 机制（(a) 隔离式并行）

原实现：串行 `for t in …; do bash "$t" > /tmp/ct-out.log 2>&1; if !…; then <D956 注解段>; fi; done`
—— 墙钟受**最长单项**支配（149s）+ 其余 449s 串行累加。

改造为**两阶段**：

1. **执行阶段**（可并行）：`xargs -P "${CT_JOBS}"`（默认 3，`workflow_dispatch` 输入 `ct_parallel_jobs` 可调；
   `1` = 串行 = 旧行为）。**每个测试写自己的日志** `${CT_LOGDIR}/<扁平化路径>.log` 与 `.rc`
   —— **彻底移除** `/tmp/ct-out.log` 这个唯一跨测试共享点。
2. **注解阶段**（串行、确定性）：按清单顺序读 `.rc`，失败者发射 D956 注解段
   —— 注解段**不再执行测试**（`bash "$t"` 已抽离），`d956-failmsg.test.sh` 新增判别性断言守住这一点。

**保留不变**：D956-MSG-START/END 标记段、`::error` 注解格式、`FAIL=1` 语义、清单顺序确定性输出。


`D1039-A4` brief，而它**认领 `ci.yml`** ⇒ 与本次声明 D1061 不一致 ⇒ 硬阻断。
