## §12 CI windows 红因定位（首推 `89d22f1c`，4 条断言连带红）—— 原始输出

**CI 失败签名**（run `36527360094` / job `109273232829`，windows CT）：

```
##[error]  ❌ 正常路径应只选 A 域 1 条，实际 3 条: tests/control-tower/sel-a.test.sh|  ❌ windows 应 2 条，实际 3|  ❌ 摘要行缺 selected_of_total|  ❌ D4 不符（rc=0 n=3）
```

即：**选择器走了「全量回退」而不是收窄 1/3**。同一夹具在 macOS **23 通过 0 失败**。

### 12.1 先验伪：队长假设「`git init` 默认分支不是 main」

```bash
$ git show 89d22f1c:tests/control-tower/ct-suite-select.test.sh > tests/control-tower/.d1061-orig-probe.sh   # 首推版夹具
$ GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=init.defaultBranch GIT_CONFIG_VALUE_0=master bash tests/control-tower/.d1061-orig-probe.sh
结果: 23 通过, 0 失败

$ bash tests/control-tower/.d1061-orig-probe.sh          # 本机默认（main）
结果: 23 通过, 0 失败
$ rm -f tests/control-tower/.d1061-orig-probe.sh         # 探针已删除，工作树零残留
```

**结论：假设不成立**（强制 `master` 下仍 23/0）。沙箱里 `git branch -M main` + `update-ref refs/remotes/origin/main`
是显式命名，与 `init.defaultBranch` 无关。

### 12.2 真根因：python 文本模式 `\n → \r\n`，`MAP_TSV` 未清 CRLF（PLATFORM-CHECKLIST #2）

Windows 上 python 的 stdout 为文本模式 → `print()` 的 `\n` 变 `\r\n`；`MAP_TSV` 逐行读入时
**尾 `\r` 落在 `IFS=$'\t'` 的最后一个字段（域名）**⇒ `DOM` 查表落空 ⇒ 退化为全量回退。
（本机 macOS 文本模式不转换 ⇒ 本地恒绿 ⇒ 典型「本地绿、CI 红」。）

**逐字复现（本机，零生产注入缝：PATH 前置 python3 shim，stdout 每行尾追加 `\r`）**：

```bash
$ SHIM=$(mktemp -d)/shim; mkdir -p "$SHIM"
$ printf '#!/bin/bash\n"%s" "$@" | awk '"'"'{printf "%%s\\r\\n", $0}'"'"'\n' "$(command -v python3)" > "$SHIM/python3"
$ chmod +x "$SHIM/python3"
$ PATH="$SHIM:$PATH" bash "$SEL" --repo "$SB" --map "$SB/map.json" --changed-files "$CHG/l3.txt"
（选择器输出）3 条 = 全量
（stderr）[D1061-DEGRADED] code=D4 reason=无域命中：选中 0 条（changed=1）——0 条静默通过被禁 → **回退全量**（fail-closed，绝不静默缩小）
        [D1061-SELECT] mode=select platform=any changed=1 selected_of_total=3/3 degraded=1
```

⇒ 与 CI 的 `rc=0 n=3` **完全同签名**，根因坐实。

### 12.3 修法 + 回归网

- **产品侧**：`MAP_TSV="$(printf '%s\n' "$MAP_TSV" | tr -d '\r')"`（PLATFORM-CHECKLIST #2）。
- **夹具侧**：把 CRLF 仿真固化为**常驻断言**（PATH 前置 shim）——该平台差异从此每次 CI 都被守住，
  不再依赖「有人记得在 Windows 上跑」。

```bash
$ bash tests/control-tower/ct-suite-select.test.sh
  ✅ CRLF 仿真（python 输出 \r\n，Windows 文本模式）→ 仍只选 A 域 1 条（PLATFORM-CHECKLIST #2）
结果: 26 通过, 0 失败
$ GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=init.defaultBranch GIT_CONFIG_VALUE_0=master bash tests/control-tower/ct-suite-select.test.sh
结果: 26 通过, 0 失败
```

### 12.4 附带修正（verifier 排障障碍）

首推版夹具 `:108` 正常路径用 `2>/dev/null` **吞掉了自己的 stderr** —— 而那正是定位本失败的唯一诊断行。
已改为 `2>"$TMPD/e0"` 且**断言失败时把 stderr 内容打进失败信息**（同 §2 其余用例惯例）。

### 12.5 跨卡可复用教训（登记）

1. **夹具不得假设平台默认**：默认分支不是唯一一类；**python stdout 的换行转换**同样属「默认值假设」。
2. **凡跨平台脚本，python/命令输出进入比较前一律 `tr -d '\r'`**（PLATFORM-CHECKLIST #2 已有条文，
   本条是**该条的又一次复发** —— 说明「写了清单」不等于「照着做」；已用常驻 CRLF 仿真断言把条文变成物理门禁）。
3. **夹具自己的 stderr 是诊断资产**：静默捕获可以（`swallow-ok` 合法），但**失败断言必须把捕获内容打出来**，
   否则 CI 上只剩「3 条 vs 1 条」，定位成本从分钟级升到小时级。
