## 一、这一批做了什么（段 1）

把门禁证据的载体从「git 跟踪的 append-only 文件 `.claude/bypass.log`」迁到 **commit trailer**
（`PreCommit-PASS: <sha256>`）。本批只落**写入侧 + 对账器三态 + CI 可见化**，**不动 union、不停写旧日志**。

| 文件 | 变更 |
|---|---|
| `scripts/control-tower/precommit-evidence.sh` | **新增**：`path`/`write`/`hash`/`verify`。把「pre-commit 已通过」落到 `$GIT_DIR/synova-evidence/precommit-pass`（**不被 git 跟踪** ⇒ 不重演「每提交必脏」） |
| `scripts/control-tower/synova-commit` | 暂存态冻结后、`git commit` 前，置入 `PreCommit-PASS: <sha256>` trailer |
| `scripts/control-tower/check-bypass-log.sh` | **三态对账**：① 有 trailer → 通过 ② 无 trailer 但旧账本有该 SHA → 通过（兼容过渡） ③ 两者皆无 → `exit 1`。用 `%(trailers:key=…)` 原生解析（不吃正文同名字符串） |
| `scripts/install-hooks.sh` | pre-commit 包装器额外写证据标记；**保留**旧 marker（护 `--no-verify` 检测） |
| `.gitattributes` | **仅加注释**：记录「union 本批保留」的理由（不删 `merge=union`） |
| `.github/workflows/ci.yml` | 增 trailer 对账 step（态2 `::warning` / 态3 `::error`+红 / exit≥2 红）；新测试登记密封清单 |
| `tests/control-tower/precommit-evidence.test.sh` | **新增** 43 项断言：契约 / 边界 / 降级 / 三态 / **判别性** / 接线 / 零副作用 |
| `tests/control-tower/check-bypass-log.test.sh` | 改 1 条断言（见下「判据变更」） |
| 其余 4 件 | 治理产物：brief / `task-state/D1068.json` / memory note / evidence JSON |

## 二、两处与派单件的偏离（均经 CTO 二次裁决，K3 请按此核）

**① 本批不删 `merge=union`（派单件原要求删两条）**
本地实测：删掉 union 后两分支各改 `.claude/bypass.log` ⇒ `CONFLICT (content)` / `CONFLICT (add/add)` **硬冲突**；
union 在时自动合并 clean。⇒ **只删 union 而不停写**，是把「可自动合并的脏」换成「不可自动合并的脏」，
合并吞吐**更差**，与 C1 目标相反。真解 = ① 停写 ② 再删 union。
裁决：CTO 2026-09-29「拆两步：写入侧先（含停写），再删 union」。

**② 改为分段交付（派单件要求「一卡两 PR 同批完成」）**
侦察实测：`.claude/bypass.log` 被 **42 个文件**引用，其中 **21 个测试硬断言日志结构**
（"存在" / "被 git 跟踪" / "每次新增恰好 1 行"）——派单件 ⑥ 只点了 6 个消费者。
段 2–5 合计 ≈30 文件，**超「PR ≤12 文件」**。裁决：CTO 2026-09-29「分段交，本批只交机制核 + CI，并声明后续段」。

## 三、判据变更（不是放宽，是换判据）

`tests/control-tower/check-bypass-log.test.sh` 原断言「`bypass.log` 缺失 ⇒ exit 1」把
「证据文件是存在性前提」当成了契约。载体迁移后该前提不再成立 —— 是否通过应由**逐提交证据三态**决定，
而非「文件在不在」。故改为：**无任何账本来源 + 空区间 ⇒ exit 0 且必须打印「转为纯 trailer 对账」（不静默）**。
真缺陷（有提交却无证据 ⇒ exit 1）由新测试 `precommit-evidence.test.sh` 的三态 + 判别性用例把关。

⚠️ 该断言在首版交付时**耦合本机状态**（`.sessions/*/bypass.log` 是 `bypass-ledger.sh` 的第二来源，
被 `.gitignore` 忽略 ⇒ 新 clone 绿、跑过提交即红）。**独立自验员退回后已修**：
测试内用三处注入缝（`SYNO_LEGACY_BYPASS_LOG` + `SYNO_BYPASS_SESSIONS_ROOT` + `SYNO_BYPASS_LEDGER_DIR`）
隔离全部来源，并以「注入 stray 账本后仍 5/5 绿」反证环境耦合已消除。
