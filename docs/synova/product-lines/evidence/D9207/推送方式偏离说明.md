## 1 事实：本机 tag 污染 ⇒ D331 假红 ⇒ **本机任何 push 必红**（与分支内容无关）

```bash
$ git log -1 --format='%h %ci %s' V5.2.11
75606bf5d 2026-10-08 01:14:07 +0800 fix(D1239): P0 返工 —— hermetic 夹具「先红」基准自包含化（解全队 PR 阻塞）
$ git for-each-ref --format='%(refname) %(objecttype) %(taggerdate) %(objectname:short)' refs/tags/V5.2.11
refs/tags/V5.2.11 tag Thu Oct 8 01:14:16 2026 8e6dcf618
$ git cat-file -p 8e6dcf618 | head -4
object 75606bf5d21f56441aefd9ca1592888604c655cc
type commit
tag V5.2.11
tagger synova-cto <cto@synova.local> 1791393256 +0800
              ↑ tag 消息: "bump V5.2.11 (synova-commit auto-tag)"
$ git branch -a --contains 75606bf5d     # ⇒ 空：该 commit 不在任何分支（tag 指向孤儿提交）
$ git ls-remote --tags origin V5.2.11    # ⇒ 空：远端没有这个 tag（纯本机产物）
$ grep -oE '^## V[0-9]+\.[0-9]+\.[0-9]+' .codex/control-tower/VERSION.md | head -1
## V5.2.11
```

⇒ `scripts/pre-push-check.sh` 的 **D331 版本锚点段**（VERSION.md 最新版本 tag 必须为 HEAD 祖先）无孤儿豁免
（第一段 `for t in git tag -l 'V*'` 循环对孤儿 tag 有 `continue` 豁免，第二段只看 VERSION.md 最新版本），
而该 tag 指向一个**永远不可能成为 HEAD 祖先**的孤儿提交 ⇒ **本机任何分支的任何 push 都被硬拒**。
实测：本机 01:15 / 01:18 两次 `git push` 均被 D331 拒绝（同一分支更早一次能过，是因为当时本机尚无此 tag）。

**处置**：CTO 2026-10-08 裁定 —— ① 请 tag 属主 `git tag -d V5.2.11`（优先，不等待）；③ **授权从干净 clone 推送**
（理由：该 tag 仅存在于本机、远端不存在 ⇒ 是本机产物而非共享事实；D331 对 feature 分支本就判「tag 未打 = 合法中间态」，
干净 clone 得到的正是门禁本意答案）。② 不做（等待 D1239 落 main 过于被动）。

## 2 ③ 的执行形态（未跳过任何检查）

```bash
git clone --no-tags /Users/wane/SynovaAgent /private/tmp/0gate-clean   # 不带本机任何 tag（含那条孤儿 tag）
cd /private/tmp/0gate-clean
git remote set-url origin git@github.com:synova-agent/SynovaAgent.git
git fetch --tags origin                 # 只取**共享真值**：37 个远端 tag；V5.2.11 命中数 = 0
git fetch --no-tags /Users/wane/SynovaAgent evidence/0gate-20261008:refs/heads/evidence/0gate-20261008
git checkout evidence/0gate-20261008    # HEAD = 74d7e1fb2（与本机分支 tip 逐字节相同）
for h in pre-push pre-commit commit-msg post-commit; do cp /Users/wane/SynovaAgent/.git/hooks/$h .git/hooks/$h; chmod +x .git/hooks/$h; done
git push origin evidence/0gate-20261008 # ← 真实 hook 全程执行：无 --no-verify / 无 -n / 无跳过 hook
```

**环境补齐三项（如实列出；均为"运行时文件/依赖"，非门禁判定输入）**：

| # | 项 | 原因 |
|---|---|---|
| 1 | `node_modules` 符号链接 → 本仓（`ln -s`） | pre-push 的 D312 baseline 段需 tsc/依赖；clone 无 node_modules |
| 2 | `.claude/bypass.log` 复制自本机工作树（4 条记录，逐条含我 4 个自撰 commit 的 HASH） | 该账本是本机 `post-commit` 写入的**执行证据**（运行时文件、不入 git）；clone 无此文件 ⇒ bypass 对账 fail-closed（首次推送实测被拒，见 `clean-clone-push-1-*.log.txt`）。补入后账本内容即"这些 commit 确实过闸"的真值，非伪造 |
| 3 | 安装真实 hooks（cp 自本仓 `.git/hooks/`：pre-push / pre-commit / commit-msg / post-commit） | git clone 不带 hooks；不装 = 门禁不跑（那才叫绕闸） |

## 4 结论与边界（诚实声明）

- **唯一差异 = 本机多了一条孤儿 tag**；其余输入（代码、依赖、hooks、门禁脚本、账本）与本机一致。
- 门禁在**共享真值**上给出的结论是 `V5.2.11 tag 未打 = feature 分支合法中间态` —— 这正是 D331 的**本意**答案；
  本机得到的是**假红**（本机孤儿产物所致）。
- 本次 push **未跳过任何检查**（无 `--no-verify`、无 `-n`、无 hook 屏蔽）；门禁在 clone 上**完整跑完并通过**。
- 遗留：本机 tag `V5.2.11` 仍在 ⇒ **本机后续任何 push 仍会红**，须由 tag 属主删除/重指（CTO 已记台账 #1317 R32）；
  D331 第二段"无孤儿豁免"的门禁缺陷由 CTO 出提案（改判据走 提案→K3→CTO）。
