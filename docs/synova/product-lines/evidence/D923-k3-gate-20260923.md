## §7 收尾任务 0.5：门禁由 **step** 改为**独立 job**（可注册 + 永远会跑）

### 7.1 问题（队长实测 + 我复现的 CI 证据）

改前 `- name: K3 merge gate (D923)` 缩进 6 空格 ⇒ 它是 `quality` **job 的 step**。两条后果：

① **无法注册**：branch protection 的 required check context 是 **job 名**，step 不是可注册单元；
② **静默缺席**：前置任一步失败 ⇒ 后续 step 全 `skipped`，违反裁定 3「永远会跑」。
（`always()` 只能治 ②，治不了 ① ⇒ 采用**独立 job**。）

### 7.2 改法（实读 `ci.yml:126-140`）

```yaml
  k3-gate:
    name: K3 Merge Gate
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # gate 要算 merge-base / base..head diff（照 D708 所在 job 的写法）
      - name: K3 merge gate (D923)
        env:
          GITHUB_EVENT_PATH: ${{ github.event_path }}   # 供第三路 D# 归因读 PR 正文
        run: |
          bash scripts/control-tower/k3-merge-gate.sh \
            --base origin/main --head HEAD \
            --pr "${{ github.event.pull_request.number || 0 }}"
```

- **不挂 `needs:`**（不被上游 job 失败拖成 skip）
- **不加 docs-only 跳过**（required check 必须在每个 PR 上都有结论；纯文档 PR 无三类命中 ⇒ PASS）
- `fetch-depth: 0`；保留 `GITHUB_EVENT_PATH`
- 调用语义与 D708 同形：`--base origin/main --head HEAD --pr <event>` + 三态 0/1/2 + diff 口径
- **required check context（供 CTO 注册）= `K3 Merge Gate`**（job `name`；job id = `k3-gate`）
- 副作用：canary 块与第 45 条行号下移 12 行 ⇒ `for t in \` = `ci.yml:250`（原 238），第 45 条 = `ci.yml:295`（原 283）。
