## 1. 落点论证：为什么 `cycles/` 目录内不新增任何文件

`src/cycles/cycle-loader.ts` 的扫描语义（实测读码）：

- `:25-29` 扫 `${process.cwd()}/cycles/{custom,industry,builtin}`
- `:59-66` 支持 `industry/<sector>/*.cycle.json` 子目录
- **`:64` / `:69` 跳过 `_` 前缀文件**（`if (sub.name.startsWith('_')) continue;` / `if (entry.name.startsWith('_')) continue;`）
- `:103-110` 只校验 `cycleId` / `nodes[]` / `overflowFormula.condition`，**不校验 `edgeRefs` / `mapping`**

结论：(b) 路线下映射信息不落 `cycles/`，而是 (i) 由 §2 定稿表承载（本文件）+ (ii) 由重写后的 `.cycle.json` 值本身承载。**因此 `_` 前缀命名问题在本卡不成立**（无同目录新增文件），亦即不存在「映射文件被当循环误加载」的风险。若将来改走 (a)，同目录落点必须用 `_` 前缀，否则 `:64/:69` 的跳过语义不生效。
