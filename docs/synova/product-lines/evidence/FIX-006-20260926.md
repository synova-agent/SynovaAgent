## 1. 取号 O(1)：修前 / 修后实测计时（真实仓库只读 dry-run；**不烧号**）

口径：`SYNO_TASK_STATE_DIR=<真仓 task-state> SYNO_LOCK_DIR=<tmp> SYNO_ALLOC_NO_REMOTE=1 SYNO_ALLOC_NO_BRANCH=1 bash <脚本> "<name>" --dry-run`（隔离 remote/branch 两项以单测本次改动的 worktree 扫描分量；dry-run 只打印不建壳）。
规模（实测）：`git worktree list | wc -l` = **308**；主仓 `task-state/D*.json` = **364**（全 worktree task-state 文件合计 ≈87,130，verifier 只读复刻同源）。

| | 耗时（`date` 秒差） | 输出 |
|---|---|---|
| **修前**（`git show <base>:alloc-task-id.sh` 副本） | **94 s** | `D1009 (dry-run, 未建壳) ` |
| **修后**（本分支） | **7 s** | `D1009 (dry-run, 未建壳) ` |

⇒ **同输入同输出（D1009 一致），耗时 94s → 7s（≈13×）**；且 7s 已远低于 `LOCK_WAIT_SEC=30`，取号入口不再挂死。
根因：`WORKTREE_USED="${WORKTREE_USED}${n}…"` 在双层循环内做字符串累加（bash 字符串不可变 → 每次复制整串 = O(n²)）；改为**追加写临时文件**（O(1)/次）+ 末尾一次读入。

## 2. 拒绝面接受读取面结果：成对反例（沙箱 git 仓 + 两个 worktree）

场景：主 worktree `task-state/D1000.json`；**另一 worktree**（目录名不含 `d9999`）内 `task-state/D9999.json`。
命令：`bash <脚本> --check-id <号>`（`--check-id` = 只读校验模式，读面不参与 ⇒ 直接考拒绝面）。

| 场景 | 修前 | 修后 |
|---|---|---|
| ⒜ 未占用名 `8888` | rc=0（放行） | **rc=0（放行）** |
| ⒝ 已占用名 `9999`（在另一 worktree 的 task-state） | **rc=0（漏判！** 拒绝面只查 worktree **目录名**） | **rc=1 + 点名**：`worktree-task-state  …/wt2/task-state/D9999.json` |
