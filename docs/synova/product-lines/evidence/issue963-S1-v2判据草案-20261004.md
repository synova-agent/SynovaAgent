## 〇、为什么要 v2（缺口来自 #997 实测，非推测）

#997 在**真实运行**上实测到两个 v1 抓不住的失败模式（原始输出见 `issue963-S2-报告质量结论-20261004.md` §五）：

| 缺口 | 实测事实 | v1 为何漏判 |
|---|---|---|
| **G-1** | 同一次运行：SSE 产出 **18 条 `expert_hypothesis`**（含「商业模式一致性低 (0%)」「现金跑道计算降级」等真实发现）；报告 `rootCauses / recommendations / expertReports` **全为 0 条** | v1 的 **RQ-06 只规定"报告非空条目必须有同源事件"（防**编造**），没有规定"运行期非空事件必须进入报告"（防**丢弃**）** ⇒ 单侧判据 |
| **G-2** | `ceo` 深度下空根因走 `assembleCeo` 返回 `诊断完成，未发现显著瓶颈。`（`src/agent/report-assembler.ts:43`）——该行**不是** `[degraded]` 空态行，且**携带溯源指针** ⇒ v1 的 RQ-03 非空性闸门 `conclusionLines ≥ 1` **通过**、覆盖审计 `missingPointerLines = 0` **也通过** | v1 的 RQ-03 闸门只防"全 `[degraded]` 空报告"（`flywheel` 深度形态），**防不住 `ceo` 深度的假阳性结论行**（`assembleCeo` 的默认文案是正面断言） |

**共同根因**：v1 把"有没有指针/格式对不对"判得很细，但**没有判"报告到底说没说出东西"**（G-1）与**"结论行的语义是否与降级事实矛盾"**（G-2）。

## 一、v2 新增判据（2 条；逐条含 ①谁判 ②按什么判 ③穿哪个生产入口 ④应红场景 ⑤复核命令 ⑥非恒真声明）

> 入口简称：**入口A** = `POST /api/diagnosis/consult`（`src/routes/diagnosis.ts:189`）；
> **入口B** = `GET /api/diagnosis/consult/:consultId/report?format=json`（`:910`）；
> **入口C** = `GET …/report?format=markdown`（`:910`）。

### RQ-10 事件不丢失（G-1 补口）

| 项 | 内容 |
|---|---|
| **谁判** | **独立自验员**（脚本比对，判定方 ≠ 报告产出方）；第三方可复跑 |
| **按什么判** | 在**同一次运行**内定义两个计数：<br>`N_sse` = SSE 流中**非空** finding 类事件数（`expert_hypothesis` / `hypothesis_generated` / `interim_finding`，其 `message` 或 `findings[].summary` 非空）；<br>`N_report` = 入口B 报告中 `rootCauses` + `recommendations` + `expertReports` 的**非空**条目数。<br>**规则**：若 `N_sse > 0`，则必须满足 **(a)** `N_report > 0`（事件被纳入报告），**或** **(b)** 报告**显式转入降级说明**——即四槽位**全部**为 `[degraded]` 空态行**且** `degradedModules` 非空且 `raw.degraded === true`。<br>(a)(b) 皆不满足 ⇒ 红。 |
| **生产入口** | 入口A（SSE 全文）＋ 入口B（报告 JSON）——**必须同一次运行的产物配对**，禁跨运行拼接 |
| **红条件** | `N_sse > 0` **且** `N_report === 0` **且** 报告未显式转入降级说明（存在任一**非** `[degraded]` 的正面/中性结论行）⇒ 红。**具体构造**：本次 #997 真实运行即天然命中（`N_sse = 18`、`N_report = 0`、结论行 = `- 诊断完成，未发现显著瓶颈。`）⇒ 该条在真实产物上**必然取红**，无需人为构造。 |
| **复核命令** | `grep -c '"type":"expert_hypothesis"\|"type":"hypothesis_generated"\|"type":"interim_finding"' /tmp/sse.txt`（→ `N_sse`）／`python3 -c "import json;r=json.load(open('/tmp/report.json'))['report'];print(len(r['rootCauses'])+len(r['recommendations'])+len(r['expertReports']))"`（→ `N_report`）／`grep -c '^\- \[degraded\]' /tmp/onepager.md` 与 `grep -c '^\- ' /tmp/onepager.md` 比对（判 (b) 是否成立） |
| **非恒真声明** | 双向可判：事件被纳入报告 ⇒ (a) 满足 ⇒ 过；报告显式降级 ⇒ (b) 满足 ⇒ 过；**有事件却不进报告、报告又不承认降级 ⇒ 红**。不存在"任何输入都通过"。 |
| **与 RQ-06 的关系** | **互补而非替代**：RQ-06 防**编造**（报告有、运行期无）；RQ-10 防**丢弃**（运行期有、报告无）。两条须**同时**生效，缺一即为单侧判据。 |

### RQ-11 结论行语义闸门（G-2 补口）

| 项 | 内容 |
|---|---|
| **谁判** | **机器判据**（语义闸门查表）＋ **第三方独立复算**（闸门与产出方同模块风险，同 v1 T2，须第三方复算，不得自判通过） |
| **按什么判** | 取入口C 的 `### 结论` 段 **与** 入口B 的 `rootCauses.length` / `degradedModules`：<br>**触发条件**：`rootCauses.length === 0` **或** `degradedModules` 非空（即"报告无根因"或"运行期已自陈降级"）。<br>**触发后要求**：该段**必须**只含 `[degraded]` 空态行；**不得**出现任何**正面/平稳断言**。禁止词表（三源合一，缺一即漏）：<br>① `assembleCeo` 空根因默认文案：`诊断完成，未发现显著瓶颈。`（`src/agent/report-assembler.ts:43`）；<br>② 一页纸头行正面措辞：`运行平稳`（`src/l3/report-templates.ts:203`）；<br>③ 通用正面词：`未发现` / `无异常` / `平稳` / `一切正常` / `运行正常` / `良好`。<br>**未触发时**（有根因且无降级）本条**不判定**（交 v1 的 RQ-02/RQ-08），不得记通过。 |
| **生产入口** | 入口C（markdown 结论段）＋ 入口B（`rootCauses` / `degradedModules`） |
| **红条件** | `rootCauses.length === 0`（或 `degradedModules` 非空）**而** `### 结论` 段出现任一禁止词、**或**该段存在非 `[degraded]` 条目行 ⇒ 红。**具体构造**：本次 #997 真实产物即命中（`ceo` 深度实测结论行 = `- 诊断完成，未发现显著瓶颈。 [src:report:rpt_…_degraded#summary]`，且 `rootCauses.length = 0`、`degradedModules = ["phase2_llm"]`）⇒ **必然取红**。 |
| **复核命令** | `grep -n -A 3 '^### 结论' /tmp/onepager.md` ／ `python3 -c "import json;r=json.load(open('/tmp/report.json'))['report'];print(len(r['rootCauses']), r['raw'])"` ／ 禁止词匹配：`grep -nE '未发现|无异常|平稳|一切正常|运行正常|良好' /tmp/onepager.md`（**在该段内有命中即红**） |
| **非恒真声明** | 未触发分支取**不判定**而非通过；触发分支可红 ⇒ 两端可判。另：**有根因的正常报告**不会命中本条的禁止词表（有根因时结论行由根因文案填充）⇒ 不误杀正常报告。 |
| **为何不是 RQ-02 的重复** | v1 的 RQ-02 要求"`degradedModules` 非空时不得出现假平稳"；**RQ-11 把面扩到 `rootCauses.length === 0` 但 `degradedModules` 为空的形态**（即"未自陈降级、却零根因地输出正面结论"）——该形态 v1 **无判据可判**（RQ-08 只判"零信息"，不判"正面措辞"）。两条**触发条件不同、覆盖面不同**。 |

## 三、v2 自检（恒真式排查，同 v1 口径）

1. **RQ-10 非恒真**：三态均可构造——纳入报告（过）／显式降级（过）／有事件未纳入且不承认降级（红）。
2. **RQ-11 非恒真**：未触发分支记**不判定**（不记通过）；触发分支可红。
3. **未被 v1 覆盖的残余（v2 仍未覆盖，诚实列出，不做隐藏）**：
   - **R-1**：`N_report > 0` 但**质量低**（如全部条目是同一句话的复读）——v2 只判"不丢"，不判"有信息量"。⇒ 属 v3 议题（需"信息量下限"或"多样性"判据）。
   - **R-2**：禁止词表属**有限枚举**，新增模板文案可能逃逸 ⇒ **应随模板变更同步维护**（建议：把词表与模板常量同源生成，避免两处漂移）。
   - **R-3**：RQ-10 的 `N_sse` 计数口径需与 SSE 事件类型定义同步；若新增 finding 类事件类型而未登记，会漏计 ⇒ 需一条"事件类型清单"的单源。
4. **本草案的自验边界（必须重申）**：本文件由 **verify-independent** 撰写。按 #996 F10「判据作者不得自验」，**本草案的应红场景 L2 复跑不得由本线自判**；须由 **K3**（或经产品线负责人指派的非本草案作者）复跑确认。**本线不产出任何"通过"结论。**
