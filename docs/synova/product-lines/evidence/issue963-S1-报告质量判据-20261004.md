## 〇、本卡的判据设计总则

1. **判据必须能红**：只能"通过"不能"失败"的判据 = 没判据。本卡 **9 条判据各给一条「应红场景」**（一一对应，见 §二）。
   > F4③ 计数口径：该字段在 §二 每条判据表内以固定行首标签书写，恰 **8 行**（= 判据条数）；本文件其余位置一律改用「应红场景 / 反例」表述，**刻意不重复该标签**，以免 F4③ 的 `grep -c` 计数被叙事文字污染。
2. **判定方独立于报告产出方**：报告产出方 = 诊断引擎（LLM 专家推理）+ `src/routes/diagnosis.ts` 装配。
   本卡每条判据的判定方**均不得是**该产出方（禁自评，#963 硬约束）。
3. **穿真实生产入口**：判据的观测面必须是真实路由/真实函数，不得用离线伪造产物或场景自产文件。
4. **L1 与 L2 分开报**：本卡是 **L1-静态可达**（判据存在且可复核）；**是否真的能红**须在 #997 用真实报告跑出来 + 第三方复跑。
5. **反恒真**：任何输入都通过的判据作废重写。本卡已**实测出 3 个既有恒真陷阱**（§三），并**实测坐实"既有审计对零内容报告全取绿"**（§三-⑤）⇒ 判据集已针对性加固（RQ-02/RQ-08 即为此设）。

### RQ-01 入口实达性（报告确实由本次真实入口产出）

| 项 | 内容 |
|---|---|

## 三、反向控制：恒真式排查（本卡硬要求 ⑤）

**排查口径**：对每条判据追问"存不存在一个输入使它在最差情况下仍取通过？"存在 ⇒ 恒真 ⇒ 作废重写。

### ① 实测出的既有恒真陷阱 T1：空报告使覆盖审计恒真通过

- **机制**：`auditConclusionCoverage` 的 `missingPointerLines = tracked.length - linesWithPointer`（E15）。全空降级报告的四槽位全为 `[degraded]` 空态行，被 `filter(line => !line.isDegraded)` 剔除 ⇒ `tracked = []` ⇒ `0 - 0 = 0` ⇒ **"零违规"**。
- **后果**：若把"`missingPointerLines === 0`"单独当判据，则**最差的空报告必然通过**。
- **加固**：RQ-03 增设非空性闸门 `conclusionLines ≥ 1`（不合格即红）；RQ-05 借 `maxLineOk/conclusionCharsOk` 的 `> 0` 前置（E19）天然取红。

### ② 实测出的既有恒真陷阱 T2：判定方与产出方同模块

- **机制**：指针**生产**（`buildReportPointer`，`report-onepager-trace.ts:117`）与**判定**（`resolvePointers`，同文件 `:258`）同模块；可读性**生产**（`renderOnePager`）与**判定**（`auditOnePagerReadability`）同在 `report-assembler.ts`（`:329` / `:439`）。
- **后果**：产物与判据同源 ⇒ 同源偏差不会被发现，形成自洽假绿。
- **加固**：RQ-03 / RQ-05 的结论一律**降级为「可提请独立审计」**，须第三方以独立实现复算，**不得由本线自判通过**（对应红线：不判自己改的门禁通过 / 禁自我审计）。

### ③ 实测出的既有恒真陷阱 T3：既有场景断言恒真/自产自证

- **GS-01 断言 8**：`expect.contains = "CONSULT_LLM_"` —— `CONSULT_LLM_GREEN`（真产出报告）与 `CONSULT_LLM_RED`（未产出）**都命中** ⇒ 该断言不区分"是否产出报告"，**恒真**。
- **GS-08 三条**：全为 `type=file` + `contains`（E8），且被断言的文件（`load-result.json` / `render-meta.json` / `templates.json`）由 `run.sh` **自己**在断言前写出 ⇒ **自产自证**；且测的是 `.hbs` HTML 模板族，**与一页纸（inline TS markdown 模板）不是同一物**（E9/E10/E11）。
- **加固**：**本判据集不得引用 GS-01/GS-08 作为报告质量验收**；GS-08 只能作为"模板加载器契约级"证据引用，并须标注同名异物（`executive_summary` vs `executive-summary`）。

### ④ 一页纸渲染路径的覆盖缺口（判据必须新增而非复用）

`renderOnePager` 在 `scripts/` 的命中数 = **0**（E6），生产调用点仅 2 处（E4），且指针覆盖审计**只告警不拦截**（E5）⇒ **报告质量今天没有任何生产入口级的机器闸门**。本卡 9 条判据即为补齐该缺口的最小集，且**不得**以"接线了/存在渲染调用"充当"报告质量可判"。

### ⑤ ⭐ 判据可红性探针实测（本卡最强证据：既有审计对「零内容假平稳报告」全取绿）
