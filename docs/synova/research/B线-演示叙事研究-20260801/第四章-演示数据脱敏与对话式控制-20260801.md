## 三、可行性评估：对话式控制脱敏

**结论：可实现，工程成本低（1 个工具 + 配置 + 接线），属于"新功能设计"，转交 Dev Doc。**

**依据**：
- 工具调用链已存在（tool-loop-executor + builtin-tools，对话→工具→执行）
- 分级能力已存在（PIIScrubber S1-S4）
- 对话语境已存在（conversation-engine.ts:145 演示场景提示词）

**实现路径要点（供 Dev Doc）**：
1. 新增工具 `set-scrub-level`（或 `demo-mode`），入参：级别（standard/demo/max）+ 可选业务字段清单
2. 对话意图识别：在 conversation-engine 提示词加入"用户要求隐藏/脱敏/演示场景 → 调用 set-scrub-level"
3. PIIScrubber 增加动态级别配置（替换当前静态初始化，bootstrap.ts Phase 4c 注入配置源）
4. 输出侧报告/卡片生成处（report-assembler / interactive-card）在 demo 级别下过滤核心财务字段（S4 移除）
5. 审计日志：级别切换事件写入 audit-store
6. 降级：工具调用失败 → log.warn + 保持最高级别（安全侧默认）

**演示话术（当前未实现时的诚实版本）**："这是设计中的能力——边界可以用一句话控制。今天的默认行为是最高等级脱敏。"（已实现后升级为现场演示）

## 四、客户A演示数据脱敏规范（草案）

### 字段分级表

| 级别 | 处理 | 字段 |
|---|---|---|
| S4 移除（演示不可见） | 删除/占位 | 客户名单、月子中心名称、报价单、供应商名称、核心财务明细（单店利润/成本结构/现金流绝对值）、员工薪酬 |
| S3 脱敏（保留形态） | 区间化/模糊 | 渠道数量（几百家→"数百家"）、转化率区间、产能利用率区间、回款周期（"30-90 天"） |
| S2 角色掩盖（保留机制） | 替换为角色 | 创始人→"老板"、销售主管→"销售负责人"、财务→"财务" |
| S1 原始（仅内部） | 不外传 | 全部原始数据仅存在于本地演示环境 |

### 演示数据包要求

1. 单一脱敏数据包（JSON/SQLite），演示前生成、哈希校验，不含 S1 数据
2. 演示环境与生产环境隔离（本地运行，不连外部存储）
3. 现场屏幕保护：报告/仪表盘字段按 S4/S3 渲染
4. 外贸企业敏感性补充：海关数据、汇率敞口、出口国别客户分布——均按 S4/S3 处理（本项目为客户A演示，外贸为后续客户场景）

### 与对话式控制的关系

演示默认最高等级；若对话式控制实现，"演示模式"口令即把级别锁定在 S4/S3，不可现场降级到 S1/S2（防误操作）。
