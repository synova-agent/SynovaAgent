## 0. 怎么用这本手册

**三条铁律：**

1. **不要引用本手册的数字而不重跑命令。** 本手册给的是「命令 + 当日输出」快照。DSH 每发一版，行号必漂移（§6 实证：同一批锚点在 0.1.2-alpha.2 → 0.1.6-alpha.1 之间漂移 1~1463 行）。**引用前先跑 §4 的现验命令。**
2. **锚点一律写「包 + 文件 + 符号」，行号只做辅助。** 符号存活率远高于行号（§6.3 实证）。
3. **任何「已验证 / 已核实 / 经验判断」都是无效表述。** 有效表述 = 命令 + 原始输出。本手册全文按此写。

## 5. 如何正确开卡并提交（硬要求 ④ —— 第 0 步产出）

> **为什么必须写进手册**：`staging_guard.py` 的认领判定会让**每一个不知道规则的新 session 撞墙**。D718 修 pre-doc-audit.sh 时真实被拦；D664 实测被拦 2 次；D328 认领校验判「他人文件」硬阻断。

### 5.1 认领判定规则（读源码得出的权威版）

判定在 `scripts/control-tower/staging_guard.py::check_staging()`，**两条独立防线**：

**防线 1 — 认领制（D329，不依赖登记时序，判定在 own_set 之前）：**

```
1. 用 session_id 调 `bash scripts/workflow/resolve-commit-brief.sh --session <sid> "<暂存文件列表>"`
2. resolver 返回一个 brief 路径
3. 仅当该 brief 的 Q2「做什么」路径**真实命中 ≥1 个暂存文件**（genuine claim）才继续
4. 比较 brief 文件名里的 D# 与 session_id 里的 D#
     精确相等 → pass；不相等 → BLOCK（exit 1）
     session_id 无 D# → 跳过本防线（不误伤）
```

**防线 2 — registry 写集（时序敏感，兜底）：**

| 情形 | 判定 |
|---|---|
| 文件 ∈ 自己（或**同 task_id** 的 session）未 committed 写集 | **pass** |
| 文件 ∈ 他人活跃 session 未 committed 写集 | **BLOCK**（输出 owner） |
| 他人在 registry 声明过但已 committed | **pass** |
| 无任何 registry 记录 | **warn**（stray，不硬阻断） |
| registry 缺失/损坏/python 不可用 | **fail-open pass + degraded 记录** |

### 5.3 正确姿势（照做即可）

**① 取号（唯一入口，禁自编号）**

```bash
bash scripts/control-tower/alloc-task-id.sh "<任务名>"
```

**② 建 brief：`.claude/task-briefs/YYYY-MM-DD-D<num>-<slug>.md`**

- **日期前缀必须在「今日 ±1 天」窗口内**（resolver 的 `DATES` 窗口，容差为 CI UTC/UTC+8 差异）。**跨日任务**靠 D718 的**身份锚点**兜底（见 ③）。
- **`## Q2:` 标题必须紧跟冒号**；「做什么」下列 `- <完整仓库相对路径>`，**一条一个文件**。
- **禁用未填模板占位**：Q2 里留 `<path/to/file.ts` 会让 `parse_q2` 提取出字面占位符 ⇒ 认领恒空 ⇒ 回退到无关 brief。现行 task-briefs 中有 11 份仍是占位状态。

**③ 让 resolver 能找到你的 brief（四条路径，按优先级）**

```
1. .claude/current-brief.<session-id>（session 专属，最优）
2. 日期窗口内 + Q2 真实认领文件数最多的 brief（同数时：强锚点 > 弱锚点 > 字典序）
3. 强锚点回退：分支名含 D# / 暂存 task-state/D#.json 指向的 brief
4. 最终回退：日期最新且 parse_criteria 可解析的 brief
```

> **强锚点在 D718 引入**，专治「brief 日期在窗口外」：**把 D# 写进分支名**（如 `feat/d782-doc-truth-wiring`）即可让跨日任务被正确认领。
> **反例实证（T1）**：本 session 用 `--session D999` 请求 `src/l3/monitoring-contract.ts`，四条路径全部落空 → 回退到**当前分支 `feat/d782-doc-truth-wiring` 的强锚点** brief（D782）：
> ```bash

> ```
> ```

> ```
> **结论：分支名会被当作你的任务身份。分支名带别人的 D# ⇒ resolver 拿别人的 brief ⇒ 若你恰好暂存了它认领的文件，直接 BLOCK。**

**④ 提交（`synova-commit` 是唯一入口）**

```bash
bash scripts/control-tower/synova-commit \
  --task-id D<num> --agent "<名称>" \
  --session-id D<num> \
  --files <文件1> <文件2> ... \
  --message "<type>(<scope>): <subject>"
```

- **`SESSION_ID` 默认取 `TASK_ID`**（`synova-commit` L360-362）。**`--task-id` 必须含 `D<num>` 且与 brief 的 D# 一致**，否则防线 1 直接 BLOCK。
- **必须用 `--files` 显式列文件**，否则 `git add` 会把工作区里别人的改动一并卷走（D286 事故根因）。
- **不要 `git stash`**（D312 事故，铁律 0-3）。要隔离就 `git worktree add`。

**⑤ 提交前自检（30 秒）**

```bash

# 2) 暂存区是否安全？

# 3) 有没有未填模板的 brief 在候选池里搅局？

```

2. **禁在 Q2 写裸基名** —— 会跨目录认领同名文件（§5.2 T5）。
