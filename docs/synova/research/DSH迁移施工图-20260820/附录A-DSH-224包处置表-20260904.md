## 三、遗漏检查（名字不起眼但确认有价值的包）

1. **dsh-output-retention**（`ItemRetainer / TextRetainer / describeOmitted / formatRetentionNotice`）——有界保留原语 + "省略说明"中性文案。极易漏掉，但它把"截断"从信息损失变成诚实披露，直接可用于 Synova 长列表/长报告的截断呈现（对照铁律 44 的消息截断算法）。
2. **dsh-repeat-tool-reminder**——同参工具调用循环的 advisory 提醒。名字像小插件，实际是 ReAct 卡死防呆的成熟实现（提醒不阻断），对照专家循环质量。
3. **dsh-session-reference**——跨会话快照引用（URI 编解码、大小上限、候选限流）+ **不可信模型上下文标注**。后者是 prompt-injection 防线的具体机制，安全价值最高、名字最不显眼。
4. **dsh-session-checkpoint-policy**——模型请求与工具副作用前的语义耐久检查点。只有 `apply/inject/name` 三个导出，极易当成空壳跳过；实际是"副作用前先落盘"的崩溃恢复策略，对照 Sentinel 写库/建工单路径。
5. **dsh-hook-protocol**——名字像协议定义，实际含 matcher 引擎、stdin/exit-code/stdout 编解码、多 hook 合并、stderr 摘要、分离运行的完整实现。Synova 控制塔就是 hook 体系，这是最同构的可参照物。
6. **dsh-atomic-write**——`writeFileAtomic + withFileLock`。两个导出的 util 包，但原子替换+文件锁是控制塔状态文件/备份脚本（铁律 0-3/0-4）可直接借鉴的原语。
7. **dsh-deque**——只有一个 `Deque` 导出，零依赖环形双端队列，摊还 O(1)、有界空置存储。流式 buffer、有界历史队列的标准解，对照铁律 41 的流式管线约束。
8. **dsh-session-stats**——只有 `apply/inject/name`，纯投影：全日志会话计数与墙钟时间。是"投影范式最小实例"，也是 Synova 会话报告统计的现成公式。
9. **dsh-launch-environment**——不可变启动环境且**记录每个值来自哪一层**。配置来源可追溯（审计友好）范式，Synova 配置散在 env/yaml/代码，此范式值得抄。
10. **dsh-storage-domain**——`defineDomain`：schema 校验 + 事件发射的 KV 域。给"不够格进 SQLite 又不能只是内存"的状态（哨兵配置、反馈行、元数据）一个中间层，Synova 缺的就是这一层。
11. **dsh-subprocess**——seam 包但内部有 `scrubbedParentEnv / SENSITIVE_ENV_PATTERN`（敏感环境变量擦除）与进程组/升级式 kill/有界溢出输出的完整治理词汇，security/ 与 ModuleRunner 直接可用。
12. **dsh-time-context**——每步注入当前时间与耗时。哨兵/专家判断"数据新鲜度"（哪天的财报、距上次检查多久）的最小机制，名字完全看不出价值。
13. **dsh-goal-round-driver**——容易被并进 dsh-goal 一起看而漏掉其独立价值：**竞态围栏**（防双驱动）+ `renderGoalRoundPrompt` 的续轮提示注入（含"完成前先取证"措辞），是长任务自动续轮的完整方案。
14. **dsh-fs-observation-policy**——只有 `apply/name` 两个导出，实际是"观察态 + 读前先读 + 版本守卫写"的完整编辑安全策略（无服务 API 的事件门）。把 Synova 的"先读再改"纪律变成运行时机制。
15. **dsh-session-telemetry**——seam 包，但四段式（捕获→投影→**脱敏**→上报）管线值得对照：PIIScrubber 应处于上报出口强制位而非散点调用。
16. **dsh-session-query-sqlite**——名字平淡，但 SQLite FTS5 会话全文检索与 Synova L5 同栈，几乎可以直接落地。

**反向结论（看过、确认无遗漏价值）**：`dsh-tmux-context`（tmux 专属）、`dsh-skill-badge`（演示技能）、`dsh-agent-spine-demo`（demo）、`dsh-llm-pi-ai`（设计验证孪生）、`dsh-cordis-host-runner`（模型挂载动态包，Synova 不开放）、`dsh-code-runtime`/`dsh-code-runtime-worker-thread`（Synova compute 自研纯函数，不执行模型代码）、`dsh-win32-process`/`node-addon-landlock-run`/`dsh-sandbox-*`（OS 级沙箱，平台专属）。

## 四、落地顺序建议（按处置聚合）

- **Stage 1/2 设计期（借鉴-范式 62 项）**：优先读 10 个机制包——`dsh-session`（surface/fold 细节）、`dsh-session-projection`（投影注册表）、`dsh-compaction-basic` + `dsh-compaction-tool-result-pruner`（上下文经济学）、`dsh-token-meter`（重放感知计量）、`dsh-llm`（错误 taxonomy）、`dsh-timeout` + `dsh-tool-call-timeout-policy`（协作式超时）、`dsh-mcp-client`（MCP client 侧）、`dsh-webhook`（事件触发路）。
- **Stage 2 契约层（接缝-预留 28 项）**：先定 6 个核心 seam 的对接词汇——`dsh-tools`、`dsh-subagent`、`dsh-jobs`、`dsh-session-persistence`、`dsh-settings`、`dsh-web`；其余按需补。
- **Stage 3 壳试点（替换-候选 6 项）**：`dsh`（CLI）+ `dsh-base`（基座）起步，按形态加 `dsh-headless`（无头批量）或 `dsh-web-app`（Web GUI）；`dsh-sdk-minimal`/`dsh-sdk-app` 作为 SDK 消费形态备选。
