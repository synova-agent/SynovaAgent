## 〇、转交说明（读给开发）

Synova 的战略已定：**通用工程借 Harness，领域深度自己做深**。以下方向是"借鉴方向"——大多数是**借鉴理念自研**（不引 Harness 依赖，因其 v0.1.0-rc.5 未稳定），而非复制代码。OpenViking 方向有 AGPL 红线（不复制代码）。

**不动的**：定位、五层架构、42 边本体、专家体系、诊断方法论。**现在不做的**：迁移底座（路径 A）、生态插件化（路径 C）——等部署稳定 + 首季度数据后评估。

---

## 一、P1 方向（部署期 9 月起）

### 方向 D1：事件溯源 session log（借鉴 Harness 范式）

- **做什么**：把 Synova 的 SessionStore 演进为 append-only 事件流 + 从事件流派生消息历史，并建立"model-visible ⟺ logged"纪律（凡进模型请求的必可从日志重建）。
- **为什么**：这是 C 线 S3-5（自诊断可信度）、S0（信任建立）的根因——没有可回放的真相流。Harness 已证明这是 Agent 基础设施的标配。
- **边界**：借鉴理念自研，不引 Harness 代码；保留 Synova 的 L5 存储层位置。
- **关联缺口**：S3-5（P0 已转交）、S0-2（闭环验证）、S5-1（反馈闭环）。

### 方向 D2：Agent Notes 四态记忆（借鉴 Harness 范式）

- **做什么**：把 Synova 的 memory/ + 铁律演进为结构化四态（proposed/implemented/archived/rejected），非平凡变更强制带 Note。
- **为什么**：补 S5-3（知识沉淀）的结构化；Harness 证明这是"知识可沉淀、可归档、不腐化"的关键。
- **边界**：借鉴理念，与现有铁律体系合并而非推翻。
- **关联缺口**：S5-3。

### 方向 D3：snapshot 测试（借鉴 Harness 范式）

- **做什么**：为模型/报告输出建立 keyless 快照回放机制，接入黄金数据集门禁。
- **为什么**：补黄金数据集未入门禁（C 线 P1-2）；模型/UI 输出可复现是"为未来迭代打基本功"。
- **边界**：借鉴理念；与现有 vitest 体系并存。
- **关联缺口**：黄金数据集门禁（P1-2）。

### 方向 D4：guard 循环卫生 + 超时（借鉴 Harness 范式）

- **做什么**：吸收 timeout-policy + repeat-tool-reminder 思想，通用化控制塔的防跑偏。
- **为什么**：控制塔已有雏形，但"超时策略 + 循环卫生"可更通用。
- **边界**：借鉴理念，融入控制塔而非新建。
- **关联缺口**：控制塔（S3-5 同源）。

### 方向 D5：组织记忆与知识沉淀的策略调整（OpenViking 应对）

- **做什么**：S5-4（组织记忆）/ S5-3（知识沉淀）从"自建通用记忆存储"转向"借鉴 OpenViking 机制（三层加载 L0/L1/L2 + 目录递归检索 + 可观测轨迹 + 会话变记忆）+ Synova 领域知识结构（42 边本体作为知识组织方式）"。
- **为什么**：OpenViking 是真实威胁，已把"上下文数据库"做到成熟；Synova 若在"通用存储层"重复造轮子必输，差异化必须在"知识结构层"。
- **边界（红线）**：**不复制 OpenViking 代码**（AGPLv3 传染）；只用 HTTP 服务接口或借鉴理念自研；42 边本体是知识组织方式，不做通用向量库。
- **关联缺口**：S5-3、S5-4、部分 S1 证据链。

## 二、P2 方向（Q4 首季度数据回收后）

| 方向 | 做什么 | 为什么 | 边界 |
|------|--------|--------|------|
| D6 seam 三角色 | 五层静态分层 → 动态接缝（先 llm，再 subagent） | 能力可换、消费方不变，为未来迭代打基本功 | 长期演进，不推翻五层架构 |
| D7 spill 超大输出持久化 | 大报告/大工具输出持久化 + 有界预览 | 上下文管理 | 借鉴理念 |
| D8 sandbox 进程沙箱 | 进程级安全（landlock/windows-acl 思想） | 补 security/DataBoundary | 长期评估 |
| D9 subagent seam 多后端 | SubAgentCoordinator → seam 化（acp/claude-code/codex/fork/spawn） | 子 agent 多后端远超现状 | 长期；评估是否引 Harness 子 agent 后端 |

## 三、明确不做（现在）

| 事项 | 原因 |
|------|------|
