# DeepSeek Harness 研究与 Synova 战略再定位——研究方案（最终版）

> 2026-08-16 | 研究 session | 最终定版（创始人确认：做深做透，定位与应用场景不动，为未来迭代发展打基本功）
> 定位声明：Synova 的定位（企业增长诊断 Agent，5-1000 人市场）与核心应用场景（组织诊断 + 持续增长导航）**本次研究不动**——研究对象是"底座与工程范式"，不是"产品方向"。

---

## 一、研究背景（为什么现在做）

DeepSeek Harness（`dsh`）已发布并开源（MIT），本地已部署（`D:\deepseek-harness`，v0.1.0-rc.5）。这是双重拐点：

1. **应验**：底座研究（08-03）预言"Harness 是持续学习的工程落点"+"Harness 通用层可能提供企业 Agent 脚手架"，现已发生且开源彻底。
2. **倒逼**：Synova 自研的通用 Agent 工程能力（Loop Engineering、控制塔、哨兵调度、N13、五层架构、契约门禁）被一套更成熟、更彻底、完全开源的底座"通用化"了。**通用 Agent 工程能力从此不是护城河，领域深度才是。**

梁文锋那句话的正面：发动机免费了，竞争回到"谁能造出最好的方向盘、仪表盘和驾驶方法论"。

## 二、前置代码侦察（方案事实底座，已完成）

已读：README、AGENTS.md、architecture.md、cordis-primer.md、package.json/pnpm-workspace、agent-presets 结构、feedback/goal/schedule/spill/sandbox/session 六包 README。

Harness "重新定义 Agent" 的三个范式（研究将逐一验证并深化）：

1. **无特权核心**：模型适配器、工具注册表、session log、agent-loop 本身都是插件，任何部分从配置替换。
2. **事件溯源（event-sourcing）**：session log 是 append-only 唯一事实源，LLM 消息历史是"派生"的，强制 model-visible ⟺ logged。
3. **capability seam 三角色**：Service Definition / Provider / Consumer 三分离，换 provider 换整个产品，consumer 不动。

工程化到极致：snapshot 测试、Agent Notes 四态记忆、verify-* 门禁全家桶、strict:true、100% 覆盖率门禁、克隆检测。

## 三、研究定位（回答什么 / 不回答什么）

**回答**：Harness 开源底座化背景下 Synova 的战略再定位——借鉴什么、复制什么、走出什么独有深度、三条路径怎么选、以及生态层（插件市场/同类项目/同类应用）全景。

**不回答**：不做 Harness 完整逐行审计；不产出可提交开发任务（给到任务级规格为止）；不重论证产品定位（C 线已定）。

**边界纪律**：终点是"战略判断 + 借鉴/特色清单 + 生态全景 + 路线图"，不是"把 Synova 改成 Harness"；任何换底座结论必须同时回答演示与客户A部署怎么办。

## 四、研究问题（Q1-Q5）

- Q1 **范式解构**：Harness "重新定义" Agent 的什么？哪些是创新（事件溯源/无特权核心/seam），哪些是工程惯例？
- Q2 **能力映射**：Synova 引擎逐模块 ↔ Harness 包族对照——独有 / 可替代 / 可借鉴 / 双方都缺。
- Q3 **何去何从**：三条路径（A 迁移底座 / B 范式借鉴渐进升级 / C 生态并存）的成本、收益、风险、时间冲击。
- Q4 **借鉴与特色**：借鉴清单（包/机制/优先级）+ 走出自己的特色清单（为什么 Harness 做不深 + 怎么加深）。
- Q5 **生态全景**：DSH 开源插件市场 + GitHub 同类开源项目 + 同类应用——生态活力、可复用资产、竞争态势。

## 五、核心模型 / 第一性原理

Synova 的价值 = 让老板愿意放下直觉、相信系统（C 线 S0），信任来自"诊断对不对"，不是"框架好不好"。

**判据**：Harness 解决"Agent 怎么运转"，Synova 的价值在"Agent 判断什么"——42 边因果本体、专家体系、25 测量器+20 哨兵、诊断方法论、GA 人机闭环、行业模板、增长导航、无数据诊断。引擎越可白嫖底座，Synova 越要把工程预算压到领域深度。

## 六、研究任务分章（8 章 + 附录 + 开发转交）

**第一章｜Harness 全包族深度解构**（核心/有借鉴价值的包逐一：机制 + 代码文件:行号 + Synova 对照）——不是 8 个机制浅版，而是完整覆盖包族。

**第二章｜DSH 开源插件市场生态研究**：GitHub `dsh-plugin` topic、插件怎么写/怎么发布、现存插件清单、生态活力、哪些可复用。

**第三章｜其他类似开源项目与应用研究**：同类 Agent harness/框架（LangGraph/CrewAI/AutoGen/OpenClaw 等，含 DSH 之外的）、同类企业诊断/增长分析类开源与应用。

**第四章｜Synova × Harness 能力映射矩阵**：Synova 引擎逐模块 ↔ Harness 包族，四分类打标。

**第五章｜三条路径评估**：A 迁移底座 / B 范式借鉴 / C 生态并存，四维量化 + 时间冲击。

**第六章｜借鉴清单 + 走出自己的特色**：借鉴（包/机制/落地/优先级）+ 特色（为什么做不深 + 加深方向）。

**第七章｜战略结论与路线图**：最终建议 + 分阶段路线图（演示前 / 部署期 / Q4+）+ 与 A/B/C 线、员工分享联动。

**第八章｜OpenViking 专项深挖**（创始人 08-16 追加）：`viking://` 虚拟文件系统 + 三层加载 + 目录检索 + 会话变记忆；判定威胁/互补/可借鉴；AGPL 许可红线；S5-3/S5-4 策略调整。

## 八、定量验收标准

1. 第一章解构 Harness 核心包族（≥20 个包），每个带代码位置 + Synova 对照结论
2. 第二章产出 DSH 插件市场实况（插件清单、发布机制、生态活力判断），证据带日期
3. 第三章覆盖 ≥5 个同类开源项目 + ≥3 个同类应用，每个有"机制提炼 + 与 Synova 差异"
4. 第四章映射矩阵覆盖 Synova 全部引擎模块 + Harness 全部相关包族，四分类无遗漏
5. 第五章三条路径各有成本/收益/风险/时间冲击四维量化，且回答演示与部署怎么办
6. 第六章借鉴清单 ≥6 条（带落地文件+优先级）、特色清单 ≥6 条（带做不深的理由+加深方向）
7. 全部结论与 C 线 33 项、A 线审计、底座研究对齐，不矛盾
8. 推测级结论零进入正式报告

## 九、研究方法与分治边界

代码审计式：读 Harness 源码 + Synova 引擎双向对照，三态判定（存在/存在但未接线/不存在）；对标"最强机制"而非功能清单；外部生态证据一律带日期与来源。

**分治边界**：发现动摇 Synova 架构地基的范式，暂停先同步；路径评估若对演示时间线冲击 >2 周，暂停先对齐。

## 十、风险与红线

1. 时间张力：演示 8/20、客户A部署 9 月——结论不得牺牲这两者；默认演示与部署优先，重构排后。
2. 持续学习红线：不因 Harness 放松"不宣称越用越准/自我进化"（S5-1 未闭环）。
3. 克制纪律：Harness 是主线内研究对象（决定何去何从），但研究止步于"战略 + 清单 + 生态 + 路线图"，不滑向给 Harness 贡献代码。
