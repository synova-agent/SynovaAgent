## 7.1 战略结论（一句话 + 展开）

**Synova 的"何去何从"：从"全栈自研 Agent 工程"收敛为"组织诊断领域的专业 Agent 应用"——通用工程借 Harness，领域深度自己做深做透。**

展开成三条铁律：

1. **不再自研通用 Agent 工程**（SessionStore/ConversationEngine/SubAgentCoordinator/LLM 适配），这些已被 Harness 底座化，继续自研是重复造轮子。路径 B 渐进借鉴，路径 A 迁移等部署稳定后再评估。
2. **把全部工程预算压到 8 项【独有】领域能力**（42 边本体/专家/25 测量器+20 哨兵/诊断方法论/GA 闭环/行业模板/增长导航/无数据诊断），这些 Harness 一个都不做也做不深。（"企业多用户"是【双缺】机会，单独做深。）
3. **定位与应用场景不动**（企业增长诊断 Agent，5-1000 人市场）——本次研究不动定位，只动"工程底盘"和"领域深度"。

这正好落在底座研究 08-03 的定位上："DeepSeek 造发动机，我们造'企业增长医生'这辆车"——现在发动机免费开源了，我们更要专注造好车。

## 7.4 风险与红线（重申）

1. **时间张力**：演示 8/20、部署 9 月——阶段 0/1 不得因 Harness 研究而延误。
2. **持续学习红线**：不因 Harness 放松"不宣称越用越准/自我进化"（S5-1 未闭环）。
3. **克制纪律**：Harness 是主线内研究对象（决定何去何从），但 Synova 不做 Harness 生态里的"又一个插件"——除非领域层成熟后路径 C 作为分发手段。
4. **OpenViking 威胁**：记忆/知识底座化是真实威胁，需专项深挖（后续触发点），必要时调整 S5-3/S5-4 的策略（从"自建记忆"转向"基于通用记忆底座 + 领域知识结构"）。

## 7.5 第七章结论

1. 战略已定：**收敛通用工程、聚焦领域深度**，路径 B 为主、A 待评估、C 为增强。
2. 路线图四阶段清晰：演示 → 部署+借鉴 → 迁移评估+领域加深 → 生态分发。
3. 全部结论与 A/B/C 线、员工分享、底座研究对齐，无矛盾。
