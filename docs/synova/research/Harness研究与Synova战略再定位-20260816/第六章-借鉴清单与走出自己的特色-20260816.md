## 6.1 借鉴清单（能借就借，补缺口 + 打基本功）

| # | 借鉴项 | Harness 来源 | 借鉴价值 | 落地方式 | 优先级 |
|---|--------|-------------|---------|---------|:---:|
| B1 | 事件溯源 session log + model-visible⟺logged | core/session + session 包族 | 唯一事实源、可回放审计、可 fork/resume——补 S3-5（自诊断可信度）+ S0（信任建立）的根因 | Synova 的 SessionStore 增加 append-only 事件流 + deriveMessages | P1 |
| B2 | capability seam 三角色 | llm/subagent/workflow/sandbox | 能力可换、消费方不变——五层静态分层 → 动态接缝 | 先 seam 化 llm（已有雏形）→ 再 subagent → 长期 sandbox | P2 |
| B3 | snapshot 测试（keyless 回放） | 工程化体系 | 模型/UI 输出可复现——补黄金数据集门禁（P1-2） | 黄金数据集接入门禁 + snapshot 机制 | P1 |
| B4 | Agent Notes 四态记忆 | .agents/notes（proposed/implemented/archived/rejected） | 知识沉淀结构化——补 S5-3 的"每次诊断沉淀" | Synova 的 memory/ + 铁律 → 结构化四态 | P1 |
| B5 | guard（循环卫生 + 超时） | guard 包族 | 防跑偏 + 超时——通用化控制塔 | 吸收 timeout-policy + repeat-tool-reminder | P1 |
| B6 | spill（超大输出持久化） | spill 包族 | 上下文管理——大报告/大工具输出不撑爆上下文 | 报告输出超大时持久化 + 有界预览 | P2 |
| B7 | sandbox（landlock/windows-acl） | sandbox 包族 | 进程级安全——补 security/DataBoundary | 长期评估进程沙箱 | P2 |
| B8 | subagent seam 多后端 | subagent 10 包 | 子 agent 多后端（acp/claude-code/codex/fork/spawn）——远超 SubAgentCoordinator | 长期：SubAgentCoordinator → seam 化 | P2 |

**复制 vs 借鉴的边界**：Harness 是 MIT，代码可直接复制，但建议**复制"范式"而非"代码"**——Synova 有自己的架构与铁律，直接引 Harness 代码会引入依赖（Harness 未稳定）。B1/B3/B4/B5/B6 复制理念自研，B2/B7/B8 评估是否引包。

## 6.2 走出自己的特色（做深做透，护城河）

> 每一项回答：为什么 Harness 做不深 + Synova 怎么加深。

| # | 特色 | 为什么 Harness 做不深 | 怎么加深 |
|---|------|---------------------|---------|
| S1 | 42 边因果本体（池-阀-流-溢出） | Harness 是通用底座，无领域真理；因果本体需要组织诊断的第一性原理 + 真实企业零基验证 | 边从 42 扩到更细的行业变体；每边标注 hard/soft/heuristic 成熟度；客户A部署数据回流校准 |
| S2 | 7 位专家体系 | Harness 无专家概念；专家是"领域知识注入"，需组织诊断方法论 | 专家提示词工程深化 + 交叉验证 + 专家与 42 边双向映射 |
| S3 | 诊断方法论（6 阶段 FDE） | Harness 无诊断流程；FDE 是"组织增长卡点"的领域管道 | 无数据诊断（问卷+导入+连接器）做深；诊断→增长导航闭环 |
| S4 | GA 人机协同闭环 | Harness 无 GA 概念；GA 是"企业场景的人验证 AI"，通用 agent 不需要 | N13（GA 纠错→规则回流）闭环接通；GA 验证/否决/仲裁真实接线（C 线 S5-2） |
| S5 | 25 测量器 + 20 哨兵（领域计算） | Harness 无组织指标计算；测量器/哨兵是组织诊断的领域计算 | 测量器覆盖 7 维度深化 + 哨兵与 42 边双向映射做深 |
| S6 | 增长导航（Goal-Proposal-中层工作台） | Harness 有 goal 包但无"增长导航"领域闭环 | Goal-Proposal 三选一 + 方案级哨兵 + 中层工作台做深 |
| S7 | 行业模板 | Harness 无行业概念 | 制造业/外贸/零售/母婴等垂直行业模板做深（客户A=产销一体外贸型） |
| S8 | 无数据诊断 | Harness 假设有工具/数据；SMB 数据不全 | 三路径（问卷+导入+连接器）+ <30% 数据仍出首诊做深 |
| S9 | 企业多用户部署【双缺机会】 | Harness 定位单 agent；Synova 也仅设计未全量验证（A线 A5） | 多用户权限 + 租户隔离 + GA 工作台做深——相对 Harness 的独特差异化机会 |

## 6.3 第六章结论

1. **借鉴清单 8 项**：核心是 B1（事件溯源）、B3（snapshot）、B4（Agent Notes）、B5（guard）——这些直接补 C 线缺口，且都是"范式借鉴非代码依赖"。
2. **特色清单 8 项（S1-S8，独有）+ 双缺机会 1 项（S9 企业多用户）**：全部是"领域深度"，Harness 一个都不做也做不深——这是 Synova 之所以是 Synova 的地方。
3. **一句话战略**：通用工程借 Harness（B1-B8），领域深度自己做深（S1-S8）——发动机是它的，方向盘、仪表盘、驾驶方法论和"路书"（42 边 + 专家 + 诊断）是我们的。
