# Synova 世界级产品研究总计划

> 研究 session 主任务（2026-08-01 确认）：聚焦"如何成为世界级产品"与"真正的缺口"。
> 本文件是总计划与追踪表。每条线展开时，先在此登记，再在独立目录中产出研究方案 + 章节交付物。

---

## 一、背景与动因

1. 目标市场：5–1000 人、请不起麦肯锡级咨询的企业（2026-08-02 修正：客户并非"没有 AI/IT 系统"，而是系统**不全/散乱/不成体系**；关键差异在软件形态——传统软件给人看，未来软件给 Agent 用；客户有系统对 Synova 是**数据利好**。完整表述待创始人补充，定稿前不传播）
2. 产品本质：Agent（驻扎企业、持续观测、主动诊断、行动建议、跟踪执行），不是 ChatBot
3. 近期压力点：盛和塾 8 月演示/演讲（面向"业务出身、一线打拼、触顶困局"型创始人的获客场景）
4. 已识别的初步缺口（种子假设，待各线研究验证/推翻）：

| # | 缺口假设 | 证据线索 |
|---|---------|---------|
| G1 | 结论真实性未经外部客户验证（条件C未闭环） | 42边体系仅客户A零基验证；部署四条件未全部达成 |
| G2 | Agent 自主性承诺 vs 实现差距 | direction-monitor 未接线；middle-evolution-engine 未接线；NCI 零代码 |
| G3 | 无数据诊断未产品化 | 研究完成；问卷/访谈/导入 vs 连接器的产品路径未验证 |
| G4 | "老板看得懂的交付物"缺失 | 创始人仪表盘/报告形态未做用户旅程研究；盛和塾演示是第一次真考验 |
| G5 | 进化飞轮未闭合（越用越准） | GA纠错→规则回流（N13）未接线 |
| G6 | 测量自己的系统不可信 | 控制塔信号文件缺失 + 完成度引擎批量误判（已转交开发修复） |

## 二、研究方法（总则）

每条线遵循：

1. **研究方案先行**：研究问题(Q1–Q4) → 定位 → 核心模型 → 分章任务 → 交付物 → 定量验收标准
2. **五原则**（权威文档14 附录）：第一性原理推导 / 物理现实锚定 / 正交性保证 / 端到端验证 / 持续进化
3. **对抗性验证**：结论经受反向攻击（"演示时老板会问哪三刀"就是最好的对抗性验证）
4. **与现有体系对齐**：每条线标注消费哪些权威文档（01–17）、修改哪些章节、衔接哪些代码
5. **边界诚实**：写清适用区间、证据局限、幸存者偏差

## 三、三条研究线

### A线｜内部真相：产品完整性缺口审计

> 定位：回答"文档承诺 vs 代码现实"的真实差距，输出可排期的缺口清单。

| 项 | 内容 |
|---|------|
| 研究问题 | Q1: 四条件（A 部署独立 / B 诊断自主 / C 结论有用 / D 持续运行）各完成到什么程度？Q2: 每个条件的缺口是"没写/没接/没验"哪一种？Q3: 哪些缺口在盛和塾演示前是致命的？Q4: 与开发者任务地图 v2 的关系如何更新？ |
| 方法 | 权威文档17 的逐行审计法：存在 / 存在但未接线 / 不存在，三态标注 + 文件:行号 |
| 消费的权威文档 | 01/03/13/14/17 + 控制塔修复转交说明 |
| 交付物 | 报告《产品完整性缺口-四条件审计-20260801》+ P0/P1/P2 缺口表（每条带证据） |
| 验收标准 | ① 四条件各有结论与证据 ② 每个缺口标注三态 + 文件:行号 ③ 缺口分级 P0/P1/P2 ④ 与开发者任务地图 v2 有差异说明 ⑤ 对抗性验证：每个 P0 缺口能回答"为什么演示前必须修" |
| 周期 | 1–2 天 |

### B线｜演示叙事：盛和塾场景端到端研究

> 定位：回答"老板打开系统后的 30 分钟里，看到什么、信什么、问什么"，产出演示剧本与产品交付物缺口。

| 项 | 内容 |
|---|------|
| 研究问题 | Q1: 这类创始人的信任决策模型是什么（什么证据能让他信）？Q2: 30 分钟演示的理想叙事结构？Q3: 他会问哪三刀，产品/数据/话术能否招架？Q4: 演示暴露的产品交付物缺口有哪些？ |
| 方法 | 应用研究用户旅程法 + 对标（麦肯锡汇报结构、Palantir demo 节奏、Linear/Notion onboarding 心智） |
| 消费的权威文档 | 01/02/13/15 + 应用研究-企业增长瓶颈突破 5 篇 |
| 交付物 | 《盛和塾演示叙事研究》含：创始人画像、30 分钟时间轴剧本、三刀问题与应答、需补产品交付物清单 |
| 验收标准 | ① 剧本按分钟可执行 ② 每个关键画面标注"产品支撑 / 需补缺口" ③ 三刀问题有数据支撑的应答稿 ④ 与 A 线缺口清单交叉引用 |
| 周期 | 2–3 天 |

### C线｜世界级基准：对标与标准定义

> 定位：回答"世界级长什么样、量化标准是什么、Synova 差多少"，作为持续研究底座。

| 项 | 内容 |
|---|------|
| 研究问题 | Q1: 世界级组织诊断/导航产品的可量化标准（诊断准确率、时间、可执行性、客户续费率）？Q2: Palantir/麦肯锡/顶级 Agent 平台各自的最强机制是什么？Q3: Synova 在每项标准的差距与优势？Q4: 哪些标准在 5–1000 人市场被重新定义？ |
| 方法 | 对标研究 + 第一性原理推导 + 行业文献（保留 C 线为持续更新底座） |
| 消费的权威文档 | 07（Agent工程能力对标）/12（Skill-Tool对标）/14 + 外部公开资料 |
| 交付物 | 《世界级基准定义 v1》+ 对标矩阵 + Synova 差距清单（差距映射回 A/B 线缺口） |
| 验收标准 | ① 每个维度有对标证据（来源+日期）② 标准可量化 ③ 差距清单能反哺 A/B 线 ④ 标注"数据真空"部分并诚实降级 |
| 周期 | 分阶段，4–6 天（第一版 2 天，后续随行业持续更新） |

## 五、追踪与展开规则

1. 每条线展开时：在 `docs/synova/research/{线}-{主题}-{日期}/` 建立目录，先写研究方案，再分章交付
2. 完成后：更新本文件状态（待展开 → 进行中 → 已完成）+ 在恢复笔记"当前进度快照"登记
3. 每条线结束时回答 Agent 自检 5 问（接线/异常处理/类型安全/测试质量/残留清理）——研究文档的对应物是：证据充分、对齐标注、无过时结论残留
