一、架构总览：文件化 vs 代码化的边界

核心原则：哨兵 = 文件化配置（manifest.json + aggregate.ts），计算模块 = 纯TypeScript函数（computes/*.ts），专家 = 纯Markdown文件（expert/{name}/*.md）。不允许跨哨兵引用（B模式绝对禁止）。

1.1 三层结构

层级是什么存储位置格式谁管理
哨兵（Sentinel）诊断信号的观测单元。包含manifest.json + aggregate.ts + computes/*.tsextensions/sentinels/{name}/文件化（JSON+TS）SentinelLoader 自动扫描
计算模块（Compute Function）纯函数，数学公式实现。输入GraphStoreReader，输出ComputeResultextensions/sentinels/{name}/computes/{fn}.ts代码化（TypeScript）aggregate.ts 静态import
专家（Expert）领域诊断师。5个Markdown文件：IDENTITY/THEORY/RULES/TOOLS/CROSS_EXPERTexpert/{name}/文件化（Markdown）expert-registry.yaml

1.2 禁止的 B 模式

绝对禁止：哨兵目录之间不得相互 import。每个哨兵目录完全自包含。唯一允许的跨目录关联是通过 manifest.json 的 auxiliaryExperts 声明"哪些专家需要同步通知"——这是编排层的事，不是代码引用。如果发现旧代码中有跨哨兵引用（如 from '../../../src/sentinel/adapters/xxx'），必须重构为本地 compute 函数。

二-A、核心理论基座与关键诊断规则（补充）

以下内容是第2章全景矩阵的必要补充。每个哨兵的诞生有其理论根基，某些规则（如"第一视角测试"、"品牌评估前置"）是诊断质量的保证，必须在技术方案中显式记录。

2A.1 增长动力学核心公式

增长 = 外部机会(External Opportunity) × 价值捕获(Value Capture) × 内生创造(Endogenous Creation) − 增长成本(Growth Cost)

其中每一项都是一个向量，由多个哨兵指标组成。
增长停滞发生在任何一个向量降至临界阈值以下。

对应关系:
  外部机会  → 环境层 E1-E6（PEST-CC框架驱动）
  价值捕获  → 界面层 I1-I13（生态位理论 + 战略7力 + 商业模式）
  内生创造  → 内部层 O1-O10（演化经济学 + 杨三角锚点）
  增长成本  → 资本层 F1-F5（公司金融理论）+ I11-I13（交易成本 + 边界决策）
  
校准器:
  技术层 T1-T9 和 匹配层 S1-S3 不直接进入增长公式，而是作为"调节器"：
  - T1-T9 评估"人+Agent混合组织的生产力基础"
  - S1-S3 评估"战略方向与组织能力的匹配度"
  
三飞轮聚合视图:
  价值创造飞轮 = E1-E6 + I1-I6 + T1-T9(AI生态部分)
  价值兑现飞轮 = F1-F5 + I7-I10(商业模式 + 单位经济)
  价值再生飞轮 = S1-S3 + O1-O10 + T5-T8(AI就绪部分)

2A.2 环境层的数据输入框架：PEST-CC

PEST-CC 框架（杨国安教授在传统PEST基础上加入两个C）：政治(P) + 经济(E) + 社会(S) + 技术(T) + 竞争态势(C1) + 客户需求变化(C2)。PEST原始框架来自Aguilar (1967)《Scanning the Business Environment》。这是环境层E1-E6的数据采集和分析框架——不是哨兵本身，而是"这6个维度各有什么信号"的输入框架。PEST-CC的分析结果映射为6个诊断哨兵（E1-E6）。每个哨兵附带一个techno-economic-phase校准参数（源自佩雷斯Perez, 2002），根据企业所处的AI革命阶段调整阈值。

2A.3 交易成本理论的AI时代修正（关键）

科斯 (Coase, 1937) 提出交易成本理论时背景是1930年代的工业经济——默认生产单位是人。在2026年AI时代，Agent正在成为新的生产单位，交易成本的计算逻辑必须修正： 三个局限:
  1. 生产单位从"人"变为"人+Agent"混合体——科斯框架没有预见到Agent可以作为独立生产单位。当Agent编码一次后可以无限复用（边际成本趋近于0），"自制vs外购"的决策逻辑根本改变。
  2. 信息处理成本成为独立的约束维度——科斯讨论的是治理成本（合同、监督、谈判），但没讨论信息处理成本。在AI时代，信息处理能力（Shannon信道容量）正成为比治理成本更重要的增长约束。本体系通过O6（组织信道容量）和O7（信息失真率）覆盖这一维度。
  3. 协调成本从人-人扩展到人-Agent和Agent-Agent——传统的层级协调（Arrow衰减p^n）不再适用。I13哨兵专门评估"人+Agent混合边界效率"，使用第一性原理推导的计算公式。 参见白皮书§7.8（I11哨兵）中"科斯框架AI时代修正"的完整论述。

2A.4 第一视角测试规则（已注入所有专家）

第一视角测试（First-Person Test）：任何专家在给出诊断建议之前，必须先回答"设计者有没有把自己放进最终用户的身体里？最脆弱的时刻能否通过信任测试？" 举例（客户A案例）： - 战略专家提出"到家月子照护"建议 → 必须回答"如果你是刚生完孩子的母亲，你会让宝宝晚上被带到酒店外另一个空间吗？" - 这条规则阻止了表面上"正确"但根本无法通过用户信任测试的建议。 - 已在 strategy/business_model/marketing 三个专家的RULES.md中注入，并附带哇呢案例作为教学案例。

2A.5 品牌评估前置规则（已注入）

在评估任何品牌哨兵（I4）之前，必须先判定"这个品类在消费者心智中是否存在？" 如果品类不存在（如手脚模纪念品）：品牌溢价和忠诚度计算的结果不应被解释为"品牌弱"，而应解释为"品类尚未建立，品牌评估不适用"。 判定标准：一个品类要进入消费者心智，需要整个产业链（上游+中游+下游）多年的共同推动，不是靠任何单一企业可以完成的。例如钻石（上游De Beers+中游零售商+下游婚庆产业链）、儿童摄影（上游摄影器材+中游影楼连锁+下游影像留存文化）。 已注入 strategy/business_model/marketing 的RULES.md。

2A.6 决策偏见审计（已退级）

行为经济学的偏见检测（Kahneman & Tversky, 1979 前景理论）——损失厌恶、沉没成本、确认偏误——这些是增长最隐形的杀手。但是偏见检测需要精心设计的对照实验，不适合自动化哨兵。已退级为专家定性判断维度（由org专家和strategy专家在诊断过程中以启发式方式评估），不设独立哨兵。如果未来有足够的纵向行为数据（决策记录+结果反馈），可以考虑重新设计为有监督学习哨兵。

2A.7 组织双环学习理论（O8的理论根源）

Argyris & Schön (1978) 双环学习： - 单环学习（Single-loop）：修表面——发现了问题，改了操作方法，但没问"为什么会产生这个问题" - 双环学习（Double-loop）：改根因——发现问题是治理变量（目标、政策、假设）本身有问题，修改的是底层逻辑 O8哨兵"组织修复能力"的诊断核心：不是看"修了多少次"，而是看"修的是表面还是根因"。compute-problem-action-cycle通过"同类问题复发率"来区分单环（高复发）和双环（低复发）。

 * KZ = -1.002×(CF/K) + 3.139×(Debt/TC) - 1.315×(Cash/K)
 * 来源: Lamont, Polk, Saa-Requejo (2001)
 */

  kzIndex: number;
  cfRatio: number;    // CF/K
  leverage: number;   // Debt/TC
  cashRatio: number;  // Cash/K
  degraded: boolean;
  warnings: string[];
}

function computeKzIndex(financials: Array<{
  operatingCashFlow: number; // Financial.operatingCashFlow
  netPpe: number;            // Financial.netPPE
  totalDebt: number;         // Financial.totalDebt
  equity: number;            // Financial.equity
  cash: number;              // Financial.cash
}>): KzIndexResult {
  // aggregate.ts负责从GraphStoreReader提取上述字段
  // 降级: totalPpe=0 → 用totalAssets近似
  // 降级: totalCapital=0 → leverage=0
  const ppe = totalPpe || (总资产近似) || 1;
  const cfRatio = totalCf / ppe;
  const leverage = totalCapital > 0 ? totalDebt / totalCapital : 0;
  const cashRatio = totalCash / ppe;
  const kz = -1.002*cfRatio + 3.139*leverage - 1.315*cashRatio;
  return { kzIndex: round(kz,3), ..., degraded: false };
}

  async check(store: GraphStoreReader, teamId: string): Promise {
    const now = new Date();
    const checkedAt = now.toISOString();
    try {
      // 1. 从本体层提取数据
      const nodes = store.queryNodes('NodeType', { teamId });
      
      // 2. 调用compute函数
      const result = computeXxx(nodes /* 或其他预处理数据 */);
      
      // 3. 根据阈值生成SentinelFinding
      if (result.value > THRESHOLD_CRITICAL) {
        return [{
          id: `sentinel-${now.getTime()}`,
          severity: 'critical',
          title: `信号标题`,
          description: '信号描述',
          evidence: [`证据1: ${result.value}`],
          suggestion: '行动建议',
          detectedAt: checkedAt
        }];
      } else if (result.value > THRESHOLD_WARNING) {
        return [{
          id: `sentinel-${now.getTime()}`,
          severity: 'warning',
          title: `信号标题`,
          description: '信号描述',
          evidence: [],
          suggestion: '行动建议',
          detectedAt: checkedAt
        }];
      }
      // 正常 → 不产生Finding
      return [];
    } catch (err: unknown) {
      log.error({ err }, '[{sentinel-name}] check 失败');
      return [{
        id: `sentinel-error-${now.getTime()}`,
        severity: 'warning',
        title: '{哨兵名称}检测异常',
        description: `${(err as Error)?.message || String(err)}`,
        evidence: [],
        suggestion: '检查数据源',
        detectedAt: checkedAt
      }];
    }
  }
};
