# 本体层因果体系权威规范 — 研究方案 v3.0

> 权威文档01 | 2026-07-14
> 合并原第1份（42边因果体系）和第2份（15概念节点池）
> 定位：Synova 组织数字孪生的唯一本体真理（Single Source of Ontological Truth）

---

## 零、为什么这是整个 Synova 大厦的地基

Palantir Foundry 验证了一个工业事实：本体层的边和节点必须一体化定义。拆成两份文档会产生跨文档循环依赖——边的 transfer_function 引用节点属性，节点的动态行为依赖边的传导。

但 Synova 的本体层不是 Palantir 的副本。Palantir 的本体层服务于"数据集成"——把企业内分散的数据源映射到一个统一的语义模型。Synova 的本体层服务于"因果推理"——回答"这家企业的增长卡在哪里？现在该做什么？"这是两个完全不同的命题。

Synova 的本体层只做三件事：
1. **定义实体**：企业里有什么？（节点池）
2. **定义因果单元**：A 的变化如何导致 B 的变化？（42条边）
3. **定义因果链**：A 的变化如何通过 B 传导到 C？（因果链——新增表达层）

它不做存储（那是数据层的事），不做计算细节（那是 compute 层的事），不做诊断流程（那是 Playbook 的事）。

## 零-A、核心思想：池-阀-流-溢出模型

Synova 本体层的第一性原理：**企业 = 一个将输入资源（资本、人力、信息）通过一系列转化活动变为对外部更有价值的输出，并从输出中捕获价值回注到输入的正反馈循环系统。这个循环的净溢出，就是利润。**

池（Pool）= 存储状态。阀（Valve）= 控制流量。流（Flow）= 池之间的流动。溢出（Overflow）= 输出价值 - 重新注入 = 利润。企业增长停滞的根本原因就是这个循环在某个阀位置断裂——输入不足、转化效率衰减、或系统摩擦力过大吞噬了本该溢出的利润。

此模型贯穿全部13份权威文档：池→15节点池（存储层），阀→42条因果边transfer_function（计算层），流→因果链（表达层），溢出→增长导航顶层Goal（权威文档13）。五循环（诊断/导航/GA/自检/知识）是这个模型的持续监测器。

## 一、设计哲学：四层分离

```
表达层  因果链（自然语言描述，用户可理解）
         ↑ 消费计算层结果，生成可解释的传导路径
编排层  Playbook + Skill（定义从A到B需要经过哪些边、按什么顺序计算）
         ↑ 按触发条件执行边序列，调用compute函数
计算层  42条因果边 + compute函数（每条边的精确数学计算，置信度输出）
         ↑ 读取存储层数据，执行transfer_function
存储层  15节点池 + GraphStore（实体状态、边参数、历史趋势）
         ↑ SOG-Core v1.0：17节点类型 + 16基础边类型
```

**每层只与相邻层通信。** 表达层不直接触碰存储层。42条因果边是计算语义——不存储在 GraphStore 中。GraphStore 只存 SOG-Core 的基础关系（INTERACTS_WITH、DEPENDS_ON 等16种边类型）。两层解耦，各自演进。

**变更频率从上往下递减**：因果链（高，随场景新增）→ Playbook（中，随诊断场景新增）→ 42边（低，核心稳定）→ 节点池（低，Schema稳定）。

## 二、第一性原理：五断裂点模型

不预设数量。"42条边"不是起点——是终点。我们从"一家企业如何运转"的最不可约简模型出发。

### 2.1 企业作为价值循环系统

任何企业，无论行业规模，其存在本质是一个闭环：

```
资本 + 人才 → (通过决策分配) → 转化为产品或服务 →
(通过渠道) → 交付给客户 → 客户付费 →
(通过利润回流) → 回到资本和人才 → 继续循环
```

这个闭环在五个位置可能断裂：

1. **获取**（Acquire）：资本和人才是否能进入循环？— 断裂表现为融资失败、招不到人
2. **配置**（Allocate）：进入循环的资源是否被正确分配？— 断裂表现为资源错配、决策集中
3. **转化**（Convert）：分配到活动的资源是否能高效产出？— 断裂表现为执行低效、协作断裂
4. **交付**（Deliver）：产出的价值是否能被客户接收并付费？— 断裂表现为定价错误、客户流失
5. **回流**（Recycle）：客户付费是否能重新进入循环？— 断裂表现为现金流断裂、利润被侵蚀

**每一个断裂点，就是企业在增长的什么位置被卡住。** 这是 Synova 诊断的底层逻辑。不是"六个环节"，是"五个断裂点"——"感知"是横切所有环节的能力，不是独立的断裂点；"再输入"是"回流"的具体表现。

### 2.2 为什么是演绎而不是归纳

五个断裂点的模型和六环节模型的核心差异在于**推理方向**：

六环节模型：穷举因果事件 → 归并 → 收敛出一个数目。这是归纳。风险：受限于穷举者的认知边界。

五断裂点模型：先定义循环在哪几个位置可能断裂 → 在每个位置穷举唯一可能的断裂方式。这是演绎。如果在"配置"环节断裂，它只能因为：资源没被分配、分配错了方向、分配被权力扭曲、或分配后无法协同。这不是"我们认为这些边重要"——是"在这个断裂点上，逻辑上只存在这几种断裂方式。"

## 三、实体池：表达层（10个）+ 存储层（15个）

表达层不是替代存储层——是用户可理解的语义面。

### 3.1 10个表达层实体

| 实体 | 定义 | 映射到存储层节点池 | 映射方式 |
|------|------|------------------|---------|
| 客户 | 为企业付费的外部实体 | 客户池 + 品牌池 | 组合映射 |
| 产品 | 企业提供给客户的价值载体 | 知识池 + 技术池 | 组合映射 |
| 团队 | 执行企业活动的人群 | 人才池 + 信任池 + 权力池 | 组合映射 |
| 现金流 | 企业资金的流入流出 | 资本池 + 数据池 | 组合映射 |
| 渠道 | 价值传递给客户的路径 | 新增外部池 | 新增 |
| 供应链 | 输入资源的来源网络 | 技术池 + 知识池 | 组合映射 |
| 技术 | 工具、系统和知识产权 | 技术池 | 直接映射 |
| 数据 | 信息和洞察资产 | 数据池 | 直接映射 |
| 决策 | 企业的关键选择 | 从治理活动池拆分 | 提取属性 |
| 事件 | 离散发生的重大变化 | 从信号池拆分 | 提取类型 |

### 3.2 存储层15节点池

保留不变。表达层实体的"组合映射"在查询时通过聚合公式计算——不预缓存，底层存储不受影响。

## 四、42条因果边：五个语义分组

42条边全部保留。transfer_function不变。compute映射不变。哨兵引用不变。新增：语义分组、因果链映射、硬度参数覆盖率。

| 分组 | 对应断裂点 | 逻辑 |
|------|----------|------|
| 获取边（E-05~E-09） | 获取 | 资本/人才/资源是否进入循环 |
| 配置边（E-10~E-23） | 配置 | 资源如何被分配和决策 |
| 转化边（E-24~E-34） | 转化 | 资源如何被加工为价值 |
| 回流边（E-35~E-39） | 回流 | 价值如何回到循环 |
| 传导边（E-40~E-42） | 跨断裂点 | 跨环节因果放大/缓冲/溢出 |

每条边完整定义：Edge ID/名称/所属分组/所属断裂点/causal_direction/transfer_function/参数语义（含来源节点属性路径）/消费的SOG-Core边/消费的节点属性/产出的哨兵信号/关联因果链/硬度+参数覆盖率+客户A验证+缺失数据。

## 五、硬度测试：参数覆盖率标准

| 硬度 | 定义 | 参数覆盖率 | 客户A验证 |
|------|------|-----------|------------|
| hard | 可写成compute函数 | ≥80% | 预测vs实际<15% |
| soft | 理论成立，部分参数需估计 | 50-80% | 偏差15-40% |
| heuristic | 经验规则 | <50% | 无法定量验证 |

**验收**：≥30条边hard，每条hard边覆盖率≥80%。
每条soft边标注"缺失什么数据、何时可重新评估"。

## 六、因果链：新增表达层

因果链是42条边的串联编排。YAML文件存储。新增=新增文件，零代码修改。提供三层能力：追溯（沿链下游遍历）、模拟（施加变化量逐节点计算）、反查（异常反向归因）。

## 七、前置研究：客户A零基验证

在研究启动前，先用客户A完整数据做彻底的因果发现。

输入：客户A诊断报告（品牌第一+利润下滑+第二曲线推演）、GraphStore全量数据（如存在）
产出：最小可行因果骨架
验收：骨架边数在35-50条→42条是合理工程估计；<30条→过度设计；>55条→不足
