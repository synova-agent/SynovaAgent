3.1 GA角色定位

GA（Growth Advisor，增长顾问）是连接AI诊断与商业现实的唯一桥梁。GA不是"操作工"——GA是"指挥官"和"训练者"。

维度GA的职责系统提供给GA的能力
质量守门人审核Agent的诊断结论，标记错误，补充背景诊断校准面板（§3.2）
信号侦察兵将线下拜访/电话中捕捉的关键信息注入系统手动信号注入（§3.3）
训练数据提供者每一次纠错和信号注入都转化为训练数据联邦进化引擎审核队列
客户关系管理者作为客户与系统之间的"翻译者"和"信任建立者"GA AI副驾（§3.4）

3.2 诊断校准面板

3.2.1 面板功能清单

操作定义数据流转
标记为错误GA选中Agent的一段诊断结论（如"成本上升的原因是原材料涨价"），标记为"错误"。弹出窗口：选择错误类型（"事实错误"/"归因错误"/"遗漏关键信息"/"过于笼统"）+ 填写正确信息或补充说明→ 形成一条带标注的训练样本 → 进入联邦进化引擎的规则审核队列 → GA的反馈即时效用计数器+1
补充背景信息GA在诊断结论旁添加"背景卡片"——如"这家客户的CEO刚刚换人，新任CEO有降本增效的背景"或"这家客户正在和竞争对手打价格战"→ 写入该客户的上下文存储（持久化，下次诊断自动加载） → 如果同类客户≥3，触发"此背景可能需要作为通用信号字段"的提案
重写诊断逻辑GA在面板中直接编辑诊断逻辑："利润下降不仅是因为成本上升——实际上他们的销售团队在过去3个月流失了40%"。GA的重写版本与Agent原版本并列存储→ 触发"联邦学习样本"——同时包含Agent版本和GA版本 → 审核通过后更新诊断逻辑权重
降级标记GA可以将某个哨兵的信号标记为"对此客户不相关"——如"制造业的流程优化哨兵对此纯服务业客户无意义"→ 写入该客户的企业画像配置 → 该哨兵对此客户的权重降低（不彻底禁用，保留意外发现的可能）

3.3 手动信号注入

GA在线下拜访、电话沟通或客户会议中捕获的信息，对系统来说是"黑域"——系统看不到这些信息。手动信号注入让GA将这些信息形式化为"信号"，立即进入哨兵和Agent的感知范围。

3.3.1 手动信号的五要素

要素类型示例
信号类型枚举（预置10种）"人员变动"/"战略转向"/"竞品动态"/"客户反馈"/"监管变化"/"供应商变化"/"市场传闻"/"技术突破"/"内部冲突"/"其他"
关联42边多选E-15（人力配置）/ E-38（人才留存）——如果信号是"该客户CTO离职"
关联节点多选（节点池中的实体）HUMAN_CAPITAL_POOL / 关键岗位节点的具体人员
严重度1-10GA主观判断——"CTO离职"严重度=8
置信度0-100%GA主观判断——"来自直接对话"=95%，"行业传闻"=40%

3.3.2 信号注入后的系统反应链

  1. GA注入手动信号 → 写入本体层（作为ManualSignal节点，data_source="GA_MANUAL"）
  2. 哨兵注册表检查——哪些哨兵消费该信号关联的42边 → 触发这些哨兵的重新评估
  3. 如果哨兵评估结果超过阈值 → 信号进入SignalAggregator → 排序器 → 可能触发主动触达
  4. GA收到即时反馈："此信号已触发对客户X的新一轮诊断，结果将于XX分钟内更新"

3.4 反馈的即时效用展示

GA需要感知到自己的贡献——不是冷冰冰的"已提交"，而是可量化的、持续积累的"效用"。

3.4.1 GA工作台首页的效用面板

GA效用仪表 — [GA姓名：张顾问]
效用指标当前值说明
诊断纠错贡献47次有效纠错 / 涉及12个哨兵"您已为8个制造企业、3个SaaS企业、1个零售企业修正过诊断逻辑"

3.4.2 效用反馈的设计原则

  • 即时性：GA操作后3秒内显示效用更新（不是"明天查看报告"）
  • 可量化：不说"您做得很好"——说"您的纠错使该哨兵对此行业的准确率提升了8%"
  • 可追溯：GA可以点击任意效用数字查看来源——"这47次纠错具体是哪些"
  • 非惩罚性：效用提示只显示正向贡献——不显示"您的纠错采纳率比其他人低"。不使用排行榜

3.5 GA的AI副驾

Agent不仅等待GA来校准——Agent也会主动为GA服务。GA从"操作工"升级为"指挥官"。

3.5.1 Agent主动为GA服务的场景

场景Agent的主动行为GA的响应
跨客户相似信号"张顾问，您服务的3家制造企业本周都触发了成本结构异常信号——这可能是一个行业性问题。要查看详情吗？"点击查看→进入3家客户对比视图→可能触发行业级通知给其他制造企业GA
GA即将拜访的客户预诊"张顾问，您明天将拜访'客户A'。这是该客户本周的关键信号摘要和过去3次拜访的未解决问题。"预诊报告→GA在拜访前准备问题清单→拜访后注入新发现信号
新类型信号的验证请求"张顾问，系统检测到一种新类型的信号模式（品牌溢价与客户留存异常关联）——您是否在客户现场观察到类似现象？"GA确认/否定→系统将此信号模式标记为"已验证"或"待观察"
高置信度诊断的GA确认"张顾问，以下哨兵对'客户A'的诊断置信度为95%——可以自动推送吗？还是需要您先确认？"GA一键确认→自动推送。或GA修改→校准后推送

3.5.2 GA副驾与主Agent的交互关系

GA副驾 = 主Agent的一个"角色实例"——它知道这是GA张顾问，知道她服务的客户列表，知道每个客户的历史诊断和GA校准记录。GA副驾在主Agent的推理上下文中拥有更高的"GA视角权重"——优先展示需要GA验证的信号，而非需要老板决策的信号。
