## 一、M1-a 运行时组合（已固化）

- **可用组合（唯一）**：`node v22.23.2` ＋ 按运行 node 重建原生件（**ABI 127**）。
- 固化位置：`scripts/control-tower/install-deps.sh` —— 安装时打印 `运行时组合(M1-a): node <ver> / ABI <abi>`；非 v22.x 发 `::warning`（**不改退出码**：CI 在 node24 下跑本器但不加载原生件，硬拦会误伤 CI）。
- 端口真值：`synova.json` server.port = **18790**（代码默认 3000；18802 不存在——v2 勘误）。

## 二、rebuilt 真计数（install-deps.sh 修复）

- 原实现：末行 `rebuilt ${ALLOW_N}`（变量冒充，包缺席/重建失败都不反映）＋ 管道 while 子 shell 丢计数。
- 修复：heredoc 重定向回主 shell 逐包累加 `REBUILT`/`ABSENT`，重建成功才 +1。
- **反例（判别力）**：白名单临时抽掉 `better-sqlite3` ⇒ 输出 `rebuilt 1`（原实现仍会打印 rebuilt 2）——见回执原始输出。

## 三、M1-c `_extinct/` 定案（依 CTO v2 裁定）

**归档件 ⇒ 不 exclude、不删。** 实测补强：`tsconfig exclude` 对被 import 拉入的文件不生效（`probe-exile-compile.ts:13` 已证伪 + 本卡复跑同结论：exclude 后错误数不变）；其 25 条错误经 `src/sentinel/types.ts` 的 12 条 `import type` 见证 + 两个合并壳（`competitive-moat/aggregate.ts:26-27`、`competitive-position/aggregate.ts:26-27`）运行时动态 import 进编译域。**真问题（断 import 路径、TS7006）归 M1b**（须动 `src/**`/归档件内容，本卡红线禁碰）。

## 四、M1-d 反例两态（禁用组合登记）

## 五、构建域收窄（M1-b，只动 tsconfig）

- `tsconfig.json` 去掉 `declaration: true` ⇒ 消 **TS4094 ×4**（`src/agent/cost-budget.ts` 匿名类私有属性 ×4，配 .d.ts 产物时触发；本仓无 .d.ts 消费者）。自包含应用不消费 .d.ts。
- 剩余 **29 错归 M1b**：`_extinct` 25（`TS2307` 断路径 ×20 + `TS7006` ×5，逐条清单见回执归因表）＋ `TS2345` ×4（`src/server.ts:165/387/597`、`src/connectors/ima.ts:143`——必须改 src/**）。
- 产物路径：`npm run build` = `tsc && build-backend.sh`（tsc 红 ⇒ build 红，诚实不吞）；`npm run build:bundle` 只出 `dist/backend.mjs`（npm start 的入口；tsc 欠账清偿前由它供产物）。`main`/`start` 同步指向 `dist/backend.mjs`（D518：`dist/src/*.js` 是 ESM 无扩展名 import，裸 node 必 `ERR_MODULE_NOT_FOUND`）。
