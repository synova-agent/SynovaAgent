## §1 模块锚

| 项 | 内容 |
|---|---|
| **模块名称** | 客户界面语言与导航（UI 重做） |
| **服务的真实客户／用户动作** | 企业老板（非工程师）打开 Synova 桌面端，要回答一个问题：「**我这家企业卡在哪、现在该做什么、做了以后对不对**」。他要看懂屏幕上的每一个词，并据此做出至少一个真实管理决定。 |
| **本模块完成后，用户能够做什么** | ① 在没有工程师在场的情况下，仅凭界面文字判断"这条结论可不可信、缺什么"；② 按「我的目标 → 卡在哪 → 该做什么 → 做到了什么」的顺序推进一件事；③ 在任何失败/空/半成品状态下，看到的是**原因与下一步**，而不是技术字段或"暂无数据"；④ 想要看协议细节时，能自己展开「技术详情」。 |
| **与首个客户闭环／部署的关系** | 直接服务宪章 §0.6 第一优先级：客户内网可运行 ＋ **至少一个真实管理决定进入系统**。决定能不能进入系统，取决于老板看不看得懂——看不懂就没有决定，闭环断在界面上。**本模块产出的《词典》同时是后续所有客户的语言契约**，不只服务首个客户。 |
| **必须遵守的长期产品边界** | ① **壳是我们的**：导航、信息架构、客户语言、主题令牌、三态/失败态表达属 Synova，不可让渡给 DSH（宪章 §6.3）；② DSH 内容只能**占插槽不 fork**，且须满足四条判据（可独立升级/可摘除/不侵入宿主/失败可降级）；③ **UI 只呈现不判断**（宪章 §4.4/§4.5）：界面不得代替引擎下结论，也不得把引擎的"空"渲染成"结论"；④ 宪章 §1.3：事实/推断/未知必须分开，**关联不得写成根因**；⑤ 宪章 §8.2：不宣称"越用越准"、每条结论带来源；⑥ 未选客户零请求，不展示跨客户聚合数。 |
| **本模块明确不做** | ① 不改引擎（`src/**` 任何判据、计算、口径）；② 不改 DSH 内核或其 UI 包；③ 不碰真实客户数据与生产库；④ 不重建通用 Agent 运行时；⑤ 不把 UI 重做当作"能用"的替代——**现场阻断缺陷属另一条线**，本模块只在《词典》里给出它们的**目标判据**，不抢改；⑥ 不做客户端性能优化、打包、升级器；⑦ 不做前端定制化（宪章 §0.7 列为延后）。 |
| **验收入口与可观察结果** | 主入口：`electron-renderer` 真机启动后，用真实账号/DevMode 走「我的目标 → 卡在哪 → 该做什么」一条完整路径。可观察结果：屏幕上**不出现**《词典》§1 的任何禁用词（技术详情展开后除外）；每个面板在"未加载/数据不足/已出结论"三态下文案互不相同且都给出原因；一轮含失败的分析，结论语不写"已完成"。**机器判据见 §7。** |
| **尚未确认的产品问题** | ① 「技术详情」是否对客户开放（还是只给顾问）——影响 §1 禁用词的豁免面；② 目标树的数据来源与形状（目标节点已在图里，但界面拿到的接口未核）；③ 谓词表/指标名表的完整性由谁维护；④ 客户语言的最终措辞由谁签。见 §8。 |

## §3 目标行为

### 3.1 主路径：入口 → 操作 → 结果

| 步 | 入口 | 客户操作 | 应看到的结果 |
|---|---|---|---|
| 1 | 启动 → 左栏「**我的目标**」 | 点开 | 目标树（我定的目标与进展）；若尚无目标 ⇒ 「还没有设定目标」+「设定第一个目标」按钮（D2 类：**说原因给动作**） |
| 2 | 「**卡在哪**」（默认首屏） | 进入 | 卡点结论一句话 + 三块：**依据（可回来源）** / **缺口（缺什么数据）** / **替代解释**（宪章 §1.3）。每条依据可点开来源，来源是**人话**（「交付批次表 第 3 行」），不是 `delivery_batches.csv#L3` |
| 3 | 「**该做什么**」 | 看建议 → 选一条 → 拍板 | 建议卡（做什么/为什么/预期效果/风险）；点「采纳」写入决策台账并显示「已记录：你决定…（当时依据已留存）」。**系统不自动执行**（宪章 §8.2/§4.2 边界 4） |
| 4 | 「**做到了什么**」 | 查看执行与结果 | 决策台账（可回放当时依据，**新决定不覆盖旧决定**）＋执行状态＋「系统当初判断 vs 实际结果」对照 |
| 5 | 任意页 | 想看协议细节 | 展开「**技术详情**」：原始 id、事件、工具全名、HTTP 码都在这里，默认收起 |
| 6 | 任意页 | 想收起/展开左右栏 | **可见按钮**（不是记快捷键）＋收起后仍能一键恢复 |

### 3.2 三态与失败（《词典》§4/§5 为判据，此处只列可观察要求）

| 情形 | 必须看到 | 禁止看到 |
|---|---|---|
| 未加载 | 「正在读取本期指标…」 | 「暂无数据」 |
| 未接入数据 | 「还没有接入企业数据」+「接入数据」 | 「请先进行一次诊断」（把未接入说成没做过） |
| 取不到（请求失败/降级） | 「暂时读不到数据」+「重试」+ 影响面 | 与"没做过"同文案；静默 console.warn |
| 部分失败 | 「已完成，但有 N 处未能核对」 | 「已完成」「运行完成」 |
| 工具全失败 | 状态语含失败汇总 | 「运行完成」与「失败」并列同屏 |
| 空结果（确实跑过、真无内容） | 「本次没有得出结论」+ 建议（补数据/换问法） | 用占位散文把四要素填满 |

### 3.3 不允许出现的假象（交付时逐条核）

1. 无来源的数字（趋势、环比、百分比、次数）。
2. 用计数或模板生成的"明细"。
3. 失败被写成成功、或成功文案不依赖失败事实。
4. 空态被画成结论卡。
5. 声明"分析完成"而 degraded 提示埋在消息流里。
6. 可见控件点了没反应。
7. 客户面出现《词典》§1 禁用词（技术详情除外）。

## §5 关键契约

### 5.1 客户语言契约（本模块的主契约）

- **唯一真源**：`docs/synova/ui-redo/客户语言词典-v1.0.md`。代码里的客户可见字符串必须能由《词典》**判定**（命中映射表 §2，或不含 §1 禁用词）。
- **判定形态**：`isCustomerSafe(text) → {ok: true} | {ok: false, violations: [{rule, match, index}]}`（纯函数，无 IO）。输入＝最终渲染前的字符串；输出＝违规清单。
- **降级**：《词典》缺失或解析出 0 条规则 ⇒ **视为不可判**（测试 exit≠0），**不得**当作通过（判据纪律 ⑨②）。
- **扩展规则**：新增谓词/指标/枚举行**只许追加**；改既有客户说法必须先升《词典》版本（§9）。

### 5.2 三态契约

每个数据面板必须能以三态中最少三值表达状态，且**四类"数据不足"原因互不混用**：
`idle | loading | empty-ish(no_data_source | never_run | no_data_in_period | fetch_failed) | ready`。
- 渲染层不得把 `fetch_failed` 渲染成 `never_run`（现状 D2 违例）。
- 降级（`degraded`）是**独立维度**，可与上述任一态同时存在，且必须可见。

### 5.3 DSH 插槽契约（宪章 §6.3）

- 壳（导航/IA/文案/主题/三态）由 Synova 拥有，DSH 内容层**不得**注入全局样式或改写壳的 class 作用域。
- DSH 内容失败 ⇒ 壳显示「内容不可用」+ 影响面；**不得白屏、不得假成功**。
- 摘除 DSH 内容层后，壳必须仍可导航并显示空态原因。

### 5.4 客户可见字符串的扫描契约（T1 的判定面）

- **被扫**：`electron-renderer/src/**/*.{ts,tsx}` 中**字符串字面量**与 **JSX 文本节点**。扫描根由 `process.env.UI_REDO_SCAN_ROOT ?? 'electron-renderer/src'` 给出（**这个覆盖点是契约的一部分**，T1-D 靠它证明"提取器失效必红"）。
- **不扫**：`className` / `data-*` / `data-testid` / `style` 值、import 路径、`console.*` 参数、注释与 JSDoc。`aria-label` **属于**客户可见（单独统计，不进 allowlist 的销账口径）。
- **构件**（落位见 §4.1）：
  - `tests/user-visible/customer-language.test.ts`
  - `tests/user-visible/customer-language.allowlist.json` —— 每条＝`{path, rule, text, why, lineHint}`。
    🔴 **键 = `(path, rule, normalizeText(text))`，不是 `path:line`**：`lineHint` 只作展示。理由：T2–T6 与并行阻断批按定义要改 `electron-renderer/src/**`，任一行插入都会让"以行号为键"的清单集体失配，把真实回归与行号漂移混为一谈（规模数百条时噪声会盖过信号）。
  - 🔴 **`normalizeText` 的定义（键的确定性依赖它，不得由实施者自选）**：
    ```
    normalizeText(raw) = raw.normalize('NFKC')     // 全角/半角、兼容字符统一
                            .replace(/\s+/g, ' ')  // 任意空白（含换行/制表/全角空格已由 NFKC 归半角）折叠为单空格
                            .trim()
    ```
    该函数**同时**作用于「从源码提取到的候选文本」与「allowlist 里的 `text`」，两侧必须用同一个实现（放在 `tests/user-visible/support/extract-visible-strings.ts` 并导出）。**改这个函数＝改键**，须升 DEV DOC 版本并在回执说明。
- **四条硬断言**：
  1. **零清单外违规**：清单外出现任何违规 ⇒ 红。
  2. **清单不许腐化**：清单里的 `(path, rule, text)` 若在源码中**不再出现** ⇒ 红（修好了必须删条目，不许留旧账假装还在）。
  3. **覆盖面不许缩水**：被扫文件数必须 **== 基线实测 43**（`git ls-tree -r --name-only <基线> -- electron-renderer/src | grep -c '\.tsx\?$'`）；且**每个被扫文件的候选字符串数 > 0** ⇒ 否则红。这条挡的是"少扫几个文件也能过"。
  4. **总量不许塌**：候选字符串总数必须等于 T1 实施时实测并写死的基线数（实施者须在回执里给出产出该数的命令与原始输出）。**不得用"一个凭感觉的阈值"** 代替实测基线数；基线数一旦写死，后续批次只能因**有序删除**而更新，不得随手调小。
