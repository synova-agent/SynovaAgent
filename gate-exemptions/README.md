# gate-exemptions/ — 门禁本体豁免（人工裁定留痕）

> 本目录是**受保护路径变更**的唯一豁免通道。检查器 `scripts/control-tower/check-gate-protection.sh`
> （三态退出码 `0/1/2`）按本文件定义的格式解析；**S2 的平台保护**（`.gitea/protected-files.txt` 粘贴进
> Gitea `protected_file_patterns`，由创始人执行）**不读本目录**。
> 🔴 自 #623（CTO 裁 217）起：**本目录（`gate-exemptions/**`）与清单自身（`.gitea/protected-files.txt`）均受保护**
> ⇒ 改本 README、加/改豁免文件**本身**，也各自需要一行合规豁免（见 §5「自我保护与自覆盖」）。

## 1 文件怎么放

- 位置：仓库根 `gate-exemptions/`；扩展名 `*.md`；文件名任意（建议 `YYYY-MM-DD-<主题>.md`）。
- 一个文件装**一次裁定**；多条路径 = **多行**，逐条判定，不"整文件生效"。
- 🔴 **新增**文件的**首行**必须是复核件指针（`# review: <PR#>` 或 `# review: docs/synova/reviews/*.json`），
  见 §6；存量文件冻结为 legacy，不要求复核件。
- 🔴 README.md 被检查器显式排除，**不作为豁免载体** ⇒ 本文中出现的示例行**一律不生效**。
  要真豁免，请新建另一份 `*.md`（且注意：README 自身也受保护，改它需要别的豁免文件覆盖）。

## 2 每一行的格式（逐字节）

```
- <路径或 glob> — <理由> — <裁定号>
```

| 段 | 要求 | 不满足的后果 |
|---|---|---|
| 路径 / glob | 相对仓库根；与清单同语义（gitea gobwas glob，**大小写不敏感**，`**` 跨目录）；**不能为空** | 该行**不生效**，且**该行本身计 failure** |
| 理由 | `strip()` 后 **≥10 个 Unicode 字符**（中文一字=1；空白视为空） | 同上 |
| 裁定号 | 必须**整体匹配** `^(裁\s*[0-9]+|#[0-9]+)$`：`裁 217`（可含空格）或 `#623` | 同上 |

- 三段之间用**破折号**分隔：规范形态 `—`（U+2014）；检查器同时接受 `–`（U+2013），两侧空白可省；
  用连字符 `-` 作分隔不解析（按『缺三段式』不生效）。
- 「不生效」的完整含义（#623 加严）：静默不算豁免，**不是**报错放行 —— 等于没有豁免，门禁照红；
  并且**该不合规行本身计 failure**（`E_EXEMPT_INVALID`），**即使同一 diff 内另一条合规行已覆盖该路径**，
  也不能把坏行洗掉（证据不完整 ⇒ exit 1）。
- 失败原因逐条点名：缺三段式／路径为空／缺理由／理由不足 10 字／裁定号不合规。
- 覆盖判据：本次 diff 里**每一条**命中受保护路径的文件，都必须**至少有一条合规行**覆盖它（**不递归、不部分豁免**）。
- 同一路径多行声明时，**取任一合规行**即可；但其余不合规行仍各自计 failure。

## 3 谁能提交豁免（#623 起：不再校验作者）

- **不再要求创始人作者**：检查器已删除提交作者校验，清单中的作者名单段已删除。
  任何作者提交的豁免（含小队身份 `k12@local`），只要**三段合规**即生效。
- **豁免 = 可审的证据链**（路径＋理由＋裁定号），**不是授权**；授权仍归 **CTO 裁定号**（台账）。
- 为什么删：主仓提交作者实测为小队身份，与创始人共用 git 身份；作者校验既拦不住蓄意冒充
  （`git config user.email` 可改），又常误伤正当豁免。删掉它不降低实际防护，但也**不再提供签名这一层**。

## 4 生效链路（一处改动，三处可见）

1. 创作者在**同一 PR**内提交 `gate-exemptions/<主题>.md`（含路径＋理由（≥10 字）＋裁定号）；
2. 检查器在 PR 上核：diff 命中受保护路径 → 找**有效**覆盖行 → 逐行三段校验（坏行本身也判红）；
3. 全过 ⇒ ①d 绿；任一缺 ⇒ ①d 红，PR 被 required status check（`local-gates / gates (pull_request)`）挡住。

## 5 自我保护与自覆盖（#623，替换旧「目录不加保护」口径）

- PATTERNS 段**首行** = `.gitea/protected-files.txt`；**末行** = `gate-exemptions/**`。
- 于是：**改清单** ⇒ 需要一行覆盖清单；**改/加豁免文件** ⇒ 该文件自身在 diff 内，需要一行覆盖它自己
  （下称**自覆盖行**）。
- 原「死锁」（加豁免本身又要一份豁免）的解法 = **同一 diff 内加自覆盖行**，**不是**把目录排除在保护外。
  🔴 旧口径「`gate-exemptions/**` 不进清单是有意设计、否则死锁」**已作废**（#623 起改为同 diff 自覆盖）。
- 例外：`README.md` 仍被检查器排除、不作为豁免载体；但 README 自身在 `gate-exemptions/**` 保护面内，
  **改它需另建豁免文件的合规行覆盖**。

## 6 新增豁免的复核件（#1100 W3 收窄版）

> 判据范围**只有新增件**：存量件（base 上已存在）冻结为 legacy，**不迁移、不加 expiry**。

- **新增**豁免文件（`git cat-file -e <merge-base>:<path>` 不存在）⇒ **首行**必须是下列之一：

  ```
  # review: <PR#>
  # review: docs/synova/reviews/<文件名>.json
  ```

  例：`# review: #1234` ／ `# review: docs/synova/reviews/1234.abcdef123456.json`。
- 缺失 ⇒ ①d **exit 1** 并**点名该文件**（`code` 复用 `E_EXEMPT_INVALID`，`phase=review`；
  C1 错误码集不扩）。三段式检查照旧**独立**判（两件事互不替代）。
- **legacy 判据 = base 存在性**（`git cat-file -e`），**不是**日期、不是内容：
  **在本 diff 内改一版旧文件也不要求复核件**（收窄版有意如此 —— 存量 86 份不被误伤；
  代价见 §8 已知限制 8）。
- 回滚点：`--require-review=0` 关闭本检查（默认 `1`）。关闭态逐件打印「未核复核件」，
  **禁读成已通过**；非法值（非 `0|1`）⇒ exit 2（判不了 ≠ 通过）。
- 本检查**只核首行形态**：不核 PR# 是否存在、不核指向的 JSON 是否已落盘 ⇒ 它是**证据指针**，
  不是审批签名（真授权仍是裁定号台账 ＋ 平台字段）。

## 7 示例（**本文件被排除 ⇒ 下面各行都不生效**，仅示形）

正确形态：

```
- scripts/control-tower/check-gate-protection.sh — 批次内同步改检查器与豁免校验 — 裁 217
- tests/control-tower/** — 同批配对测试与自证预期更新 — #623
```

反例分两类：

- **前三行（三段不合规）⇒ 该行不生效，且该行本身计 failure**：

```
- scripts/control-tower/** — 不足十字的理由示例 — #623          ← 理由只有 9 字（要求 ≥10）
- scripts/control-tower/** — 批次内同步改门禁脚本与豁免校验 — abc   ← 裁定号不合规（须 裁 NNN 或 #NNN）
- scripts/control-tower/** — 只有两段（缺裁定号）
```

- **末行（行首不是「- 」）⇒ 整行被跳过、不解析（不产生 failure）**：

```
– scripts/control-tower/** — 行首不是「- 」（en dash 当列表符）⇒ 整行被跳过、不解析
```

## 8 已知限制（做不到什么 —— 禁读成"已防护"）

1. **不核平台侧**：本目录与检查器只核仓内清单与仓内豁免；Gitea 平台规则是否被改/删，**核不到**
   （活腿 token 读 `branch_protections` = 403 实测）。真正的授权边界在 S2 的平台字段。
2. **作者签名语义消失（#623）**：不核作者 ⇒ 豁免**不证明"谁批准"**，只证明「有路径/理由/裁定号的证据链」；
   真正授权仍在平台字段与 CTO 裁定号台账。
3. **不递归、不批量**：一条豁免只覆盖它写出的路径/glob；新增一条受保护路径 ⇒ 需**新的**合规行。
4. **不能事后补**：豁免必须出现在**同一次** diff 里；PR 合完再补不算（历史合入不看后加的豁免）。
5. **README 排除**：`README.md` 不作豁免载体（无论里面写什么示例行都不生效）。
6. **历史引述不回改**：`docs/plans/**`、旧 `memory/notes/**`、旧 `.claude/task-briefs/**` 中的
   「创始人作者」等引述保持原样（历史引述性质）⇒ **全仓** grep 作者名单不为 0 是预期。
7. **理由字数按 Unicode 字符数**（代码 `len()`），中文一字=1；不按字节、不按词。
8. **复核件只对新增件生效（#1100 收窄版）**：base 上已有的豁免文件即使被改也不要求复核件
   ⇒ 蓄意者可「先合入空壳豁免件（无复核件），下一 PR 再填内容」绕过本检查。与限制 2 同性质：
   本检查是**证据链完整性的报警器**，真防线仍是独立复核与 K3 审计。
   **不核 PR# 存在性/指针文件存在性**（复核件通常晚于豁免件产生）。
