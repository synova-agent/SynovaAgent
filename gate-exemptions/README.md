# gate-exemptions/ — 门禁本体豁免（人工裁定留痕）

> 本目录是**受保护路径变更**的唯一豁免通道。检查器 `scripts/control-tower/check-gate-protection.sh`
> （三态退出码 `0/1/2`）按本文件定义的格式解析；**S2 的平台保护**（`.gitea/protected-files.txt` 粘贴进
> Gitea `protected_file_patterns`，由创始人执行）**不读本目录**。
> 🔴 本目录不在受保护路径清单内（`gate-exemptions/**` 不进 `.gitea/protected-files.txt`）—— 否则"加豁免"本身又要一份豁免，形成死锁（规格 §附录）。

## 1 文件怎么放

- 位置：仓库根 `gate-exemptions/`；扩展名 `*.md`；文件名任意（建议 `YYYY-MM-DD-<主题>.md`）。
- 一个文件装**一次裁定**；多条路径 = **多行**，逐条判定，不"整文件生效"。
- 🔴 README.md 被检查器显式排除，不参与豁免解析 ⇒ 本文中出现的示例行**一律不生效**。
  要真豁免，请新建另一份 `*.md`。

## 2 每一行的格式（逐字节）

```
- <路径或 glob> — <理由> — <裁定号>
```

| 段 | 要求 | 不满足的后果 |
|---|---|---|
| 路径 / glob | 相对仓库根；与清单同语义（gitea gobwas glob，**大小写不敏感**，`**` 跨目录） | 匹配不到受保护路径 ⇒ 该行**不覆盖任何变更** |
| 理由 | **非空**（空白视为空） | **无理由不生效** |
| 裁定号 | **非空**（推荐 CTO 裁定编号；例 `210`／`CTO-2026-10-18-裁001`；口头裁决无法机器判别，无号的形态会被判红）；口头/内部裁决**不算**裁定号 | **无裁定号不生效** |

- 三段之间用**破折号**分隔：规范形态 `—`（U+2014）；检查器同时接受 `–`（U+2013），两侧空白可省；用连字符 `-` 作分隔不解析（按『缺三段式』不生效）。
- 覆盖判据：本次 diff 里**每一条**命中受保护路径的文件，都必须**至少有一条合规行**覆盖它；
  缺一条 ⇒ 检查器判红并逐条点名（**不递归、不部分豁免**）。
- 同一路径多行声明时，**取任一合规行**即可（规格 C2）。
- 「不生效」= 静默不算豁免，**不是**报错放行 ⇒ 等于没有豁免，门禁照红。

- 为什么：主仓提交作者实测为小队身份 `k12-batch5 <k12@local>`，与创始人身份（`synova <huangxuesongvip@163.com>`）
  **可判别** ⇒ 作者校验具备区分力（规格 F8）。这条**不是**形式主义：它挡的正是"agent 给自己开豁免"。

  小队**可以**起草文本，但**不得**代为 `git commit`。

## 4 生效链路（一处改动，三处可见）

1. 创作者在**网页**提交 `gate-exemptions/<主题>.md`（含理由 + 裁定号）；
2. 检查器在 PR 上核：diff 命中受保护路径 → 找覆盖行 → 核理由/裁定号 → 核作者 ∈ APPROVERS；
3. 全过 ⇒ ①d 绿；任一缺 ⇒ ①d 红，PR 被 required status check（`local-gates / gates (pull_request)`）挡住。

```

```

反例（都不会生效，用于自查）：

```
- scripts/control-tower/** —
- scripts/control-tower/** — 有理由但没裁定号（只有两段 ⇒ 按「缺三段式」不生效）
– scripts/control-tower/** — 行首不是「- 」（en dash 当列表符）⇒ 整行被跳过、不解析
```

## 6 已知限制（做不到什么 —— 禁读成"已防护"）

1. **不核平台侧**：本目录与检查器只核仓内清单与仓内豁免；Gitea 平台规则是否被改/删，**核不到**
   （活腿 token 读 `branch_protections` = 403 实测）。真正的授权边界在 S2 的平台字段。
2. **同机同身份下作者校验可被绕过**：若操作者直接改 `git config user.email` 伪装成创始人身份提交，
   作者校验失效；拦得住的是"顺手冒充"，拦不住"蓄意冒充"。
3. **不递归、不批量**：一条豁免只覆盖它写出的路径/glob；新增一条受保护路径 ⇒ 需**新的**合规行。
4. **不能事后补**：豁免必须出现在**同一次** diff 里；PR 合完再补不算（历史合入不看后加的豁免）。
5. **本条目录不加保护是有意设计**：把 `gate-exemptions/**` 纳入清单会形成"豁免需要豁免"的死锁。
