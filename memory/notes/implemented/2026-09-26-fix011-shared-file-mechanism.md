# 决策 Note — 共享治理文件的多卡归属机制（FIX-011 / D979）

**状态**：proposed（待执行）
**日期**：2026-09-26
**问题**：`D328 提交声明与暂存文件归属不一致 — 疑似并行劫持` 在 24h 内拦下 CTO 3 次，全部因**共享文件有历史归属**（`ci.yml`→D954、`task-state/D954.json`→D954、`派单模板.md`→D931/D943）。后果：FIX-003 后半被迫移出、R1–R4 两轮无法落 main。
**决策（待执行）**：二选一或组合 —— ⒜ **一对象一文件**（如 `号段水位.md`→`号段/水位.yaml`）⒝ **显式多卡共享声明**（文件头/卡内 `共享声明: D931,D943`）。**同时保留真劫持拦截**（非授权卡改共享文件仍拒）。
**理由**：治理件天然被反复修改，"文件有历史归属"⇒"任何新卡不能改"是**结构性死结**，不是偶发误判。
**边界**：**不得**以放宽门禁换通过；门禁语义变更 ⇒ 必过 K3；同类第 2 次 ⇒ 完成后升级创始人。
**过渡机制（CTO 2026-09-26 裁定二）**：⒝ 显式共享声明批为**过渡机制**，非终态 —— **阶段 3 由行级 blame 取代**（届时声明行/解析器/放行分支一并退役；本次仅三处标注，不改语义）。
