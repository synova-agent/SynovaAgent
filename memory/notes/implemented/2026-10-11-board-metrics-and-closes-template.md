# Note: 进度口径门禁 + `Closes #N` 模板（CTO 裁定 011）

- **日期**：2026-10-11 ｜ **裁定人**：CTO ｜ **执行**：CTO 专项会话（事实采集与实现）
- **背景**：`check-board-truth.ts` 宽口径曾抓 29 张「已合并 PR 引用仍 open」，大半为建卡/卡面/修判据类引用；
  且 K12 完成率虚高（关闭 8 含 1 张撤销 #197 ⇒ 虚报 38%，真实 35%）。

## 决策

1. **进度口径（逐字）**：
   完成 = 判据 exit 0（可复跑）｜部分 = 部分判据达成（卡保持 open，正文记差额）｜撤销 = retired ⇒ 不计入完成率
2. **PR 正文必含（交付类）**：必须在正文写 `Closes #N`（或 Fixes/Resolves）——这是回填的上游信号。
   理由：门禁只能查「有引用却没关」，查不到「没引用」（没有信号 ⇒ 看不见）。

## 落点

- `scripts/control-tower/check-board-metrics.ts`：真实完成率 = 完成卡/(总数−retired)；
  「误标 closed」报警（closed 无任何已合并 PR 交付性引用且非 retired ⇒ exit 1）。
  改坏即红实测：#205 误关 ⇒ K12 7/20(35%)→8/20(40%) + 进报警名单 + exit 1；已恢复。
- 开工令模板（§6 八节→九节）＋ 卡面 Done 标准区提示行，`.dsh/skills/…` 与 `.synova/skills/…` 镜像同步。
- 13 个模块里程碑描述已写入口径三行。

## 边界

- 不关任何卡；不改任何卡的既有判据；撤销卡以 `执行态/retired（撤销）` 标签显式声明（#197 已打标）。
