# 2026-10-20 · 判据纪律 ⑨（任何检查必须能回答三问）

## 为什么立
**一天之内，同一个病换了四种形态**：

| # | 形态 | 实际损失 |
|---|---|---|
| ① | 镜像落后 **106 commit** 无人管（`dual-repo-sync` 只报不推、只写 log） | GitHub 上跑的是 10-19 的旧代码，一份"11绿"的旧体检单被当成现状 |
| ② | `Gate Integrity` 把自己的红算成"未登记 CI 失败" ⇒ 判自己违规 ⇒ **红一次永红** | GitHub 上红了很久，因为镜像断着无人看见 |
| ③ | 注入夹具继承外层 CI 环境 ＋ 探针文件泄漏 | **本地绿、CI 红**，我复现不出，来回两批 |
| ④ | 夹具缺 `tsx`（克隆无 node_modules，job 不装依赖） | 组 13 恒 exit 2，但只在 CI 出现 |

**四个单点都修了，但机制没有** ⇒ 换个夹具、换个检查器，同族问题必然重演。

## 共性
**验证的结论无法被独立复核**：
- ① 报了没人看 → 看不见
- ② 不知道自己检查谁 → 对象错
- ③ 不知道自己在什么环境 → 复现不了
- ④ 不知道自己要什么依赖 → 前提隐式

## 立了什么（根件 §8.1）
```
判据纪律 ⑨ · 任何检查（门禁/夹具/探针）必须能回答三问：
  ① 对象：检查谁？          禁自指 ｜ 禁"恰好出现的状态"
  ② 环境：在什么环境下跑？  依赖显式 ｜ 环境隔离
  ③ 证据：结论谁复核？      失败可见 ｜ 可复现
缺任一 ⇒ 该检查的结论不得计入「通过」（可跑、可绿，但不算数）
```
