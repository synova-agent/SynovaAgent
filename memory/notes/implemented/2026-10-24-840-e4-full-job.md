# 2026-10-24 · #840 E-4：全量测试 job ＋ 收窄排除 ＋ tests 类型检查

## 现状（实测，锚 12466d63d）

- `.gitea` 的测试是 `vitest --changed`（③ 步）⇒ **新 acceptance 件可能不被执行**（未被依赖图命中）。
- `vitest.config.ts` 的 CI 分支排除 6 条，其中 3 条**非环境依赖**（acceptance/zero-code-industry、routes/ga-evolution、l4/ontology-loader）。
- `tsconfig.json` 的 `exclude` 含 `tests` ⇒ **tests 无类型检查**。

## 决定

1. 新增 **full-tests job**（`needs: gates` 串行、独立 15 分钟预算）：①h 全量 `vitest run`（不按 --changed）＋ ①h-types tests 类型检查。**不计入 pre-commit 组号**（12 组不变）。
2. 排除面收窄到**只许环境依赖**：留 `circular-dependency`（Node 运行时）／`e2e/**`（LLM API）／`data-pipeline.*.integration`（Feishu）；移出 3 条非环境项（其中 acceptance 件按设计语义修正后转绿）。
3. tests 类型检查：新增 `tsconfig.tests.json`（extends 主配置，补 DOM lib/jsx）＋ `tests/tsconfig.known-errors.txt`（**首日按实测 355 条生成**，禁手抄）；CI 步做 `comm -13` 只减不增（新增即红；减少只提示重测下调基线）。

## 验收件语义修正（例外，PR 正文登记）

`tests/acceptance/zero-code-industry.test.ts` 原断言「行业 `node-types` 被 ontology 加载」，与产品设计不符：
`src/l4/ontology-loader.ts:88-115` 明确只读 `extensions/ontology/{resource,activity,outcome}` 与行业 `edge-types/`，
**不读**行业 `node-types/`（源码注释：「行业模板使用新实体 ID 空间，不读旧 node-types/ 目录」）。
故改为：主断言 = 行业 **edge-types** 加载 ＋ `getTypesByTags(['food_service'])` 命中；node-types 用例保留为**反向断言**「按设计不加载」。

## 已知限制

- full-tests job 在**所有触发**（push 任意分支/PR/dispatch）都跑：Gitea host 模式 job 级 `if:` 表达式不可靠（既有教训），保守选"全触发"。代价 = 非 local-main 分支 push 也跑一次全量。
- `tsconfig.tests.json` 补了 DOM lib（tests 会 import electron-renderer 组件）；这不是"放宽类型"，而是让测试程序与它引用的渲染层代码同环境。
- 基线 355 条是**测得值**，包含 packages/ 与 scripts/ 经 import 拉入的错误；只减不增由 CI 步强制。
