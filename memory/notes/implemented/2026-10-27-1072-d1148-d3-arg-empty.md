# 2026-10-27 · 裁 427-D3 落地（#1072 · 空参 fail-closed ＋ 调用点守卫）

## 现状（改前，钉 `gitea/local-main` 0fda487e2 / 起点 = T1 head `8bd33a5ff`）

1. **空参静默判错对象**：`scripts/workflow/check-brief-parseable.sh:41-44` 只判 `[ -z "$BRIEF" ]`
   ⇒ 「未传参」与「显式传空参」同一条回退（`resolve-commit-brief.sh ""`）。实测本树三条命令**输出完全一致**：
   ```
   $ bash scripts/workflow/check-brief-parseable.sh ""   → ⚠️  brief 不存在 — 跳过 (fail-open)   rc=0
   $ bash scripts/workflow/check-brief-parseable.sh      → ⚠️  brief 不存在 — 跳过 (fail-open)   rc=0
   $ bash scripts/workflow/check-brief-parseable.sh "$PWD/no-such-brief.md" → 同上                   rc=0
   ```
   即**调用方传空参根本不可判**；有回退目标时它会静默改判「别人那份 brief」（受控复现见 C11-B）。
2. **调用点恒传空参**：`scripts/pre-commit-check.sh:1878` 原样 `"${BRIEF_RESOLVED:-}"`；而
   `:1004 BRIEF_RESOLVED="$BRIEF"` 直接搬 resolver 结果，**:982 的 resolver 无认领即空**
   ⇒ 空值不是调用方 bug，是常态（规格 §3-E9）。
3. **测试件既有缺口**：`tests/control-tower/brief-parseable.test.sh` 7 组用例全绿基线实为
   **11 通过 / 1 失败（rc=1）** —— 用例 7「legacy brief 必须报 #CRITERIA 缺失」的**前提已被
   授权清理推翻**（见「规格外必要修正」）。

## 决定

- **脚本**（`check-brief-parseable.sh`）：
  ① 头部补 DSH 契约注释（`@input/@output/@exit/@degraded`）＋设计哲学一句＋已知限制 2 条；
  ② 新增「显式传空参」分支（`$# ≥ 1 ∧ $1 为空`）⇒ `rc=2` ＋ stdout 点名 `BRIEF_ARG_EMPTY`
  ＋ degraded 记录（码字段 `time/component/code/phase/retryable`），**放在 PYBIN 探测之前**
  （调用方 bug 不得被「环境缺 python」这条降级路径盖住）；
  ③ **未传参**保留既有回退、**坏路径**维持 fail-open 原行为（C12 逐字对照相同：stdout 与改前一致，
  degraded 仍走 `reason` 口径、不混入 `code`）。
- **调用点**（`scripts/pre-commit-check.sh`，**仅** :1883-1891）：`BRIEF_RESOLVED` 非空才传参；
  为空时**不回退**（回退＝判错对象假绿），改打一行显式跳过（`⏭ … code=BRIEF_UNCLAIMED …
  不计入闸②`），不进 `DECL2`、不计 `HARD_FAIL`。
- **测试件**：追加用例 8/9/10/11（断言形态统一 `EXIT=0; OUT=$(…) || EXIT=$?`；禁 `|| true` 后读 `$?`）；
  用例 7 按事实重基并**补判别力用例**（自造「其余字段齐、仅缺 #CRITERIA」的 brief ⇒ rc=1 ＋点名缺失项）。
  **path rename**：`brief-parseable.test.sh` → `check-brief-parseable.test.sh`（见「规格外必要修正 ②」）。
- **配套件**：`.claude/claims/1072.yaml`（门禁硬要求：claim_store resolver 规则①＋D328 对账；
  本卡分支名不被 `parse_issue` 解析出 issue ⇒ 缺该文件会回退命中陈旧 claim ⇒ 判「并行劫持」硬阻断）。
