# DSH rc.2 运行时落地（#1411 T1/T2）

- **现状**：`src/runtime/dsh/*` 的 installDir 是 `%LOCALAPPDATA%\Programs\DeepSeek Harness`（无版本）；启动走 Electron 桌面宿主；`scripts/dsh-sidecar/` 只有薄包装，没有沙箱输入/配置/生命周期/交接/证据验证；`tests/runtime/dsh/sidecar-lifecycle.test.ts` 只用 fake ACP。
- **决定（T1）**：新增 `pinned-version.ts` 作为版本单源（`0.2.2-rc.2` 生产锁、`0.2.2-rc.1` 唯一显式回退、含版本默认目录、package.json 版本读取）；`sidecar.ts` 在 spawn 前做版本门并以 `--expected-version` 只接受白名单值（rc.3／任意串／空值一律 `DSH_VERSION_MISMATCH` 且不 spawn），supervisor 侧二次校验；`profile.ts` 启动命令改为 npm 布局优先 `<node> <install>/node_modules/@deepseek-ai/dsh/lib/bin.js --profile synova-sidecar`，桌面分支保留但非默认；`session.ts` 与 buildDshInvocation 同源取 `SYNOVA_DSH_INSTALL_DIR ?? overrides.installDir ?? defaultInstallDir()` 并固定校验 rc.2。
- **决定（T2）**：`Fetch-DshSandboxInputs.ps1` 只做 3 个白名单匿名下载 + 干净 worktree 的 `git archive`；`New-DshSandboxConfig.ps1` 生成两条映射的 .wsb 并做 reparse/白名单/哈希/硬链接检查；`SandboxLifecycle.psm1` 是唯一状态机（PREPARED→RUNNING→FINISHED/FAILED/TIMED_OUT→DESTROYED），`Start-DshSandbox.ps1` 是薄 CLI，`RealSandboxProcessAdapter.ps1` 是唯一能碰 WindowsSandbox/CloseMainWindow/Stop-Process 的适配器；`Complete-DshBuildHandoff.ps1` 只复制探针入口 + runtime-bundle 并原子改名；`Test-DshEvidence.ps1` 严格校验十项证据与 DESTROYED 绑定。
- **依据**：Gitea #1411 Mandate 评论 12927（v6 12907 ＋ v7 12924 ＋ v8 12948，冲突以 v8 为准）、开车门 12965、独立复核 12964；固定写集见 v6 §6.4 + v7 §B 新增两个文件。
- **验证**：宿主只做静态验证（`git diff`、PowerShell 语法解析、`New-DshSandboxConfig.ps1` 配置生成冒烟）；动态测试（vitest）由 PR CI 执行，本 Note 不声称宿主跑过测试；真实 rc.2 安装／ACP／备份恢复／十项探针／锁版记录全部 NOT DONE（T3–T5 未授权）。
- **边界**：不改 `.gitea`、`scripts/audit`、参数/导航主流程；不启用 Windows 功能、不装/启动 DSH 或 Sandbox、不操作真实 home、不使用模型/Secret/客户数据；不提交探针输出 JSON 与锁版记录（只有十项真实全过后才允许）；最终状态只到 `OFFLINE_IMPLEMENTATION_READY`。
