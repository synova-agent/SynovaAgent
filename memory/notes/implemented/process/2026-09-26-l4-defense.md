# L4 防线补强（约束类条款交叉验证 + 状态不得自宣）

状态: implemented
日期: 2026-09-26

## 一句话

给两道防线各补一问：规范类文档必须说明它会拦截谁；文档状态不得由撰写者自宣。

## 问题

K3 对文档契约 v1.0 的审计抓出：契约的「入库白名单」本意挡"过程文档"，
却**同时挡住了「加目录就能加专家/技能」这个产品核心机制**（P0-1）。
且「状态写进文档本体」是同一错误模式的第三次出现（§5 越界 / §7 快照 / §8 未审先生效）。

## 决定

按 K3 的 L4 建议（**不新增脚本、不新增机制**），在既有 skill 里各补一条：

- `north-star-guard`：三问 → **四问**（加"这条约束会拦截哪条既有工作流？"）
- `dev-doc-spec`：新增「状态不得自宣」（front-matter status 由流程决定）

## 考虑过的其他方案

① 新增一个 check 脚本强制 —— 否决：违反 Anti-bloat（用户令"不能再搞一堆控制体系"）
② 只在文档契约里写 —— 否决：契约生效前的错误拦不住

## 后果

- 两道 skill 各多一条，**零新增脚本 / 零新增门禁**
- `.claude/skills` 与 `.dsh/skills` **逐字节一致**（满足铁律 13）

## 取代

无。
