# 派单模板 v2（预置坑位版）

状态: implemented
日期: 2026-09-27

## 一句话

把「执行者会踩的坑」预置进每张派单 —— 让执行者不必"边做边撞"。

## 问题

2026-09-27，A 波与 CT 系列的执行方**反复被 CI 绊住**：
反复 sync main、反复取消 35 分钟的 Windows job、Q2 缺路径导致三连锁红、
squash × union 假冲突……**合计白烧数小时**。
根因不是执行方能力，是**派单里没写"他们会踩什么"**。

## 决定

在 `cto-handover` skill 新增 `§〇c' · 派单模板 v2`（九段固定结构），
核心两段是 **③ 门禁合规（六条）** 与 **④ 推送纪律（四条）**。

## 考虑过的其他方案

① 就地改 `docs/synova/coordination/派单模板.md` —— **否决**：该区按契约 §7 属"待分流（过程性⇒出库）"，
   再往里加内容等于给待出库区增肥。
② 新建 `docs/` 下的模板文件 —— **否决**：多一个"要记得找"的载体；
   skill 是开工必读，放这里**才会真被执行**（呼应教训库 L-018）。

## 后果

- 派单将默认携带"门禁合规 + 推送纪律"两段 ⇒ 执行方不必边做边撞
- 遗留：`docs/synova/coordination/派单模板.md`（232 行）属"长期有效"⇒ 应迁 `docs/`（记入待办）

## 取代

不取代 `docs/synova/coordination/派单模板.md`（其"路由判定/命名规范/写前核实"三段仍有效，
本 v2 补的是"**预置坑位**"这一段）。
