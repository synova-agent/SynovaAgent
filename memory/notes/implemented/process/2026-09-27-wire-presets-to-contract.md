# 把 K3 审计预设与小队队长预设接到文档契约上

状态: implemented
日期: 2026-09-27

## 一句话

让所有干活的 session（审计 / 小队）开工就知道新文档契约是什么。

## 问题

实测：`synova-k3-audit/preset.yml`（2 行）与 `README.md`（6 行）提契约 **0 次**；
`synova-squad-lead/SYSTEM-PROMPT.md` 提契约 **0 次**。
⇒ 契约立了，但**干活的人不知道**。

## 决定

① `synova-k3-audit/persona-block.yml` 加「文档契约」节（三项）：
   · **审计范围新增一项**：被审对象须核是否符合契约 §1/§2/§3（尤其豁免类不得当过程文档拦）
   · **审计产物落点规矩**（§10/§11）：报告本体 ⇒ 独立仓（不入主仓）；结论一行回执；
     证据只留指针；**主仓库不得新增"报告类 md"**
   · **你也要审 CTO**：契约 §8「CTO 不得豁免」⇒ 抽审"CTO 是否遵守契约"
② `synova-k3-audit/README.md` + `preset.yml` 各加一行指向契约
③ `synova-squad-lead/SYSTEM-PROMPT.md` 加「文档契约（全员统一）」节：
   唯一判据 / 五层 / 三闸 + 豁免类 / 过程产出进 `~/Synova-过程档案/` / 禁新建索引 md

## 考虑过的其他方案

只改 CTO 预设（已做）—— 否决：**干活的是 K3 与各小队，他们不知道就等于没立**。

## 后果

- 三个预设（cto / k3-audit / squad-lead）全部接到契约
- ⚠️ **门禁本身仍未生效**（实测：契约未合并且闸 1/2/3 未实现）
  ⇒ 预设是"让人知道"，门禁是"强制" —— 两者都要，当前只有前者

## 取代

无。
