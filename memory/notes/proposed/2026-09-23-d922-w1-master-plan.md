## 决策（Phase 0 冻结的三条口径）

1. **W1 三卡（D923/D924/D925）在 `.github/workflows/ci.yml` 上必须串行**。理由不是成员数，而是三卡都要往同一个**显式 `for t in` 夹具清单**（实测 42 条、无 glob）加行，按「同文件同一时间只有一个写者」必须串行。推荐序 **D924 → D925 → D923**（风险与前置驱动：D923 唯一带仓外前置，且它落地会抬高同波兄弟卡的合并成本）。
2. **D923 的「必经」= 仓外设置变更**。实测 main 分支保护已有 12 项 required checks 且 `enforce_admins=true`；PR 只能交付"可被注册的 job + 注册说明"，**注册动作本身与回执是完成定义的一部分**——未回执只能标"已交付、未生效"。
3. **门禁类检查器统一契约**：`0` 通过 ／ `1` 命中违规 ／ `2` 检查执行失败（fail-closed，绝不等同通过）；反例一律为**变异体判别性夹具**（把判据改坏 → 夹具必须报红），**禁用 grep 型静态判据当验收**。

## 依据（参考系，K3 可核）

- **第一性原理**：门禁的价值 = 能被第三方在无上下文条件下复算 → 本件所有事实性前提逐条给「命令 + 原始输出」，禁"我认为"。
- **Anthropic 工程基线**：门禁改动必须配判别性夹具；本仓既有 `check-canary-drift.sh` 的「awk 缺失 → exit 2 + ::error」即 fail-closed 先例（D858 K3 复审闭环）。
- **开源实证 / 本仓既有范式**：ratchet（存量清单只减不增）是 `as any` 门禁与 `check-pr-budget` 的成熟做法 → D924/D925 沿用 baseline 清单（D924 存量实测仅 1 处，base 极小）。
- **收敛检查**：依赖边由实测推出而非抄清单顺序；与清单 §五 的两处偏离均已给出实测理由（B4∥C2 不可并行；D1 不排在"下一批"）。

## 实测发现的门禁自身缺口（登记，不在本件写集）

1. `pre-dispatch-check.sh` **④ 只匹配行首路径**（探针实测：行中路径完全不被检查），且**未实现**头部注释承诺的「新建」豁免（⑥ 在 D919 已实现）→ 写集路径存在性实际近乎不设防。
2. `pre-dispatch-check.sh` **⑨ 互斥启发式按路径聚合全文语境、不区分输入** → 同一门禁的「正常（期望 0）+ 反例（期望 1）」必然误报。
3. `verify-parallel.sh` 的 `_is_closed_doc()` 把「有 K3 报告」当**放宽写集检查**的信号，与 D923 想立的「有 K3 PASS 才放行」**方向相反**，二者交互须在 D923 规格里写清。
4. `pre-audit-summary.sh`（166 行、三态退出码、聚合 5 门禁）**未接线**（三处引用数全 0）→ D923 必须先裁"接线复用 vs 新建"。

## 失效条件

本 Note 的决策 1（串行序）在下列任一成立时失效并需重裁：① canary 清单改为 glob 发现（则 `ci.yml` 不再互斥）；② W1 三卡被 CTO 改为单 PR 合并。决策 2 在 K3 门禁被 CTO 撤销或改由别处承载时失效。
