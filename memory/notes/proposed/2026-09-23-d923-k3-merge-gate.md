# 决策 Note — D923 K3 必经合并门禁（判据、归一与口径钉死）

> 本 Note 按 `memory/notes/README.md`「四字段头契约」撰写（状态/日期/决策/理由四项必填）。
> 涉及卡号：D923（`task-state/D923.json`）。

## 触发现场（实测）

存量 **183** 张卡无 K3 结论（= 键缺失 2 + `audit:null` 181）；其中仅 **8** 张库内已有报告文件（`D558/D651/D819/D839/D850/D854/D862/D864`），**175** 张确无。
`task-state/D923.json` 自身 `audit:null` ⇒ 门禁注册后本卡若改三类路径亦判③红。

## 决策内容（五条，均为技术自决 + 队长核准）

1. **判据取"实测信噪比最高"，不取"语义最全"**：A 类只保留 `src/security/**`（13）+ 6 条精确枚举 + `packages/engine-auth/**`（7），
   **不取** `src/routes/**` 整包（53 条中仅 4 条鉴权相关，误报 92%）；B 类取五子域 `computes/**` 白名单（9/7/4/3/1）并**排除 `_extinct`**（33，仅 type-only 引用）。
2. **DDL 用 pickaxe（`git diff -G`）而不是"静态含 DDL"**：静态口径 98 文件（生产 29）无法表达"本次是否改了 DDL"。
   **并且 pickaxe 必须限定生产路径**——本卡实测发现：不加排除时**门禁自己的说明文档正文含 `CREATE TABLE` 字面量即被误命中**（首轮 `three_category_hits=1` 假红）。
3. **结论归一覆盖 10 种存量取值**：`CONDITIONAL PASS`/`FAIL`/`NOT-AUDITABLE`/`NOT_K3` 一律**红**；
   `NOT-AUDITABLE` 的理由串固定写「**不可审计 ≠ 通过**」；`NOT_K3` 必须给出出口「补结论，或由 CTO 具名豁免」。
   **小写 `pass`（D799/D815）归一为 PASS 必须显式可见**（`::notice` + 具名），禁静默归一。
4. **D# 解析三路且必须可归因**：分支名 / 变更集 brief 文件名 / PR 正文；红时报出"查过哪几路、结果分别是什么"。
   多 D# → 全部检查、任一非 PASS 即红；三路皆空 → 红（fail-closed）。
5. **降级 fail-closed 且不吞三类**：扫描器不可用 → exit 2；能分类但结论源读不出 → NO_VERDICT → exit 1。
   **三类命中场景下一律非 0**，不得静默放行。

## 依据（参考系，K3 可核）

- 第一性原理：门禁的价值 = 覆盖高风险 ∩ 低误报；误报会诱发绕过，绕过使门禁归零。
- Anthropic 工程基线：契约优先（`@input/@output/@exit/@degraded/@error`）+ 三态 fail-closed + 政策外置可审。
- 开源自证：确定性抽样（`pr%5==0`）优于随机——可复算才可审计。
- 本地实证：判据冻结阶段先量化误报面（53/13/24/33/12/6/9 各数均附命令）再定判据——**先量后写**。

## 收尾补记（缺陷 A/B 修复提交 `d82bc484` @ 2026-09-23T20:02:14+0800，d923-prep 接手）

**缺陷 A（自命中）**：判据已排除 `docs/**`/`tests/**`/`*.md`，但**未排除门禁自身产物** ——
`k3-gate-policy.yaml` 与 `k3-merge-gate.sh` 以**数据**形式承载 DDL 模式字面量（YAML `cmd:` 证据串 / `pattern:` 常量 /
`reason:` 散文 / shell 注释，共 5 处），实测 `--base origin/main --head HEAD` 下 `three_category_hits=2` **全来自这两个文件**。
⇒ 注册后**任何触碰门禁文件的 PR 都会被误红**（长期运营缺陷）。
**修**：pickaxe 排除面 + `C_storage.pickaxe.exclude_globs`（`scripts/control-tower/k3-*`）；准入条件写死为
「该文件**无 DB 执行能力**」（可核：`git grep -nE 'sqlite3|better-sqlite3|\.prepare\(|\.exec\(|new Database' -- 'scripts/control-tower/k3-*' | wc -l` → **0**）。
**判别性对照**：阳性（真 DDL 落非三类路径 → 仍命中）/ 阴性（DDL 落 `scripts/control-tower/非 k3-*` → 仍命中，证明排除面窄）/
变异体（去掉 `exclude_globs` → 同一 diff 复红，证明排除承重）。

**缺陷 B（不可归因）**：红理由说"命中 N 项"，而清单只打印 glob 命中 ⇒ 读者不知是哪 N 项（违背 CTO「红必须可归因」）。
**修**：`print_hits()` 同时逐条列出 **glob 命中（含规则名）** 与 **pickaxe 命中（含规则名）**，红 / NO_CARD_ID 两出口均调用。

**方法论补记（口径必须带时点）**：原证据 S3 记 `hits=0 → PASS`，在 tip `bf92b4d5` 复现为 `hits=2 → REJECT`。
根因 = 该数在 `HEAD=2b9bfddc`（门禁两文件**尚未提交**）时测得；`92cdd2a8` 提交后两文件进入 diff 即自命中。
⇒ **报告必须带「截至 HEAD=<sha>」**（与裁定 10 同族的时点漂移），否则同一命令不可复现。

## 收尾补记 2（任务 0.5：门禁由 step 改为独立 job；L9 落地）

**step → job（结构性，非风格）**：改前 `- name: K3 merge gate (D923)` 缩进 6 空格 ⇒ 是 `quality` job 的 **step**。两条致命后果：
① **无法注册** —— branch protection 的 required check context 是 **job 名**，step 不是可注册单元 ⇒ 交付目标「注册为必经门禁」按现状不可达；
② **静默缺席** —— job 内某 step 失败后其余 step 全 `skipped`（CI 实测：`Iron laws check` 失败 ⇒ `Verify parallel`/D708/K3 三步全 skipped）⇒ 违反裁定 3「永远会跑」。
`always()` 只治 ② 不治 ① ⇒ **改为独立 job `k3-gate`（`name: K3 Merge Gate`）**，不挂 `needs:`、不加 docs-only 跳过、`fetch-depth: 0`、保留 `GITHUB_EVENT_PATH`。
**required check context = `K3 Merge Gate`**（供 branch protection 注册）。遗留：D708 与 `Iron laws` 仍是 step，同样会被 skip（不在本卡改）。

**L9（声明与实现一致）**：`B_finance.exclude` 此前**已声明但抽取器从未消费**（惰性配置）⇒ 按「声明即生效」实现：
`excludes()` 抽 `<规则>.exclude` → `EXCL\t<规则标签>|<glob>` → `match3()` 命中后按规则标签过 `rule_excluded()`。
**判别性回归用例 17**（宽 glob 沙箱：`_extinct` 不命中 / 子域仍命中）+ **变异体对照**（删掉 `rule_excluded` 分支 ⇒ 同一变更复红）。
当前五子域 glob 下该排除本不可达 ⇒ 对现行判据无行为变化；实现价值是消除声明/实现不一致，并在未来放宽 glob 时立即生效。
