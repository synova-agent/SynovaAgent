理由: ① **第一性原理**：同一份 ci.yml 密封清单在同一个 job 内被跑两次（外层 52 条 for 清单 + 内层 44 条重跑），第二次是纯重复，无信息增量；② **不选「调用方侧数次数」**：`tests/control-tower/simulate-ci.test.sh` 正被在飞 PR #868 占用（其新增内层输出透传场景**可能增加 `bash "$SIM"` 调用次数**）⇒ 计数法必漂移；在 `simulate-ci.sh` 侧做环境判定则对调用次数**完全不敏感**（调 3 次或 30 次，CI 内层执行数恒为 0）；③ **本地语义不可损**：`simulate-ci.sh` 是「push 前 CI 等价模拟」工具（synova-submit.sh:51 本地调用它），本地全量是它的价值 ⇒ 只在 `GITHUB_ACTIONS=true` / `CI=true` 时跳过，本地照跑全量；④ **一律 fail-closed**：选择器任何无法安全判定影响面的情形 → 全量，宁多跑不漏跑；⑤ **平台敏感判据不另立标准**，直接落仓库自带的 `scripts/control-tower/PLATFORM-CHECKLIST.md`（D520）9 条，且**只收「断言链路上真的会执行平台分歧命令」的套件**，仅提及或使用可移植形式的（`date +%s` / `sed -i.bak` / 纯三级探测）一律剔除（28 → 23，逐条理由见 A-02）。

## 1. 触发场景

CI `Control Tower Gate Tests (windows-latest)` 腿实测中位 **2035s**（占 run 墙钟 89.6–99.9%），
其中**单个测试文件** `tests/control-tower/simulate-ci.test.sh` = **1051s（占该腿 65%）**。

机制（前提实测 N1 段，本卡复算一致）：

```
tests/control-tower/simulate-ci.test.sh:37,47,52   三次调 bash "$SIM"
scripts/control-tower/simulate-ci.sh:49            每次从 ci.yml 提取 44 条密封测试全量重跑
⇒ CI 内嵌套 44 × 3 = 132 次内层执行；外层 job 早已逐条跑同一份 52 条清单
```

## 2. 决策与实现边界

| 决策点 | 选法 | 否掉的选法及理由 |
|---|---|---|
| 消解位置 | `simulate-ci.sh` 侧环境判定 | 调用方侧计数（#868 会改调用方，计数必漂移） |
| CI 判定信号 | `GITHUB_ACTIONS=true` 或 `CI=true` | 只看 `SYNO_CI`（本地也可置，判别力不足） |
| 本地语义 | 零损（不带 CI 标记即全量） | 一律跳过（会毁掉 synova-submit 的本地 CI 等价模拟） |
| 覆盖缝 | `SYNO_SIM_NESTED=auto\|full\|skip`；非法值 fail-closed 按 full | 无覆盖缝（夹具无法构造判别场景） |
| 降级可见性 | stderr 打原因 + `degraded-events.log` 落 N1 事件 | 静默（铁律 11 禁） |
| 选择器降级 | D1–D6 全部 **显式回退全量** | 返回 0 条（CI 会"全绿"跳过一切 = 假绿） |
| 平台敏感集 | 落仓库自带 PLATFORM-CHECKLIST 9 条，逐套件复核 | 自拟标准（会与 D520 漂移） |
| windows 全量 | 夜间 schedule + 合并前 workflow_dispatch **保留** | 直接删（违反「不删任何现有门禁」） |
