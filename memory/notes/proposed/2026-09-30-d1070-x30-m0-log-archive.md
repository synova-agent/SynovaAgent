# D1070 — X30 M0 基础层：merge_group 触发器 + 门禁日志有界归档

- **状态**: proposed
- **日期**: 2026-09-30
- **决策**:
  ① `.github/workflows/ci.yml` 的 `on:` 块新增 `merge_group:` —— X30 迁移 M0①，Q3 硬顺序① 的物理先决条件（不开 merge queue，但触发器必须先就位，否则队列里永不产生 required check）。
  ② 新增 `scripts/control-tower/log-snapshot.sh`：门禁日志「**有界快照 + 轮转**」归档，快照落 `.codex/snapshots/log-archive/`（`.gitignore:41` 已忽略）、单份上限 `--max-bytes`（默认 5 MiB）、保留份数 `--keep`（默认 7），索引 `index.json` 供 K3 消费；**不入 git 主路径**。
- **理由**:
  - 创始人 2026-09-30 裁定（X30 落地启动令 §二 T2 的路径分歧上报后）：「有界快照+轮转，不进 git 主路径」。
  - 先例 D1065：`.claude/bypass.log` 入 git（append-only + `merge=union`）后，GitHub 可合并性计算不尊重 union driver → 每 PR 必须贴最新 main，单轮 CI ≈40 分钟，成为合并吞吐瓶颈。三件门禁日志同型（每 commit 追加），入 git 即复发该病。
  - 令中路径勘误（实测）：令点名 `.claude/degraded-events.log` 是**死文件**（105 B，2026-08-21 后未再写）；活账本是 `.codex/control-tower/logs/degraded-events.log`（2.4 MB，scripts/ 下 10 处写入）。脚本默认取活账本，并把死文件作为独立行显式标出。
  - 参考系：第一性原理（日志的价值是可复跑证据，不是版本库内容）+ Anthropic 工程基线（fail-closed、脚本化验证、机器可验契约）→ 收敛：有界快照+索引，git 零污染。
- **验收证据**（2026-09-30，worktree `.synova-wt-x30-48h`）:
  - `grep -c merge_group .github/workflows/ci.yml` = 3（含注释）。
  - `bash scripts/control-tower/log-snapshot.sh --root /Users/wane/SynovaAgent --dry-run`：gate-hits 830,684 B / pre-commit-failures 9,841 B / degraded-events(活) 2,432,157 B + 死文件 105 B 显式标出。
  - 真实快照（`--max-bytes 1048576`）：degraded-events 截尾至 1 MiB 并打 degraded 告警；`git status --porcelain | grep -c '\.log'` = **0**（未污染版本库）。
  - `bash tests/control-tower/log-snapshot.test.sh` = **PASS=20 FAIL=0**（正常/边界/降级三路径 + 轮转 + dry-run + 参数校验）。
