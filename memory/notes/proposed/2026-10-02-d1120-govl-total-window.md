# D1120 · 治理线总窗：门禁总收口 + 散落门禁归一 + 文档治理总收口

- **状态**: proposed
- **日期**: 2026-10-02
- **背景**: 创始人 2026-10-02 令「给治理线一个大任务，让他去负责治理线的工作，包括 ci 门禁，包括控制塔，
  还有文档，一大堆文档，还有 HTML」；CTO 出总窗锚（A1–A8 + 附一散落门禁归一 + 附二范围与顺序 1→2→3）。
  本窗是**一窗（D1112）的续窗**，一窗已合（#935），本窗只做增量 + 收口。
- **决定**:
  1. **先复算再动手**：CTO 给的 8 项读数逐条复算 ⇒ **6 项逐字成立、2 项对不上**（#5 撞号"四个分支"实为
     1085 个分歧分支；#6 水位滞后从 146 扩大到 151）。
  2. **机械项自裁、语义项送审**：
     - 自裁（已落地）＝ ① `.gitattributes` 增 `docs/authority/DOCS-REGISTRY.yaml merge=union`
       ② `ci-red-baseline.txt` 删 2 条**已死**条目（D1118 §四-① 有条件授权）
       ③ `号段水位.md` 加 2026-10-02 实测更正（滞后 151，本卡取 D1120）
     - 送审（未落地）＝ ⓐ `Gate Integrity` 进必需集 ⓑ `merge_group` 触发器 ⓒ `DOCS-REGISTRY` 查重
       ④ 死条目删除动作的终审 —— 见 `K3审计请求-D1120-门禁语义变更-20261002.md`
  3. **union 的必要配套**：夹具实测出 union 的副作用——两侧改同一 entry 同一行时**不报冲突**、
     产出**重复键**（`status: draft` + `status: active`），而 `doc-registry-gate.sh` **无查重**。
     ⇒ 判据：**不许用一个静默缺陷换一个显式失败**；查重方案 + 正反例夹具已备，**待 K3**。
     中间窗口的风险写进 `.gitattributes` **注释正文**（读文件者必见），不靠口头传递。
  4. **PR 阻塞全量图**：41 个 open PR 逐支取 check-run 级结论 ⇒ 11 支必需腿红、9 支冲突；
     **main 自身 12 条必需 context 全绿**（红是分支自带的）⇒ 根因收敛为 **5 条**，其中 **R1 是 CTO 锚件里
     一行未登记的 DSH 版本串**（`方向锚-基座线-20261002.md:52`）同时打红 3 条必需 context、波及 5+ 支 PR。
- **考虑过的其他方案**:
  1. **只加 union、不做查重** ⇒ 否决（倾向乙案）：append-only 场景 100% 解，但"改同一行"从**响亮失败**
     变**静默脏**；改既有闸加查重**不新增门禁条目**，属"补缺口"而非"加税"。
  2. **删全部 6 条存量红** ⇒ 否决：实测另 4 条（产物新鲜度 / TS+Lint / CT ubuntu / CT windows）
     在**对账面仍出现 failure**，删掉会让真实红变"未登记失败"⇒ 阻断更狠。**目标数 6→4，非 6→2。**
  3. **本窗顺手改 `check-ci-stale-red.sh`** ⇒ 否决：它把"形状不对"从 exit 0 改成 exit 2 = **改阻断行为**
     ⇒ 属门禁语义变更，须夹具 + K3；本窗只留证据（取数路径 301 + fail-open `for…else`）。
  4. **重写 O1/E/F 分层与出口** ⇒ 否决：一窗已在 main 上定义（新增 **F 层 = 在库但已出役**、6 类闭集
     算术闭合 257/257、四态出口）⇒ 重写 = 制造双真值源；本窗改为**承接 + 只出增量**。
  5. **开 merge queue** ⇒ 否决（顺序硬约束）：`merge_group` 命中 0 ⇒ 队列一开，12 条必需 context
     永不报告 ⇒ 永久 blocked。**先触发器、后队列。**
- **后果**:
  - 好：新增文档 PR 不再必然冲突（append-only 场景实测绿）；存量红棘轮真实下调 2 条；
    号源真相源恢复可核（水位表带滞后量）；PR 阻塞第一次有"全量图 + 根因收敛"而非逐支救火。
  - 坏/要长期承担：① **union 的静默重复键窗口**在查重落地前存在（已写进注释正文，K3 送审中）；
    ② union 驱动依赖**本机** `git config merge.union.driver` 注册（`install-hooks.sh:141`），
    **未注册的机器/服务端合并**可能退回普通冲突（`bypass.log` 历史上就出现过"有 union 仍冲突"）；
    ③ 死条目删除后，若 `Vitest` 再次转红，会立即成为"未登记失败"= 红（**这是棘轮的本意，不是缺陷**）；
    ④ 本窗**未**动 `merge_group`/`Gate Integrity`/ruleset ⇒ "PR 合不进去"的 R1–R5 根因**仍在**
    （其中 R1/R2 归 CTO 侧处置）。
- **取代**: 无（新增）。与 `memory/notes/proposed/2026-10-02-d1112-govl-window1.md` 的关系 = **续窗**
  （承接其 A5/A3/E5/A1-① 与 `.html` 范围件，本窗不重复其已合内容）。
