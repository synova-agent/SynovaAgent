3. **执行点口径：先定口径再给数（CTO 明裁），且不落新执行体**
   - 定义：**执行点 = 树上一个会自行点火、能产出可判定结论（三态）的检查调用点**；计数单位 = call site。
   - **含** git hook 内被实际调用的检查 / CI 自行点火的 job / 真能阻断的平台配置 / 自动触发的独立脚本；
     **不含** advisory 顾问腿、纯提示项（opt_check·note_check·bypass_run）、无执行体的历史门禁名、手工脚本、文档自称。
   - 可复跑命令 **E0** 以"文档内嵌 + `sed` 抽取执行"形式提供（`sed -n '/^# ===E0-BEGIN===/,/^# ===E0-END===/p' <doc> | bash`），
     **不新建** `scripts/control-tower/check-execution-points.sh`：①口径未裁前落地 = 先给数后定口径；②新脚本会自指污染 G5 分母；
     ③密封面棘轮会因新夹具判红（循环依赖）；④新增执行体须先有替代与退出条件（自繁殖对冲）。
   - **拒给新总数**：130 的八个分量里当前只有 `hook 11（D1146 已归零）`可一一复现；`pre-commit 58`（"+3 无具名"实测 = 0）、
     `commit-msg 3` / `post-commit 3` / `pre-push 13` / `CI 25` / `独立脚本 14` / `平台 3` 的口径均未写明或与实测不符。
     ⇒ `130 → ≤86` **不是可用验收判据**（本件已证不可复算）；可用过渡判据 = hook 11→0（已在 main 成立）、
     声明类 15→3（#1107 自报、判据在 PR 内）、退役 3 脚本 + 1 夹具（#1078 已在 main 成立）。
