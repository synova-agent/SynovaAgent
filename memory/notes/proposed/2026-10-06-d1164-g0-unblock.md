## 决策

1. **先解冻，再谈其余（第一性原理）**：CTO 2026-10-06 派单 A 槽 W 组 12 项，但**当前 main 物理上不接受任何非 docs-only PR**——
   两处破损叠加：① 依赖 peer 互斥 ⇒ `npm ci` 红；② 必需 context `Control Tower Gate Tests (ubuntu-latest)` 因两条**存量**失败恒红。
   ⇒ W 组的 12 项**全部**排在这两处之后；不先解冻，W2–W12 的交付物只能悬空。
   ⇒ 决策：**三处最小修复合成一笔**（依赖 + 两条存量红），先让"能不能合"成立。

2. **W1 的形态偏差（依 P-02「写形态而非目的」+ P-01「配方也要核」）**：CTO 原文 W1 = 「合 PR #1159」。
   实测 #1159 **单独不可绿**：其 diff 触发 `control-tower-tests` 重活（`package.json` 在分类器 RULES 内），
   而该 job 现存两条存量红 ⇒ #1159 的 required context 恒红。反之，只想修存量红的那笔 PR 又必过 `npm ci`（依赖仍互斥）。
   ⇒ **两者互为前置，必须同笔**。本件**取 #1159 的 diff 逐字**（`git apply --check` 通过，未自行另生成 lock）承载其内容，
   W1 的**判据**（main 的 `npm ci` 可解析）不变；PR 号这一"形态"发生偏差，已在 PR 正文与回执显式标注。

3. **W1 判据本身有缺陷（P-03 断言不变性）**：CTO 原文判据 `npm ci --dry-run ⇒ exit 0` **结构性不可满足**——
   npm 在 `--dry-run` 下**仍执行根 `postinstall`**（本项目 `package.json:12` = `patch-package`），
   而 dry-run 不落 `node_modules` ⇒ `sh: patch-package: command not found` ⇒ **exit 127**。
   实测对照组（本卡，as_of 2026-10-06T13:57Z）：修前 = ERESOLVE（exit 1，红在"依赖"）；修后 = 127（红在"脚本"）。
   ⇒ **健康 main 同样 127**，与本次修复无关。本件改用 `--ignore-scripts` 变体作**依赖解析**判据，另附**真跑 `npm ci`** 作端到端判据。
   ⇒ 建议 CTO 把 W1 判据改为：`npm ci --dry-run --ignore-scripts` ⇒ exit 0 **且** CI 的 `Run npm ci` step 绿。

4. **门禁面两处只做"修复既有件"，不新增机制**：
   - **F2 红例基线**：旧夹具把 `origin/main` 当"旧实现"来源；D1157(`9e29d88e0`) 已把锚定判据并进 main，且把旧模式串**逐字写进注释**
     ⇒ 旧 prefilter（`grep -q` 扫**全文含注释**）误判"main 仍是旧实现" ⇒ 真跑锚定实现 ⇒ 得到"补记" ⇒ `❌ F2 **红例失效**`。
     ⇒ 修法：红例基线改钉「引入 `D1157-REC-RE` 那个提交的**父提交**」（`git log -S` 动态定位，不硬编码 sha），
       prefilter 只看**非注释行**。**保判别力**（把该基线换成锚定版 ⇒ F2 立刻红），非"改夹具迁就实现"。
   - **DSH 断面登记**：`check-dsh-anchor.py:114` 判 `docs/synova/coordination/提案/RbacContext-org-team-维度.md:405-406`
     的两个版本串未登记。二者是**该表逐字列举的机上台账**（三棵 DSH 树），非新的现状断言。
     该表自身 note（`DSH-断面.json:24`）明文「**历史版本一律入本表，不用豁免段**」⇒ 按既有口径补登 `known_versions`，
     **不动检查器判据**、**不开豁免段**。

5. **红线遵守**：不碰 `scripts/audit/**`；不改 `ci.yml` 的 job `name:`；W2/W3/W5/W6/W9/W11 属门禁语义变更，
   **另笔 D1165 走 提案→K3→CTO 裁**，不在本件暗中夹带。
