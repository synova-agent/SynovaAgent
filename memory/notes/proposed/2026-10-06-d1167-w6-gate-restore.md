# D1167 — W6：把三条「写着阻断、实际旁路」的门禁恢复阻断力（proposed）

- **日期**: 2026-10-06 ｜ **线**: 治理线（govl）｜ **分支**: `fix/govl-w6-gate-restore` ｜ **卡号**: D1167
- **状态**: proposed（**送审中：门禁语义变更 ⇒ 提案 → K3 过审 → CTO 裁；K3 结论出来前不合并**）
- **任务**: D1167 ｜ **相关 D#**: D1148 / W6 / #1017

## 决策

1. **本卡治的是「失败无后果」**（第一性原理）：D1148 把三条门禁从 `soft_check` 转成 `bypass_run`
   —— 运行命令、失败**只打印**、`return 0`、**不进 gate-hits、CI strict 也不转硬**
   ⇒ 三条门禁「写着阻断、实际旁路」。W6 撤销该旁路，恢复为**本地软提示 + CI(SYNO_CI=1) 硬阻断**。

2. **判例 P-01：CTO 配方要核，且这条配方缺了一步**
   派单原文写「`bypass_run` → `v5_soft`」。但 `scripts/pre-commit-check.sh:192` 的
   `v5_soft <名称>` **只收名称、不执行命令**；而 `soft_check <名称> <匹配串>`（`:145`）第 2 参数是
   **匹配串**、也不是命令 —— 三个原调用点要执行的是**外部脚本**。
   ⇒ 照字面替换会**丢掉门禁脚本的执行**（把"旁路"换成"根本没跑"，比旁路更坏）。
   ⇒ 本卡实现为 `_run_gate <名称> <命令...>`：执行命令、非 0 时先打印其输出（前 5 行，保持可见），
   再调 `v5_soft` ⇒ 语义与既有 `par_collect … || v5_soft …` **逐字对齐**。

3. **夹具用「单一真值源 + 反例」**（V-08）：`_run_gate` 与 `v5_soft` 由夹具**从被测脚本提取**
   （`W6-RUN-GATE-BEGIN/END` 标记 + 花括号配对），不抄死。判别性四支：
   - A `SYNO_CI=1` + 门禁失败 ⇒ `HARD_FAIL=1`（**提交被拒**）← W6 判据
   - B 无 `SYNO_CI` + 失败 ⇒ `SOFT_COUNT=1`、`HARD_FAIL=0`（本地不阻断，符合 D515）
   - C 门禁通过 ⇒ 两者皆 0（不误伤）
   - 🔴 D 反例：**旧的 `bypass_run` 形态** + `SYNO_CI=1` + 失败 ⇒ `HARD=0 SOFT=0`
     ⇒ 证明"阻断力"确由本卡引入，而非夹具根本没看计数

4. **🔴 必须上报的连带效应（本卡最大的事，比 W6 本身更重要）**
   恢复阻断力后，`:1738` 的 D734 预算门禁（`control-tower/check-pr-budget.sh`，`MAX_FILES=12`）
   从"旁路"变为"**CI 硬阻断**"⇒ **任何变更文件数 > 12 的 PR 会在 CI 被拒**。
   - 实测耦合：`tests/control-tower/check-pr-budget.test.sh` 的「0 文件（空写集）」用例，
     在本分支**文件数 13** 时由 `exit 0` 变 `exit 1`（脚本在 `--files ""` 时回落为**取分支 diff**）。
   - ⇒ 本卡**自己也受影响**：W6 必须单独成 PR（本分支 5 文件），不能与 W2/W3/W9（12 文件）同笔，
     否则两者合计 14 文件 ⇒ CI 必红。
   - ⇒ 这正是 **#1017**（「D708 ⊇ 变更集 / D734 ≤ 12 / G12 brief ⊇ 变更集 —— 三个门禁对同一件事阈值互斥」）
     的现实形态：**越守规矩越红**。W6 落地 = 把这条互斥从"潜伏"变成"每天发生"。
   - ⇒ **建议裁决**：W6 与 #1017 需**同批或先 #1017 后 W6**；否则 W6 一落，全组织的宽 PR 全线转红。
     本卡只做 W6，**不动 `check-pr-budget.sh` 的任何阈值**（那归 #1017，另卡）。

5. **红线**：不改 13 组编号与横幅（会连锁打破 AGENTS/CLAUDE/LOOP 的「13 组」声明，
   且 `fastlane-bypass-only.test.sh` 依赖该横幅）；不碰 `scripts/audit/**`；不改 `ci.yml` 任何既有 job 的 `name:`。
