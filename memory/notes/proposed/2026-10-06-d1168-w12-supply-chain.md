## 决策

1. **npm 没有 per-package 白名单字段 ⇒ 必须自建等价语义**（实测：无 `.npmrc`、无 pnpm 配置；
   npm 只有全局 `ignore-scripts`）。DSH 的 `onlyBuiltDependencies` 在 npm 下**无原生等价物**。
   ⇒ 本卡自建：`npm ci --ignore-scripts`（默认拒）+ 仅白名单包 `npm rebuild --foreground-scripts`（显式放行）。

2. **🔴 刻意不用 `.npmrc ignore-scripts=true`（与 CTO 措辞的偏差，代价已标）**
   派单写「默认拒」，最直译的实现是根 `.npmrc` 全局拒脚本。**但那会让本地 `npm install` 也默认不跑脚本**
   ⇒ 开发者拿不到 `better-sqlite3` / `bcrypt` 的原生模块 ⇒ 本地跑不起来（而铁律 40 的 `patch-package` 也会静默失效）。
   ⇒ 本卡把"默认拒"落在**受控安装路径**上（`install-deps.sh`），并把「CI 里不得再有裸 `npm ci`」写成
   **夹具断言**（`install-deps.test.sh` ⑤）⇒ 覆盖面用机器判据兜住。
   **代价**：开发者手敲 `npm install` 仍会跑全部脚本（不受本卡约束）。
   **需要你裁的**：是否要**再加**根 `.npmrc`（把本地也一并默认拒）——若加，须同时给 `npm run setup` 入口与文档。
   **我倾向**：先不加（本地 DX 优先），等 `npm run setup` 入口落地后再加。

3. **白名单按"非它不可"定，不按 lock 猜**（本表自带「新增一行的代价」节）：6 条，
   其中 `esbuild` 已标注「待复核：若实测不跑脚本也能用，应移出」；`fsevents` 如实登记
   "lock 标 hasInstallScript=true 但包体无 install 脚本"的元数据不一致。

4. **三态纪律（M-02）**：0 = 装好且白名单包全重建成功；1 = 安装失败或某白名单包重建失败；
   2 = 降级（白名单缺失/为空、npm 不可用）——**fail-closed，2 绝不等于通过**。禁 `|| true`。
