## 决策

1. **本卡只出提案，不实现**：W5 的三个候选**差别在于"判据是否成立"**（A 字面满足 / C 需改判据 /
   B 需动 branch protection）⇒ 实现前必须先裁，否则实现的形态可能整条作废。
2. **关键判断：W5 不可被 W3 替代**。W3 的 `all-checks-passed` 判 **job 级** `needs.*.result`；
   本处被 skip 的是 **job 内的 step**，而该 job 结论 = **success**（D1039 的设计：job 恒被调度、必需 context 必报）。
   ⇒ **W3 在结构上抓不到本处**，两条正交。
3. **旧账要认**：该路径门正是 CTO 自己在 **D1014/D1039** 立的（"每次 feature push 都跑全量 CI 是**队列放大器**"）。
   ⇒ W5 与那两条**方向相反**：A 候选会让 CI 成本升一档、吞吐降。**这不是谁错**，是**目标换挡**
   （当时优先吞吐，现在优先"必需 context 不得在没跑时报绿"）——但我必须把这条张力写出来再交裁。
