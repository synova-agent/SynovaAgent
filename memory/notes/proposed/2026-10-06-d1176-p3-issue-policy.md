## 决策

1. **权威数据源用 `closingIssuesReferences`，不扫 PR 正文。**
   正则扫正文 = S-04「grep 结论分两层」的反面教材（形式上像、语义上不是）。
2. **`--from-json` 是刻意设计（离线可测性）。** 夹具**不依赖网络、不依赖 token**
   ⇒ 判别力可被任何人复跑；否则夹具会退化成"只有 CI 能跑"的黑箱。
3. **R3 的 SKIP 必须说出来**：`⏭️ R3: SKIP —— 不冒充通过（不代表合规）`。
   判据静默跳过 = 假绿（铁律 11 同精神）。
4. 🔴 **本卡把"接线"排除在外**：加 job 并在必需 context 集里加它 = **"改哪条检查阻断合并"**
   ⇒ 按纪律走 **提案 → K3 → CTO 裁**。本卡只交判据体，**不自裁上线**。

## 🔴 夹具的负对照抓出了我自己实现里的一个真缺陷

第一版 R3 只判"有没有 `p0-p3` 标签"，于是
「**PR 声明了 Priority、但关联 Issue 一个优先级都没有**」落进了 SKIP 分支。
夹具的**负对照**（同一载荷 + 一个不一致的 PR Priority）当场报 `expect=1 got=0`。
⇒ 判据「PR Priority = 最高 resolving Issue 的 Priority」的**反面**就是：
**Issue 没有优先级时 PR 也不该有** ⇒ 那是**不一致**，不是 SKIP。已补这一支。
**这条正是"改坏即红"（V-08）的价值**：它不是关于别人的代码，是关于**我自己的**。
