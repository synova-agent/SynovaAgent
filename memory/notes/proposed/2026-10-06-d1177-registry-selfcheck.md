## 决策
1. **ID 唯一 = 硬检查**（存量只有 2 个重复 ⇒ 本卡内修掉 ⇒ 从第 1 天起就是绿的）。
2. **path 存在 = 只查「仓内相对路径」**：绝对路径 / `~` / 盘符（`D:\…`）**不适用仓内存在性** ⇒ 跳过；**glob 先展开**再判。
3. 🔴 **`status: draft` 的悬空 path = 显式 SKIP，不判红**。
   理由：draft = **尚未编写的规划文档**，path 悬空是**预期**。
   **但必须打印** `⏭️ … status=draft（规划中，预期未建）` —— 与本线 P3 的 R3 同一纪律：**跳过必须说出来**。
   反向对照（夹具用例 3）证明**豁免是有界的**：同一条悬空 path 改成 `active` ⇒ **立刻红**。
4. **不新开"基线豁免表"**（M-03 棘轮只减不增）。存量小 ⇒ 直接修。

## 🔴 本卡踩到的两个真陷阱（都写进代码注释与夹具注释，防复发）
1. **`while IFS=$'\t' read` 的顺序陷阱**：第一版 awk "path 之后遇到任意行就打印" ⇒
   在 `status:` 排在 `path:` **之后**的条目上把 status 读成空 ⇒ **整段静默失效**（实测 59 条全空、查 0 条）。
   ⇒ 改 **flush-on-next-entry**（新 `id:` 出现时才输出上一条），顺序无关。
2. 🔴 **夹具穿软链改坏了真仓库的台账**：第一版 `mkroot` 把 `docs/*` 软链进临时根，
   随后 `cp`/python 改写临时路径时**穿过软链改到了真仓库的 `DOCS-REGISTRY.yaml`**（我确实改坏了，靠 `git checkout --` 还原）。
   ⇒ 已三重加固：① `rm` 掉 `authority` 软链、用真目录；② 每次篡改后 `guard_real()` 校验真台账 **sha256 未变**，变了就 `exit 2` 中止；
   ③ 用例改成**追加合成条目**而不是改既有条目（既有条目 `status` 不确定 ⇒ 第一版曾因此**假过**）。
