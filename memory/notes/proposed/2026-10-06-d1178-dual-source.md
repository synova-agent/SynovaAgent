## 🔴 配方更正（判例 P-01：先核派单方的配方，不照抄）
派单原文 = 「双真源 ⇒ **合并**」。**实测不支持这个配方**：

| 源 | 条数 | 消费者 |
|---|---|---|
| `docs/authority/DOCS-REGISTRY.yaml` | **59** 条（id/type/path/status/owner） | 本登记门禁 |
| `scripts/control-tower/doc-registry.json` | **18** `docs` + **16** `aliases` | `inject-context.py:34` |
| **交集** | **1 条** | —— |

⇒ 两者**近乎不相交、用途不同**（前者 = 登记台账；后者 = **权威文档短名 → 路径**）。
**强行合并会打断 `inject-context.py` 的消费面，而且解决不了一个真实存在的问题。**

**真正的问题是**：「**两个源互不校验**」—— JSON 今天恰好干净（**18/18** path 存在、**16/16** alias 指向真实 key），
但**没有任何检查**保证它明天还是。⇒ 本卡改为**立交叉不变量**。

## 三条不变量（已实现）
1. JSON 的每个 `docs` 值 ⇒ **仓内路径必须存在**
2. JSON 的每个 `aliases` 值 ⇒ **必须是已存在的 `docs` key**（不是路径、也不是悬空名）
3. 两源**同一条路径**时必须逐字一致（当前交集 1 条；规则先立住）

## 实现细节（两处必须写下来）
1. **只把 D3 段的增量计入 FAIL**：第一版写 `FAIL=$((FAIL+SELF_FAIL))` ⇒ 若 D2 段已失败，
   会被**重复计一次**（汇总数字虚高）。⇒ 用 `SELF_BEFORE` 取增量。
2. **夹具加固**：D2 已因"夹具穿软链改坏真仓库台账"吃过一次事故。本次为改 JSON，
   `mkroot` 必须**再给 `scripts/control-tower/` 造真目录**（只拷 JSON、其余软链），
   并把 `guard_real()` 扩成**同时校验台账与 JSON 的 sha256**。
