# D1172 — D734 同构批量豁免（#1017 路径级口径）

- 状态: proposed（2026-10-07，治理线）
- 来源: 卡 #1017（D734 与 D708/G12 阈值互斥——归集型 PR 越守规矩越红）
- 写面: `scripts/control-tower/check-pr-budget.sh` + 判据配套夹具 `tests/control-tower/check-pr-budget.test.sh`

## 决策内容
D734 新增「同构批量豁免」：五条件**同时**成立才豁免 ① 文件数上限（其余判据照旧）：
1. 变更集全部为 M（零新增 A/复制 C/删除 D/重命名 R）——「零新增文件」硬条件
2. M 件数 ≥ 10 且全部同扩展名（同构代理 1）
3. 每件 churn（numstat added+removed）**完全相等且 ≤ 6**（同构代理 2 =「零逻辑改动」的机器可判代理）
4. `## 同构批量声明`（来源链同 D1028-A2v2：--iso-decl-file / $SYNO_ISO_DECL_FILE / brief 链当日窗口）
   逐条**精确路径** ⊇ 变更集（禁通配）+ ≥1 条依据非空
5. 域信息 / 落后告警 / 旁路封堵等其余判据不受豁免影响

## 口径解释（保守 + 代价标注）
- CTO 卡 #1017 原文口径 =「同构 ≥10 文件零逻辑改动 + 零新增文件 + 完整清单进 PR 正文」。
  「零逻辑改动」无直接机器判据 ⇒ 用「churn 相等且 ≤6」做**保守代理**（每件改动行数一致且极小，
  形态上只能是同型批量数据变更；一行逻辑改动如果每件都有且行数相同，本口径会放行——这是代价，
  由声明依据 + D708 合并级对账兜底）。
- 「完整清单进 PR 正文」在 pre-commit 读不到 PR 正文（D1028 同款约束，禁假接线）⇒ 清单落
  brief 链「## 同构批量声明」，PR 正文对账归 D708。

## 判据与夹具（先红后绿 + 判别性）
17.1 生效（#948 形态解锁）/ 17.2 无声明 / 17.3 混入 A / 17.4 churn 不等 / 17.5 churn>6 /
17.6 声明缺 1 条 / 17.7 混扩展名 / 17.8 变异体（ISO_OK 恒 0 ⇒ 生效场景必红）。既有 192 项零回归（合计 200）。

## 退出条件
若 K3/CTO 认为 churn 代理过宽 ⇒ 收紧为「added-only（零删除行）」或降 churn 上限；过窄 ⇒ 提阈值（须重校准 #948/#1017 实例）。
