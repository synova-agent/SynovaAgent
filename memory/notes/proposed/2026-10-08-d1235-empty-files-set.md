# D734 空写集注入缝：`--files ""` 不再直落真实 diff（D1235）

- 状态: implemented · 编号 **D1235** · 来源：卡 #1302 附带发现（Lead 批准修法，编入 **K3 批五**）

## 一、现象与根因（定位到行）

`scripts/control-tower/check-pr-budget.sh:137`：
```bash
elif [ -n "$FILES_OVERRIDE" ]; then      # ❌ 空串与「未提供」不可区分
```
⇒ `--files ""` 落空 ⇒ **直落真实三点 diff**（`origin/main...HEAD`）。

**同文件内已有正确范式**：`--diff-status` 用 `DIFF_STATUS_SET`（`:104` 定义 / `:134` 判定）
⇒ 作者**知道**这个陷阱，只是 `--files` 没照做 ⇒ 属**同文件不一致**，修法即对齐。

**实测后果**：造 14 文件三点 diff 的工作树 ⇒ `tests/…/check-pr-budget.test.sh` **rc=1**，
失败行却是 `❌ 0 文件（空写集）`（**误报**：真实原因是"分支 diff >12"）。
⇒ 该用例的成败取决于**开发者工作树的 diff 大小** ⇒ 任何 diff>12 的分支**本地必红**；
`git fetch` 令 `origin/main` 前移后同一棵树**自动转绿** ⇒ 表现为"flake"。
（今日两次「看似的红其实不是」即此类；比 flake 更贵：**它伪造失败理由**。）

## 二、修法（对齐式最小修）

```bash
FILES_SET=0                                  # 新增：与 DIFF_STATUS_SET 对称
--files) FILES_OVERRIDE="${2:-}"; FILES_SET=1; shift 2 ;;
...
elif [ "$FILES_SET" -eq 1 ]; then            # 判据从「值非空」改为「是否显式提供」
```
语义：**提供即接管**（空串 ⇒ 变更集为空 ⇒ 0 ≤ 上限 ⇒ exit 0）；**未提供**才走真实三点 diff。

## 三、夹具（先红后绿 + 反例，自建沙箱 ⇒ CI 确定性）

| 断言 | 内容 |
|---|---|
| 夹具自查 | 沙箱三点 diff = **14** 文件（> 上限 ⇒ 缺省路径必红）—— 防夹具自身失真 |
| **17.1 先红后绿** | `--files ""` ⇒ exit 0（**旧口径此处 exit 1**） |
| 17.2 判据实况 | 输出含「变更文件数 **0**」（真空集确已接管） |
| **17.3 反例** | **不传** `--files` ⇒ 仍走真实 diff（14>12）⇒ exit 1（**缺省路径未被改坏**） |
| 17.4 对称性 | `--diff-status ""` 亦为「显式提供 ⇒ 接管」 |

**为什么自建沙箱**：旧口径下该用例的成败取决于工作树 diff ⇒ 只有**自带受控 diff 的沙箱**
才能让「先红后绿」在 CI 中**确定性成立**（而非随开发者工作树随机红绿）。

## 六、变更点 / 旧口径 vs 新口径 / 回滚（K3 批五用）

| 项 | 旧 | 新 |
|---|---|---|
| `--files ""` | 落真实三点 diff | **真空写集** ⇒ exit 0 |
| 不传 `--files` | 真实三点 diff | **不变**（反例 17.3 钉住） |
| 与 `--diff-status` | 不一致 | **一致**（皆 `_SET`） |
| 回滚 | — | 单文件 3 处改回 `[ -n "$FILES_OVERRIDE" ]` |

**属门禁语义变更** ⇒ 送 K3 批五，作者（线 D）不自行合并。
