## 决定

1. **W1 清单**（`.gitea/protected-files.txt`）：删 `# APPROVERS=` 行；PATTERNS 首行 `.gitea/protected-files.txt`、末行 `gate-exemptions/**`（共 22 条）；头部注释同步为「清单自我保护＋豁免目录自我保护」；按「非空非注释行、文件顺序、trim、`\n` 连接＋末尾 `\n`」重算 sha256 写回 `# PROTECTED-PATTERNS-SHA256=`。
2. **W2 检查器**（`scripts/control-tower/check-gate-protection.sh`）：删 `APPROVERS_MASK`／approvers 解析／`E_APPROVERS_EMPTY`／`last_author`／`author_ok`／report 的 approvers 字段／默认模式第 4 项；`parse_exempt_text` 加严三段（路径非空／理由 strip 后 ≥10 字／裁定号 fullmatch）；**不合规行本身计 failure**（`E_EXEMPT_INVALID`，即使另一行覆盖了该路径）；主逻辑（受保护必须被有效覆盖／glob／pin／`E_BAD_BASE`／三态／`@降级`／UTF-8／只读承诺）**不动**；头部契约/已知限制/结构表/`--help` 行号区间同步。
3. **W3 配对测试**（`tests/control-tower/check-gate-protection.test.sh`）：T1 条数 20→22；删除「非 approver ⇒ 1」，改「k12@local 作者齐全 ⇒ 0」；新增清单自改 ⇒ 1（加行＋重算 pin，点名清单）、缺理由/9 字理由/坏裁定号 ⇒ 1、不合规行＋另一合规覆盖行 ⇒ 仍 1、齐全 ⇒ 0；保留 #610 的陈旧 base ⇒ 2、T10b、坏 base、DS-6、`--json`（need 删 approvers）、glob 4/4、README 排除。

## Known Limitations（做不到什么 —— 每条都是「做不到」，不得改写成「已核过」）

1. **作者签名语义消失**：删 `APPROVERS` 后，豁免不再证明「谁批准」；豁免=**可审证据链**，授权仍归 CTO 裁定号（台账）。作者校验本就可被同机 `git config user.email` 绕过，删除不降低实际防护，但也**不再提供**签名这一层（原本就不可靠）。
2. **历史引述不回改**：`docs/plans/**`、旧 `memory/notes/**`、旧 `.claude/task-briefs/**` 中出现的 `APPROVERS`／「创始人作者」引述保持原样（历史引述性质，`memory/notes/AGENTS.md` 红线）⇒ **全仓** `grep APPROVERS` 不为 0 是预期；本批只保证清单/检查器/两测试/README 四处清零。
3. **平台侧核不到**：Gitea `branch_protections`／`force-merge` 限制／`protected_file_patterns` 是否生效，本器与测试均**核不到**（活腿 token 403）；真正的授权边界仍在 S2 平台字段（创始人执行）。
4. **本 PR 的 ①d 红是预期**：本批触碰受保护路径且豁免文件不在写集 ⇒ CI ①d 将红；**禁**写成「本 PR 已被 ①d 核过」，也**禁**为此改检查器/写豁免变绿；合入前由 L1/创始人补 7 行豁免（5 路径＋自覆盖＋DOCS-REGISTRY）。
5. **D2 未在写集**：豁免文件是新增 `.md`，D2 要求 `docs/authority/DOCS-REGISTRY.yaml` 条目（DOC-0209）或排除 `gate-exemptions/` —— 本批不改该文件，需 CTO 裁（规格 §7 P3）。
6. **同 diff 自覆盖规则**：`gate-exemptions/**` 入保护面后，豁免文件自身在 diff 内也需一行覆盖 ⇒ 本 PR 的豁免必须含「自覆盖」行；这是**有意的无死锁解法**（不是把目录排除在保护外）。**旧 README 的「目录不加保护是有意设计」作废**。
