## 决定

1. **六段一次贯通（#718）**：一个 vitest 文件、一个进程、一个临时 DB（`SYNOVA_DB_PATH`=mkdtemp）、一个 full server 实例，按顺序检查 ① 输入 → ② ingest → ③ 本体/哨兵/计算 → ④ 参数/决策 → ⑤ 出口 → ⑥ 冻结对照；数据依赖只声明 money→metric→trends→M4；入口 Document 与 overflow 是同一 run 的独立检查（不是 money 的父节点）。
2. **③ 夹具 = 生产 `SqliteGraphStore.createNode`（CTO 批准 A／L1 收件追认 2026-10-21）**：写 2 条 `resource/money`（2026-01 `rev100/cost40/opex10/cash60`；2026-02 `rev200/cost60/opex20/cash120`，合计 300/100/30/180），替代批规格 §1.3 原文的 `ingestBatch`。🔴 **产品缺口披露**：`resource/money` 与 `outcome/financial` 两个 schema 均无 `operating_expenses`（`extensions/ontology/resource/money.json`／`outcome/financial.json` 实查；后者只有单数 `operating_expense`），而 cash-flow 哨兵只读 `operating_expenses`（`src/sentinel/adapters/cash-flow-sentinel.ts:116`），且 `ingestBatch` 有 schema 白名单（`src/agent/data-ingest-service.ts:175` 跳过不在目标 schema 的 prop）⇒ 期望 `NET_MARGIN=170/300` 与 `RUNWAY=12` **物理上无法经 `ingestBatch` 达到**。本批按裁决 A 用生产 createNode API（禁 raw SQL），**不得写成「已按 ingestBatch 贯通」**；修复方向（schema 补 `operating_expenses` 或哨兵读别名 `operating_expense`）另开卡，交 CTO/K3。
3. **⑥ 冻结 = 只读源码扫描 ＋ 链运行期间不调用（#720）**：产品**无**进化开关（无 DISABLE_CRON/EVOLUTION env）；六段链 15 个模块零 import 进化引擎/`applyEvolutionActions`/`processFeedbackSignals`/`loop-handlers`（扫描清单含 `src/cycles/overflow-compute.ts`），全 `src/` 调用点仅 `src/agent/loop-handlers.ts`；0 调用只作基线，R6 以「verify 树加 import（不调用）⇒ 扫描红」证判别力。**不冒充「产品开关已实现」（C1 CTO 待签）**。
4. **不新建 runner／不改生产代码／不新增依赖或 mapping**：既有 `scripts/integration/e2e-*.ts` 是 SEED 直写范式（M9 明令禁 SEED），且出口段需同进程 render 桥；验收件自身即复跑入口（vitest 直接跑）。
