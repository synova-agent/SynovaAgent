# 2026-10-24 · #912 批 1 · G3 反例两态 = **L1 复核清单**（A2：不进机器阻断）

## 现状

`check-quality-delta.py` 的机器判据只覆盖**可执行项**：R3.1（行为断言形态）、R3.3（禁 skip/空 expect/恒真断言）、
R3.4（禁对源码文本断言）、R1.1/R1.2（G1 可达）、R4.1–R4.4（G4 边界）。

原提案里的 R3.2「PR 正文含『改坏』＋两段 rc」被 **裁 330-A2 否决**：用 grep 判散文 = 逼人造假（写两个字就过），
且模板一改全红。**改为 L1 复核清单（人判），不进阻断。**

## 决定

新增/修改测试件的「反例存在」由 L1（包负责人）在收口时逐条核，条目如下（缺一即不收）：

```
  □ 1. 反例存在：PR 正文贴两段**原始输出**——改坏被测件 ⇒ 该测试红（给出失败断言原文）；
       还原 ⇒ 绿（给出末行通过计数）。只有"已通过"三字 ⇒ 视为缺。
  □ 2. 判别力承重：反例必须落在**被本 PR 改动的代码**上（改别处的红不算）。
  □ 3. 断言是行为断言：断言对象是返回值/副作用/落盘结果，不是源码文本（源码文本断言见 R3.4）。
  □ 4. 非空壳：无 skip/xit、无空 expect、无恒真断言（机器已抓，L1 抽查复核）。
  □ 5. 覆盖据实：新增能力的测试必须至少覆盖"正常 + 1 条失败路径"。
```

## 依据

裁 330（#912 批准 ＋ A2）｜#912 评论 5792（判据 ②⑤ 要求两态原始输出）｜`docs/authority/quality-standard-g1g6.md` G3。

## 生效时点

随 PR-A 生效；L1 收口时按本清单核，**不通过 ⇒ 不收**（不改机器判据）。

## 已知限制

- 清单是**人判**：无法防"写手自证"。缓解 = 复核者与实施者分离（四条件③ 独立复核）。
- 若将来要做机器判，须先解决"如何证明反例真的跑过"（如要求 CI 产物/日志 artifact 绑定 sha），
  **不是**在本闸里加一条 grep。
