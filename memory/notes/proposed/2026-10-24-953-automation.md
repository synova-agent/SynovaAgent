# #953 自动化工作流一期（裁 367）

## 做了什么
- `scripts/control-tower/ledger-sync.sh`：把 `local-main` 的 merge 提交自动同步进 #918 §G（幂等）
- `scripts/control-tower/auto-merge.sh`：对 open PR 逐个判「四条件 can ＋ 变更集不触受保护路径」，满足才允许自动合；**默认 dry-run**
- 配对测试两份：`tests/control-tower/ledger-sync.test.sh`（12 例）＋ `tests/control-tower/auto-merge.test.sh`（6 例）

## 复核退回后修的三条（#954 round 1）
- **B1 fail-open**：`auto-merge` 取变更文件失败时，`$(... || exit 2)` 只退出子 shell ⇒ 父脚本继续用空列表判定并合并。现改为：命令替换后检查 `$?`，失败/空 ⇒ **exit 2**；`files` 端点补分页（防 >100 文件挤出受保护路径）。
- **B2 假绿**：open PR 列表 API 失败被吞成"无 open PR" + exit 0。现为 **exit 2**（与 header `E_NET` 契约一致）。
- **B3 state 不落盘**：`mapfile` 在 macOS bash 3.2 不存在 ⇒ 改 `while read` 循环；补 `SYNO_LEDGER_SYNC_MOCK_WRITE=1` 测试接缝与"state 落盘＋重跑幂等"用例。
- 另修：`--limit` 非整数 ⇒ exit 2；`@exit 1` 与实现对齐（API 写失败 = 1，环境失败 = 2）；`SYNO_AUTO_MERGE_BASE` 真接线；`urlopen` 全加 timeout；受保护匹配大小写不敏感。

## 为什么
去掉「合并／记账」环节的人工往返（裁 367 一期）；红线不变：**受保护路径与 A 类一律人合**。

## 已知限制
1. `ledger-sync` 行内"验收要点"无法自动生成，统一写"自动同步（详见 #N）"；
2. `auto-merge` 只判路径与四条件，**不做语义裁决**；TOCTOU（取 head 后到合并前的新 push）未防，靠四条件的 ③ 回执指纹兜；
3. state 文件本机、不跨机；
4. 两份配对测试**尚未接 CI**（无消费者）——属已知缺口。
