# #968 摩擦治理③：③ 指纹绑 patch-id（③-2.1）

## 改了什么
`check-merge-conditions.sh` 的 `patch_fingerprint()`：
- 旧：`sha256(git diff -M --full-index --binary mb..head)`（上下文/行号参与哈希）
- 新：`sha256(git patch-id --stable(<同一 diff>))` —— **只哈希增删行**
- `_repo_fp`（自检侧）与测试 `fp_of` 同步为同一口径。

## 为什么
sync（`git merge main`）会改 diff 的上下文与行号 ⇒ 旧指纹必变 ⇒ 回执作废 ⇒ 白跑一轮复核。今天实测 3 次。

## 判据（两态）
- **sync 不变**：feat 分支合 main 前后指纹相等（`062dafb3c09f`）；
- **内容变必变**：再改一行 ⇒ `4432e9b21ac9`；
- 既有 14 判定点 + `--selfcheck` 13/13 全过。

## 已知限制
1. 二进制文件：`git patch-id` 对 binary 段的处理依赖 git 版本，本仓极少；
2. 若 sync 冲突解决时**改动了 PR 自己的行**，指纹会变（这是正确的：内容变了）；
3. 旧回执（③-2.0 口径）与新口径不兼容 ⇒ 在飞 PR 需重出一次（当前无）。
