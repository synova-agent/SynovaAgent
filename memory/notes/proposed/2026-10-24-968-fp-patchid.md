# #968 摩擦治理③：③ 指纹绑 patch-id（③-2.1）

## 改了什么（**v2：设计已被复核推翻一次，勿回退到 patch-id**）
`check-merge-conditions.sh` 的 `patch_fingerprint()`：
- 旧（③-2.0）：`sha256(diff mb..head)`（上下文/行号参与哈希 ⇒ sync 一次即作废）
- 曾被复核退回的 v1：`sha256(git patch-id --stable(diff))` —— **git patch-id 默认 strip whitespace**，只改缩进/空格的真改动不改指纹 ⇒ R3 可绕过（复核用控制流级比对立证）。
- **现版（③-2.1）**：逐字 canonical —— 只取「文件路径 ＋ 增删行原文（含空白）＋ 模式/改名/二进制标记」，**不含 hunk 头/上下文** ⇒ 行号/上下文无关、空白参与哈希。
- `_repo_fp`（自检侧）、测试 `fp_of`、`docs/synova/reviews/README.md` 三处同口径；新增 `--fp-of <mb> <head>` 测试缝让用例**驱动被测脚本**。

## 为什么
sync（`git merge main`）会改 diff 的上下文与行号 ⇒ 旧指纹必变 ⇒ 回执作废 ⇒ 白跑一轮复核。今天实测 3 次。

## 判据（两态）
- **sync 不变**：feat 分支合 main 前后指纹相等（`062dafb3c09f`）；
- **内容变必变**：再改一行 ⇒ `4432e9b21ac9`；
- 既有 14 判定点 + `--selfcheck` 13/13 全过。

## 已知限制
1. 二进制文件：`git patch-id` 对 binary 段的处理依赖 git 版本，本仓极少；
2. 若 sync 冲突解决时**改动了 PR 自己的行**，指纹会变（这是正确的：内容变了）；
3. 旧回执（③-2.0 口径）与新口径不兼容 ⇒ 在飞 PR 需重出一次（当前无）。
