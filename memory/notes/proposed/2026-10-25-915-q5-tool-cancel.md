## 决定

1. **execute 收 signal**：`ToolExecOptions { signal?: AbortSignal }`；`isToolAbortEnabled() = process.env.SYNO_TOOL_ABORT !== '0'`；开关开时 dispatch 前 `opts?.signal?.throwIfAborted()`（副作用前），handler 收可选第二形参 `ctx.signal`（S9 严格相等）；`executeParallel` 透传。
2. **结构化取消、永不抛**：取消 ⇒ `ToolCallResult.error = { name:'AbortError', code:'TOOL_ABORTED_BEFORE_DISPATCH'|'TOOL_ABORTED', message }`（按 handlerStarted 标记选码）；与 Q-1 的 ToolArgsError 同族；`log.info({code:'TOOL_ABORTED'})` 留痕一次。
3. **链路贯穿**：WebAdapter 断线 ⇒ `abortController.abort(new Error('CLIENT_DISCONNECTED'))`，`get signal()` 只读暴露；路由把 `{signal: adapter.signal}` 传 `processMessageStream`；引擎与工具循环入口/每轮判 aborted，取消 ⇒ 返回 `${已生成前缀}${TOOL_CANCELLED_REPLY}`，不再发 LLM、取消不当普通失败。
4. **中断锚不变量不破**：取消也以「已生成前缀＋取消标记」settle，路由 ⑩ 落库时序不变（已见前缀 ⊆ 落库内容）。
5. **回滚单一谓词**：`SYNO_TOOL_ABORT=0` ⇒ execute 不检查＋引擎不传 signal，两处同读 `isToolAbortEnabled()`。
6. **闸只扩不建**：check-tool-args-delta 增 R4（副作用工具 handler 须有 ctx＋throwIfAborted）／R5（tool-signal-baseline.txt 双向棘轮，3 行存量）／R6（src/agent/** 内 execute 调用参数 <3 ⇒ 红）；`--selfcheck` 增 f4/f5；复用 CI 步 ①i，无新步。

## 已知限制（禁读成「已防护」）

- **connector/http 模式是协作式取消**：connector 接口不收 signal（`src/connectors/**` 不改）⇒ 只能外层 abort，底层连接可能仍在收尾。
- **存量 3 件 side-effect 工具不修**：其取消检查只在注册表层（dispatch 前）；handler 内多步操作的中途中断不保证（R5 基线登记，只减不增）。
- **未接线工具不在扫描面**（`src/l3/knowledge-agent.ts` 2 个）；**CLI/TUI SIGINT 与 im-inbound 非流式入口未接**（独立卡）。
- **取消文案含已生成前缀 ⇒ 落库内容比完整回复短**，属有意语义（§4.3）。
- **R4–R6 是正则非 AST**：字符串/注释里的同名文本可能误判（同 Q-1 R1/R2 限制）。
