# #1096 W6 判据自检库（ga_run 三态归一 · 128 不当 0）

## 现状（问题是什么，证据）

判据（门禁脚本 / 探针 / 一次性核查）的退出码在实现上处处按「布尔」处理，而实际有五种事实：

| 事实 | 典型码 | 旧写法常把它当 |
|---|---|---|
| 判据通过 | 0 | 通过（对） |
| 判据发现真问题 | 1 | 真红（对） |
| 判据自身失败/降级 | 2 | 有的当红、有的当通过 |
| 判据被信号杀死 / 非法退出参数 | 128 / 137 | **红**（污染真红台账）或 **通过**（假绿） |
| 命令不存在 / 不可执行 | 127 / 126 | **红**（伪装成业务问题） |

历史形态（仓内可核）：`ctrl-tower-change` 模式 1 记的 D328-D335 台账一半是「门禁本身失败被当业务结论」；
`|| true` / `2>/dev/null` 把故障洗成空的先例（D329 P2-5）；`grep -c` 双 0 致 `[: integer expected`（V4.5.1）。
⇒ 结论是**共享件缺失**：没有一处机器可判的「码 → 三态」真源，于是每份判据各写一份，必然漂移。

## 依据（为什么这样做）

- **三态是契约**：`scripts/control-tower/AGENTS.md`「0 通过｜1 真红｜2 检查自身失败，信号量==0 ⇒ exit 2」
  ＋ `.gitea/AGENTS.md`「门禁判别力自检：信号量==0 ⇒ exit 2（禁把看不见当没问题）」。
- **单一真源**：归一表只允许一份实现（`ga_normalize_code`）；`--table` 打印的就是它。
  双真源必然漂移（同仓先例：brief 字段曾有第二套 awk 解析 ⇒ D707/D665 两轮假红）。
- **改坏必红**：把 `128` 分支改成 `0` 后，配对测试必须翻红 —— 这是「判据承重」的唯一证据（CT-40）。
- **不接线是有意**：接入既有判据 = 改受保护路径里的行为语义（需独立送审），本批只交付库件；
  WIRING 如实记 `declared-only`，**禁读成 wired**。
