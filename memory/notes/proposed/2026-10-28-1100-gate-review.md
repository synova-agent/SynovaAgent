# 决策 Note — #1100 W3 · 豁免证据链收窄（新件须带复核件 · 存量冻结 legacy）

## 现状（起点 `gitea/local-main`@`0569f2d4b`）

- 检查器只在 diff 内做「受保护路径 → 合规豁免行」覆盖判定（`exempt_info` / `parse_exempt_text`）；
  `is_exempt_file()` 已排除 README，但**无任何 base 存在性判定** ⇒ 「新增 vs 存量」无判据。

## 决定

1. **只收窄新增件**：新增豁免文件（`git cat-file -e <merge-base>:<path>` 不存在）**首行**必须是
   `# review: <PR#>` 或 `# review: docs/synova/reviews/<文件名>.json`；缺失 ⇒ exit 1 并**点名该文件**。
2. **legacy 判据 = base 存在性**（唯一）：`in_base()` 单函数；**禁**日期/内容启发式 ⇒ 同 diff 内改一版旧文件
   仍免检（M-2′ 用例锁死）。存量不迁移、不加 expiry、不改文件名。
3. **不新增错误码**：复核件缺失复用 `E_EXEMPT_INVALID`（phase=`review`）—— C1 错误码集是契约，扩码需 CTO；
   三段式与复核件**独立判**，互不替代。
4. **开关 `--require-review=0|1`（默认 1）**：非法值（非 0/1）⇒ `E_USAGE` exit 2（判不了 ≠ 通过）；
   `=0` 回滚态逐件打印「未核复核件」，禁读成已通过（M-3′/M-4′）。
5. **`--help` 取界改动态**（原 `sed -n '5,79p'` 写死行号，头部一加行就截断契约 ⇒ 文档失真）。
6. **422-R1 归一化自检缝平台差异修复**：POSIX 上 `C:\repo\…` 是字面相对名（relpath 原样返回
   `C:/repo/.gitea/...`），Windows ntpath 上解析为盘符绝对路径（relpath 得 `.gitea/protected-files.txt`）⇒
   断言接受两形态、**仍拒绝任何含反斜杠的结果**（判别力不降，变异体证据见「证据」）。
7. **验收自证脚本夹具首行**（写集外 1 件，L2 授权 A 案）：④/⑤/⑥ 三处新建的 `e-compliant.md` 首行补
   `# review: #1100`；**断言、PASS==12 计数、判据语义零改**。

## 依据

- **收窄而非全量**：旧 PR 的豁免件无法事后补复核件 ⇒ 全量迁移会把「历史证据缺失」变成恒红或诱导造假；
  legacy 冻结是唯一诚实解（代价写进检查器已知限制 16 与 README §8-8：可「先合空壳件、下一 PR 填内容」绕过）。
- **指针而非签名**：只核首行形态，不核 PR 是否存在、不核指针 JSON 是否已落盘（复核件通常晚于豁免件产生）
  ⇒ 与 #623「豁免=可审证据链，不是授权」同口径；真授权仍是裁定号台账 ＋ 平台字段。
- **回滚可读**：开关关闭时打印「未核复核件」，避免把「没检查」读成「已通过」（铁律 11 不静默）。
