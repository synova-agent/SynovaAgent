# #1112 W6 接线（gate-assert 接入 inventory/empty-green · 判不了归 2）

> 四态：**proposed**（未过独立复核／未合并；禁读成 implemented）
> 卡：Gitea Issue **#1112** ｜ 分支 `feat/1112-w6-wiring`（base `gitea/main` = `b8edf9860`）
> 归属：P4 门禁包（B6＝CTO 的眼睛）；本批为 #1096（W6 批一）的**接线批**。
> 创始人令：**补接线优先于退役**；未接线前一切"全绿"必须带「诚实层未接线」。

## 一、现状（问题是什么，证据）

#1096 交付了归一库 `scripts/control-tower/gate-assert.sh`（`ga_normalize_code` 是「码 → 三态」唯一真源），
但当时 WIRING 记 `declared-only`、**零生产调用点**。后果有二：

1. 制度没生效：`docs/authority/gate-pitfalls.md` 写的「执行退出码一律走 `ga_run`」只是清单条目。
2. 两个在生产链上的判据仍是旧形态：
   - `check-gate-inventory.sh` 尾行 `exit "$RC"` —— 判据子进程原始码**直接当自己的退出码**；
   - `check-ci-empty-green.sh` 的三个出口（file／env／selfcheck）同样是裸 `exit $?`。

实测（基线件 = `gitea/main` 版本，注入假 `python3`，见 §四 证据）：

| 注入 | 基线件 rc（未接线） | 本批 rc（已接线） |
|---|---|---|
| 假 python3 `exec` 不存在（→127） | **127** | **2**（`判据故障: 127`） |
| 假 python3 `exit 128` | **128** | **2**（`判据故障: 128`） |
| 假 python3 `exit 137` | **137** | **2**（`判据故障: 137`） |
| 假 python3 `exit 126` | **126** | **2**（`判据故障: 126`） |

⇒ 旧形态下「判据被信号杀死」在本器退出码上冒充成一个**第四种结论**；按 `==2` 判"判不了"的消费方
（pre-commit `hard_check`、CI ①d／⑤ 步）读不到它。这就是「128 不当 0」这条制度此前**没有落点**的原因。

## 二、决定（本批做什么）

| 面 | 决定 |
|---|---|
| inventory 归一 | 判据子进程改为 `ga_run "check-gate-inventory" -- "$PYBIN" - …`（heredoc 原样作该命令 stdin）。0/1/2 透传；126/127/128/137/白名单外码 ⇒ 2 ＋ stderr `判据故障: <code>` |
| empty-green 归一 | `file`／`env`／`selfcheck` 三出口各经 `ga_run`（`ci-empty-green:--summary`／`--env`／`--selfcheck`） |
| 自身"不可判"路径 | **语义不变**（python3 缺失／清单缺失·不可读／段缺失／零条目 仍 exit 2）；变化只在：异常码不再穿透，且归一库缺失也归 2 |
| 归一库缺失 | 两器均 fail-closed exit 2（inventory 打 `GATE-INVENTORY: DEGRADED E_INTERNAL`；empty-green 打 `CI-EMPTY-GREEN: UNJUDGED reason=no-assert-lib`） |
| WIRING | `gate.assertLib`：`declared-only` → `wired`；`consumer` = `scripts/control-tower/check-gate-inventory.sh:98`（主调用点；R5 只容单条 path:line）；另一消费者 `check-ci-empty-green.sh:259/260/261` 记在 `notes` |
| 测试 | 两件配对测试各补三组：⑬ 异常码注入（127／128／137／126）／⑭ 归一库缺失／⑮ 归一里 128→0 改坏即红 |

**零判据语义改动**：不改 A/B/C 判据、不改 P0 逻辑、不改 `gate-assert.sh` 本体（只消费）、
不新增「组 N」（防撞 D782 组数口径）、不改 `.gitea/workflows/**`。

### 一个必须记下的夹具修正（诚实层）

两件配对测试里原有的"改坏即红"用例，把被测件 `sed` 成变异体后**复制到临时目录**再跑。接线后被测件
依赖**同目录**的 `gate-assert.sh`，否则会 fail-closed 判 2 —— 那样"变异体 rc≠0"就不再说明"判据被改坏"，
而只是"归一库找不到"（把两个变量压成一个，测试失去判别力）。故该用例加上一行
`cp "$GA" "<临时目录>/gate-assert.sh"`，并把「归一库缺失 ⇒ 2」单独立成 ⑭ 用例 —— 两件事各判各的。

## 三、依据（为什么这样做）

- **三态是契约**：`scripts/control-tower/AGENTS.md`「0 通过｜1 真红｜2 检查自身失败；信号量==0 ⇒ exit 2」。
- **单一真源**：归一表只允许一份实现（`ga_normalize_code`，`--table` 打印的就是它）；本批两器只 `source`，不抄第二份 case。
- **改坏必红**：把归一里 128 分支改成 0（/tmp 副本，不动工作树）⇒ ⑬b／⑬ 的 rc=2 断言必须失效（rc 2→0）。
  这是"归一入口真的在承重"的唯一证据（CT-40）。
- **不顺手重构**：`--json` 输出契约、python 判据正文、`GATE-INVENTORY.yaml`（本批不新增 check/verify 件 ⇒ 枚举面无漂移）均不动。

## 四、证据（命令名；原始输出见 PR 正文，此处只留末行／关键行）

- 配对测试 `bash tests/control-tower/check-gate-inventory.test.sh` → exit 0，`结果: 32 通过, 0 失败`（基线 22）。
- 配对测试 `bash tests/control-tower/check-ci-empty-green.test.sh` → exit 0，`结果: 38 通过, 0 失败`（基线 30）。
- 注入证据（假 python3，真执行路径）：127／128／137／126 四个码在**基线件**上分别 rc=127/128/137/126，
  在本批件上**均为 2**（且 stderr 点名 `判据故障: <code>`）。
- 改坏即红：`cp` 到 /tmp 后 `sed 's/^    128).*/    128) printf 0 ;;/'` 改归一库 ⇒ 同一 128 注入下
  本批件 rc 由 2 变 **0**（= ⑬b／⑬ 的断言会红）。测试内置用例 ⑮ 复现同一变异。
- `bash scripts/control-tower/check-gate-inventory.sh --root .` → `条目 40 ／ 盘上件 40`、`GATE-INVENTORY: OK`。

  （逐条受保护路径「有合规豁免」）。

## 五、已知限制（禁写"暂无"）

1. **归一库缺失即判不了**：两器把 `gate-assert.sh` 当同目录邻件；把它单独拷走会 fail-closed exit 2
   （方向是 fail-closed，不冒充红/绿）。这是**有意**：看不见归一真源 = 判不了。
2. **`ga_run` 看不见判据内部被 `|| true` / `2>/dev/null` 吞掉的错**（#1096 已知限制 1，本批未变）：
   本批只保证"本器这一层的出口码"被归一，不保证 python 判据内部没吞错。
3. **`--json` 模式下 `[ga] …` 点名行仍在 stderr**：stdout 契约不变（JSON 仍单行可 `jq`），
   但消费方若把 stderr 也当 JSON 读需自行分流（既有调用点均不这么做）。
4. **`WIRING-REGISTRY.yaml` 的校验器存量红**：`python3 scripts/control-tower/quality-baseline.py
   --check-registry docs/authority/WIRING-REGISTRY.yaml` 在 **base `b8edf9860` 上即 rc=2**
   （YAML 子集解析器遇存量裸标量报 `E_YAML`，line 137）；把裸标量临时加引号后可跑完 R1–R7，
   余下两处失败（`entries[2].test null` 与 `entries[11].owner` 缺）**均为存量行、非本批引入**；
   本批新增/改写行（`gate.assertLib`）R5／R6 全绿。
5. **未做独立复核与 K3 审计**：本批为交付态，只到"可提请独立复核"级别，不作通过判决。
