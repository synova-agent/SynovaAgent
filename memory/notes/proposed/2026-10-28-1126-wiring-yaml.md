- **日期**: 2026-10-28
- **批次**: 门禁修复（单件）· 分支 `fix/1126-wiring-yaml`（base `gitea/main` = `94ed76b2d`；**PR base = main**）
- **依据**: Issue #1126 ｜ 归属依据 `docs/authority/DOCS-REGISTRY.yaml` 的 `DOC-0295`（同属 #1034 ⇒ CTO）

## 一、缺陷（锚上实测，不是转述）

```
$ python3 scripts/control-tower/quality-baseline.py --check-registry docs/authority/WIRING-REGISTRY.yaml
degraded: [E_YAML] YAML 子集解析失败: docs/authority/WIRING-REGISTRY.yaml
  (line 137: 裸标量含不支持的字符（中文/特殊符号请加双引号）: scripts/control-tower/report-mirror-push)
EXIT=2
```

两处根因，都在**数据**不在**判据**：

1. `tool.reportMirrorPushes` 的 `defined_at: scripts/control-tower/report-mirror-pushes.sh:15` **未加双引号**。
   `scripts/product-lines/productline_yaml.py` 是**严格 YAML 子集**解析器（fail-closed）：裸标量允许
   `- _ . /` 与部分标点，但 `:` 是映射分隔符 ⇒ 出现即 `YamlSubsetError`，整器归 **2（判不了）**。
2. 该条目**缺 `owner`**：同表 `fields.owner.required: true` ⇒ 只补引号必然转 **R3 红（rc=1）**。

连带影响（同因，非本缺陷语义面）：下游两处**实测常量**已漂移——
`tests/control-tower/quality-baseline.test.sh` 的真实件断言 `REGISTRY-OK rows=11`（实际 21）与
`--orphans-only` 真树分母 `/35`（实际 `/40`）；`tests/control-tower/quality-standard.test.sh` 的
`rows=11` 同因（该件另有 C10/C10b 盘点漂移，属 #1087/#1093/#1108 盘点线，**不在本批写集**）。

## 二、决定

| 面 | 决定 |
|---|---|
| 载体 | `docs/authority/WIRING-REGISTRY.yaml` 单条目两处数据修复：`defined_at` 加双引号 ＋ `owner: CTO` |
| 归属 | `owner: CTO`——依据 `DOCS-REGISTRY` 的 `DOC-0295`（DeployKey 旁路 SOP 登记，同属 #1034） |
| 语义 | **零变更**：不动任何 capability／provider／consumer／test／status／notes，不改校验器 R1–R7 判据 |
| 解析器 | **不放宽** `productline_yaml.py`（fail-closed 是有意设计；禁把"看不见"变"能通过"） |
| 防回退 | 并入**既有**配对测试（不新建测试件）：真件钉死两断言（引号＋owner 非空）＋ 两条改坏反例（去引号 ⇒ rc=2 E_YAML；删 owner ⇒ rc=1 R3） |
| 常量同步 | 同件内 `rows 11→21`、真树 `orphans` 分母 `35→40`——**仅同步实测常量，判据一字不动**（沿用 #915/#975 先例口径） |
| 受保护路径 | `tests/control-tower/**` 在册 ⇒ 新增豁免件（三段式＋自覆盖）＋ `DOCS-REGISTRY` 登记 `DOC-1126`（按已裁 R1：id=`DOC-<Issue#>`） |

## 四、已知限制（禁写"暂无"）

- **KL-A 只治这一处**：本批不普查全表其它裸标量/缺字段（真件其余条目已双引号 + 字段齐套，实测 R1–R7 全绿即为证）；
  若将来手改 YAML 再引入同类错误，靠**本批新增的两条反例 ＋ 真件钉死断言**报红，而非靠人眼。
- **KL-B 真件钉死是"点名式"**：`bare-scalar` 反例锚定 `report-mirror-pushes.sh:15` 这一行；
  换成别的裸标量仍是 `E_YAML` rc=2（同一机制），但测试不会逐行覆盖全表。
- **KL-C `rows=21` / `orphans=40` 是实测常量**：新增登记行/盘点行会再次让该断言红（既有先例即如此）；
  本批不改成动态推导（会改判据面，超出本批写集）。
- **KL-D `quality-standard.test.sh` 仍红（存量，非本批引入）**：其 `rows=11` 与本批同因，
  但 C10/C10b 的 `wired_to` 复算不一致属盘点线（#1087/#1093/#1108），本批不动。
- **KL-E 未接 CI**：`quality-baseline.test.sh` 与 `--check-registry` 当前**无 CI／pre-commit 调用点**
  （本批不新增接线，避免把一个纯数据修复扩成接线批）；因此回归防线是**人工跑测试**，不是 CI。
