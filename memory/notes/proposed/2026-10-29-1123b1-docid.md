# Note — #1123 批1 DOC 编号形态（R1）＋ Issue 来源（R2）判据（proposed）

## 现状
`DOCS-REGISTRY` 编号靠"看 main 取下一个空号"，并行分支必然撞号（#1119/#1110 同取 DOC-0324；DOC-0325 被三条分支同时使用）。门禁原本只查"文件内唯一"，不查形态与来源。

## 决定
1. **R1 形态**：新登记条目 id 必须 `DOC-<Issue#>` 或 `DOC-<Issue#>-NN`（一卡多件，按 path 字典序两位）；
2. **R2 来源**：须可派生 —— front-matter `任务: "#N"` 或文件名含 `-<N>-`；**两处皆无 ⇒ 红并点名**；
3. **唯一性正则扩为** `DOC-[0-9]+(-[0-9]{2})?` —— **只扩大合法形态，不放宽唯一性本身**（#942 强度不变，重号仍逐条点名）；
4. **存量冻结**：基线（`gitea/<trunk>` → `origin/main`）已存在的 id **跳过**；无基线（夹具/裸仓）时 `DOC-0xxx` legacy 亦跳过，并打印显式降级留痕。
