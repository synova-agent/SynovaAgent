# Note — T2.5 门禁元数据生成器（proposed · #1147）

## 现状
`GATE-INVENTORY.yaml` 有两套半口径：
- `classification`（41 条）：有 `class/owner/review_after/required_ci`，但只覆盖 check/verify 件；
- `run_by`（117 条，S0 建账）：有 `run_by/quota`，但**没有 class / quota_scope / orphan / nature**；
- 旧段 `meta/gates/checkers/pairing/candidates` 与 `run_by_candidates` 是历史产物，语义与新段重叠。

结果：`orphan` 只在旧处出现 8 个 true，与 join 实测（ORPHAN=22）不一致；"谁算 quota:true"仍是人填 ⇒ 不满足 D1 硬条件（quota:true 必须由 join/生成物机械判定并回填）。

## 决定
新增 `scripts/control-tower/gen-gate-meta.sh` 作为**唯一生成器**：
- `--emit` 产出 `gate_meta:` 段（纯追加；117 行；六字段 `class/run_by/orphan/quota/quota_scope/nature`）；
- `--check` 与库内段逐行比对（`measured_at` 行除外，防每次提交必红），不一致 ⇒ exit 1 并点名；
- 三态：0 一致 ｜ 1 违规（缺段/不一致/非法组合/orphan∧quota）｜ 2 判不了（清单不可读、无 run_by 段、腿源全缺、段名重复、python 缺失）；
- `legacy_sections` 固化登记 `meta/gates/checkers/pairing/candidates/run_by_candidates` 及各自 reason（C8 要求标注可机检，不靠口头）。

`check-gate-inventory.sh` 不再重算 join，只调 `--check`（单一真源），结果记为 `R10`；生成器缺失或自身判不了 ⇒ exit 2（fail-closed）。

## 依据
- 创始人 D761-C2：生成器前移并入 T2.5；
- D761-B1：新段名 `gate_meta`（`meta` 已被历史统计占用），旧段视为 stale legacy、本次不改；
- D1 硬条件：`quota:true` 与 `quota_scope` 必须机械判定并回填、同批机检。

## 生效时点
PR 合入 main 起：`gate_meta` 段随每次 `--emit` 重生成；`--check` 在 `check-gate-inventory.sh` 内常态执行。
