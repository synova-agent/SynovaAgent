# Note — B3 DOC-GATE 批 1（G-DOC-3 日期戳 ＋ G-DOC-5 裸文件名）

## 做了什么

- 新增 G-DOC-3 检查器 scripts/doc-system/check-doc-g3-datestamp.sh：每份追踪 .md 只读前 12 行，取行首引用行或「日期／date／更新时间／updated」字段行的第一个 YYYY-MM-DD，与 git 首次 add 日期（一次 git log --diff-filter=A 取 %aI 前 10 位）比较；绝对差 ≤ 1 天为过。
- 新增 G-DOC-5 检查器 scripts/doc-system/check-doc-g5-bare-filename.sh：逐份 .md 扫内联代码 span，内容整串是「裸文件名（已知扩展名且不含路径分隔符）」即判违规。
- 两支都是三态：0 通过／1 有新增违规／2 判不了；信号量==0（检出对象为 0）一律 exit 2，禁把「看不见」当「没问题」。降级统一走 stderr 一行加一条 JSON 到 SYNO_GATE_DEGRADED_LOG（time/component/code/phase/retryable）。
- 配对测试各一份（tests/doc-system/ 下同名 .test.sh）：覆盖正常、判据两态、边界、基线棘轮、三态、以及「改坏即红」（把判定点 sed 成恒假后必须逃逸，否则测试判红）。
- 登记与豁免：docs/authority/GATE-INVENTORY.yaml 纯插入两支检查器入册（run_by=无 加候选段加 gate_meta 行）；docs/authority/DOCS-REGISTRY.yaml 纯追加 DOC-1148-01；gate-exemptions/2026-10-30-b3-docgate2.md 记 6 条受保护路径豁免加两段机器基线。

## 为什么

- 台账 §二「文档桶」把 G-DOC-1…G-DOC-6 记为文档门禁全集，但六组都没有常驻执行点。D761 定的是「按批落地、先机械可判」；日期戳与裸文件名是其中判据最机械的两组：一个比 git 首次提交日，一个比内联代码 span，均可全仓一次跑完、存量可数。
- 判据必须 fail-closed：查不到（非 git 仓／git log 失败／追踪文件在工作树被删／检出头部日期为 0）一律 exit 2，绝不把「判不了」当「没问题」。

## 当前状态（未接线）

- 本批不接 pre-commit、不接 CI：两支检查器只能显式调用（L1/L2 手跑与配对测试）。
- 未接线不改变判据有效性，但也不产生日常拦截；接线属后续 task（须走 A 类判据变更加独立送审）。

## 基线口径（只减不增）

- 存量违规与命中写入 gate-exemptions/2026-10-30-b3-docgate2.md 的两段机器基线：G-DOC-3 每行一个路径，G-DOC-5 每行「路径 TAB 计数」。
- 基线内不阻断；基线外新增才 exit 1 并逐条点名；基线路径修好后运行时提示「基线可收紧」，但不判红（棘轮不自动收紧）。

## 依据

- 台账 §二文档桶（G-DOC 组全集与未接线现状）；D761（文档门禁批次化）。
- 存量实测（交付时原始输出）：G-DOC-3 扫描 1929 份 .md，检出头部日期 940 份，存量违规 194 条；G-DOC-5 文档面 1929 份，存量命中 4471 条（覆盖 871 份文档）。

## 已知限制

- G-DOC-3 头部日期只认前 12 行的第一条候选行：更深的日期头（如 CHANGELOG 式多日期）不判；被纯 rename 搬过家的文档首次提交记录不可得，判不了（exit 2），不猜 rename 前历史。
- G-DOC-5 只认内联代码 span：正文里不带反引号包裹的裸文件名不在本批判据面。
- 两支的路径按行解析，含换行的文件名不支持。
