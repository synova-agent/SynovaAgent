# Note — #1205 W0-A（proposed）

## 现状
- 两仓共 10 个 workflow（GitHub 6／Gitea 4）**零统一登记**：`dual-repo-sync.yml` 自行判「门禁放行」后推送镜像（真阻断腿不在账），`ci.yml` 12 个 job 无 category，无法按 §二 判「GitHub 腿 0 个纪律/质量阻断」。
- 配额现状（实测）：`quota_true=39`（non-doc 37 ＋ doc 2），`bypass=0/8`；`check-fixture-requires.sh`（工装）与 `workflow/check-integration.sh`（集成）仍占 non-doc 桶。
- 配对测试 `tests/control-tower/gen-gate-meta.test.sh` 在 base 就已红（18 通过 4 失败）：⑫/⑫b/⑬/⑰b 硬编码 `rows=120`，而清单实际 122 行（陈旧夹具数，非本批引入）。

## 决定
1. `GATE-INVENTORY.yaml` **纯追加** `workflows:` 段：10 条，字段 `id/repo/trigger/state/category/reason`；`github/ci` 内含 `jobs:` 12 条（各带 `category`/`state`）。trigger 逐条取自两仓 `on:` 实况（`project-coordinates` 实为 `issues[opened, edited]`，不抄先例文本）。
2. A2 固化：两件留 GitHub 件改为 `quota:false` ＋ `scope: github-only-integration` ＋ `na_cmd`（负证据命令，只校验存在）。
3. A3 回填：`check-bypass-log.sh`（pre-push）与 `workflow/wire-check.sh`（npm）改 `quota:true` ＋ `quota_scope: bypass`。
4. 机检不新增文件：workflow 定态校验并入 `gen-gate-meta.sh --check`（双向对账：登记须有真 yml；目录 yml 须全在册），违规 exit 1 逐条点名、结构不可解析 exit 2。

## 依据
GATE-STANDARD v3.1 §二（两仓分工与四态登记）／§三（39−2）／§十一 W0 出口（workflow 无账外、bypass ≥2）／§十二 判据 1、8、11；创始人裁定 #1212（non_doc=35／total=37／39=35+2+2）。

## 生效时点
PR 合入 main 起；本次机检挂在既有 `gen-gate-meta.sh --check`（已由 pre-commit／①d 消费），不新增门禁件。
