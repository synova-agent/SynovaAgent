# Note — #1210 W0 附：sealed-tests 扩面 ＋ 耗时机检（proposed）

## 现状
`sealed-tests.sh` 的发现面只 glob `*.test.sh` / `*.test.py`，而全仓多数测试是 `.test.ts`（tests/control-tower 11 个、tests/security 19 个）⇒ 发现制对 .ts 恒 0 发现（GATE-STANDARD v3.1 §六 O2 已证不可达），退 `canary-drift` 的前置判据无法出具。另一面 `gate-stats.sh` / `gate-telemetry.sh` 只出中位耗时，无墙钟、无阈值、无数据也 exit 0（§七）⇒ 耗时预算无判据（§十二 判据 9 不可判）。

## 决定
1. `sealed-tests.sh` 发现面扩为 `tests/control-tower tests/doc-system tests/security`，`scan_face` 支持 `.test.ts`（含 `.integration.test.ts` / `.e2e.test.ts`）；`--face-total` 改为逐面一行（count ＋ runner），某面 0 ⇒ exit 1、面目录缺失 ⇒ exit 2；新增 `--list-ts`（runner=vitest，缺 runner ⇒ exit 2 ＋ degraded）。
2. `--list`（CI bash 执行集）**保持只出 .sh/.py**，.ts 存在时 stderr 明示「未进 bash 执行集，runner=vitest 待接线」——不改 workflow 行为。
3. 棘轮 `# FACE-TOTAL=` / `--slack` / `scan_face_at` 仍按**执行集口径（.sh/.py）**计数：台账 204 不在本卡写集，若把 .ts 计入则余量 8→35 撞 SLACK-CAP=10（假红）。.ts 可见性由逐面行承担。
4. 新建 `scripts/control-tower/check-gate-budget.sh`：默认读 `wall_ms=<n>` 日志 / `--cmd` 用 `time.monotonic` 实测，阈值默认 90000ms，三态 0/1/2，无数据或无法计时 ⇒ exit 2（禁 exit 0）；**旁路，不接 pre-commit 主路径**（接线归 W6/A3）。
5. 登记三件（L1 批准写集 +3，全部纯追加）：`WIRING-REGISTRY.yaml` 加 `check-gate-budget` 行（declared-only，consumer 空，R1.2 显式豁免）；`DOCS-REGISTRY.yaml` 加 `DOC-1210`；`GATE-INVENTORY.yaml` 加 classification/run_by/run_by_candidates 各 1 条（`gate_meta:` 段由 `--regen` 重放，不手改）。
6. **B-Redo 批（A 的 #1214 合入后，main=de485d272）**：`git merge gitea/main` 后 GATE-INVENTORY 的冲突不复用文本合并 —— 只保留非生成段（A 的 `workflows:` 段与 run_by 4 条 ＋ 本卡 3 处登记），`gate_meta:` 段一律交给新 `gen-gate-meta.sh --regen` 重放。`--regen` 是 gate_meta 段的**唯一写盘入口**（explicit authority）：内存校验（N1/N2＋B1＋workflows 定态，与 --check 同规则）→ 同目录 tmp ＋ `os.replace` 原子写 → 重读等价校验 → 失败回滚原件；保留旧 `measured_at`、逐行行尾（本仓该文件实测混合行尾：gate_meta 段 CRLF、其余 LF）⇒ 登记批 diff 只有新增行（`git diff --numstat gitea/main...HEAD` 删除行 = 0）。内部 python 引入 typed error `GateError(code/phase/retryable)`；bash 侧 degraded 行同时写 `SYNO_GATE_DEGRADED_LOG`。
7. 新建 `scripts/control-tower/gate-inventory.invariant.sh`（B3 不变式伴生件，**唯一不重复判据**：④ 直接复用 `check-gate-inventory.sh --root` 的 rc）＋配对测试：① 配额恒等式 39=35+2+2（并对照 `--quota` 的 QUOTA-SRC）；② 段内 id 唯一；③ workflows n=10／账外 0；④ disk↔registry 对齐；另加 schema 白名单与必填/类型。文件名 `gate-inventory.invariant.sh` **不匹配** `{check,verify}-*` 盘上件枚举面 ⇒ 无需（也**不得**为逃避登记而改成 check-*）。
8. 合并后账本 +1 行（本卡新 gate）⇒ A 的配对测试 `tests/control-tower/gen-gate-meta.test.sh` 里 4 处硬编码 `QUOTA-SRC ... rows=122` 同步为 `rows=123`（L1 批准写集 +1；**只改这 4 个数字**，A 的断言语义不变）。不修则 CT-40（gen-gate-meta.sh 被本卡改过 ⇒ 必跑其配对测试）与 CI 必红。

## 依据
GATE-STANDARD v3.1 §六 O2（扩面 ＋ `scan_face` 支持 `.test.ts` ＋ 指定 runner）与 §七「耗时预算须新建 check-gate-budget.sh」、§十一 W0 出口判据「`--face-total` 各面非零」。配对测试含改坏必红两态（删 .test.ts glob ⇒ tests/security 归零 ⇒ exit 1；阈值比较改恒假 ⇒ 超限夹具变 PASS）。

## 生效时点
本批合入 main 起。已知限制：.ts 尚无 CI 执行（runner 未接线）；FACE-TOTAL 不覆盖 .ts；`--face-total` 输出形状由单整数改为逐面行（消费方 `check-gate-integrity.sh` 的展示字段会变多行，不影响退出码）。
