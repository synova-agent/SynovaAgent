# #1210-T3（W6）pre-commit 墙钟预算接线：从"有数"到"有判定"

- **状态**: proposed
- **日期**: 2026-11-01
- **批次**: P4 门禁自身可靠性批次 **T3**（#1255）｜分支 `ct/1255-t3-budget`｜卡 **#1210**（判据 7 遗留项）
- **授权**: CTO 会话｜判据源：GATE-STANDARD §七「pre-commit ≤90 s」＋ §十二 ⑨

## 一、现状（接前）

- `check-gate-budget.sh` 2026-10-31 已建（#1210），**唯一落盘 = 降级日志**，契约头明写
  「**不接 pre-commit 主路径**（卡 #1210 判据 7；接线由后续 W6/A3 卡决定）」。
- ⇒ ⑨ 判据「墙钟 ≤90s 由 check-gate-budget.sh 出数」**从未在真实提交链上执行**：
  `ci.yml`／`local-gates.yml`／`pre-commit-check.sh` **命中 0**（本日实测）。
  即：判定器存在、口径存在，但**每次提交都没有耗时数** —— 标准要的是"有数且能判"。

## 二、决定

- 在 `pre-commit-check.sh` **结果段**接线（两条出口都接：失败分支与通过分支）：
  1. 顶部记 `_GATE_T0_MS`（`python3/python/date` 三级回退，跨平台）；
  2. 结果段先落盘 `wall_ms=<elapsed>` 到 `SYNO_GATE_BUDGET_LOG`（默认 `<root>/.claude/gate-budget.log`）；
  3. 再调 `check-gate-budget.sh --log <log>` 取判定，打印 `⏱ 墙钟预算: BUDGET: PASS|FAIL|判不了`。
- **只告警不阻断**：超标不改变提交结果（W6 出口判据写的是"破则告警"；转阻断需另行裁定）。
- **不另造算法**：判定唯一来源仍是 `check-gate-budget.sh` 的 0/1/2 三态。
- 台账同步：`CT-check-gate-budget` 的 `required_ci` 改 **true**（已被 pre-commit 引用）、
  `run_by` 改 **pre-commit**、从 `run_by_candidates` **移出**（不再是无主件）；`--regen` 重放 `gate_meta`。

## 三、依据与证据

| 项 | 修前 | 修后 |
|---|---|---|
| 提交链有无耗时数 | **无**（三处命中 0） | 每次 pre-commit 落一行 `wall_ms=` |
| 判定 | 手工调用才有 | 结果段自动出 `BUDGET: PASS/FAIL/判不了` |
| 台账账实 | run_by=无 / candidates | run_by=pre-commit / required_ci=true / 移出 candidates |
| 一致性 | — | `--check` OK（rows=126）｜`inventory` **43 通过 / 0 失败** |
| 判定器三态 | — | 达标 1200ms⇒PASS(0)｜超限 120000ms⇒FAIL(1)｜无数据⇒degraded(2) 实测 |

## 四、边界与失效条件

- 计时含 Python 启动（每次 ~30 ms），不影响 90 s 量级判定；无 python 时退化为秒级精度。
- 计时**不含** pre-commit 自身启动前的部分（git hook 派发），即报的是"脚本内耗时"；
  若将来要卡"提交总时长"，须改由 hook 侧落盘（另卡）。
- 日志文件在 `.claude/`（ignored）；CI 上每次 run 覆写为最后一条，故 `--log` 取"最后一条"符合预期。
- 若 `check-gate-budget.sh` 缺失 ⇒ 明确打印"判不了"，**不静默通过**。
