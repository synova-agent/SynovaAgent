# #1255-T6 skill 收敛：④ 口径改正 ＋ 零活面引用退役（自研 12 → 11）

- **状态**: proposed
- **日期**: 2026-11-01
- **批次**: P4 门禁自身可靠性批次 **T6**（#1255）｜分支 `ct/1255-t6-skill`｜卡 **#1227**（W3 skill 收敛）
- **授权**: 创始人 2026-11-01 口令「**减少我们自己写的 skill，产品自带的那些不要清理**」＋ CTO 会话执行

## 一、口径错在哪（这是本条真正的价值）

标准原文（§一 D2 行 ／ §十二 ④）把上限写成 **「全树 ≤40」**。而实测：

| 归属 | 数量 | 说明 |
|---|---|---|
| **自研**（`.dsh/skills` ＝ `.synova/skills`，两处**差集 0** ⇒ 同一套双轨副本） | **12** | 我们写的 |
| **产品自带** `extensions/skills/builtin` | 41 | 随产品交付，客户可见 |
| **产品自带** `skills/` | 6 | 运行时技能面（cross_validate／detect_contradiction／…） |
| **第三方** `vendor/` | 1 | 外部 |
| 合计 | **72**（去重后 60） | |

⇒ 按「全树 ≤40」判：**无论自研砍到几个都判红**（12 自研 + 48 产品 = 60 > 40）。
原判据把**产品内容面**算进了研发上限，指向错误 —— 这正是"判据口径错一次，账上多一条假通过/假红"的又一例。

## 二、决定

1. **口径改为「自研 ≤40，产品自带不计入」**（`.dsh` 根 ≤12 不变）。
   - §一 D2 行、§十二 ④、§三载体表、批 D 标题四处同步；并留**口径更正依据**（创始人 2026-11-01 口令）。
   - 这是**判据口径变更（A 类）**，由 CTO 直裁并留痕（本 Note ＋豁免件 ＋ 提交正文）。
2. **按活面审计退役 1 个自研 skill**：`line-audit-and-cards`
   - 活面引用 **0**（`scripts/**`／`tests/**`／`AGENTS.md`／四态登记全零）；
   - 内容半部是**已退役**的 legacy brief 卡面规范（AGENTS §9 明写"legacy brief 规范，已退役；现行 = Gitea Issue + claim"）；
   - **双轨同删**（`.synova` 真源 ＋ `.dsh` 镜像）⇒ 组 13 技能同步 `SYNC-OK（11 个技能）`；
   - 内容可由 git 历史恢复：`git show <本提交父>:<path>`。
3. **产品自带 48 一个不动**（`extensions/skills` 41 ／ `skills/` 6 ／ `vendor/` 1，实测复核仍为 41/6/1）。

## 四、边界与失效条件

- 只按"**活面引用 0 + 内容描述已退役规范**"两条同时成立才退役；仅"引用 0"不够（技能靠语义匹配加载，可能仍在用）。
- 其余 11 个自研 skill 的活面引用与职责见会话审计（`pr-review` 被 `check-merge-conditions.sh` 硬引用、`cto-handover` 被 `weekly-selfcheck.sh` 硬引用 ⇒ **均保留**）。
- 若将来 DSH 改为按名字显式装载技能，本条的"零引用"口径需重估。
- `extensions/skills` 等产品面带**不属于**本判据的治理对象；它们的增删由产品线决定，不由门禁体系裁剪。
