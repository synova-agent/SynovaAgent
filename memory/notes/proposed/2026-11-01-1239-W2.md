# #1239 W2 批C：6 道门禁迁 Gitea 权威腿

## 1 现状与触发

GATE-STANDARD v3.1 §二 定死两仓分工（Gitea 权威腿 / 唯一阻断；GitHub 集成测试腿 / 只报不拦），§六 批 C 逐字列出 6 条 entrypoint：

1 `scripts/control-tower/check-gate-integrity.sh`（P0）
2 `scripts/control-tower/check-required-contexts.py`（P0）
3 `scripts/control-tower/verify-parallel.sh`
4 `scripts/ci/diagnosis-quality-check.sh`
5 `scripts/ci/golden-case-checker.ts`
6 `scripts/workflow/check-brief-vs-code.sh`

迁前状态：6 道只在 `.github/workflows/ci.yml` 跑，而 GitHub 腿实测不点火／只报；`.gitea/workflows/local-gates.yml` 是权威阻断腿（`SYNO_CI=1` 转硬阻断）却零这 6 道 ⇒ 纪律判定事实上无人阻断。

## 2 做法（三件，按写集互斥）

- T1（`.gitea/workflows/local-gates.yml`）：job `gates` 末尾追加 ⑦～⑫ 六步，**真阻断**：无 `continue-on-error`、无吞 rc 后缀，三态经 `|| exit $?` 原样透传（禁把 2 折成 1）。
- T2（`.github/workflows/ci.yml`）：同 6 道对应 step/job 降 **step 级** `continue-on-error: true`。job 数不减（12 个业务 job 集合改前改后逐字相同）、step 零删除、判据语义零改动；原 `check-brief-vs-code` 行尾吞 rc 后缀删掉，改由该字段吸收（rc 可见、日志照出）。
- T3（本件 + `docs/authority/GATE-INVENTORY.yaml`）：6 条 `run_by: github-ci → gitea-ci`；`gate_meta:` 段只由 `bash scripts/control-tower/gen-gate-meta.sh --regen` 写。

不用 job 级 `continue-on-error` 的理由：job 级会把该 job 内其余真阻断步骤（docs-only 检测、D708 写集对账、checker-review 本体、fixture 工装步）一并降级，等于扩大口子。

## 3 账本改动与「顺手修存量」

- 6 条 `run_by` 迁 `gitea-ci`（只改字段）。
- **顺手修存量 ①**：`verify-parallel.sh` 的 `run_by` 段与 `gate_meta` 快照原本不一致（段=github-ci / 快照=pre-push）。本次段已迁 gitea-ci；快照值仍会被生成器判成 `pre-push`，根因见 §5-④（本批写集修不了，已上报 L1）。
- **顺手修存量 ②**：`CT-check-gate-integrity` / `CT-check-required-contexts` 原 `required_ci: false`；T1 把两者引用落进 `.gitea/workflows/*.yml` 后，`check-gate-inventory.sh` R4（真值面＝`.gitea/workflows/*.yml` ＋ `pre-commit-check.sh` ＋ `pre-push-check.sh`，见该脚本 `:206-254`）判「账实不符」⇒ 改 `true`（数据对齐事实，不改判据、不改阈值）。
- 三条基线（改后逐条重跑，原始输出见 PR/回执）：`gen-gate-meta.sh --check` → `GATE-META: OK（rows=123 orphan=76 quota=32）`；`gen-gate-meta.sh --quota` → `QUOTA: non_doc=28/30（超编 0） total=30/45 bypass=2/8`；`check-gate-inventory.sh` → 末行 `GATE-INVENTORY: OK`（42 通过 0 失败）。

## 4 两态证据（全部在 $TEMP 副本上做，共享树零脏写）

- (i) 手改快照一行 ⇒ 红 ⇒ `--regen` ⇒ 绿：副本里把 `scripts/workflow/check-brief-vs-code.sh` 的 `quota: true` 手改成 `false` ⇒ 同一副本 `--quota` 数字位移为 `non_doc=27/30 total=29/45`，`--check` 判 `❌ [B3] gate_meta 与生成物不一致（第 742 行）` rc=1；`--regen` 后 `--check` 回 `GATE-META: OK` rc=0。⇒ 「gate_meta 只由 --regen 写」有判别力。
- (ii) 把 `run_by` 改回 `github-ci`：**本批 6 条不成立**（改回后 check-gate-inventory 仍 OK，rc=0）——R9 的判据是「该腿源文本（去注释）里有没有这个脚本名」，而本批按判据 (d) 要求 GitHub 腿**仍真跑**这 6 道（只报不拦）⇒ 6 条在 github 腿源里仍命中 ⇒ 改回 github-ci 不红。用只在 gitea 腿被引用的 `scripts/control-tower/check-gate-protection.sh` 改回 github-ci ⇒ `❌ [R9] … 该腿源文本（去注释）零命中（名义在跑）` rc=1，判别力成立。⇒ `run_by` 语义＝「被该腿引用」，**不是**「该腿阻断」；两者拆开后，「只报」这件事只能由 `ci.yml` 的 `continue-on-error` 承载，账本不承载。

## 5 已知限制（如实登记，禁读成「已核」）

- ① 门禁 ⑤ 的 C 段（`check-gate-integrity.sh --ci-reds`）在 Gitea 腿**显式不跑**：对账对象是 GitHub check-runs JSON，Gitea runner 无该数据源亦无凭据。脚本契约明载「未给 `--ci-reds` 时 C 段显式 SKIPPED（不参与 OK/违规判定）」⇒ 输出有可见 SKIPPED 行，非假绿、非静默跳过。该面对账仍归 GitHub 腿 gate-integrity job（本批已降只报）。
- ② 门禁 ⑥ 的 `--api-check`（`gh api …/branches/main/protection`）在 Gitea 腿同样**显式不跑**（branch protection 是 GitHub 侧对象；`ci.yml:1122-1127` 已记 CI 的 `github.token` 无 admin）。静态面（基线 9 条 ⊆ 可产出 check-run 名全集）仍阻断。
- ③ 门禁 ⑫ `check-brief-vs-code.sh --strict` 在 CI 干净树上按脚本自身语义「无实际变更文件（CI 检出场景）⇒ 跳过文件范围检查 rc=0」（`scripts/workflow/check-brief-vs-code.sh:79-80`）。本批**只迁腿、不改判据对象**（改成按 base..HEAD 判 diff 属改判据＝A 类，另批）。
- ④ 「顺手修存量 ①」未闭环：`gen-gate-meta.sh` 的 `run_by` 由 **basename join 机械判定**（`:300-305`，PRIORITY＝pre-commit > pre-push > gitea-ci > github-ci > npm），而 `scripts/pre-push-check.sh:493` 有一行**路径变量赋值**（`VERIFY_PARALLEL="$SCRIPT_DIR/control-tower/verify-parallel.sh"`，D540 后只做可用性探针、不执行）⇒ `verify-parallel.sh` 被实测为 `pre-push`，与本批 `run_by: gitea-ci` 仍不一致。真修须动 `scripts/pre-push-check.sh` 或生成器 join 规则（均非本批写集，受保护路径）⇒ 上报 L1 裁定。
- ⑤ 同上机制的副作用：根级重复件 `scripts/check-brief-vs-code.sh` 因 basename 与 `scripts/workflow/check-brief-vs-code.sh` 相同，`gate_meta` 被生成为 `gitea-ci`（其 `run_by` 段按派单要求**未动**，仍 github-ci）。该件在 `retired` 段已登记退役，配额 `quota: false`，不影响三桶数字。
- ⑥ #1234 的 `ci-step` 证据映射注释**本批无需补**：`gate_meta.rows` 六字段无 `evidence` 字段；本批不改任何 step 名，既有 5 条映射不失效。⚠️ 更正一处预期：`grep -c 'evidence: ci-step' docs/authority/GATE-INVENTORY.yaml` 实测 **5**（不是 0），位于 `classification:` 段 L1009／L1102／L1207／L1229／L1275（对应 check-board-truth／check-gate-protection／check-registry-invariants／check-test-obligations／check-ci-empty-green），与本批 6 条无交集。
- ⑦ GitHub 腿「绿」**须队外/合并后核**：本机无 GitHub 凭据（gh 未登、无 ssh key、无 token），GitHub 腿不能触发/观测；本批 GitHub 侧证据全是静态自证（YAML 解析、diff、grep 阈值、两个配对测试）。
