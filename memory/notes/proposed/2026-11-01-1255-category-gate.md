# #1255-T5 ⑤ 基线 category 标注 ＋ 机检（`category≠integration` 行数）

- **状态**: proposed
- **日期**: 2026-11-01
- **批次**: P4 门禁自身可靠性批次 **T5**（#1255）｜分支 `ct/1255-category-gate`（本轮在 T4 分支基础上续做，落地时拆 PR）
- **授权**: CTO 会话｜判据源：GATE-STANDARD v3.1 §十二 ⑤ ＋ §二 两腿分工

## 一、现状

- `scripts/control-tower/required-checks-baseline.txt` 是 `check-gate-integrity.sh` 的 C 段参与集**生产单源**（D1219），
  同时被 `check-required-contexts.py`（⑧）读取；两处都只取 `|` 前的 name ⇒ **加字段是向后兼容的**。
- 但 9 行**一条 `category` 都没有** ⇒ 标准 §十二 ⑤ 的判据（`category≠integration 行数＝0`）**从未被机检**。

## 二、决定

- 给 9 行逐条**如实**标注 `category=`（枚举与 GATE-INVENTORY 同词表：integration/quality/discipline/advisory/mixed）。
- **在既有脚本里加一个模式**，不新建脚本：
  `python3 scripts/control-tower/check-required-contexts.py --category-gate [--category-advisory]`
  - 输出 `REQUIRED-CATEGORY: total= integration= non_integration= missing=`
  - 违规逐条 `REQUIRED-CATEGORY-VIOLATION: <name> category=<c>`
  - 三态：0 通过／1 违规／2 判不了（基线缺失走既有 `Degrade` ⇒ exit 2）
  - `--category-advisory`：违规仍 exit 0（W8 清理前的过渡态，数值照出）
- **不改 ruleset**（`main-protect` 9 条 context 的清理是 W8，admin 在创始人）。

## 三、依据与证据（本轮实测）

```
REQUIRED-CATEGORY: total=9 integration=1 non_integration=8 missing=0
REQUIRED-CATEGORY-VIOLATION: Checker Review (maker/checker) category=discipline
REQUIRED-CATEGORY-VIOLATION: Control Tower Gate Tests (ubuntu-latest) category=discipline
REQUIRED-CATEGORY-VIOLATION: Golden Case F1 Gate category=quality
REQUIRED-CATEGORY-VIOLATION: Test-Kit Architecture Tests (ubuntu-latest) category=quality
REQUIRED-CATEGORY-VIOLATION: PR 元信息门禁 (docs/evidence/write-set) category=discipline
REQUIRED-CATEGORY-VIOLATION: Vitest (1/2) category=quality
REQUIRED-CATEGORY-VIOLATION: Vitest (2/2) category=quality
REQUIRED-CATEGORY-VIOLATION: Gate Integrity (pattern sentinel + injection fixture + ci-reds) category=discipline
```

**这是本轮最重要的一个事实**：GitHub 分支保护的 9 条必需 context 里，**8 条是纪律/质量**，
与 §二「GitHub＝集成测试腿（只报）」**结构性冲突**。W2 批C 只让它们 step 级不阻断（job 仍绿），
但**规则层面仍在要求**这些 context ⇒ ⑤ 不可能自然转绿，**必须 W8 清 ruleset**（admin 在创始人）。

配对测试：`tests/control-tower/check-required-contexts.test.sh` **51 通过 / 0 失败**（新增 9 例）。
⑧ 静态面复跑仍 `REQUIRED-CONTEXTS: OK（9/9 命中）`。

## 四、边界与失效条件

- 只标注**当前 ruleset 里实际存在的 9 条**；ruleset 变更后须按文件头重放命令重取并重新标注（否则基线漂移）。
- `category` 是**人工判定**（哪条腿该判什么），不是从数据派生；判错会导致 W8 清错 ⇒ 每条都写进本 Note 供复核。
- 本件不动 `check-gate-integrity.sh` 的 C 段逻辑（它只取 name，加字段无影响 —— 已实测）。
