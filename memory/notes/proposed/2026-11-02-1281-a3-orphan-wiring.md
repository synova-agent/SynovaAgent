## 二、决定

- 给 `check-customer-deps.ts` 一条**正式调用通道**（explicit authority）：
  `package.json` 增 `"check:customer-deps": "tsx scripts/control-tower/check-customer-deps.ts"`；
  `GATE-INVENTORY` 的 `run_by`: `无 → npm`，并移出 `run_by_candidates`（不再是"无主件"）。

> 🔴 **2026-11-02 独立复核更正（必须照录，防记账骗人）**：复核指出 `run_by: npm` 是**自证式**——
> 该判据的"真值面"就是 `package.json`（`check-gate-inventory.sh:309`），而 `check:all` =
> `bash scripts/pre-push-check.sh` 内**没有任何 `npm run` 循环**，所以**没有任何腿会自动执行它**。
> ⇒ 本卡能诚实说的只有：**「记账闭合（有正式调用通道），但仍不自动执行」**；
> **不能**说"接线 8/8"。要让它在每次提交/推送时真跑，须把它挂进某条腿（另卡，并计入 D3 门禁预算）。
- `--regen` 重放 `gate_meta`；`check-gate-inventory.sh` **42/0**、`--check` **OK**。

## 三、边界（不做什么，以及为什么）

- **不下调 P0 棘轮**：`check-gate-inventory.sh` 有 `SYNO_P0_FLOOR=8`（⑤ P0 计数 < floor ⇒ 红），
  把 P0 改分类来"凑 100%"会触发棘轮红，属于**把账做平而不是把事做完**。
- 不动 `check-block-paths.sh` / `auto-merge.sh`：它们已有真实调用点，属"腿外自动化"而非缺口。
- "接线"定义（本卡口径，供复核）：**腿 ∈ {gitea-ci, github-ci, pre-commit, pre-push, npm} 有 run_by**
  ∨ **仓内有非测试的真实调用点**（grep 到 `脚本:行`）。两条都不满足才算缺口。

## 四、已知限制

- 本机 worktree 无 `node_modules` ⇒ `npx tsx` 无法就地验证；**须在 CI／主树复跑一次 `npm run check:customer-deps`**。
- `npm run` 通道是"人/CI 可调用"，**不等于"每次提交都执行"**；若将来要求它进腿，需另卡（并计入 D3 门禁预算）。
