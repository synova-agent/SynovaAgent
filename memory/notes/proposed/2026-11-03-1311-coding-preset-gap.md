# 编码预设：从「知道去哪读」到「开工即知道答案」

- **状态**: proposed ｜ **日期**: 2026-11-03 ｜ **卡**: #1311
- **背景**：创始人指出 —— 一周未完成的根因不是门禁太多，而是**判定位置太靠后**：
  agent 开工时不知道「文件放哪／怎么命名／证据怎么锚／什么算不适用」，同一错误被反复判几百次。

## 一、验收判据的转变（这是本批真正的判据）

原判据：「预设包存在且格式合规」——**错**，那是交付物判据，不是目的判据。
新判据（创始人给的目的）：**一个零上下文 session 只加载该预设，能否不查文档答出四问**：
① 给控制塔脚本加检查要同改哪些文件 ② 豁免件文件名与每行格式 ③ 怎么证明判据没被改坏 ④ 新增一行 `2>/dev/null` 要注意什么。

实测旧版：四问 **0/4** 命中（persona 里 `gate-exemptions/`／`memory/notes/`／`.claude/claims/`／`命名`／`path:line`／`不适用` 全部 0 命中）。

## 二、做法：把答案写进 D0（不新增门禁）

persona 新增「开工四问」块（20 行），直接给答案：固定路径、命名规则（带 Issue 号）、
证据锚（`path:line@sha` / 三态 0/1/2 / 改坏必红 / `E_<CODE>`＋JSON 日志）、高频红线
（`2>/dev/null` 需同行 `swallow-ok`、`python3` 带 `PYBIN`、改控制塔脚本须同名配对测试、禁 `--no-verify`/`--force`/`git stash`）。

**为什么不做门禁**：语义项机检必假绿，且要占 45 配额、每次提交付耗时 —— 正是要退的旧循环。

## 三、附带修掉的两个真实缺陷

1. **`install-dsh-preset.sh` 只写 bundles、不写 dependencies**（preset-authoring「落盘机制」要求两处都登记）。
   后果：profile 重装/prune 时该包被当多余清掉 → 选择器里消失且**看不出原因**。实测：`CONSISTENT` 但 `dependencies` 缺。
   已修：安装时同时写 `dependencies[包名] = file:<bundle 源绝对路径>`，幂等（第二次输出"既有"）。
2. **`dsh-code-standards` 的 B1–B6 证据锚点全部失效**（旧锚 `dsh-*/lib/index.js`，该版本源码已改成 `packages/<域>/<包>/src/*.ts`）。
   已校准到 v0.2.1-rc.2 真实路径，双轨逐字节一致。

## 四、已知限制

- 预设**只对新会话生效**（DSH 启动时叠加 bundle）⇒ 「四问达标」必须在**新开会话**里验；本批只做了内容与落盘验证。
- `dependencies` 的 `file:` 路径指向**当前 worktree**；合入 main 后须从主仓重跑一次 `--install` 使路径指向主仓（否则删 worktree 会悬空）。
- 「开工四问」是**答案快照**：门禁语义变更时必须同步改这一块（它是 D0 载体，不进机检，易漂移）——靠 PR 评审看。
