决策: 将九条付费客户最小闭环行为纳入核心门无条件回归
理由: 受影响测试无法发现无关任务改坏既有用户行为，必须用真实入口守住既有能力
---

## 现状

核心门此前只无条件运行契约测试，再按变更集运行受影响测试；任务 B 改坏未关联的既有行为 A 时可能无测试报警。首批行为覆盖首启配置、建档、资料入图、普通对话、经营测量、诊断报告、桌面趋势、行动闭环与 GA 校准。

## 决定

新增 `tests/user-visible/`，使用真实 Express 路由、HTTP、SQLite、JWT/RBAC、生产桌面 loader/store/controller 和渲染组件。外部模型只由本地 OpenAI 兼容 HTTP 端点替代，内部 provider、SSE、诊断引擎与存储不 Mock。核心 runner 新增独立、无条件 user-visible 阶段，日常修改该目录不进入 trusted regex。

## 依据

CTO 在 Issue #1367 评论 11616 批准九条清单、外部模型传输边界和一次性受信接入。新增 shell 配对测试使 SEALED 执行集口径 scan 从 225 增至 226，slack 从 10 增至 11；同批将 FACE-TOTAL 从 215 最小上调至 216，保持 slack=10，不改 SLACK-CAP 或隔离台账。

## 生效时点

正常全量回归、两个核心配对 harness、类型检查、核心门正常绿与隔离副本反例红分别取证后，随本 PR 提交生效；反例只在隔离副本执行，不进入交付树。
