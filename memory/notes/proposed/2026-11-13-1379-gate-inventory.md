# 决策: #1379 历史门禁残余先盘点后删除

状态: proposed
日期: 2026-11-13

## 现状

新核心门已切换，旧 `local-gates` 仅手动，但仓内仍有旧治理检查、配对测试、豁免、claim 与登记条目。旧台账的部分退役理由已漂移：例如 `check-customer-deps.ts` 后续已有 npm 消费入口，`check-board-truth.ts` 的旧 `wired_to` 则只剩注释和独立实现，不能照旧账机械删除。

## 决定

第一阶段只交付一份带机器证据的退役候选清单及必要配套登记，不删除任何对象。候选区分删除、保留手动与留档；Secrets、真实测试、核心门、条件保留面与当前安全守卫不纳入直接删除。第二阶段须由 CTO／创始人批准清单后逐项开 PR，先摘调用再删文件，并重新证明无活调用链。完整 pre-commit 暴露旧台账漏登现存 `gitea/core-gates`，随后发现旧校验器 `WF_IDS` 也硬编码拒绝该 workflow；经用户明确批准，本批仅补登该当前 workflow 并在旧校验器合法集合增加一行兼容，配对断言改为枚举实际 workflow／run_by 数并修正 N2 作用域夹具，不新增门禁、不改退役状态。
